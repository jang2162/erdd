# 비전과 타깃

## 제품 정의

**ERDD**은 웹 기반 ERD 협업 SaaS다.

> 웹에서 ERD를 실시간 협업으로 설계하고, 한국 실무의 명명 체계(단어·용어·도메인)와 산출물까지 관리하며, CLI로 코드베이스와 AI agent에 연결된다.

[dbdiagram.io](https://dbdiagram.io/)를 벤치마킹하되, 편집 모델은 DSL 중심이 아닌 **GUI 중심**으로 하고, 글로벌 도구가 다루지 않는 **한국 실무의 명명 체계와 산출물 관리**를 핵심 차별화로 삼는다.

## 문제 인식

1. **ERD 도구와 산출물 관리의 단절.** 한국 SI/공공 프로젝트는 단어사전·용어사전·도메인정의서·테이블정의서 같은 산출물을 요구한다. 대부분의 팀이 ERD 도구 따로, Excel 산출물 따로 이중 관리하며, 시간이 지나면 둘이 어긋난다.
2. **명명 관리 기능의 부재.** dbdiagram.io 등 글로벌 도구에는 논리명/물리명 이원 관리, 단어사전 기반 물리명 생성·검증이라는 개념 자체가 없다.
3. **코드베이스와의 단절.** 설계는 웹이나 문서에 있고 실제 스키마는 코드(마이그레이션, ORM)에 있다. 사람도 AI agent도 "이 프로젝트 DB 설계의 진실 원천"을 찾기 어렵다.
4. **데스크톱 모델링 도구의 한계.** DA#, exERD 등은 기능은 강력하지만 고가 라이선스에 설치형이라 협업·웹 접근성이 떨어진다.

## 타깃 사용자

| 우선순위 | 대상 | 핵심 니즈 |
|---|---|---|
| 1 | 한국 SI/공공 프로젝트의 DA, DB 설계자, 개발 리더 | 표준 명명 체계 준수, 산출물 자동화, 이력 관리 |
| 2 | 스키마 설계를 문서화하려는 일반 개발팀/스타트업 | 쉬운 GUI 편집, 협업, 코드베이스 동기화 |
| 3 | AI agent 기반 개발 워크플로를 쓰는 팀 | 스키마의 단일 진실 원천, agent가 조회·수정 가능한 인터페이스 |

## 경쟁 분석

| | dbdiagram.io | ERDCloud | DA# / exERD | drawDB |
|---|---|---|---|---|
| 편집 모델 | DSL(DBML) 중심 | GUI 중심 | GUI 중심(설치형) | GUI 중심 |
| 실시간 협업 | 제한적 | 지원 | 없음 | 없음 |
| 논리/물리명 이원 관리 | 없음 | 지원 | 지원 | 없음 |
| 단어/용어/도메인 사전 | 없음 | 부분적 | 지원 | 없음 |
| 산출물(정의서) 내보내기 | 없음 | 부분적 | 지원 | 없음 |
| 버전/스냅샷 | 제한적 | 제한적 | 파일 기반 | 파일 기반 |
| 코드베이스/CLI 연동 | 없음 | 없음 | 없음 | 없음 |
| AI agent 연동 | 없음 | 없음 | 없음 | 없음 |
| 형태 | SaaS | SaaS(무료 중심) | 유료 설치형 | 오픈소스 웹 |

ERDD은 **"ERDCloud의 접근성 + DA#의 명명·산출물 체계 + dbdiagram.io에도 없는 코드베이스/AI 연동"** 조합을 노린다.

## 차별화 포인트

1. **단어–용어–도메인 3단 명명 체계 내장** — 행안부 표준 체계와 호환. 물리명 자동생성, 미등록 단어 경고, 공용 사전(행안부 등)을 서비스 차원에서 제공.
2. **산출물 자동 생성** — 테이블정의서, 단어/용어/도메인 정의서를 Excel로 즉시 내보내기. 커스텀 항목 포함.
3. **그룹 단위 설계 관리** — 업무 영역별 그룹핑, 그룹별 독립 배치와 분리 조회.
4. **CLI + 에이전트 스킬** — 스키마를 코드베이스에 파일로 pull/push. AI agent가 CLI로 설계를 파악하고 수정하는 워크플로를 스킬로 제공.
5. **실시간 협업 + 버전/스냅샷** — Figma 수준의 동시편집, 자동 이력, 명명 스냅샷과 diff.

## 수익 모델 (초안)

구독제. 무료 티어(개인, 프로젝트 수 제한)와 조직 플랜(멤버 수 기반)을 기본 구도로 하되, 상세 설계는 Phase 4(로드맵 참조)에서 진행한다.
