# 컬럼 이름 형식 템플릿 — 만들지 않기로 한 결정과, 만든다면의 설계

**작성:** 2026-08-20 / **상태:** 결정(만들지 않는다) / **코드 변경:** 없음 /
**대체하는 것:** 이월 항목 「컬럼 물리명 템플릿 — 요청 밖」

---

## 0. 이 문서를 읽는 법

이 문서는 두 가지를 한 번에 한다.

1. **결정** — 컬럼 물리명·논리명에 형식 템플릿을 **두지 않는다.** 근거는 2절이다.
2. **설계** — 그럼에도 만들기로 뒤집을 때 **처음부터 다시 조사하지 않아도 되게** 설계를 3절에
   그대로 실어 뒀다. 3절만 떼어 읽으면 그것이 곧 설계서다.

「범위 밖」과 「의도적으로 두지 않는다」는 다른 말이다. 앞엣것은 요청이 없었다는 사실 진술이고,
뒤엣것은 근거를 요구한다. 이 문서가 그 근거다.

## 2. 결정 — 만들지 않는다

### 2.1 (가장 무겁다) 컬럼 최종 이름에 접두가 붙으면 용어 체계와 정면으로 부딪힌다

`docs/13-naming.md` 의 3단 체계 표는 용어를 이렇게 정의한다.

> Term(용어) | 회원번호 = [회원]+[번호] → `MBR_NO`, … | **컬럼 논리명과 1:1로 대응하는 표준 명칭**

이 제품의 명명 체계는 **행안부 표준 체계와 호환**을 목적으로 하고, 그 체계에서 **컬럼 물리명은
표준용어의 물리명 그 자체**다. 컬럼 물리명 템플릿을 두면 최종 컬럼명이 `ORD_MBR_NO` 가 되어
용어의 표준 물리명 `MBR_NO` 와 **정의상 항상** 어긋난다.

그런데 **경고조차 뜨지 않는다.** 용어 불일치 검사는 부분 기준이어야 하고(테이블 템플릿 설계 D1 이
정한 경계 — 조합 이름과 비교하면 접두 때문에 항상 불일치가 난다), 부분은 `MBR_NO` 라 일치하기
때문이다. 즉 **표준을 벗어난 이름이 조용히 산출물로 나간다.**

테이블에는 같은 문제가 없다. 테이블은 용어 1:1 대상이 아니고, 조직 접두(`TB_`·그룹 약어)는 표준
체계 바깥의 조직 관례라 템플릿이 그것을 흡수하는 것이 자연스럽다. **이 비대칭은 실수가 아니라
문서에 적힌 설계다.**

### 2.2 테이블 템플릿을 정당화한 검사 근거에 컬럼 대응물이 없다

테이블 템플릿의 핵심 근거(설계 D3)는 **중복 검사가 최종 이름 기준이라야 옳다**는 것이었다 —
다른 그룹의 두 테이블이 부분은 같아도(`ORD`) 최종이 갈리면(`TB_MBR_ORD` · `TB_PRD_ORD`) 충돌이
아니다. 그 판별력이 조합을 검사에 배선할 값을 만들었다.

**컬럼에는 그 대응물이 없다.** 컬럼 물리명 중복은 「같은 테이블 안」에서만 본다
(`warnings.ts` 1번 블록). 그런데 컬럼 템플릿의 접두 재료는 전부 테이블 스코프(테이블 이름·그룹)라
**한 테이블 안에서 접두가 상수**다. 접두가 상수면 부분 중복 ⟺ 최종 중복이므로 조합해도 판정이
한 건도 안 바뀐다.

판별력이 생기는 것은 컬럼 스코프 변수(`{논리명}` 과 `{커스텀:항목이름}` 의 컬럼용 항목 — §3.1 표의
스코프 열)를 접두에 쓸 때뿐인데,
그것은 현실적인 템플릿이 아니고 3.3 의 왕복 제약이 어차피 금지한다.

**남는 검사 값은 길이(30바이트)·예약어 둘뿐이다.** 그 둘은 진짜다 — 접두가 30바이트 예산을
말없이 먹는다. 다만 값의 크기가 이 규모의 사이클을 정당화하지 못한다.

### 2.3 왕복 비용이 방금 닫은 것을 다시 연다

직전 사이클이 머릿말(`erdd:v2`)로 **테이블 왕복을 닫았다.** 컬럼 템플릿을 얹으면 셋 중 하나다.

| 안 | 대가 |
|---|---|
| 머릿말에 컬럼 항목을 싣는다 | 한 줄이 **약 19배**(2.4) |
| 왕복을 깨진 채로 둔다 | 방금 닫은 구멍을 컬럼 쪽에서 다시 연다. 문서가 「테이블은 닫혔고 컬럼은 깨진다」로 갈라진다 |
| 제약을 걸어 결정론적으로 역분해한다 | 크기 문제는 사라지지만(3.3) **새 개념**(제약을 지키는 템플릿만 왕복이 닫힌다)이 하나 는다 |

셋째가 가장 낫고 3절이 그것을 설계했다. 그래도 사이클 하나의 절반을 왕복에 쓰게 된다.

### 2.4 머릿말 19배 — **산술 추정치다(실측 아님)**

아래는 실제 덤프를 측정한 값이 **아니라** 다음 가정으로 계산한 수다.

- 지금의 테이블 항목 한 개: `"TB_MBR_ORD":{"p":"ORD","l":"주문"}` — 33자,
  한글 2자가 UTF-8 로 3바이트씩이라 **37바이트**
- 컬럼 항목 한 개(가정): `"ORD_MBR_NO":{"p":"MBR_NO","l":"회원번호"}` — 38자,
  한글 4자 → **46바이트**
- **테이블당 컬럼 15개**로 가정 → 컬럼 몫 **690바이트/테이블**
- (37 + 690) / 37 ≈ **19.7배**
- **100테이블** 모델: 약 3.6KB → 약 71KB(1KB = 1024바이트). 그것도 `serializeNameMeta` 의 계약상
  **개행 없는 한 줄**이다.

컬럼 수·논리명 길이가 다르면 배수도 달라진다. 자릿수(≈20배, 파일 머리에 수십 KB짜리 한 줄)를
말하는 수치로만 쓰라.

### 2.5 요청이 없고, 비용은 세 트랙 중 가장 크다

3사이클째 이월 목록에 「요청 밖」으로만 적혀 있었고 사용자 요청이 한 번도 없었다. 비용은 3절이
보여 준다 — 배선 19자리 + 엔진 분리 + `NamingRules` 필드(필드 하나에 저장소 전역 리터럴 11곳이
깨진 전례가 있다) + 왕복 + web 설정·미리보기 + CLI + 문서.

## 3. 그래도 만든다면 — 설계 (구현하지 않는다)

**범위:** 컬럼 **물리명만.** 논리명 템플릿은 더 뒤다(테이블 사이클이 물리→논리 순서로 간 것과 같은
이유 — 엔진을 물리명으로 검증한 뒤 재사용한다).

### 3.1 변수

| 변수 | 값 | 스코프 |
|---|---|---|
| `{물리명}` | 컬럼 물리명 **부분** | 컬럼 |
| `{논리명}` | 컬럼 논리명 부분 | 컬럼 |
| `{테이블물리명}` | 소속 테이블의 물리명 **부분** | 테이블 |
| `{테이블논리명}` | 소속 테이블의 논리명 부분 | 테이블 |
| `{그룹별칭}` · `{그룹명}` | 소속 테이블의 그룹 | 테이블 |
| `{커스텀:항목이름}` | **컬럼용** 커스텀 항목 값 | 컬럼 |

⚠️ **`{테이블물리명}` 은 조합 결과가 아니라 부분이다.** 테이블 템플릿의 불변식(변수는 언제나 저장된
부분을 돌려준다)을 그대로 따른다 — 그래야 재귀가 원리적으로 성립하지 않는다. 그 대가로 **DDL 에
찍히는 테이블 이름과 이 변수의 값이 다르다**(`TB_MBR_ORD` vs `ORD`). 도움말과 미리보기에 반드시
적어야 하는 함정이다.

⚠️ **실제로 쓸모 있는 형식은 사실상 `{테이블물리명}_{물리명}` 하나다.** 그리고 그것이 쓸 만한
것은 **테이블 템플릿을 함께 쓰는 프로젝트뿐이다** — 안 쓰면 테이블 부분이 `TB_MBR_ORD` 라
`TB_MBR_ORD_MBR_NO` 가 되어 30바이트를 즉시 넘긴다.

⚠️ **테이블에는 그룹의 `alias` 같은 「조합 전용 짧은 식별자」가 없다.** 테이블 템플릿은 직전
사이클이 `TableGroup.alias` 를 먼저 만들어 둔 덕에 성립했다. 컬럼 템플릿의 자연스러운 재료는
`Table.alias` 인데 그런 필드는 없다. **만들 거면 그 필드를 먼저 논의하라**(5절 재검토 조건).

### 3.2 검사 경계

| 최종(조합) 기준 | 부분 기준 |
|---|---|
| 길이(`maxLengthBytes`) · 예약어 | 용어 불일치 · 미등록 단어 · 논리명 구분자 · `required-empty` |

배선 지점은 `warnings.ts` 의 컬럼 루프 한 줄이다 — 지금은 `checkNamingEntity('column', …)` 가
`finalName` 인자를 **일부러 안 넘겨** 부분으로 떨어지고, 여기에 조합 결과를 넘기면 된다.

⚠️ **같은 테이블 안 물리명 중복은 배선하지 않는다.** 3.3 의 제약을 지키는 템플릿에서는 접두가
테이블 안에서 상수라 조합이 **단사**이고, 판정이 바뀌는 입력이 존재하지 않는다(2.2). 배선하면
**판별력 있는 테스트를 만들 수 없는 코드**가 하나 늘어난다. 제약을 어긴 템플릿은 왕복도 이미
포기한 상태이므로 그쪽에 일반성을 맞출 이유가 없다.

### 3.3 왕복 — 제약을 걸면 역분해가 **결정론적**이다 (이 트랙이 새로 알아낸 것)

테이블 사이클은 역분해를 **원리적으로 모호하다**고 판정했다(설계 D2): `TB_MBR_ORD_DTL` 을
`TB_{그룹별칭}_{물리명}` 로 가르면 「그룹=MBR, 부분=ORD_DTL」과 「그룹=MBR_ORD, 부분=DTL」이
둘 다 맞는 문자열이다. **자유 변수 둘이 인접해 있는 것이 모호성의 원인이다.**

컬럼에는 그 원인을 **제약으로 배제할 수 있다.**

> **제약:** 컬럼 물리명 템플릿은 `{물리명}` 을 **정확히 한 번** 포함해야 하고, 나머지 변수는 전부
> **테이블 스코프**여야 한다(`{논리명}` · `{커스텀:…}` 금지).

이 제약 아래에서 한 테이블의 모든 컬럼의 조합 결과는 `A + 부분 + B` 꼴이고 **A·B 는 그 테이블에서
상수**다. 가져오기는 이렇게 한다.

1. 머릿말이 테이블의 부분 이름을 이미 복원해 준다(기존 v2 동작).
2. 최상위에 **컬럼 템플릿 문자열 한 필드**(`ct`, 약 40바이트)를 싣는다.
3. 그 테이블 문맥으로 `compose(ct, 물리명=SENTINEL)` 을 한 번 계산해 SENTINEL 앞뒤를 A·B 로 얻는다.
4. 컬럼 이름에서 A 접두와 B 접미를 벗기면 **부분이 정확히 나온다.** 추측이 없다.
5. 안 벗겨지면(손으로 고친 이름 · 남의 DDL · 머릿말을 지운 파일) 통째로 부분 — **지금 동작으로
   자연스럽게 떨어진다.**

**머릿말은 파일당 약 40바이트만 는다.** 2.4 의 19배가 사라진다.

⚠️ **못 잡는 경계 하나:** 부분이 빈 컬럼은 접기 규칙이 A·B 를 바꾸므로 SENTINEL 로 잰 A·B 와
어긋난다. 부분이 빈 컬럼은 `required-empty` 대상이라 실사용에서 드물지만, **못 잡는다는 것을
알고 두어라**(그 컬럼만 옛 동작).

⚠️ **제약을 어긴 템플릿은 막지 말고 `ct` 를 안 싣는다.** 설정 화면이 「이 형식에서는 왕복이
닫히지 않는다」를 알리고, 그 프로젝트의 산출물은 컬럼 왕복만 옛 동작이 된다. 형식 입력을 거절하면
설정 화면이 모델을 죽이는 자리가 된다(테이블 템플릿이 「알 수 없는 변수는 빈 값」으로 피한 것과
같은 철학).

### 3.4 배선 19자리

**「19」는 조합 이름을 써야 하는 자리를 센 수다.** `warnings.ts` 의 2 는 **검사 둘**(길이·예약어)이고,
그것을 켜는 **호출 지점은 컬럼 루프 한 줄**이다(§3.2) — 두 수는 세는 대상이 다르다.

| 파일 | 자리 |
|---|---|
| `ddl.ts` | 컬럼 정의 · `CHECK (…)` · PK 목록 · FK 자식 컬럼 · FK 부모 컬럼 · 인덱스 컬럼 · 인라인 코멘트 · `COMMENT ON COLUMN` · `hasEmptyPhysicalName` · `ddlWarnings` 라벨 (10) |
| `dbml.ts` | 컬럼 정의 · note · PK 목록 · 인덱스 컬럼 · `Ref` 자식 · `Ref` 부모 (6) |
| `excel-sheets.ts` | 컬럼 정의서의 물리명 열 (1) |
| `warnings.ts` | 길이 · 예약어 (2) |

⚠️ **DDL 의 컬럼 정의 · PK · FK · 인덱스 · 코멘트가 전부 같은 조합 이름을 써야 한다.** 하나만
안 바뀌면 DDL 이 통째로 깨진다(문법은 맞고 실행이 실패한다). 테스트가 그 다섯을 함께 본다.

⚠️ **엔진의 `resolveVar` 가 `Table` 타입에 묶여 있다.** 컬럼용 해석기를 형제로 뽑되 `compose`
몸통과 접기 규칙은 공유한다(논리명 사이클의 D4 와 같은 형태).

### 3.5 저장·서버·CLI

`NamingRules.columnPhysicalTemplate: string`(기본 `''`). 비면 `column.physicalName` 을 그대로
돌려준다 — 소비처는 템플릿 유무를 모른다.

⚠️ **`NamingRulesStrictSchema` 에 같은 키를 다시 적어야 한다.** `.extend` 로 덮지 않으면 읽기
스키마의 `.default('')` 를 물려받아 **키를 안 보낸 `project.update` 가 설정해 둔 템플릿을 지운다.**
같은 자리에서 두 사이클이 연속으로 실증으로 잠갔다.

마이그레이션 없음(jsonb 읽기 시점 주입). CLI `config.ts` 는 옵셔널 키 하나.

### 3.6 UI

- **프로젝트 설정** — 「컬럼 물리명 형식」 입력란 하나 + 미리보기. 제약 위반이면 왕복 안내를 함께 낸다.
- **컬럼 편집 패널** — `물리 → ORD_MBR_NO` 한 줄. **`NamePair` 에 새 prop 을 뚫을 필요가 없다** —
  컬럼의 「용어 등록」이 쓰는 `extra` 렌더 prop 이 이미 두 입력란 아래 슬롯이다.
  ⚠️ 논리명 사이클 설계 3.4 의 「`NamePair` 에 슬롯을 뚫지 마라 — 컬럼에는 템플릿이 없다」는
  근거가 이 안에서 **무효가 된다.** 그 결정을 다시 읽고 시작하라.
- **캔버스 컬럼 행 · 사이드바 · 클립보드 · CLI 파일 · 역설계** — 부분 그대로(테이블 D3 의 경계).

### 3.7 테스트로 잠글 것

- 템플릿이 `''` 면 부분을 그대로 낸다(기존 동작 보존)
- `{테이블물리명}` 이 **조합이 아니라 부분**이다 — 테이블 템플릿을 함께 걸어 갈리는 입력으로
- **길이 초과가 최종 기준** — 부분은 30바이트 이내, 최종은 초과하는 입력
- **용어·미등록 단어·구분자 경고가 한 건도 안 바뀐다**(2.1 의 경계를 잠근다)
- DDL 의 컬럼 정의 · PK · FK · 인덱스 · 코멘트가 **모두 같은 조합 이름**을 쓴다
- 왕복 3형: 내보내고 되읽으면 부분이 돌아온다 / 머릿말을 지우면 통째로 부분 /
  **제약을 어긴 템플릿에서는 `ct` 가 안 실린다**
- 접기 규칙은 엔진 공유라 회귀만 본다(새 케이스를 만들지 마라)

⚠️ **잠기지 않는 것:** 같은 테이블 안 중복 판정(3.2 — 판별력 있는 입력이 존재하지 않는다),
부분이 빈 컬럼의 왕복(3.3).

## 5. 재검토 조건 — 언제 이 결정을 뒤집나

셋 중 하나라도 참이 되면 3절을 들고 다시 논의하라.

1. **사용자가 실제로 요청한다.** 조직 표준이 컬럼 접두를 요구해 `↻ 물리명 재생성`(용어 물리명을
   낸다)과 손으로 붙인 접두가 서로를 지우는 마찰이 보고되면, 그것이 이 기능의 진짜 근거다.
2. **테이블에 조합 전용 짧은 별칭(`Table.alias`)이 생긴다.** 그러면 `{테이블별칭}` 이
   `{테이블물리명}` 보다 나은 재료가 되어 3.1 의 함정이 사라진다.
3. **용어 체계가 「컬럼 물리명 = 용어 물리명」 1:1 을 포기한다.** 2.1 이 통째로 무효가 된다.
