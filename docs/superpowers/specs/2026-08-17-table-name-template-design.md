# 테이블 물리명 형식 템플릿 — 설계

**작성:** 2026-08-17 / **상태:** 사용자 확정 / **마이그레이션:** 없음(jsonb) /
**서버 변경:** 스키마 파싱 · **core 변경:** 조합 엔진 + 산출물 4곳 · **CLI 변경:** config 옵셔널 키

---

## 1. 목적과 범위

**테이블 물리명을 「접두 + 입력한 부분」으로 조합한다.** 조직 표준이 `TB_{서브시스템}_{업무}` 같은
형태를 요구하는데, 지금은 사용자가 그 접두를 테이블마다 손으로 반복해 친다. 그룹 별칭(직전 사이클)이
그 접두의 재료인데 **아직 쓰이는 곳이 없다** — 이 사이클이 그 소비자다.

**범위 안**

| 대상 | 하는 일 |
|---|---|
| `packages/core/src/name-template.ts` (신설) | 템플릿 파싱 · 변수 해석 · 빈 구간 접기 |
| `packages/core/src/naming.ts` | `NamingRules.tablePhysicalTemplate` + 스키마 |
| `packages/core/src/ddl.ts` | `CREATE TABLE` · FK 참조 · 인덱스 대상 · 코멘트 · 빈 이름 판정 |
| `packages/core/src/dbml.ts` | `Table` 이름 · `Ref` 양쪽 · `TableGroup` 멤버 |
| `packages/core/src/excel-sheets.ts` | 물리명 열 |
| `packages/core/src/warnings.ts` | `duplicate-physical-table` · `too-long` · `reserved` |
| `apps/server/src/routers/project.ts` | 확인만 — 이미 `NamingRulesSchema.parse`를 태운다 |
| `packages/cli/src/config.ts` | 옵셔널 키 |
| `apps/web` 설정 · 편집 패널 | 템플릿 입력란 · 미리보기 |

**범위 밖 (건드리지 않는다)**

- **논리명 템플릿** — 다음 사이클(2절 D6). 같은 엔진을 재사용한다.
- **컬럼** — 요청이 「테이블명」이다.
- **역설계 역분해**(D2) · **중복 별칭 경고** · **마이그레이션**(jsonb라 불필요).
- **CLI 파일 포맷·클립보드·사이드바** — 부분을 그대로 쓴다(D3).

## 2. 확정된 결정 (사용자 확정)

### D1. 저장은 부분만, 읽을 때 조합한다

`table.physicalName`에는 사용자가 친 `ORD`만 저장하고, 산출물은 매번 `TB_MBR_ORD`로 조합한다.

**근거:** 그룹 별칭이 바뀌면 전체가 즉시 따라간다. **대가는 「갈림이 소비처마다 걸린다」는 것**이고
그것을 알고 고른 것이다 — D3가 그 경계를 못 박는다.

### D2. 역설계는 통째로 부분에 넣는다 — 왕복이 깨진다

`CREATE TABLE TB_MBR_ORD`를 읽으면 `physicalName = 'TB_MBR_ORD'`다. 역분해하지 않는다.

**근거:** 역분해는 원리적으로 모호하다. `TB_MBR_ORD_DTL`을 템플릿 `TB_{그룹별칭}_{물리명}`로 가르면
「그룹=MBR, 부분=ORD_DTL」과 「그룹=MBR_ORD, 부분=DTL」이 **둘 다 맞는 문자열**이다.

⚠️ **수용한 결과: 템플릿이 걸린 프로젝트에서 DDL을 내보내 다시 가져오면 `TB_MBR_TB_MBR_ORD`가 된다.**
사용자가 접두를 손으로 지워야 한다. 문서에 명시한다.

### D3. 조합을 쓰는 곳과 부분을 쓰는 곳

| 조합 | 부분 |
|---|---|
| DDL · DBML · Excel | 편집 패널 입력란(+ 미리보기) |
| 중복검사 · 길이(30바이트) · 예약어 | CLI 파일 포맷 · 클립보드 · 사이드바 · 역설계 |

**근거(검사가 조합인 이유):** 실제 DB에서 충돌하는 것은 최종 이름이다. 다른 그룹의 두 테이블이
부분은 같아도(`ORD`) 최종 이름이 다르면(`TB_MBR_ORD`·`TB_PRD_ORD`) 충돌이 아니다. 길이 30바이트도
최종 이름 기준이라야 의미가 있다.

### D4. 변수는 다섯이다

`{그룹별칭}` `{그룹명}` `{물리명}` `{논리명}` `{커스텀:항목이름}`.

커스텀은 **정의 이름으로 지목한다** — 값 맵의 키가 UUID라 사람이 쓸 수 없다.

### D5. 빈 변수는 구간을 접는다

`TB__ORD` 같은 것이 안 나오게 한다(3.2에 규칙).

### D6. 물리명 먼저, 논리명은 다음 사이클

**근거:** 조합 엔진을 물리명으로 만들고 검증한 뒤 재사용한다. 물리명만으로도 DDL이 바로 바뀌어
완결된 값이 있고, 논리명은 **용어·사전 매칭과 얽혀** 판단할 것이 따로 생긴다(조합된 논리명이 용어와
비교돼야 하는가 등).

## 3. 구조

### 3.1 조합 함수 — 템플릿을 모르는 소비처

```ts
// packages/core/src/name-template.ts
export function composeTablePhysicalName(
  table: Table, model: ProjectModel, rules: NamingRules,
): string
```

⚠️ **템플릿이 `''`면 `table.physicalName`을 그대로 돌려준다.** 소비처는 이 함수만 부르면 되고
「템플릿이 있는가」를 몰라도 된다 — 분기가 소비처로 새면 20곳이 각자 판단하게 된다.

`NamingRules.tablePhysicalTemplate: z.string().default('')` — 기본값이 빈 문자열이라 **기존 프로젝트는
동작이 하나도 바뀌지 않는다.**

### 3.2 빈 구간 접기 — 규칙을 하나로 못 박는다

⚠️ 이 규칙이 애매하면 구현자마다 다르게 짠다. 하나로 정한다:

> **빈 변수는 자기 자신과 바로 뒤의 리터럴을 함께 지운다. 뒤에 리터럴이 없으면 바로 앞의 리터럴을
> 지운다.**

```
템플릿                   빈 변수      결과
TB_{그룹별칭}_{물리명}    그룹별칭     TB_ORD      (TB__ORD 아님)
{그룹별칭}_{물리명}       그룹별칭     ORD
{그룹별칭}_{물리명}       물리명       MBR
TB_{A}_{B}_{물리명}      A와 B        TB_ORD
```

파싱은 토큰 배열(`[{lit}, {var}, {lit}, {var}, …]`)로 하고, 위 규칙을 그 배열 위에서 적용한다.
정규식 후처리(`_{2,}` → `_`)로 흉내내지 않는다 — 구분자가 `_`가 아닐 수 있고 부분 이름 안의
연속 밑줄까지 접는다.

**알 수 없는 변수**(`{없는것}`)는 **빈 값으로 취급**한다. 오류를 던지지 않는다 — 설정 화면에서 오타를
쳤을 때 모델 전체가 죽으면 안 된다. 대신 설정 화면이 미리보기로 결과를 보여 주므로 즉시 알 수 있다.

### 3.3 소비처 배선

| 파일:행 | 자리 |
|---|---|
| `ddl.ts:99` | `CREATE TABLE <이름>` |
| `ddl.ts:43` | 테이블 정렬 키 — **조합 이름으로 정렬해야** DDL 순서가 최종 이름 기준이 된다 |
| `ddl.ts:101` | 코멘트 대상 + `commentText(logicalName, <조합>, comment)` — ⚠️ 「논리명==물리명이면 생략」 판정이 **조합 이름과 비교**해야 한다 |
| `ddl.ts:136-137` | FK의 부모·자식 테이블 이름 |
| `ddl.ts:158` | 인덱스의 대상 테이블 이름 |
| `ddl.ts:112` | `hasEmptyPhysicalName` — ⚠️ **조합 결과가 비었는가**로 판정한다(부분이 비어도 접두가 있으면 유효한 이름이 나온다) |
| `dbml.ts:133` | `Table <이름>` |
| `dbml.ts:124` | note의 물리명 |
| `dbml.ts:148` | `TableGroup` 멤버 목록 |
| `dbml.ts` Ref | 관계 양쪽 테이블 이름 |
| `excel-sheets.ts` | 테이블 목록·정의서의 물리명 열 |
| `warnings.ts` | `duplicate-physical-table` · `too-long` · `reserved` |

⚠️ **인덱스·제약의 자동 이름**(`IX_<테이블>_<n>`, `UX_<테이블>_<n>`)은 위 배선을 따라 **자동으로
바뀐다** — 별도 자리가 아니라 같은 한 곳에서 테이블 이름을 받아 쓴다.

⚠️ **`ddl.ts`·`dbml.ts`·`excel-sheets.ts`가 `rules`를 이미 받는지 확인해야 한다.** 안 받으면 인자를
뚫어야 하고 그 호출처가 따라 바뀐다. **`DEFAULT_NAMING_RULES`를 하드코딩해 메우지 마라** — 논리명
구분자 사이클이 정확히 그 결함을 닫았다.

### 3.4 UI

**프로젝트 설정** — 「테이블 물리명 형식」 입력란. 비우면 템플릿을 안 쓴다. 변수 목록을 도움말로 적고,
**현재 모델의 테이블 하나로 미리보기**를 보여 준다(오타를 즉시 안다).

**편집 패널** — 테이블 물리명 입력란 아래 미리보기 한 줄. **템플릿이 없으면 렌더하지 않는다.**

```
테이블 물리명 *
[ ORD                    ↓ ]
 → TB_MBR_ORD
```

### 3.5 서버·CLI

`NamingRulesSchema`에 필드를 더하면 서버는 **확인만** 하면 된다 — 논리명 구분자 사이클이
`project.get`에 `NamingRulesSchema.parse`를 이미 태워 놨다(그 사이클의 급소였다). CLI `config.ts`는
같은 패턴으로 옵셔널 처리한다.

## 4. 테스트

**core — 조합 엔진**
- 변수 5종 각각
- ⚠️ **빈 구간 접기 4형**(3.2의 표 그대로) — 이 규칙이 이 사이클의 급소다
- 템플릿이 `''`면 부분을 그대로 돌려준다(기존 동작 보존)
- 알 수 없는 변수는 빈 값
- `{커스텀:이름}` — 정의가 없거나 값이 비면 빈 값

**core — 소비처**
- DDL — `CREATE TABLE`·FK·인덱스·코멘트가 **모두 같은 조합 이름**을 쓴다(하나만 안 바뀌면 DDL이 깨진다)
- ⚠️ `hasEmptyPhysicalName` — 부분이 비어도 접두가 있으면 **DDL에 나간다**
- DBML — Table·Ref·그룹 멤버
- Excel — 물리명 열
- 경고 — **다른 그룹의 같은 부분 이름이 중복으로 잡히지 않는다**(D3의 근거를 잠근다) · 길이가 조합 기준

**server** — `tablePhysicalTemplate`가 없는 기존 행을 읽으면 `''`

**web** — 설정 입력·미리보기 / 편집 패널 미리보기(템플릿 없으면 안 보인다)

**잠기지 않는 것 (명시)**
- **왕복이 깨지는 것**(D2)은 「깨진다」를 고정하는 테스트로 남긴다 — 나중에 역분해를 넣으면 그
  테스트가 빨개져 재검토를 강제한다(MSSQL 코멘트 왕복이 같은 형태로 고정돼 있다).
