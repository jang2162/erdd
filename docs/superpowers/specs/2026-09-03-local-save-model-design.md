# 로컬 모드 저장 모델 — 명시적 저장(드래프트 계층)과 스냅샷의 git 이관 설계

**작성:** 2026-09-03 / **상태:** 사용자 확정(접근 A + 딸린 결정 넷) / **마이그레이션:** 없음 /
**서버 변경:** 없음 / **새 tRPC 프로시저:** 없다(§6 이 이유다)

---

## 1. 목적과 범위

로컬 모드(`erdd serve`)를 실제로 쓴 사용자가 낸 피드백 둘을 닫는다.

**(6) 웹에서 고치면 곧바로 파일이 바뀐다.** 명시적으로 「저장」해야 파일에 반영되게 한다. 사용자가
거슬린 지점을 둘로 특정했다.

- **git diff·커밋이 지저분해진다** — 버릴 시도·중간 상태까지 전부 실제 파일에 쌓인다. 테이블을
  만들었다 지우고, 컬럼을 넣었다 빼는 동안 `erdd/tables/*.yaml` 이 계속 쓰이고, 커밋할 때가 되면
  무엇이 의도한 변경인지 diff 로 가려내야 한다.
- **편집기 관례를 원한다** — 「편집된 것」과 「저장된 것」이 구분되고 `Cmd+S` 로 확정하는 동작.

> ⚠️ **「다른 프로세스와의 충돌」은 사용자가 문제로 꼽지 않았다.** 자동 3-way 병합은 이 설계에
> 넣지 않는다(YAGNI). 외부 변경은 **알리고 사용자가 고르게** 할 뿐이다(D2).

**(7) 스냅샷이 팀과 공유되지도 이력에 남지도 않는다.** 지금은 `.erdd/snapshots.json` — gitignore
되는 디렉터리 안의 평문 JSON 단일 파일이고, 모델 전체가 통째로 들어간다. 저장 위치를 커밋 대상인
`erdd/` 아래로 옮기고 압축해 담아 git 이력에 남긴다.

**범위:** 드래프트 계층(`FileStore` 의 쓰기 대상 전환) · 로컬 전용 저장/버리기/재읽기 HTTP 채널 ·
외부 변경 배너 · 저장 UI(버튼·표시·`Cmd+S`) · 스냅샷 새 포맷과 이행 · `status`·`validate` 의 미저장
알림 · 문서 갱신.

**범위 밖:** 자동 병합 · 파일별 부분 저장 · 저장 이력(그 자리는 git 커밋이 맡는다) · 서버 모드의
동작 변경 · 새 마이그레이션 · 새 런타임 의존성(압축은 Node 내장 `node:zlib`).

## 2. 확정된 결정 (사용자 확정)

### D1. 접근 A — 드래프트 파일 계층

`FileStore`(`packages/cli/src/local/store.ts`)의 **편집 경로는 그대로 둔다.** `model.mutate` 는
지금처럼 op 를 적용하고 `seq` 를 올리고 디바운스 타이머를 건다. **바뀌는 것은 그 디바운스가 쓰는
대상 하나다** — `erdd/` 가 아니라 드래프트 파일이다.

- 드래프트는 **파일별 diff 가 아니라 모델+배치 전체 스냅샷 한 덩어리**다. 저장 시
  `modelToFiles` → `writeTreeChanges` 가 어차피 **변경분만** 쓰므로(`tree.ts`) 드래프트를 파일 단위로
  쪼갤 이유가 없다.
- **저장 대상에 배치(`erdd/layout.yaml` — 좌표·메모)도 포함된다.** 모델과 배치는 한 덩어리다.
  테이블을 옮기기만 해도 「미저장」이 된다.
- 드래프트 파일은 **gitignore 된다**(§4.2 가 위치와 근거).
- `serve` 시작 시 드래프트가 있으면 **그것을 얹어 열고** 「미저장 변경 있음」으로 표시한다.

### D2. 외부 변경은 배너로 알리고 사용자가 고른다

미저장 드래프트가 있는데 `erdd/` 파일이 밖에서 바뀌면 배너를 띄우고 **「내 편집 유지 / 파일 다시
읽기」**를 사용자가 고른다. 자동 병합 없음.

### D3. CLI 는 파일만 본다

`validate`·`push`·`export` 는 **파일만 본다** — 저장하지 않은 것은 보이지 않는다. 대신
`status`·`validate` 가 드래프트를 발견하면 「미저장 편집이 있습니다」를 알린다.

### D4. 스냅샷은 저장된 상태만 담는다

미저장 편집으로 버전을 만들 수 없다. 드래프트가 있으면 `snapshot.create` 를 거절한다.

### D5. 저장 UI 는 로컬 모드에만 있다

헤더에 저장 버튼 + 변경 표시, `Cmd+S`. 서버 모드에는 아무것도 늘어나지 않는다.

### D6. 스냅샷은 `erdd/` 아래에 압축해 담고, **하나당 파일 하나**다

단일 파일에 몰아넣지 않는다 — 새 스냅샷이 새 blob 하나만 더하고 기존 blob 을 재사용해야 git
친화적이다. 단일 파일이면 스냅샷 하나를 만들 때마다 전체가 새 blob 이 된다.

## 3. 접근 A 를 고른 이유와 버린 안

### 3.1 지금은 「잃을 것이 없는」 상태다 — 그것을 깨뜨리는 것이 이 사이클의 진짜 비용

지금 모든 편집은 300ms 뒤 파일이다. 그래서 **프로세스가 죽어도, 브라우저가 닫혀도, 전원이 나가도
잃는 것이 없다.** 명시적 저장으로 바꾸면 「저장 안 된 편집」이라는 상태가 새로 생기고, **없던 유실
위험이 함께 생긴다.**

드래프트 **파일**이 정확히 그 자리를 메운다. 편집은 지금과 똑같이 자동으로 기록되고(디바운스도
그대로다), 다만 기록되는 곳이 커밋 대상이 아닌 곳이다. 사용자가 얻는 것은 「내 실험이 git 에 안
보인다」이고, 잃는 것은 없다.

### 3.2 버린 안 B — 메모리 드래프트

저장 전 편집을 서버 메모리에만 두고 저장 시 파일에 쓴다. 구현이 가장 작다(드래프트 파일도, 재시작
복원도 없다). **버린 이유는 §3.1 그대로다** — `Ctrl+C`·크래시·`serve` 재시작이 한 시간치 작업을
말없이 날린다. 지금은 그런 사고가 원리적으로 불가능한데, 이 사이클이 그것을 만들어 낸다면 피드백이
요구한 것보다 큰 대가를 치르는 것이다.

### 3.3 버린 안 C — 스냅샷 인프라 재사용

「저장」을 스냅샷 생성으로 구현하고 미저장 상태를 최신 스냅샷과의 차이로 본다. 새 저장소를 만들지
않아 매력적으로 보이지만 셋이 어긋난다.

- 스냅샷은 **사용자가 이름을 붙여 남기는 복원점**이다. 자동 드래프트가 그 목록에 섞이면 목록이
  자동 항목으로 뒤덮여 원래 용도가 죽는다.
- D4 가 「저장된 상태만 스냅샷 대상」이라고 정했다 — 드래프트를 스냅샷으로 구현하면 그 결정이
  자기모순이 된다.
- 스냅샷은 이번 사이클에서 **커밋 대상으로 옮겨간다**(D6). 드래프트가 그 위에 얹히면 미저장 실험이
  다시 git 에 새는데, 그것이 바로 피드백 (6) 이 없애려던 것이다.

### 3.4 그래서 A 다

A 는 기존 코드에서 **디바운스의 쓰기 대상 한 줄**을 바꾸는 것에서 출발한다. `mutate`·`setModel`·
`#serialize`·`seq`·읽기 전용 잠금은 손대지 않는다. 늘어나는 것은 드래프트 파일 하나와 그것을
「채택할지 / 버릴지」를 정하는 상태 셋(§4.3)뿐이다.

## 4. 상태 모델 — 무엇이 어디에 있는가

### 4.1 세 자리

| 자리 | 무엇 | 언제 바뀌나 |
|---|---|---|
| **파일**(`erdd/**` + `erdd/layout.yaml`) | 저장된 모델. git 이 보는 유일한 것 | **저장**할 때만. 그리고 밖에서(에이전트·`git`·`erdd pull`) |
| **드래프트**(`.erdd/draft.json`) | 저장되지 않은 편집. 프로세스가 죽어도 남는다 | 편집 300ms 뒤(디바운스). 저장·버리기가 지운다 |
| **메모리**(`FileStore.#state.model`) | 브라우저가 보는 것 = 파일 + 드래프트 | 편집마다 즉시 |

**메모리가 진실이고 드래프트는 그 사본이다.** 드래프트는 재시작을 건너뛰기 위한 장치이지 별도의
상태가 아니다 — 그래서 드래프트 파일을 사람이 고치는 것은 지원 대상이 아니다(`.erdd/` 의 다른
파일과 같다).

### 4.2 드래프트를 `.erdd/draft.json` 에 둔다

**`.erdd/` 안에 둔다.** `ensureGitignore` 가 이미 `.erdd/` 한 줄을 넣으므로 새 gitignore 규칙이
필요 없고, 그 디렉터리는 이미 「이 머신에만 있는 상태」(`base.json`·`sync.json`·`credentials.json`)의
자리다. 별도 최상위 경로를 만들면 (a) 새 gitignore 줄이 필요하고 (b) 기존 사용자의 저장소에는 그
줄이 없어 **드래프트가 커밋 후보로 뜬다** — 미저장 실험을 git 에서 없애려는 사이클이 정확히 반대
결과를 낸다.

> ⚠️ **이 사이클이 `.erdd/` 의 구성을 뒤집는다.** `snapshots.json` 은 **나가고**(§7) `draft.json` 이
> **들어온다.** 문서의 트리 그림 넷을 모두 고쳐야 한다(§10).

포맷:

```json
{
  "formatVersion": 1,
  "baseSignature": "<드래프트를 뜬 시점의 파일 서명>",
  "seq": 42,
  "updatedAt": "2026-09-03T05:25:30.000Z",
  "model": { "tables": {…}, "columns": {…}, … }
}
```

- `model` 은 **배치가 적용된 완전한 `ProjectModel`** 이다(좌표·메모 포함). D1 의 "한 덩어리".
- `baseSignature` 는 `signatureOf(tree, layout)`(`store.ts` 의 기존 함수) 값이다. **재시작 시
  드래프트가 여전히 지금 파일 위에 얹힌 것인지 판정하는 근거**다 — `serve` 가 꺼진 사이 `git pull`
  이 파일을 바꿨으면 그 사실을 알아야 한다(§5.4).
- **원자적으로 쓴다** — 임시 파일에 쓰고 `rename` 한다. 이것이 사용자의 미저장 작업 전부를 담은
  파일이므로, 쓰다가 죽어 반쪽이 남는 갈래를 만들면 안 된다.

> ⚠️ **드래프트를 읽을 때 `ProjectModelSchema` 로 검증한다 — 생략하면 조용한 데이터 손실이다.**
> 반쪽짜리 `model` 을 그대로 얹으면 `{ ...createEmptyModel(), ...model }` 정규화가 「유효한 빈
> 모델」을 만들고, 그것은 무결성 검사에 걸릴 것이 없어 통과한 뒤 **다음 저장이 사용자의 `erdd/` 를
> 통째로 비운다.** `snapshots.ts` 의 `snapshotModel` 이 막는 것과 **같은 사고이고 더 나쁘다**
> (스냅샷은 사용자가 복원을 눌러야 닿지만, 드래프트는 기동 시 자동으로 얹힌다). 같은 방어를 같은
> 방식(`ProjectModelSchema.safeParse`)으로 옮겨 심는다.

검증에 걸린 드래프트는 **지우지 않는다.** `.erdd/draft.corrupt-<타임스탬프>.json` 으로 옮기고 파일만
열며, 터미널 note 와 배너로 알린다. 사용자의 유일한 사본일 수 있는 것을 조용히 없애지 않는다.

### 4.3 `FileStore` 에 늘어나는 상태

| 이름 | 뜻 |
|---|---|
| `#base` | `{ tree, layout, signature }` — **마지막으로 채택했거나 사용자가 인정한 디스크 상태.** 저장의 비교 기준(`writeTreeChanges` 의 `base`) |
| `#external` | 디스크가 `#base` 와 달라졌는데 **사용자가 아직 고르지 않았다** |
| `#draftPending` | 드래프트 **파일에 쓸 것**이 남았는가. 기존 `#dirty` 의 역할을 그대로 물려받는 디바운스 플래그 |
| `#dirty` | **저장할 것**이 남았는가. 플래그가 아니라 **내용 비교 결과**다(§5.1) |
| `#pendingDraft` | 아직 얹지 못한 드래프트(첫 load 가 실패했을 때) |

> **`#external` 은 밖에서 온 내용을 들고 있지 않고 플래그 하나다.** 들고 있으면 그 사이 디스크가
> 또 바뀌었을 때 낡은 것을 `#base` 로 승격시킨다. 대신 `keep`·`discard` 가 **그 시점에 디스크를
> 다시 읽는다** — 두 번째 외부 변경에 대해 스스로 교정된다.

> ⚠️ **`#draftPending` 과 `#dirty` 를 하나로 합치지 마라.** 앞의 것은 「디스크에 반영할 것이
> 남았다」이고 뒤의 것은 「파일과 내용이 다르다」다 — 되돌리는 편집(A→B→A)에서 앞은 참이고 뒤는
> 거짓이다. 합치면 「미저장」 표시가 거짓말을 한다.

**`#written`·`#selfWrite` 는 사라지고 `#base.signature` 로 승격된다.** 지금의 자기 쓰기 판정은
「방금 읽은 것 == 내가 마지막으로 쓴 것」인데, 새 모델에서는 「방금 읽은 것 == 내가 아는 파일
상태(`#base`)」가 **자기 쓰기 거르기와 외부 변경 감지를 동시에** 한다. 비교식은 그대로 남고
(읽은 것 vs 쓴 것 — `load()` 전후 비교로는 판정할 수 없다는 기존 주석의 이유도 그대로다) 이름과
용도만 넓어진다.

> 🔥 **덤으로 자기 쓰기 이벤트 대부분이 아예 사라진다.** 지금은 편집 한 번마다 `erdd/` 에 쓰고
> 그 쓰기가 감시를 깨워 재로드를 부르므로, 드래그 한 번이 수십 번의 「깨웠다가 걸러내기」를 낸다.
> 드래프트는 `.erdd/` 에 있고 **`watchProject` 는 `erdd/` 와 `erdd.config.yaml` 만 본다** — 편집은
> 이제 감시를 아예 깨우지 않는다. 감시가 깨어나는 것은 **저장할 때와 진짜 외부 변경뿐**이다.

### 4.4 신규 id 되쓰기는 그대로 남는다 (그리고 함정이 하나 있다)

`#loadOnce` 는 `filesToModel` 이 발급한 id 를 **파일에 되쓴다**(`result.assignedTree`). 이것은
「명시적 저장」의 예외처럼 보이지만 유지한다 — 되쓰지 않으면 다음 로드가 또 새 id 를 발급해 같은
테이블이 매번 다른 객체가 되고(HANDOFF 3.9 와 같은 문제), 그 사이 만든 드래프트의 id 가 파일과
어긋난다. 되쓰기는 **사용자의 편집이 아니라 파일 정규화**이고, id 가 없는 파일에 대해 한 번만
일어나며 멱등이다.

> ⚠️ **되쓴 내용을 `#base` 에 반영해야 한다 — 안 하면 자기 쓰기를 외부 변경으로 오인한다.**
> 지금 코드는 되쓰기 **전**의 `tree` 를 `#tree` 로 커밋하는데, 새 모델에서는 그 직후 감시가 깨어나
> 되쓰인 파일을 읽고 `#base` 와 다르다고 판정해 **거짓 충돌 배너**를 띄운다(지금은 `#written` 이
> `modelToFiles` 결과라 우연히 가려져 있다). 되쓴 항목을 `tree` 에 반영한 뒤 커밋한다. §12 의
> 잠금 대상이다.

## 5. 라이프사이클

### 5.1 편집 → 드래프트

```
model.mutate ─▶ applyOps ─▶ #state.model 갱신, seq+1 ─▶ #draftPending=true ─▶ 300ms 디바운스
                                                                                    │
                            ┌───────────────────────────────────────────────────────┘
                            ▼
                     flushDraft()
                       next  = modelToFiles(model).tree + layoutFromModel(model)
                       sig   = signatureOf(next)
                       #dirty = (sig !== #base.signature)
                       #dirty ? 드래프트 원자적 쓰기 : 드래프트 삭제
                       #dirty 가 바뀌었으면 SSE status 브로드캐스트
```

**`#dirty` 는 플래그가 아니라 내용 비교다.** 「편집했다가 그대로 되돌렸다」가 「미저장」으로 남으면
표시가 거짓말을 하고, 저장 버튼이 쓸 것 없는 저장을 하게 된다. 비교 비용(`modelToFiles` 한 번)은
**디바운스된 드래프트 쓰기 시점에만** 든다 — 드래그 프레임마다 계산하지 않는다.

`load()` 가 하던 「다시 읽기 전에 대기 중인 편집을 먼저 flush 한다」는 **사라진다.** 그 로직은 디스크가
메모리 모델의 유일한 보관처였기 때문에 필요했다(디바운스 대기 중인 편집을 「파일에 없다」로 읽어
되돌리는 사고를 막는 자리였다). 드래프트 이후에는 **읽기가 미저장 편집을 건드릴 수 없으므로** 겹친
편집을 만난 로드는 그냥 다시 읽으면 된다.

> ⚠️ **`#commitLoad` 의 seq 가드는 그대로 남는다 — `#dirty` 로 대신할 수 없다.** 「dirty 면 채택하지
> 않는다」(§5.3)만 두면 새는 갈래가 있다: `#dirty` 는 **디바운스 뒤에야** 갱신되므로, 로드가 IO 로
> 양보하는 사이 커밋된 편집은 커밋 시점에 아직 `#dirty=false` 다. 그 상태로 디스크를 채택하면 방금
> 커밋된 편집이 조용히 되돌아간다 — 지금 `seqAtStart` 가드가 막는 바로 그 사고이고, 이유가 하나도
> 약해지지 않았다. **실패(`!ok`) 결과에는 그 가드를 적용하지 않는다는 예외도 그대로다.**
>
> 재시도 상한 `MAX_LOAD_ATTEMPTS` 도 그대로 두되, **상한에 닿았을 때 결과를 버리지 않고
> `#external` 을 세운다.** 지금은 버려도 「자기 flush 가 다시 감시를 깨운다」가 회수해 줬는데,
> 편집이 더 이상 `erdd/` 를 쓰지 않으므로 그 회수 경로가 없어진다 — 버리면 그 로드가 들고 온 외부
> 변경 알림이 통째로 사라진다. 편집이 쉼 없이 들어오는 중이면 어차피 곧 `#dirty` 이므로 §5.3 의
> 「미저장 있음」과 같은 처리로 수렴한다.

### 5.2 저장

```
POST /local/save
  ① 파일이 깨져 있으면            → ok:false, reason:'blocked'
  ② 디스크를 다시 읽어 서명 비교
       #base 와 다르면            → #external=true, SSE, ok:false, reason:'external'
  ③ writeTreeChanges(cwd, #base.tree, next.tree) + layout 쓰기
  ④ #base = next,  드래프트 삭제,  #dirty=false
  ⑤ SSE status 브로드캐스트(다른 탭의 표시도 내려간다)
  ⑥ ok:true, { seq, written[], deleted[] }
```

**②가 이 설계의 안전 계약이다 — 저장은 사용자가 보지 못한 외부 변경을 절대 덮어쓰지 않는다.**
감시(150ms 디바운스)가 늦어 배너가 아직 안 떴어도, 저장 직전의 재읽기가 구조적으로 막는다.
`written`·`deleted` 가 둘 다 비면 쓸 것이 없었다는 뜻이고 그것도 `ok:true` 다.

### 5.3 외부 변경

| 상태 | 감시가 잡았을 때 |
|---|---|
| **미저장 없음**(`#dirty=false`) | 지금과 같다 — 채택하고 `#base` 를 옮기고 SSE `reload`. 브라우저가 다시 읽는다 |
| **미저장 있음**(`#dirty=true`) | 채택하지 **않는다.** `#external=true` 로 세우고 SSE `status{external:true}`. 배너: 「파일이 밖에서 바뀌었습니다 — 내 편집 유지 / 파일 다시 읽기」 |
| **자기 저장** | 읽은 서명 == `#base.signature` → 아무 일도 없다(브로드캐스트 없음) |
| **파일 손상** | 지금과 같다 — `ok:false`, `blocked` 브로드캐스트, 편집·저장 모두 잠긴다. **드래프트는 그대로 남는다** |

사용자의 선택:

| 선택 | 엔드포인트 | 하는 일 |
|---|---|---|
| **내 편집 유지** | `POST /local/keep` | **디스크를 지금 다시 읽어** `#base` 로 삼고 `#external=false`. 모델은 그대로. 그 뒤의 저장은 **화면이 곧 파일**이 된다 |
| **파일 다시 읽기** | `POST /local/discard` | 드래프트 삭제, `#dirty=false`·`#external=false` 로 내린 뒤 `load()` 로 디스크를 채택. SSE `reload` |

> ⚠️ **「내 편집 유지」를 고른 뒤의 저장은 밖에서 추가된 파일을 지운다.** `#base` 를 새 디스크로
> 옮겼으므로 `writeTreeChanges` 가 「base 에 있는데 모델에 없는 파일」을 삭제한다 — 즉 저장 결과가
> **화면과 정확히 같은 파일 상태**가 된다. `#base` 를 옛 값으로 두면 밖에서 추가된 파일이 살아남아
> **화면에 없는 테이블이 파일에 있는** 조용한 부분 병합이 되는데, 그것은 「자동 병합 없음」(D2)과
> 어긋나고 사용자가 다음 재로드에서야 알게 된다. 배너 문구가 이 사실을 말해야 한다:
> 「내 편집을 유지하면 저장할 때 화면의 내용이 파일을 덮어씁니다.」 (§13-①)

**「파일 다시 읽기」는 확인 다이얼로그를 받는다** — 미저장 작업을 버리는 유일한 파괴적 동작이다.

### 5.4 `serve` 재시작

```
startLocalServer
  └ store.load()                 파일 읽기(+ 신규 id 되쓰기) → #base 확정
  └ store.adoptDraft()           .erdd/draft.json 이 있으면
        ├ ProjectModelSchema 실패 → draft.corrupt-<ts>.json 으로 이름 바꾸고 파일만 연다 + note
        ├ baseSignature === #base.signature → 그대로 얹는다. dirty=true
        └ baseSignature !== #base.signature → 얹고 dirty=true, **그리고 #external 을 세워
                                              외부 변경 배너를 함께 띄운다**
```

마지막 갈래가 「`serve` 가 꺼진 사이 `git pull`/`git checkout` 이 파일을 바꿨다」이다. 조용히 얹으면
사용자는 브랜치가 바뀐 줄 모른 채 저장해 남의 변경을 덮는다.

**첫 `load()` 가 실패하면(파일 손상) 드래프트를 얹지 않고 `#pendingDraft` 로 들고 있는다.** 파일이
고쳐져 로드가 성공하는 순간 그때 얹는다 — 손상 상태에서는 `#base` 가 없어 판정할 근거가 없고, 어차피
편집이 잠겨 있다.

### 5.5 종료

`Ctrl+C` → `close()` 가 대기 중인 **드래프트** 쓰기를 flush 한다(지금은 파일 flush 였다). 미저장
편집이 있으면 터미널에 한 줄 남긴다: `미저장 편집이 있습니다 — 다음 erdd serve 에서 이어집니다`.

**사용자의 편집은 저장 없이 절대 파일에 쓰이지 않는다** — 이것이 사이클의 핵심 성질이고 §12 의 첫
잠금이다. **유일한 예외는 §4.4 의 신규 id 되쓰기**이고, 그것은 편집이 아니라 「id 없이 쓰인 파일의
정규화」이며 그런 파일이 있을 때 한 번만 일어난다.

### 5.6 브라우저 새로고침 / 탭 여러 개

드래프트는 **서버가 들고 있다**(탭이 아니다). 새로고침하면 `model.get` 이 드래프트가 얹힌 모델을
그대로 주므로 미저장 편집이 살아 있다. **`beforeunload` 경고를 붙이지 않는다** — 탭을 닫아도 잃는
것이 없는데 경고를 띄우면 거짓말이다.

탭이 여럿이면 dirty 표시는 SSE `status` 로 함께 맞춰진다. 다만 **한 탭의 편집 내용이 다른 탭에
즉시 반영되지 않는다는 기존 성질은 그대로다**(자기 쓰기를 모델 재로드로 브로드캐스트하지 않는다 —
드래그가 튄다). 로컬 모드는 한 사람이 한 화면에서 쓰는 것을 전제한다.

### 5.7 스냅샷 만들기·복원

- **만들기**: `#dirty` 면 `BAD_REQUEST` — `저장하지 않은 편집이 있습니다. 먼저 저장한 뒤 스냅샷을
  만드세요`(D4). UI 는 버튼을 비활성화하고 같은 문구를 곁에 둔다.
- **복원**: `setModel` 을 타므로 **편집과 똑같이 드래프트가 된다.** 복원 직후 화면은 그 시점이지만
  파일은 아직 그대로이고, 「저장」해야 파일이 바뀐다. 지금 문서가 "복원 = `erdd/` 파일이 그 내용으로
  다시 쓰인다"고 적고 있어 그 문장이 거짓이 된다(§10).

### 5.8 `erdd.config.yaml`(방언·명명 규칙)은 드래프트 대상이 아니다

`project.update` 는 지금처럼 **즉시** config 파일에 쓴다. 그 화면에는 **이미 「저장」 버튼이 있고**
누를 때만 프로시저가 나가므로, 명시적 저장이라는 성질이 이미 성립한다. 모델과 같은 덩어리로 묶으면
설정 화면의 저장 버튼이 「진짜 저장」이 아닌 이상한 상태가 된다.

## 6. 저장 채널 — tRPC 를 늘리지 않는다 (HANDOFF 3.18)

### 6.1 제약

`router.test.ts` 의 `LocalOnly` 타입은 **서버 라우터에 없는 로컬 전용 프로시저를 전부 이름으로
뱉는다.** 「저장」은 정의상 서버에 없는 개념이므로, tRPC 프로시저로 만들면 그 잠금이 곧바로 깨진다.
그리고 더 근본적으로 **웹은 `AppRouter` 타입으로 클라이언트를 만들기 때문에 `trpc.local.save` 를
타입으로 부를 수조차 없다** — 부르려면 서버 라우터에 쓰지 않을 더미 프로시저를 만들어야 한다.

### 6.2 그래서 로컬 전용 HTTP 라우트로 낸다 — 선례가 이미 있다

`GET /local/events`(SSE)가 **이미 tRPC 밖의 로컬 전용 채널**이고, 웹은 그것을 `EventSource` 로
직접 받는다(`use-local-watch.ts`). 저장도 같은 형태로 낸다.

| 라우트 | 입력 | 출력 |
|---|---|---|
| `POST /local/save` | 없음(드래프트는 서버가 들고 있다) | `LocalSaveResult` |
| `POST /local/discard` | 없음 | `{ ok: true }` |
| `POST /local/keep` | 없음 | `{ ok: true }` |
| `GET /local/events` | — | 기존 + `status` 이벤트 |

**결과: 로컬 라우터의 프로시저 집합이 하나도 늘지 않는다.** `router.test.ts` 의 이름 목록 단언과
`InputGaps`/`OutputGaps`/`LocalOnly` 셋이 **바뀌지 않고 그대로 초록이어야 한다** — 그것이 3.18 을
지켰다는 증거다. 구현 사이클이 그 테스트를 건드리게 되면 설계에서 벗어난 것이다.

`Host` 검사 `onRequest` 훅은 라우트 전체에 걸리므로 새 라우트도 자동으로 DNS 리바인딩 방어 아래에
들어온다(설계 D8). **`POST` 인 것도 중요하다** — GET 이면 공격자 페이지의 `<img>` 한 줄로 저장이
불린다.

### 6.3 대신 프로토콜을 core 에 못 박는다

tRPC 밖으로 나가면 **타입 계약이 사라진다.** 지금도 SSE 페이로드 모양이 `server.ts` 와
`use-local-watch.ts` 에 **각각 인라인 리터럴로 두 벌** 적혀 있다 — 3.18 이 닫으려는 것과 같은 종류의
표류다. 이번에 한자리로 모은다.

**`packages/core/src/local-protocol.ts` (신규)** — `realtime-protocol.ts` 와 같은 형태(순수 타입 +
상수 + 파서, IO 없음. HANDOFF 3.5).

```ts
export const LOCAL_EVENTS_PATH = '/local/events'
export const LOCAL_SAVE_PATH = '/local/save'
export const LOCAL_DISCARD_PATH = '/local/discard'
export const LOCAL_KEEP_PATH = '/local/keep'

export type LocalLoadFailure = { path: string; message: string }

export type LocalEvent =
  | { type: 'reload' }
  | { type: 'blocked'; failures: LocalLoadFailure[] }
  | { type: 'status'; dirty: boolean; external: boolean }

export type LocalSaveResult =
  | { ok: true; seq: number; written: string[]; deleted: string[] }
  | { ok: false; reason: 'blocked' | 'external'; message: string }

/** 반환 null = 형식 오류. 모르는 type 은 null 이다(옛 웹이 새 이벤트를 만나도 죽지 않는다). */
export function parseLocalEvent(raw: string): LocalEvent | null
```

`status` 는 **접속 시에도 한 번** 보낸다(늦게 붙은 탭이 미저장·충돌 상태를 즉시 안다 — `blocked` 를
접속 시 보내는 것과 같은 이유). 기존 웹 핸들러는 모르는 `type` 을 이미 무시하므로 추가는 안전하다.

## 7. 스냅샷 — `erdd/snapshots/` 로 옮기고 압축한다

### 7.1 배치

```
erdd/
├─ tables/*.yaml
├─ groups.yaml · words.yaml · terms.yaml · domains.yaml · custom-fields.yaml
├─ layout.yaml
└─ snapshots/                     ★ 신규 — 커밋 대상
   ├─ index.yaml                  목록 메타(평문). git diff 로 읽힌다
   ├─ 018f6b0e-1111-7000-8000-….json.gz
   └─ 018f6b12-2222-7000-8000-….json.gz
```

**`readTree`/`writeTree` 는 이 디렉터리를 보지 않는다** — `TOP_LEVEL_FILES`(5개)와
`erdd/tables/*.yaml` 만 훑기 때문이다(`tree.ts`·`file-format.ts` 확인). 그래서 `erdd/` 안에 두어도
모델 파싱에 섞이지 않고, **`erdd pull` 의 `writeTree` 가 지우지도 않는다.**

> ⚠️ `watchProject` 는 `erdd/` 를 **재귀로** 감시하므로 스냅샷을 쓸 때마다 감시가 깨어난다.
> 깨어난 로드는 `readTree` 결과가 그대로라 서명이 `#base` 와 같고, 따라서 아무것도 브로드캐스트하지
> 않는다(무해). 다만 **스냅샷 하나를 만들 때마다 `readTree` + `filesToModel` 이 한 번 더 돈다** —
> 정상 동작이므로 막지 않는다. 이 사실을 주석으로 남긴다.

### 7.2 파일명은 `<id>.json.gz` 다 — 사용자 입력을 파일명에 넣지 않는다

- **id 는 uuidv7 이라 사전순 = 시간순이다**(앞 48비트가 밀리초 타임스탬프). 시각을 접두로 붙이지
  않아도 `ls` 가 시간순으로 나온다.
- **스냅샷 이름을 파일명에 넣지 않는다.** 넣으면 `unsafeFileName`(`packages/core/src/file-format.ts`)
  이 이미 푼 문제 — 경로 구분자·`.`·`..`·빈 문자열 — 를 다시 만난다. 게다가 이 프로젝트의 스냅샷
  이름은 **한국어**가 정상이고, macOS 는 파일명을 NFD 로, git 인덱스는 NFC 로 들고 있어 **같은
  파일이 플랫폼마다 다른 이름으로 보이는** 고전적인 함정에 정면으로 들어간다. 사람이 읽을 이름은
  파일명이 아니라 §7.3 의 인덱스가 맡는다.
- **id 는 접미 8자가 아니라 전체를 쓴다.** `tableFileName` 이 8자를 쓰는 것은 파일명이 물리명이라
  id 가 덤이기 때문이고, 여기서는 id 가 유일한 식별자다 — 자르면 충돌 회피 로직이 또 필요해진다.

### 7.3 목록 메타는 평문 인덱스에 둔다 — 단, **디렉터리가 진실이다**

```yaml
# erdd/snapshots/index.yaml
snapshots:
  - id: 018f6b0e-1111-7000-8000-000000000001
    name: 1차 정리
    description: 회원 도메인 정리 전
    revisionSeq: 42
    createdAt: 2026-09-03T05:25:30.000Z
```

**인덱스를 두는 이유 둘.** (a) 그것이 없으면 `git diff` 에 `.gz` blob 추가만 보여 리뷰어가 무엇이
늘었는지 알 수 없다 — 「git 이력에 남긴다」는 목적의 절반이 그 가독성이다. (b) `snapshot.list` 가
스냅샷 N 개를 전부 gunzip 하지 않아도 된다(모델 전체 사본 N 개를 푸는 것은 목록 한 번의 비용으로
과하다).

**대가는 인덱스와 디렉터리가 갈릴 수 있다는 것이다**(머지 충돌을 잘못 풀거나, `.gz` 를 손으로
지우거나). 규칙을 못 박는다.

| 상태 | `list` | `get`/`restore`/`delete` |
|---|---|---|
| 파일 O · 인덱스 O | 인덱스의 이름·설명으로 표시 | 정상 |
| 파일 O · **인덱스 X** | **표시한다** — `(이름 없음) <id 앞 8자>` | 정상(파일만 있으면 된다) |
| **파일 X** · 인덱스 O | 표시하지 않는다 | `NOT_FOUND` |

즉 **`list` = 디렉터리 스캔 ∩ 인덱스 라벨**이다. 어느 방향으로도 조용히 사라지지 않는다 — 라벨을
잃은 스냅샷도 복원·삭제할 수 있고, 파일 없는 인덱스 항목이 「있다」고 거짓말하지 않는다. 인덱스는
다음 쓰기(생성·삭제) 때 실제 디렉터리에 맞춰 정리한다.

**쓰기 순서: `.gz` 를 먼저 쓰고 인덱스를 나중에 쓴다.** 중간에 죽으면 「라벨 없는 복원 가능한
스냅샷」이 남는다(위 표의 2행) — 반대 순서면 「가리키는 파일이 없는 항목」이 남는다.

읽기-수정-쓰기는 지금처럼 단일 체인으로 직렬화한다(`updateSnapshots` 의 이유 그대로 — 탭 둘이나
빠른 연속 클릭이면 충분히 겹친다).

### 7.4 압축은 `node:zlib` 의 gzip

새 런타임 의존성을 늘리지 않는다. 내용은 지금과 같은 JSON(`{ id, name, description, revisionSeq,
model, createdAt }`)을 gzip 한 것이다.

**같은 내용이면 같은 바이트다** — Node 는 gzip 헤더의 mtime 을 0 으로 쓴다(실측). 다만 OS 바이트는
플랫폼에 따라 다를 수 있으므로 「다른 머신에서 재생성하면 같은 blob」에 의존하지 않는다. 스냅샷은
**한 번 쓰고 다시 쓰지 않는** 파일이라 이 성질에 기대는 자리도 없다.

### 7.5 기존 방어를 그대로 옮긴다

> ⚠️ `snapshotModel` 의 `ProjectModelSchema` 판정은 **새 포맷에서도 유지한다.** 이유가 하나도 약해지지
> 않았고 오히려 세졌다 — 스냅샷이 이제 **커밋 대상**이라 머지 충돌·부분 체크아웃·LFS 오설정처럼
> 「손으로 열지 않아도 내용이 반쪽이 되는」 경로가 새로 생긴다. 그리고 `.gz` 는 사람 눈에 내용이
> 안 보여 손상을 더 늦게 안다.
>
> 판정 지점은 **gunzip → `JSON.parse` → `ProjectModelSchema.safeParse`** 이고, 셋 중 어디서 걸리든
> `snapshot.get`/`restore` 는 **「스냅샷이 손상됐습니다」(`BAD_REQUEST`)** 다 — `NOT_FOUND` 로 뭉개지
> 않는다(파일이 보이는데 없다는 말을 들으면 사용자는 무엇을 고쳐야 하는지 알 수 없다). 반환값은
> 원본이 아니라 **파싱 결과**여야 한다(옛 스냅샷의 누락 컬렉션 보충이 파싱 안에서 일어난다).

### 7.6 이행 경로 — 기동 시 한 번, 자동, 소리 나게

`.erdd/snapshots.json` 을 가진 사용자는 그것을 잃으면 안 되고(그 머신에만 있는 유일본이다), 두
포맷을 오래 함께 읽는 것은 `list` 합치기·id 충돌·삭제 대상 판정이라는 부채를 남긴다.

```
serve 기동
  └ .erdd/snapshots.json 이 있으면
      · 레코드마다: 이미 erdd/snapshots/<id>.json.gz 가 있으면 건너뛴다(멱등)
      · ProjectModelSchema 를 통과한 것만 옮긴다
      · 통과하지 못한 레코드는 옮기지 않고 id·이름을 note 로 나열한다
      · 옮긴 뒤 .erdd/snapshots.json → .erdd/snapshots.json.migrated 로 이름을 바꾼다(지우지 않는다)
      · note: "스냅샷 N개를 erdd/snapshots/ 로 옮겼습니다 — 이제 커밋 대상입니다. git add erdd/snapshots"
```

- **자동 이행을 고른 이유:** 옛 파일은 gitignore 된 머신 로컬 파일이라 「둘 다 읽는 기간」이 사 줄
  것이 없다. 한 번 옮기고 옛 파일을 남겨 두면 되돌릴 길도 있다.
- **손상 레코드를 옮기지 않는 것이 요점이다** — 옮기면 손상이 **커밋 대상**으로 승격되고, 그때부터
  팀 전체가 그 파일을 본다. 남겨서 알린다.
- 이행은 `erdd/snapshots/` 에 **새 파일만 더한다**(기존 파일을 고치지 않는다).

> §5.5 의 「저장 없이 파일을 쓰지 않는다」와 어긋나 보이지만 아니다 — 이행이 만드는 것은 **모델
> 파일이 아니라 스냅샷 파일**이고, 기존 파일을 하나도 고치지 않으며, 옛 파일을 가진 사용자에게 한
> 번만 일어난다. 그리고 그 결과를 커밋 대상으로 만드는 것이 (7) 피드백의 요구 자체다.

|---|---|
| `serve` | 저장 라우트 3개, 드래프트, 스냅샷 이행. 종료 시 미저장 note |

경로를 다시 적으면 갈린다.

## 9. UI

### 9.1 헤더 (로컬 모드에서만)

```
[ERDD]                    ● 미저장  [저장]  [⋯]   버전 | 사전·리소스 | 모델 검사 | 파일 | 설정
                          └─────────┬─────┘  └┬┘
                            isLocal 일 때만    변경 버리기(확인 필요)
```

- **자리는 `project.tsx` 의 헤더**, `HeaderTools` **앞**이다. `HeaderTools` 는 다이얼로그를 여는
  도구 모음이고 저장은 문서 수준 동작이라 성격이 다르다.
- 컴포넌트 `apps/web/src/editor/local-save-controls.tsx`, 훅
  `apps/web/src/editor/use-local-save.ts`.
- **가드는 렌더 자체다** — `{isLocal && <LocalSaveControls/>}`. 서버 모드에서는 마운트되지 않으므로
  `Cmd+S` 리스너도 붙지 않는다(HANDOFF 3.18 의 「닫아 두는 것이 아니라 렌더하지 않는 것」).
- 저장 버튼은 `#dirty` 가 아니면 비활성. 파일이 깨져 `blocked` 면 비활성 + 사유 툴팁.
- **「변경 버리기」를 함께 둔다.** 피드백이 명시한 동기가 「**버릴 시도**가 diff 를 더럽힌다」인데,
  버리는 수단이 없으면 드래프트가 재시작을 넘어 살아남아 **없앨 방법이 없다.** 확인 다이얼로그를
  거친다(미저장 작업을 버리는 동작이다).

### 9.2 `Cmd+S`

- **`use-shortcuts.ts` 에 넣지 않는다.** 그 훅은 `isTypingTarget`/`isDialogOpen` 에서 **먼저
  물러나는데**, 저장을 가장 누르고 싶은 순간이 바로 편집 패널 입력란에 타이핑하던 중이다. 그리고 그
  훅은 `Canvas` 가 마운트된 동안만 산다.
- `use-local-save.ts` 가 `document` 에 자기 리스너를 단다. `(metaKey || ctrlKey) && key === 's'` 면
  **입력 중이든 다이얼로그가 열려 있든** `preventDefault()` 하고 저장한다.
- **`preventDefault` 는 로컬 모드에서만 일어난다** — 서버 모드에서 브라우저의 「페이지 저장」을
  가로채면 안 된다. 훅이 로컬에서만 마운트되므로 구조적으로 보장된다.

### 9.3 배너

`project.tsx` 는 이미 `blocked` 배너 자리를 갖고 있다. 그 아래에 외부 변경 배너를 둔다.

```
파일이 밖에서 바뀌었습니다. 내 편집을 유지하면 저장할 때 화면의 내용이 파일을 덮어씁니다.
                                            [내 편집 유지]  [파일 다시 읽기]
```

**두 배너가 동시에 뜰 수 있다**(파일이 깨진 채로 밖에서 또 바뀌는 경우). `blocked` 가 위다 — 편집이
잠긴 것이 더 급한 사실이다.

### 9.4 상태의 출처

dirty·external 은 **서버가 진실**이고 웹은 SSE `status` 로 받는다. 낙관적으로 「편집했으니 dirty」를
먼저 켜 두는 것은 허용하되(반응성), 도착한 `status` 가 이긴다 — 되돌리는 편집으로 dirty 가 내려가는
판정(§5.1)은 서버만 할 수 있다.

에디터 store 에 `localSave: { dirty, external, saving }` 를 둔다. `blocked` 와 같은 자리다.

## 10.3 다음 사이클이 붙을 자리 — `erdd apply` (2026-09-03 사용자 확정)

이 사이클의 **범위 밖**이지만, 여기서 만드는 것이 그 토대가 되므로 자리를 못 박아 둔다. 사용자가
방향을 확정했다: **에이전트는 `erdd/` 의 YAML 을 직접 고치지 않고 CLI 로 고친다.**

- **모양:** `erdd apply <ops.json>`(`-` 면 stdin) — core 의 op 포맷을 그대로 받는 얇은 명령 하나다.
  `parseOps` · `applyOps` · `MAX_OPS_PER_MUTATION` 을 그대로 재사용하므로 웹·서버·로컬과 **규칙이
  한 벌**이고, 엔티티 10종을 덮는 하위 명령 수십 개를 만들지 않아도 된다.
- **도는 서버와의 관계:** `serve` 가 떠 있으면 **그 서버로 보낸다** — 에이전트 편집이 사람의 편집과
  **같은 드래프트**에 합류해 충돌 배너가 아예 뜨지 않고 브라우저가 즉시 따라온다. 꺼져 있으면 파일에
  직접 쓴다.
- **그래서 이 사이클이 남겨야 할 것 둘:**
  1. `POST /local/apply` 가 `/local/save` 옆에 자연스럽게 붙도록 **라우트 등록을 한 함수에 모아 둔다**
     (§6.2 의 세 라우트를 각각 흩어 놓지 않는다).
  2. 실행 중인 서버를 찾는 수단 — `serve` 가 포트를 어딘가에 적어 두어야 한다. **이번 사이클에서는
     만들지 않는다**(YAGNI). 다음 사이클이 `.erdd/serve.json`(포트·pid)을 더하면 되고, `.erdd/` 는
     이미 gitignore 되어 있어 새 규칙이 필요 없다.
- **이 사이클의 D2(외부 변경 배너)는 그래도 남는다.** `erdd apply` 가 생겨도 `git pull`·
  `git checkout`·`erdd pull`·`erdd import` 가 파일을 밖에서 바꾼다. 줄어드는 것은 빈도이지 갈래가
  아니다.
- **강제는 코드가 아니라 지침이다.** 파일을 못 고치게 막을 수단이 없다(사람도 git 도 쓴다) — 금지는
  `packages/cli/skill/SKILL.md` 의 워크플로 개정으로 한다(§10.1 의 그 항목이 다음 사이클에서 한 번 더
  바뀐다).

## 12. 테스트 전략 — 무엇을 잠가야 하는가

> ERDD 의 지배적 결함군은 「아무것도 붙잡아 두지 않는 맞는 코드」다. 아래 각 항목은 **되돌리면 반드시
> 빨개져야 한다.** 특히 ①과 ②는 이 사이클의 존재 이유 자체다.

### 12.1 조용한 데이터 손실을 막는 잠금 (최우선)

| # | 잠글 것 | 되돌리면 |
|---|---|---|
| ① | **편집은 `erdd/` 를 건드리지 않는다** — mutate 여러 번 + 드래프트 flush 뒤 `erdd/**` 의 내용과 mtime 이 그대로. ⚠️ **픽스처의 테이블 파일에 `id` 가 이미 있어야 한다** — 없으면 §4.4 의 되쓰기가 파일을 건드려 이 테스트가 그 쓰기를 재는 것이 된다 | 디바운스를 파일로 되돌리면 빨개진다 = 이 기능이 실제로 있다는 유일한 증거 |
| ② | **깨진 드래프트로 파일을 비우지 않는다** — `.erdd/draft.json` 의 `model` 을 `{}`·반쪽·잘린 JSON 으로 만들어 두고 기동 → 파일이 그대로 열리고, 이후 저장해도 `erdd/**` 가 비지 않으며, 원본 드래프트가 `draft.corrupt-*` 로 남는다 | `ProjectModelSchema` 검증을 빼면 빨개진다(`snapshots.ts` 방어의 이식본) |
| ③ | **저장은 보지 못한 외부 변경을 덮지 않는다** — 감시를 끈 채 파일을 밖에서 바꾸고 저장 → `ok:false, reason:'external'` 이고 파일이 그대로 | 저장 직전 재읽기(§5.2 ②)를 빼면 빨개진다 |
| ④ | **손상 스냅샷 거절**(기존 3건: `model` 키 없음·`{}`·컬렉션 부족) + **gunzip/JSON 실패**도 `BAD_REQUEST` 이고 사용자 모델이 그대로 | 새 포맷으로 옮기며 방어를 흘리면 빨개진다 |

| # | 잠글 것 |
|---|---|
| ⑥ | 재시작 복원 — 드래프트를 쓴 뒤 새 `FileStore` 로 load+adopt → 편집이 살아 있고 `dirty=true` |

## 13. 미결 사항 (각각 추천을 단다 — TBD 로 두지 않는다)

> **2026-09-03 갱신:** **①은 사용자가 확정했다 — 「지운다」다.** 더는 작성자 판단이 아니므로
> 구현 사이클은 그대로 간다. **②는 여전히 작성자 판단**이고(사용자에게 묻지 않았다) 나머지도 같다 —
> 뒤집는 비용을 각 항목에 적어 두었으니 리뷰에서 바꿔도 태스크 하나 안에서 끝난다.

**① 「내 편집 유지」 뒤의 저장이 밖에서 추가된 파일을 지우는가.**
→ **지운다 — 2026-09-03 사용자 확정.** 근거는 §5.3 의 ⚠️ 다 — 대안(옛 base 유지)은 「화면에 없는
테이블이 파일에 있는」 조용한 부분 병합이고, 그것은 D2 의 「자동 병합 없음」과 어긋난다. **조건은
배너 문구다** — 사용자가 그 대가를 읽고 고르게 한다.
**뒤집는 비용:** `keep()` 이 `#base` 를 옮기지 않게 하고 테스트 ⑬의 단언을 반대로 적으면 된다 —
한 태스크 안이다.

**② `push` 에도 미저장 알림을 붙일까.**
→ **붙인다(추천, 계획서가 채택).** D3 이 고정한 것은 「`push` 는 파일만 **본다**」이지 「알리지
않는다」가 아니다. **뒤집는 비용:** `push.ts` 의 한 줄과 그 테스트 하나를 지우면 된다.
알림은 판정을 바꾸지 않는 한 줄이고, **미저장 편집이 실제로 새어 나가는 유일한 자리가 `push`** 다
(`validate` 는 검사일 뿐이다). `status`·`validate` 와 같은 함수·같은 문구를 쓴다.

**③ 드래프트 디바운스를 300ms 로 둘까.**
→ **그대로 둔다(추천).** 쓰기 대상이 `erdd/` 의 여러 파일에서 `.erdd/` 의 한 파일로 줄어 비용이

값이 절반으로 준다. 대가(갈릴 수 있음)는 「디렉터리가 진실」 규칙으로 갇힌다.

**⑤ 「변경 버리기」의 자리 — 헤더 vs 「파일」 메뉴.**
→ **저장 버튼 옆 오버플로(추천).** 저장과 짝이라 붙어 있어야 찾는다. 「파일」 메뉴는 가져오기·
내보내기(문서 입출력)의 자리다.

**⑥ 옛 `.erdd/snapshots.json` 을 지울까.**
→ **`.migrated` 로 남긴다(추천).** gitignore 된 파일이라 남겨도 저장소가 더러워지지 않고, 이행이
잘못됐을 때 되돌릴 유일한 근거다. 사용자가 직접 지우면 된다.

**⑦ 저장이 undo 스택을 비우는가.**

저장하는 것이 편집기 관례이고, 이 사이클의 목표가 바로 그 관례다.

**⑧ 큰 모델에서 `#dirty` 재계산 비용.**

넣으면 검증되지 않은 최적화다.
