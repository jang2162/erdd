## 1. 목적과 범위

논리명·물리명을 실제로 치는 자리(편집 패널의 테이블·컬럼)에서 **사전을 오가지 않고 이름을 완성**할 수
있게 한다. 지금은 이름을 치다 사전에 없는 단어를 만나면 흐름이 끊긴다 — 헤더 「사전·리소스 ▾」를 열고,
미등록 항목 탭을 찾고, 등록하고, 다이얼로그를 닫고, 다시 컬럼을 골라 재생성 버튼을 누른다.

걸리는 것이 다섯이다.

- **컬럼 행이 2열 가로 배치**(`edit-panel.tsx:300-305`)라 폭 320px 사이드바에서 두 이름이 다 잘린다.
  라벨을 그릴 자리가 없어 **필수 표시(`*`)도 붙지 못한다**(HANDOFF 6절 이월).
- **재생성·복원 버튼이 입력 아래 한 줄에 셋**(`edit-panel.tsx:308-317`)이라 어느 필드에 걸리는지가
  배치로 드러나지 않는다. 이름도 「재생성」/「복원」으로 갈려 무엇을 기준으로 도는지 안 보인다.
- **그 버튼들이 blur 커밋 전의 값을 읽는다**(HANDOFF 6절 이월). 치고 바로 누르면 옛 값으로 동작한다.
- **미등록 단어를 그 자리에서 등록할 길이 없다.** 사전 화면의 「미등록 항목」 탭으로 가야 한다.
- **사전 화면의 「미등록 항목」 탭이 두 방향 목록을 상하로 이어 붙여**(`dict-panel.tsx:184-197`)
  세로로 길다.

**범위 안**

| 대상 | 하는 일 |
|---|---|
| `apps/web/src/editor/name-pair.tsx` (신설) | 논리·물리명 쌍을 쥐는 컨테이너 + 필드 컴포넌트 |
| `apps/web/src/editor/edit-panel.tsx` | 테이블·컬럼의 명명 영역을 신설 컴포넌트로 교체 |
| `apps/web/src/editor/dict-edits.ts` | 등록 가능 판정 `canRegisterWord` 추가 |
| `apps/web/src/editor/dict-panel.tsx` | 「미등록 항목」 하위 탭 2개 + 두 섹션 통합 |
| `packages/core/src/naming.ts` | 자동완성 후보 산출 `suggestCompletions` 추가 |

**범위 밖 (건드리지 않는다)**

- **사전 다이얼로그의 단어·용어 편집 폼**(`WordEditDialog`·`TermEditDialog`) — 사용자 확정(2절 D1).
  그쪽은 다이얼로그 저장 버튼이 있어 커밋 동선이 다르다.
- **서버·마이그레이션·CLI·파일 포맷·DDL·DBML·Excel** — 결과물이 기존 `table`/`column`/`word`/`term`
  엔티티의 평범한 값 변경이라 이들이 새로 알 것이 없다.
- 컬럼 행 접기, 자동완성의 퍼지 매칭(접두일치만 한다), 물리명 형식 템플릿·그룹 별칭(별도 사이클).
- 캔버스 노드 안의 이름 편집 — 이름을 치는 자리는 편집 패널 하나로 유지한다.

## 2. 확정된 결정 (사용자 확정)

### D1. 적용 범위는 편집 패널의 컬럼과 테이블 둘이다

논리·물리명 쌍이 나오는 폼은 넷이다(편집 패널 테이블·컬럼, 사전의 단어 편집·용어 편집). 새 형태는
**앞의 둘에만** 적용한다.

**근거:** 뒤의 둘은 다이얼로그이고 저장 버튼이 커밋을 확정하므로 "blur 커밋 전 값" 결함의 동선이
아니다. 단어 편집 폼에 「단어 등록」을 붙이면 순환이 되기도 한다. 넷을 한 컴포넌트로 통일하는 것은
값이 있으나 이번 사이클을 사전 화면까지 번지게 한다.

**따라서 이월 항목 「복원·재생성 버튼이 blur 커밋 전 값을 읽는다」는 완전히 닫히지 않는다** — 남는
두 곳(단어·용어 편집 다이얼로그)으로 **좁혀서** 다시 적는다. 통째로 지우면 다음 세션이 남은 결함을
잃는다.

### D2. 자동완성은 논리명·물리명 둘 다에서 돈다

논리명에서는 단어 논리명·용어를, 물리명에서는 약어·용어 물리명을 제안한다.

**근거:** 물리명 우선 명명 사이클 이후 물리명을 직접 치는 경우가 정상 동선이 됐다. 한쪽만 두면
그 대칭이 깨진다.

### D3. 미등록 단어는 칩으로 보여 주고, 누르면 그 자리에서 펼친다

미등록 구간을 칩 한 줄로 상시 표시하고, 칩을 누른 것만 약어(또는 논리명) 입력란으로 펼친다.

**근거:** 상시 인라인 폼은 미등록이 3~4개면 컬럼 하나가 화면을 다 먹는다. 다이얼로그는 컬럼 행 높이를
안 늘리는 대신 **단축키를 전부 멈추고**(`use-shortcuts.ts`의 `isDialogOpen` 가드) 문맥을 가린다.
칩은 평소 한 줄이고, 지금은 경고 배지 숫자로만 알던 "무엇이 미등록인가"를 이름 옆에서 바로 읽게 한다.

### D4. 입력란을 제어 인풋으로 승격하고, 두 필드의 draft를 한 컨테이너가 쥔다

`CommitInput`(`edit-panel.tsx:29`)은 비제어(`defaultValue` + `key`)라 타이핑 중 값을 볼 수 없다.
자동완성이 그 값을 요구하므로 제어 인풋으로 바꾼다. 그러면서 **논리·물리 두 draft를 한 컨테이너에**
둔다.

**근거:** ↻ 버튼은 *반대편 필드의 아직 커밋되지 않은 값*을 기준으로 삼아야 맞다. draft가 각 필드
안에만 있으면 그 값에 닿을 방법이 없다. 이것이 blur 경합을 구조적으로 없애는 자리다(3.2).

## 3. 구조

### 3.1 신설 모듈 `apps/web/src/editor/name-pair.tsx`

```
NamePair                     두 draft를 쥐고, mutate 진입점을 하나로 모은다
 ├─ NameField(kind='physical')   라벨 + 제어 인풋 + 내부 ↻ + 자동완성 + 미등록 칩
 └─ NameField(kind='logical')    같은 컴포넌트, kind만 다르다
```

`NamePair`가 받는 것:

| prop | 뜻 |
|---|---|
| `logicalName` / `physicalName` | 모델의 현재 값(커밋된 값) |
| `onCommit(next)` | `{ logicalName?, physicalName? }` 부분 갱신을 한 mutation으로 반영 |
| `canEdit` | 읽기 전용 판정 |
| `idPrefix` | `tbl-` / `col-<id>-` — 라벨 `htmlFor`와 목록 `id`의 접두 |
| `extra` | 컬럼에서만 넘기는 「용어 등록」 슬롯 |

`words`·`terms`·`namingRules`는 store에서 직접 읽는다(부모가 실어 나르지 않는다).

**`onCommit`이 부분 갱신 객체 하나를 받는 것이 핵심이다.** ↻ 한 번이 "내 draft 확정 + 상대 재생성"
두 변경을 낳는데, 그것이 mutation 두 건이 되면 Revision 2건 · undo 2회가 된다. 한 객체로 받아
producer 하나 안에서 처리한다.

### 3.2 커밋 시점과 blur 경합 제거

커밋은 셋뿐이다 — **blur**(값이 바뀌었을 때만) · **Enter**(신규) · **버튼 동작에 동반**.
타이핑 중에는 커밋하지 않는다(디바운스 자동 저장은 Revision을 폭증시킨다).

⚠️ **이월 결함(「버튼이 blur 커밋 전 값을 읽는다」)의 수정 본체는 D4 의 draft 다.** 옛 코드는 비제어
인풋이라 친 값이 React 상태 어디에도 없었고, 그래서 버튼이 모델의 커밋된 값밖에 못 봤다. 두 draft 를
컨테이너에 두면 버튼 핸들러가 그것을 직접 읽어 한 번에 반영한다.
*실증: `regenerate` 가 draft 대신 커밋된 props 를 읽게 바꾸면 「방금 친 값」·「뮤테이션 한 건」 2건이
빨개진다.*

⚠️ **`onMouseDown={(e) => e.preventDefault()}` 는 별개의, 더 작은 것을 막는다 — 포커스 이탈뿐이다.
뮤테이션 수와는 무관하다.** 이 문서의 초판은 그것을 "수정 본체"로 적었고 구현자는 "없으면 뮤테이션이
2건이 된다"로 고쳐 적었는데 **둘 다 사실이 아니었다.**

blur 는 실제로 발화하고 `commitSide` 까지 **도달한다.** 억제하는 것은 **`use-model` 의
`ops.length === 0 → noop` 하나뿐이다** — `regenerate` 가 반대편 draft 를 같은 patch 에 접어 넣어
모델이 이미 그 값이 된 뒤에 blur 커밋이 도착하므로 diff 가 비어 있다.
⚠️ **`commitSide` 의 값-동일 조기 반환은 걸리지 않는다.** `onBlur` 콜백이 자기가 만들어진 렌더의
props 를 쥐고 있어 `current` 가 옛 값이라 통과한다 — 초판 수정 라운드가 이것을 "(a) 또는 (b)" 로
적었는데 **(a) 는 발화하지 않는다.** 그럴듯한 인과를 계측 없이 적은 같은 종류의 결함이었다.
*계측: `commitSide side=logical value="회원주문번호" current="회원" skip=false` / blur 는 발화한다.*
*실증: 그 줄들을 지워도 web 전건이 통과했다. 빨개지는 것은 포커스 케이스뿐이다.*

그래도 **남긴다** — 커서가 입력란에 남아 이어서 칠 수 있는 것이 실사용 가치다. 대신 그 효용을
직접 보는 테스트(「↻ 를 눌러도 포커스가 입력란에 남는다」 등 3건)로 잠근다.

**대상은 넷이다 — ↻ 2개 · 미등록 칩 · 「단어 등록」, 그리고 컬럼의 「용어 등록」.** 마지막 것이 초판
구현에서 빠져 같은 카드 안에서 이월 결함이 열린 채 남았다(리뷰 M1). 「용어 등록」은 `extra` 슬롯으로
들어가므로 그 슬롯을 **렌더 prop**(`(draft) => ReactNode`)으로 두어야 draft 에 닿는다.

**"버튼을 필드 안으로 옮기는 것"이 draft 수정을 필수로 만든다** — 밖에 있을 때는 가끔 밟는 결함이지만,
안에 있으면 "치고 바로 옆 버튼"이 주 동선이 되어 상시화된다. 배치 변경과 결함 수정은 분리할 수 없다.

### 3.3 ↻ 버튼의 방향

> ⚠️ **이 절은 옛 설계다**(위 갱신 표시 참조). 지금 버튼은 아래 표의 **반대 방향**으로 동작한다 —
> 물리명 칸의 화살표가 **논리명**을, 논리명 칸의 화살표가 **물리명**을 채운다. 기준(어느 draft 를
> 읽는가)과 실패 시 토스트는 그대로다.

| 위치 | 하는 일 | 기준 | 실패하면 |
|---|---|---|---|
| 물리명 필드 안 | 물리명 재생성 | 논리명 draft → `generatePhysicalName` | 빈 결과면 no-op + 토스트 |
| 논리명 필드 안 | 논리명 재생성 | 물리명 draft → `restoreLogicalName` | `ok:false`면 no-op + 토스트 |

방향은 **현재 동작과 같다**(`edit-panel.tsx:102-109`·`130-138`). 바뀌는 것은 배치와 이름이다 —
`aria-label`을 「물리명 재생성」/「논리명 재생성」으로 통일한다(지금은 「재생성」/「복원」/「컬럼 논리명
복원」으로 갈려 있다).

⚠️ **실패를 조용히 넘기지 않는다.** 지금 논리명 「복원」은 `r.ok ? … : m`이라 미등록 약어가 있으면
**아무 일도 일어나지 않는다** — 사용자에게는 먹통으로 보인다. 토스트로 사유를 낸다:
「등록되지 않은 약어: ORD, NO」. 칩 줄이 같은 정보를 상시로 보여주므로 서로를 보강한다.

↻는 **덮어쓴다**(기존 정책). blur 커밋에 딸린 자동 생성은 **반대쪽이 비어 있을 때만** 돈다
(`edit-panel.tsx:118`·`147`의 기존 규칙 그대로) — 두 자동 규칙이 서로를 덮어쓸 수 없다는 물리명 우선
명명 사이클의 대칭이 유지된다.

⚠️ **컬럼에만 있는 규칙 하나가 함께 따라간다 — 「논리명이 용어와 완전일치하면 그 용어의 도메인도
채운다」.** 이것도 **물리명이 비어 있던 경우에만** 도는 것이 기존 동작이고(그 가드 안에 있었다),
`NamePair` 는 컬럼인지 테이블인지 모르므로 `applyNames` 가 그 규칙을 담는 자리다. 계획서가 이 규칙을
옮겨 담지 않았고 초판 구현이 손으로 되살리면서 가드를 빠뜨려 **「항상」으로 넓어져 있었다**(리뷰 M3).
가드 안으로 되돌렸다 — 확대는 제품 동작 변경이라 별도 사이클에서 정한다.

### 3.4 자동완성 — core `suggestCompletions`

**core에 두는 이유:** 후보 산출은 "논리명을 어떻게 끊는가 / 약어를 어떻게 인덱싱하는가"이고,
`naming.ts`가 이미 *"generatePhysicalName의 분해 규칙을 고치면 이 함수도 함께 고쳐야 한다 — 그래서
같은 파일에 둔다"* 를 못 박고 있다. `abbreviationIndex`(`naming.ts:57`)가 그 파일의 private 함수라
밖에서는 같은 규칙을 재현할 수도 없다.

```ts
export type Completion = { insert: string; hint: string; kind: 'word' | 'term' }
export type CompletionResult = { query: string; start: number; items: Completion[] }

export function suggestCompletions(
  input: string, side: 'logical' | 'physical',
  words: Record<string, Word>, terms: Record<string, Term>, rules: NamingRules,
): CompletionResult
```

**쿼리 = 입력값 중 아직 사전에 매칭되지 않은 꼬리 한 조각.**

| side | 쿼리 산출 | 후보 |
|---|---|---|
| `logical` | `decomposeByWords(input, words)`의 **마지막 세그먼트가 `word: null`** 이면 그 `text` | 단어 `logicalName` 접두일치 + 용어 `logicalName`이 **입력 전체**에 접두일치 |
| `physical` | `rules.separator`가 있으면 마지막 구분자 뒤 토큰, 없으면 약어 그리디로 끊고 남은 꼬리 | 약어 접두일치(대소문자 무시) + 용어 `physicalName`이 입력 전체에 접두일치 |

- **용어만 입력 전체를 본다.** 용어는 논리명 *전체* 완전일치가 적용 규칙이므로(`generatePhysicalName`
  1단계) 꼬리 조각으로 찾으면 의미가 달라진다.
- **쿼리가 빈 문자열이면 「단어」 후보를 내지 않는다.** 매칭으로 딱 떨어졌는데 단어 목록을 열면 한
  글자마다 사전 전체가 뜨기 때문이다. ⚠️ **이 규칙은 단어에만 걸린다 — 용어에는 걸리지 않는다.**
  초판은 이 둘의 적용 범위를 나누지 않아 "쿼리가 비면 `items: []`" 로 적었고, 구현이 그것을 용어
  탐색보다 앞에 두는 바람에 **입력이 사전 단어로 딱 떨어지는 순간 용어 후보가 통째로 죽었다**
  (리뷰 m5). 하필 용어로 가는 길목의 접두가 대개 그 모양이라 주 동선이 막혔고, 물리명 쪽은 구분자
  덕에 우연히 안 걸려 **D2 의 대칭도 깨져 있었다.** 용어는 입력 전체 접두일치라 폭발하지 않으므로
  두 규칙은 애초에 충돌이 아니다.
- 정렬은 **짧은 것 먼저 · 동률이면 사전순**, 상한 8. 유일 후보가 쿼리와 완전히 같으면 빈 배열
  (이미 다 친 상태).
- **8칸의 배분: 용어 최대 3, 나머지는 단어 몫.** 합친 뒤에 한 번만 자르면 접두일치 용어가 8개 이상인
  프로젝트에서 단어 자동완성이 조용히 죽는다(리뷰 m6).
- `start`는 쿼리가 시작하는 인덱스다. 확정 시 `input.slice(0, start) + insert`로 치환한다.

**UI 쪽 동작:**

- 조작은 `↓↑` 이동 · `Enter` 확정 · `Esc` 닫기 · 클릭.
- **확정은 커밋이 아니다.** 쿼리 구간만 치환하고 draft에 머문다 — 이어서 다음 단어를 칠 수 있어야
  한다. 목록이 열린 동안 `Enter`는 확정에만 쓰이고 커밋으로 내려가지 않는다.
- `Esc`는 `stopPropagation` 한다(상위로 새면 안 된다).
- `role="listbox"` / `role="option"` + `aria-activedescendant` + `aria-expanded`.
- 캔버스 단축키와 충돌하지 않는다 — `use-shortcuts.ts`의 `isTypingTarget`이 `INPUT`을 이미 걸러낸다.

### 3.5 미등록 칩과 인라인 등록

⚠️ **칩은 커밋된 값 기준으로만 그린다.** draft 기준이면 타이핑 중 마지막 구간이 늘 미등록이라 칩이
깜박인다. **자동완성은 입력 중, 칩은 입력 후** — 역할을 가른다.

| 필드 | 칩 산출 | 칩을 누르면 | 등록 |
|---|---|---|---|
| 논리명 | `generatePhysicalName(값).unknownWords` | `약어 [___] [등록]` | `createWord({ logicalName: 칩, abbreviation: 입력 })` |
| 물리명 | `restoreLogicalName(값)` 실패 시 `unknownTokens` | `논리명 [___] [등록]` | `createWord({ logicalName: 입력, abbreviation: 칩 })` |

둘 다 **같은 `createWord` 경로**다(물리명 우선 명명 사이클이 세운 역방향 등록과 동일한 형태).
한 번에 하나만 펼쳐진다. 나머지 필드는 사전 화면의 일괄 등록과 같다 — `englishName: null` ·
`description: null` · `origin: null`.

이 산출은 `dict-edits.ts`의 `unregisteredWords`(206)·`unregisteredAbbreviations`(225)가 **모델 전체**로
도는 것의 단일 엔티티판이다. 같은 core 함수를 쓰므로 사전 화면과 결과가 어긋나지 않는다.

**중복 가드를 새로 둔다** — `createWord`(`dict-edits.ts:6`)에는 검사가 전혀 없어서 같은 논리명 단어를
두 번 만들 수 있고, 그러면 `decomposeByWords`가 하나만 쓰고 나머지는 유령이 된다.

⚠️ **이 판정이 필요한 곳은 인라인 등록만이 아니다.** 사전 화면의 일괄 등록도 **역방향**은 사용자가
논리명을 직접 치므로 두 약어 후보에 같은 이름을 넣으면 그대로 중복이 생긴다. "미등록 목록에서 오므로
정의상 중복이 아니다"는 **정방향에만** 성립한다(리뷰 m9). 역방향은 사전 중복과 배치 안 자기 충돌을
행별로 걸러 사유를 보여 주고 일괄 등록에서 제외한다.

```ts
export type WordRegisterCheck = { ok: boolean; reason?: 'duplicate-logical' | 'empty'; abbrClash?: boolean }
export function canRegisterWord(model: ProjectModel, w: { logicalName: string; abbreviation: string }): WordRegisterCheck
```

- 같은 **논리명** 단어가 이미 있으면 `ok:false` → 등록 버튼 비활성 + 사유.
- 같은 **약어**가 겹치면 `ok:true` + `abbrClash:true` → 경고만 표시하고 막지 않는다.
  `abbreviationIndex`가 id가 작은 쪽으로 결정론적으로 고르므로 무결성 문제가 아니다.
- 양쪽 어느 하나라도 공백이면 `ok:false`.

**등록 성공 시 반대편 이름이 비어 있으면 같은 mutation 안에서 자동 생성한다.** 채워져 있으면 건드리지
않는다 — 3.3의 「비어 있을 때만 자동」 정책 그대로다. Revision 1건.

### 3.6 용어 등록 (컬럼만)

버튼은 유지하고(`edit-panel.tsx:240-251`) 두 결함을 닫는다.

- **중복 검사 없음** → 같은 논리명 용어가 이미 있으면 비활성 + 사유. `canRegisterWord`와 같은 형태의
  `canRegisterTerm`을 둔다.
- **성공 피드백 없음** → 토스트.
- 논리명·물리명 중 하나라도 비면 지금은 조용히 `return`한다 → 비활성으로 미리 보여준다.

```
┌ 컬럼 카드 ─────────────────────────────┐
│ 물리명 *                        [⚠ 2]  │  ← 경고 배지는 카드 우상단
│ ┌────────────────────────────────┐    │
│ │ MBR_ORD_NO                  ↻ │    │

```

물리명이 위다(물리명 우선 명명 사이클이 정한 순서). 테이블 쪽은 이미 세로 배치이므로 바뀌는 것은
버튼 위치와 칩 줄뿐이다.

**부수 효과 — 이월 항목이 함께 닫힌다.** 「컬럼 행에 필수 표시가 없다」는 *"`CommitInput`이 라벨을
그리지 않는 압축 레이아웃이라 별표가 붙을 자리가 물리적으로 없다"* 가 이유였다. 세로 배치가 되면
라벨 자리가 생겨 `FieldLabel required`를 그대로 쓴다. **인덱스명은 그대로 남는다**(같은 이월 항목의
다른 절반 — 이번 범위가 아니다).

**대가는 높이다.** 컬럼 하나당 대략 +60px(라벨 2줄 + 칩 줄), 컬럼 10개면 사이드바가 600px 길어진다.
칩 줄은 미등록이 있을 때만 그리므로 사전이 채워질수록 줄어든다. **컬럼 접기는 넣지 않는다** — 별개
주제이고, 접으면 칩과 자동완성이 다시 안 보이게 되어 이 사이클의 목적과 어긋난다.

### 3.8 사전 다이얼로그 하위 탭

```
[단어] [용어] [미등록 항목 (5)] [가져오기]
               └ [논리명 → 약어 (3)] [물리명 → 논리명 (2)]
```

상위 탭 배지는 합계 유지(`dict-panel.tsx:77-80` 그대로), 하위 탭에 각 건수. 기본은 「논리명 → 약어」.
건수가 0이어도 탭은 남긴다(빈 상태 문구는 기존 그대로).

**두 섹션을 `direction` prop 하나로 통합한다.** 이월 항목이 *"55줄 구조 중복 — 등록 로직(중복 검사·
origin)이 추가되면 두 곳이 갈릴 수 있다"* 고 경고했는데 이번 사이클이 정확히 그 등록 로직을 추가한다.

통합하면서 **`dict-panel.tsx:42`의 `DEFAULT_NAMING_RULES` 하드코딩을 store 규칙으로 바로잡는다.**
정방향은 관측 가능한 차이가 0이지만(`rules`가 조합·케이스·길이에만 쓰인다), 통합 후 두 방향이 같은
인자를 받게 되므로 규칙이 갈려 있으면 안 된다 — 역방향은 `restoreLogicalName`이 `rules.separator`로
분기하므로 store 규칙이 필수다.

- **칩 줄이 늘어난 뒤의 실제 스크롤 길이**도 같다. 컬럼 10개 이상 모델로 스모크에서 확인한다.

⚠️ **"이 테스트가 이 줄을 잠근다"를 적을 때는 실제로 되돌려 확인한 것만 적는다.** 이 문서는 초판에서
그것을 어겼고(3.2), 그 결과 `preventDefault` 가 "잠겨 있다"고 적힌 채 아무것도 잠그지 않은 상태로
리뷰까지 갔다. **실증은 최종 코드에서 다시 돌려야 한다** — 구현자가 Task 3 시점에 본 「뮤테이션 2건」은
그 시점에는 참이었지만, Task 4 가 blur 를 `setTimeout` 으로 미루면서 순서가 뒤집혀 거짓이 됐다.
