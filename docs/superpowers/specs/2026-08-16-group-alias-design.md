# 그룹 별칭 (+ 컬럼 행 배지 레이아웃 수정) — 설계

**작성:** 2026-08-16 / **상태:** 사용자 확정 / **마이그레이션:** 0013(그룹 별칭 컬럼) /
**서버 변경:** 스키마 · **core 변경:** 모델 스키마 · **CLI 변경:** 파일 필드

---

## 1. 목적과 범위

**그룹에 물리 식별자 별칭을 붙인다.** 그룹 이름은 `회원관리`처럼 한글이라 물리명 조합에 쓸 수 없다.
다음 사이클의 **테이블명 형식 템플릿**(`TB_{그룹별칭}_{커스텀속성}_{물리명}`)이 그 값을 요구하는데,
템플릿보다 **모델·마이그레이션·등록처 배선을 먼저 닫아** 검증하는 편이 안전하다.

**함께 고치는 것 하나** — 직전 사이클(`ca34846` 이전, 명명 입력 UI)이 만든 컬럼 행 레이아웃 결함:
경고 배지가 `NamePair`와 같은 flex row에 있어 **경고가 있는 컬럼만 입력란이 좁아진다.**

**범위 안**

| 대상 | 하는 일 |
|---|---|
| `packages/core/src/model.ts` | `TableGroupSchema`에 `alias` |
| `apps/server/src/db/schema.ts` + **마이그레이션 0013** | `model_table_groups.alias` |
| `packages/core/src/file-merge.ts` | `FILE_FIELDS.tableGroup`에 `alias` |
| `apps/web/src/editor/group-panel.tsx` | 별칭 입력란 + 사전 기반 자동 생성 |
| `apps/web/src/editor/edit-panel.tsx` | 컬럼 행 배지를 `absolute`로 (B) |

**범위 밖 (건드리지 않는다)**

- **테이블명 형식 템플릿** — 다음 사이클(2절 D1).
- **중복 별칭 경고** — D5.
- **DBML·Excel·DDL 노출** — 쓰이는 곳이 없는데 산출물 포맷을 바꾸면 왕복 테스트만 흔들린다.
- `op.ts`는 손대지 않는다 — `ENTITY_SCHEMAS`가 `TableGroupSchema`를 참조하므로 따라온다.

## 2. 확정된 결정 (사용자 확정)

### D1. 이번 사이클은 **별칭만** 넣는다

**근거:** 필드 추가가 마이그레이션 + 등록처 6곳으로 그 자체로 한 사이클감이다. 템플릿은
「저장된 물리명 vs 조합해서 보여 주는 물리명」이라는 **새 개념**을 들여와 DDL·Excel·DBML·역설계
왕복·중복검사가 전부 그 갈림에 걸린다 — 배선이 검증된 뒤에 얹는다.

⚠️ **대가: 이번 사이클이 끝나도 별칭은 쓰이는 곳이 없다.** 입력만 되고 아무 산출물에도 안 나간다.
그것을 알고 고른 것이다.

### D2. 별칭은 **물리 식별자**다 — 영문·숫자·밑줄, 대문자

**근거:** 결국 물리명 조합에 들어간다. 나중에 규칙을 세우면 이미 입력된 값이 전부 위반이 된다
(논리명 구분자 사이클에서 겪은 형태).

### D3. 규칙은 **타이핑 중에** 강제한다

`onChange`에서 `value.toUpperCase().replace(/[^A-Z0-9_]/g, '')`.

**근거:** 커밋 후 검증해 토스트로 거절하는 쪽보다 예측 가능하다. 한글을 치면 아무것도 안 들어가서
규칙을 즉시 알 수 있다.

### D4. 사전 기반 **자동 생성**을 붙인다

별칭 칸 안의 화살표 버튼. 그룹 이름을 `generatePhysicalName`으로 돌려 채우고, 사전에 없는 단어면
토스트로 사유를 낸다.

**근거:** 이 도구는 사전으로 물리명을 만드는 것이 본령이고, 직전 사이클의 `NamePair`가 같은 형태를
세웠다. 산출물이 「약어를 구분자로 이은 대문자」라 **D2 규칙을 자동으로 만족한다.**

### D5. 중복 별칭은 다루지 않는다

**근거:** 템플릿이 없으면 두 그룹이 같은 별칭이어도 아무 문제를 일으키지 않는다. 경고를 만들면 새
`Warning['kind']` 등록처 4곳(HANDOFF 3.14)이 따라온다. **템플릿 사이클에서 판단한다** — 그때는
충돌이 실제 결과를 갈라 놓으므로 판정 근거도 분명해진다.

## 3. 구조

### 3.1 모델 — `alias`는 nullable이 아니라 빈 문자열이다

```ts
export const TableGroupSchema = z.strictObject({
  id: z.string(),
  name: z.string(),
  color: z.string(),
  comment: z.string().nullable(),
  /** 물리명 조합용 짧은 식별자(영문·숫자·밑줄, 대문자). 선택 입력이고 없으면 빈 문자열이다. */
  alias: z.string().default(''),
})
```

⚠️ **HANDOFF 3.3은 「엔티티에 새 필드를 추가하면 `.nullable().default(null)`」을 관례로 적는다.
여기서는 따르지 않는다.** 근거: 별칭은 `comment`(없음이 의미 있다)가 아니라 `physicalName`
(비어 있을 수 있는 식별자) 쪽 성격이다. `null`로 두면 소비처마다 `alias ?? ''`를 써야 하고, 템플릿이
붙을 때 그 분기가 늘어난다. **`.default('')`도 옛 op 페이로드 파싱을 똑같이 만족한다**(3.3이 막으려는
것은 `undefined`가 그대로 흘러드는 것이다).

⚠️ **3.3이 요구하는 회귀 테스트를 반드시 남긴다** — 「구 스냅샷(엔티티에 `alias` 없음)을 복원해도
깨지지 않고, 빈 `changes`의 update op가 생기지 않는다」. 커스텀 항목 사이클에서 실제로 물린 자리다.

### 3.2 서버 — 마이그레이션 0013

```ts
// apps/server/src/db/schema.ts
alias: text('alias').notNull().default(''),
```

`drizzle-kit generate`로 0013을 만든다. `loadProjectModel`은 `db.select().from(modelTableGroups)`로
행 전체를 읽으므로 **매핑 배선이 자동으로 따라온다** — 확인만 하고 손대지 않는다.

### 3.3 CLI 파일 포맷

`FILE_FIELDS.tableGroup`에 `alias: 'alias'`를 더한다. 넣지 않으면 `applyMerge`가 「파일에 없는 것은
서버 값을 그대로 통과시킨다」로 처리해 **데이터가 깨지지는 않지만 CLI로 별칭을 다룰 수 없다.**
`name`·`color`·`comment`가 이미 파일에 있으므로 별칭만 빠질 이유가 없다.

### 3.4 그룹 패널

```
그룹
  이름  [ 회원관리                    ]
  별칭  [ MBR_MGMT                 ↑ ]   ← 이름으로 채우기
  색상  [ ██ ]
  설명  [ …                          ]
```

- 입력은 기존 세 필드와 같은 **blur 커밋**(`defaultValue` + `key`).
- `onChange`에서 D3의 정규화를 적용한다 — 제어 인풋이 아니라도 값 필터는 가능하다
  (`e.target.value = 정규화값`이 아니라, 로컬 state를 두는 편이 React와 어긋나지 않는다).
- 자동 생성 버튼은 `NamePair`와 같이 `onMouseDown={(e) => e.preventDefault()}`로 포커스를 지킨다
  (직전 사이클이 계측으로 확정한 그 효용).
- `canEdit`가 false면 입력은 `readOnly`, 버튼은 렌더하지 않는다(기존 패널 관례).

### 3.5 (B) 컬럼 행 배지 레이아웃

지금(`edit-panel.tsx:246-280`):

```tsx
<div className="flex items-start justify-between gap-2">
  <div className="min-w-0 flex-1"><NamePair … /></div>
  <WarningBadge className="shrink-0" />   ← 폭을 뺏는다
</div>
```

배지가 `shrink-0`이라 자기 폭(≈38px)을 지키고 `NamePair`가 나머지를 먹는다. **경고가 있는 컬럼만
입력란이 좁아져 컬럼마다 폭이 들쭉날쭉하다.**

고친 뒤:

```tsx
<li className={cn('relative grid gap-2 rounded-md border p-2', …)}>
  <WarningBadge warnings={props.warnings} className="absolute top-2 right-2" />
  <NamePair … />        {/* flex wrapper 제거 */}
```

직전 사이클 설계 3.7의 ASCII가 배지를 「카드 우상단」에 뒀는데 구현이 flex row로 넣은 것이다 —
의도대로 되돌린다. 물리명 라벨이 짧아 겹치지 않는다.

⚠️ **이 수정은 테스트로 잠기지 않는다.** jsdom이 레이아웃을 계산하지 않아 「폭이 같다」를 관측할 수
없다. DOM 구조를 단언하는 것은 억지다(`absolute`를 클래스 문자열로 확인하는 것은 스타일 복사일 뿐
동작을 보지 않는다). **스모크에서 본다**고 문서에 적는다.

## 4. 테스트

**core**
- `TableGroupSchema` — `alias` 없는 페이로드를 파싱하면 `''`가 들어간다
- ⚠️ **구 스냅샷 회귀**(3.1) — `alias` 없는 그룹이 든 모델을 복원해도 깨지지 않고 **빈 update op가
  생기지 않는다**. HANDOFF 3.3이 명시적으로 요구하는 케이스다
- `file-merge` — 파일에 `alias`가 실리고 3-way 병합이 그 필드를 다룬다

**server**
- 마이그레이션 적용 후 그룹 생성·조회 왕복에서 `alias`가 보존된다
- ⚠️ **기존 행(마이그레이션 전에 만들어진 그룹)을 읽으면 `''`가 나온다** — DB 기본값이 실제로 먹는지.
  논리명 구분자 사이클에서 「서버가 파싱을 안 태워 기본값이 주입되지 않던」 자리와 같은 부류다

**web**
- 별칭 입력이 blur로 커밋된다
- ⚠️ **타이핑 중 정규화** — 한글·소문자·특수문자를 넣으면 각각 제거·대문자화된다
- 자동 생성 — 그룹 이름으로 채우고, 사전에 없으면 토스트를 내고 값을 바꾸지 않는다
- 읽기 전용에서 입력이 `readOnly`이고 버튼이 없다

**잠기지 않는 것 (명시)**
- (B) 배지 레이아웃(3.5). 스모크에서만 확인한다.
- 「별칭이 어디에도 안 쓰인다」 — 이번 사이클의 의도된 상태라 잠글 대상이 없다.
- ⚠️ **「마이그레이션 전에 만들어진 행을 읽으면 `''` 가 나온다」(위 server 두 번째 항목)는 관측
  불가로 판정했다.** 컬럼이 `NOT NULL DEFAULT ''` 라 SQL 로 `NULL` 을 넣을 수 없고, 테스트 DB 는
  항상 마이그레이션이 적용된 상태에서 시작한다. 실질적으로 확인할 수 있는 것은 **생성된 0013 SQL 이
  `DEFAULT ''` 를 담고 있는가**뿐이라 파일을 눈으로 확인하는 것으로 갈음했다(억지 테스트를 만들지
  않았다). 대신 남긴 것은 「별칭을 비운 그룹은 빈 문자열로 왕복한다」다 — `null` 이 아니라 `''` 로
  돌아오는 것을 본다.
