# 에디터 도구 재분배 — 상단 묶음 + 하단 바 설계

**작성:** 2026-08-12 / **상태:** 사용자 확정 / **마이그레이션:** 없음 / **서버·core·CLI 변경:** 없음

---

## 1. 목적과 범위

에디터 헤더(`apps/web/src/pages/project.tsx:42~64`) 한 줄에 도구가 전부 몰려 있다. 우측 클러스터만
13개다.

```
접속자 · 뷰 전환 · 버전 · 도메인 · 사전 · 커스텀 항목 · 공용 리소스 · 모델 검사 ·
가져오기 · 내보내기 · 논리|물리|혼합 · 설정 · 사용자 메뉴
```

한글 라벨 버튼 8개(`버전`~`내보내기`)가 나란히 있고 거기에 3칸 토글과 드롭다운이 붙어, 좌측의 브랜드 +
편집 툴바까지 합치면 한 줄이 화면 폭을 넘는다. 작은 해상도에서 오른쪽 끝이 잘린다.

이 사이클은 **도구를 성격으로 나눠 상단과 하단 두 줄로 재분배**한다.

| # | 변경 | 위치 |
|---|---|---|
| 1 | 캔버스 편집 도구를 하단 바로 이동 | 테이블 추가·메모·자동 정렬·삭제·실행 취소/다시 실행 |
| 2 | 뷰 상태를 하단 바로 이동 | 뷰 전환(그룹 뷰) · 논리\|물리\|혼합 |
| 3 | 줌 컨트롤을 하단 바로 흡수 | React Flow `<Controls>` 제거 |
| 4 | 상단 관리 도구 8개 → 4개로 묶기 | 「사전·리소스 ▾」 · 「파일 ▾」 |

**모델·프로토콜은 하나도 바뀌지 않는다.** op 엔티티도, presence 프로토콜도, API도 그대로다. 변경은
**웹 UI 배치**에 갇힌다.

### 목표 폭

**1024px에서 상단·하단 어느 줄도 잘리지 않는 것**을 목표로 한다. 아래 폭은 계산 추정치이고, 확정은
브라우저 스모크에서 실측한다.

| 줄 | 구성 | 추정 폭 |
|---|---|---|
| 상단 | 브랜드 + 접속자 + 버튼 4 + 설정 + 사용자 메뉴 | ~730px |
| 하단 | 편집 도구 4 + 실행 취소/다시 실행 + 뷰 전환 + 표시 모드 + 줌 | ~930px |

### 범위 밖 (의도적)

- **1024px 미만의 반응형** — 태블릿 세로·모바일은 이 도구의 대상이 아니다. 하단 바가 그보다 좁으면
  넘치는 것을 그대로 둔다.
- **단축키 추가·변경** — 기존 `cmd+Z`/`cmd+shift+Z`(`toolbar.tsx:28~41`)와 클립보드 단축키를 그대로
  둔다. 하단 바는 배치만 바꾼다.
- **도구의 기능 변경** — 각 다이얼로그의 내용·동작은 한 줄도 안 고친다. 바뀌는 것은 **누가 여는가**뿐이다.
- **미니맵 위치** — 캔버스 우하단에 그대로 둔다(하단 바 위에 뜬다).
- **`BulkPanel`·`table-tree`** — 병행 트랙(`2026-08-12-group-from-selection-design.md`)이 만지는
  파일이라 건드리지 않는다.

## 2. 확정된 결정 (사용자 확정)

### D1. 분배 축은 **"캔버스를 조작하는가"** 다

하단 바에는 캔버스를 직접 바꾸거나(테이블 추가·메모·자동 정렬·삭제·실행 취소) 캔버스를 어떻게 볼지를
정하는 것(그룹 뷰·표시 모드·줌)을 둔다. 상단에는 다이얼로그를 여는 관리 도구(버전·사전류·모델 검사·
파일)와 계정·접속자를 둔다.

**근거:** 캔버스를 보면서 반복해 누르는 것이 캔버스에 붙고, 한 번 열어 작업하고 닫는 것이 상단에 남는다.
Figma·draw.io 계열의 익숙한 배치와 같다.

### D2. 상단 관리 도구는 **성격별 드롭다운 2개**로 묶는다

| 트리거 | 안에 들어가는 것 |
|---|---|
| 「사전·리소스 ▾」 | 도메인 · 단어·용어 사전 · 커스텀 항목 · 공용 리소스 |
| 「파일 ▾」 | DDL·DBML 가져오기 · 내보내기 |
| (단독) 「버전」 | — |
| (단독) 「모델 검사 (N)」 | — |

**버전·모델 검사를 묶지 않는 이유:** 앞의 넷은 "재사용할 정의를 관리한다"는 한 성격이지만 이 둘은 각각
이력과 진단이라 성격이 다르다. 특히 모델 검사는 **경고 건수 배지가 상시 보여야** 해서 메뉴 안에 숨기면
신호가 죽는다.

**부수 효과:** HANDOFF 6절의 「같은 이름의 「가져오기」가 서로 다른 두 기능이다」 마찰이 함께 해소된다.
헤더 쪽이 「파일 ▾ → **DDL·DBML 가져오기**」가 되어, 「사전」 다이얼로그 안의 Excel 업로드 탭
(「가져오기」)과 이름이 갈린다.

### D3. 하단 바는 **화면 전체 폭 고정 바**다

좌측 트리·우측 편집 패널 아래까지 지나가는 40px 바를 둔다. 캔버스 위에 떠 있는 플로팅 바로 두지 않는다.

**근거:** 그룹 뷰와 표시 모드는 트리·편집 패널의 표시에도 걸리는 **전역 상태**라 전역 바가 의미상 맞다.
플로팅 바는 노드를 가리고, 편집 패널이 열리면 중앙 정렬이 어긋난다.

### D4. 줌 컨트롤을 하단 바가 흡수한다

React Flow 기본 `<Controls>`(`canvas.tsx:345`, 캔버스 좌하단)를 제거하고 하단 바 오른쪽 끝에 줌 아웃 ·
현재 배율 · 줌 인 · 화면 맞춤을 둔다.

**근거:** 전체 폭 바를 깔면 그 바로 위에 뜬 기본 컨트롤이 "두 겹 툴바"로 보인다. 줌은 명백히 뷰 상태라
그룹 뷰·표시 모드 옆이 제자리다.

### D5. 다이얼로그는 **전부 제어형**으로 통일하고, 트리거는 헤더가 렌더한다

지금은 각 패널이 자기 트리거 버튼을 자기가 렌더한다(`DialogTrigger` + 자체 `useState`). 드롭다운 항목이
다이얼로그를 여는 형태에서는 그 구조가 성립하지 않는다 — Radix에서 메뉴 항목으로 다이얼로그를 여는
정석은 **다이얼로그를 메뉴 밖에 두고 열림 상태를 부모로 올리는 것**이다.

**선택적 제어(prop이 있으면 제어, 없으면 자체 상태)로 두지 않는다.** 규칙이 두 벌이 되고 트리거가 두
군데서 날 수 있다. 이 저장소가 반복해서 경계해 온 형태다(HANDOFF 3.13).

### D6. 읽기 전용 사용자에게도 하단 바는 남는다

`canEdit === false`면 하단 바 왼쪽 편집 도구 자리에 「읽기 전용」 배지만 뜬다(현재 `Toolbar`의 동작
그대로). 뷰 전환·표시 모드·줌은 읽기 전용도 쓰므로 그대로 산다.

### 3.2 파일

| 파일 | 변경 |

| `editor/version-dialog.tsx` 등 **8개** | 제어형으로 전환(자체 트리거·자체 open 상태 제거) |
| `editor/naming-check.tsx` | 위 + 경고 계산을 `useWarnings`로 교체 |

**`toolbar.tsx`·`group-view-select.tsx`·`view-mode-toggle.tsx`는 한 줄도 안 고친다.** 옮기는 것은
배치일 뿐이라 `BottomBar`가 그대로 조립해 쓴다. 기존 테스트가 전부 그대로 산다.

### 3.3 `HeaderTools` — 열린 도구는 단일 상태

```tsx
type ToolId =
  | 'version' | 'domain' | 'dict' | 'customField'
  | 'resource' | 'namingCheck' | 'ddlImport' | 'export'

const [tool, setTool] = useState<ToolId | null>(null)
```

버튼·드롭다운 항목과 다이얼로그 8개를 전부 이 컴포넌트가 렌더하고, 각 다이얼로그에
`open={tool === '<id>'}` / `onOpenChange={(v) => setTool(v ? '<id>' : null)}` 를 넘긴다.

**단일 상태라 두 다이얼로그가 동시에 열리는 상태가 구조적으로 생기지 않는다.** 지금은 8개가 각자
`useState`를 들고 있어 그 보장이 없다(현실에서 안 겹치는 것은 트리거가 서로 가리기 때문일 뿐이다).

드롭다운 항목의 `onSelect`가 `setTool`을 부르면 메뉴는 닫히고 다이얼로그가 열린다. 다이얼로그가
메뉴 바깥에 있으므로 메뉴 언마운트에 딸려가지 않는다.

**「파일 ▾」의 「DDL·DBML 가져오기」 항목은 `canEdit`일 때만 렌더한다.** 지금 그 가드는 컴포넌트
안에 있다(`ddl-import-dialog.tsx:64`의 `if (!canEdit) return null`) — 제어형이 되면 컴포넌트가 스스로
사라져도 **메뉴에는 죽은 항목이 남으므로** 조건이 항목 쪽으로 와야 한다. 8개 중 이 가드를 가진 것은
이것 하나다(나머지 일곱은 트리거에 조건이 없다). 「내보내기」는 읽기 전용도 쓸 수 있어 조건이 없다.

### 3.4 `useWarnings` — 경고 건수의 단일 소재지

「모델 검사」 트리거의 건수 배지는 헤더가 렌더하고, 목록은 다이얼로그가 렌더한다. 계산이 두 벌이 되지
않도록 `computeWarnings(model, namingRules, dialects)` 호출을 훅 하나로 뺀다.

```ts
export function useWarnings(): Warning[]   // store 3개 값 → useMemo
```

`naming-check.tsx`의 기존 `useMemo`(`:43~44`)가 그대로 이 훅이 된다. 종류별 묶음(`groups`)은 표시
전용이라 다이얼로그에 남긴다.

### 3.5 `ZoomControls`

React Flow의 `useReactFlow()`에서 `zoomIn`·`zoomOut`·`fitView`를 쓰고, 현재 배율은 스토어의 transform을
구독해 백분율로 보인다. 배율 표시를 누르면 100%로 되돌린다.

읽기 전용에서도 동작한다(뷰 조작이지 편집이 아니다).

## 4. 테스트

### 4.1 기존 테스트에 미치는 영향

다이얼로그 테스트 6개(`domain-panel` · `dict-panel` · `custom-field-panel` · `resource-panel` ·
`export-dialog` · `ddl-import-dialog`)와 `version-dialog` · `naming-check`는 지금 **트리거 버튼을 클릭해
다이얼로그를 연다**. 제어형 전환 후에는 `open` prop을 주고 렌더한다 — "여는" 줄을 지우는 기계적 수정이고
**검증 내용 자체는 바뀌지 않는다.**

`toolbar.test.tsx`는 그대로다(`Toolbar` 무변경).

### 4.2 새 테스트

| 대상 | 잠그는 것 |
|---|---|
| `header-tools` | 드롭다운 항목을 고르면 해당 다이얼로그가 열린다(4+2개 각각) |
| `header-tools` | **한 번에 하나만 열린다** — 하나를 연 뒤 다른 것을 열면 앞의 것이 닫힌다 |
| `header-tools` | 경고가 있으면 「모델 검사」에 건수가 붙고, 0이면 안 붙는다 |
| `bottom-bar` | 편집 권한이 있으면 편집 도구가 보인다 |
| `bottom-bar` | **읽기 전용이면 편집 도구가 없고 뷰 전환·표시 모드·줌은 남는다**(D6) |
| `header-tools` | **읽기 전용이면 「파일 ▾」에 「DDL·DBML 가져오기」가 없고 「내보내기」는 있다** |
| `zoom-controls` | 줌 인/아웃/화면 맞춤이 React Flow API를 부르고 배율이 표시된다 |

### 4.3 브라우저 스모크

**1024px 폭에서 상단·하단 어느 줄도 잘리지 않는 것**을 눈으로 확인한다(목표 폭이 계산 추정치이므로
이 확인이 필수다). 함께 볼 것 — 드롭다운에서 연 다이얼로그가 정상 동작하는지, 하단 바가 미니맵과
겹치지 않는지, 그룹이 없을 때 뷰 전환이 사라져도 레이아웃이 깨지지 않는지(`GroupViewSelect`는 그룹 0개면
`null`을 낸다).

## 6. 위험

- **제어형 전환이 8개 파일에 걸친다.** 기능은 안 바뀌지만 파일 수가 많다. 다이얼로그 하나가 트리거를
  덜 지우면 그 버튼만 헤더 밖에 남는다 — 각 파일의 테스트가 `open` prop 렌더로 바뀌므로 트리거가 남아
  있으면 중복 렌더로 드러난다.
- **컴포넌트 안에 있던 `canEdit` 가드가 메뉴 항목으로 옮겨진다**(`ddl-import-dialog.tsx:64`, 3.3).
  옮기지 않으면 읽기 전용 사용자의 메뉴에 눌러도 아무 일도 안 일어나는 항목이 남는다. 8개를 전수
  확인해 이 가드를 가진 것은 그 하나뿐임을 확인했다(`resource-panel`은 트리거에 조건이 없고
  `canPromote`로 **다이얼로그 안의 탭**만 가른다 — 옮길 것이 없다).
- **하단 바가 캔버스 높이를 40px 먹는다.** `h-dvh` 안의 flex 계산이라 캔버스는 자동으로 줄지만,
