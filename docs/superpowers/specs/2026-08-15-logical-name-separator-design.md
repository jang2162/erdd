# 논리명 구분자 + 상대 필드 적용 — 설계

**작성:** 2026-08-15 / **상태:** 사용자 확정 / **마이그레이션:** 없음(jsonb 읽기 시점 기본값 주입) /
**서버 변경:** 있음(스키마 파싱) / **CLI 변경:** 있음(config 옵셔널 키) / **core 변경:** 명명 규칙 전반

---

## 1. 목적과 범위

**논리명에 단어 경계를 넣는다.** 지금 논리명은 `회원주문번호`처럼 붙여 쓰고, 단어 경계는 사전을
최장일치 그리디로 훑어야만 알 수 있다. 사전에 없는 단어가 끼면 경계가 어긋나고(`회원쿠폰` → `회원`+
`쿠폰`인지 `회원쿠`+`폰`인지 알 수 없다) 자동완성 쿼리도 그 추측 위에 선다. 물리명은 이미
`MBR_ORD_NO`로 경계가 명시적인데 논리명만 그렇지 않다.

**그리고 이름을 한쪽에서 반대쪽으로 바로 밀 수 있게 한다.** 직전 사이클의 `↻`는 「**내** 필드를 상대
기준으로 다시 만든다」인데, 실제로 자주 하는 일은 그 반대 — 「방금 친 이 값으로 **상대**를 채운다」다.

**범위 안**

| 대상 | 하는 일 |
|---|---|
| `packages/core/src/naming.ts` | 분해·조립·후보 산출이 `logicalSeparator`를 안다. 용어 정규화 2종 신설 |
| 같은 파일 | `NamingRulesSchema`(zod) 신설 + export |
| `packages/core/src/warnings.ts` | 구분자 없는 논리명 경고 1종 |
| `apps/server/src/routers/project.ts` | 손-미러 zod 제거 · **DB jsonb를 스키마로 파싱**해 기본값 주입 |
| `apps/web/src/editor/name-pair.tsx` | `↻` 2개 → 화살표 2개, 덮어쓰기 정책, 자동완성 연동 |
| `apps/web` 프로젝트 설정 | 「논리명을 밑줄로 구분」 토글 1개 |
| `packages/cli/src/config.ts` | `logicalSeparator`를 옵셔널로 읽는다 |

**범위 밖 (건드리지 않는다)**

- **기존 논리명 일괄 변환 도구** — 경고만 띄우고 사용자가 고친다(2절 D3).
- **명명 규칙 나머지 3개(`case`·`separator`·`maxLengthBytes`)의 설정 UI** — 지금도 화면이 없다.
  이번에 여는 것은 `logicalSeparator` 토글 하나뿐이다(D7).
- **DDL·Excel·DBML·CLI 파일 포맷의 코드** — 논리명을 그대로 싣기 때문에 **값만 바뀌고 코드는
  그대로**다. 왕복 테스트 픽스처도 구분자 없는 논리명을 쓰면 그대로 왕복한다.
- 캔버스 노드 안의 이름 편집.

## 2. 확정된 결정 (사용자 확정)

### D1. 논리명 구분자는 `NamingRules`의 **별도 필드**다

`logicalSeparator: '_' | ''` 를 새로 둔다. 물리명용 `separator`를 공유하지 않는다.

**근거:** 논리명은 한글, 물리명은 영문 약어라 구분자 정책이 다를 이유가 충분하다. 공유하면 물리명
규칙을 `''`로 바꾸는 순간 **논리명 저장값 전체가 규칙 위반**이 된다 — 저장 데이터가 다른 축의 설정에
끌려다니는 결합이다.

### D2. 논리명 **저장값 자체**에 구분자가 들어간다

모델에 `logicalName: "회원_주문_번호"`가 그대로 저장된다. DDL 코멘트·Excel 정의서·DBML·CLI 파일에
나가는 값도 그것이다.

### D3. 기존 프로젝트도 기본값 `'_'` — 열자마자 경고가 뜬다

`projects.naming_rules` jsonb의 기존 행에는 이 키가 없다. 읽기 시점에 `'_'`를 주입하므로 **기존
프로젝트를 열면 구분자 없는 논리명이 전부 경고로 뜬다.**

**근거:** 사용자가 「강제 — 구분자 없으면 경고」를 택했다. 조용히 두면 언제 정리할지 알 수 없다.
일괄 변환 도구는 만들지 않는다 — 사용자가 보고 고친다.

### D4. 용어는 **매칭할 때 구분자를 무시**한다

용어 저장값(`회원주문번호`)은 그대로 두고, 비교 시 양쪽에서 구분자를 벗겨 맞춘다. 용어를 논리명에
**넣을 때**는 구분자를 넣어 변환한다.

**근거:** 용어는 전역·조직 라이브러리에서 fork로 내려오고 전역 시드가 「행안부 표준 사전」이다.
**남의 라이브러리 데이터에 이 프로젝트의 구분자 정책을 강요할 수 없다.** 용어 저장값을 구분자
형식으로 바꾸는 쪽은 fork할 때마다 경고가 새로 생긴다.

### D5. 버튼은 **화살표 2개**다 — `↻`를 없앤다

각 필드에 「상대를 내 값으로 채운다」 하나씩. 직전 사이클이 만든 `↻`(자기 필드를 상대 기준으로
재생성)는 제거한다.

**근거:** 둘을 함께 두면 버튼 4개가 되는데 **동작은 2가지뿐이다** — 물리명의 `↓`와 논리명의 `↻`가
둘 다 `restoreLogicalName`을 부르고 결과가 같다. 반대편 화살표가 `↻`의 일을 완전히 흡수한다.

⚠️ **이 결정은 직전 사이클(`48ea752`)의 산출물을 되돌린다.** `aria-label` 「물리명 재생성」/「논리명
재생성」에 걸린 테스트, `preventDefault` 포커스 잠금 4건 중 `↻` 관련 2건, 설계 3.2·3.3과 HANDOFF의
`↻` 서술이 함께 바뀐다. **잃는 것 하나:** 자기 필드가 이미 채워져 있고 그것을 상대 기준으로 다시
만들려면 이제 **반대편 칸의 화살표**를 눌러야 한다(같은 칸에서 못 한다).

### D6. 덮어쓰기는 **blur만 제외**한다

| 경로 | 상대 필드 | 커밋 |
|---|---|---|
| blur | **비어 있을 때만** | O |
| Enter (목록 닫힘) | 덮어쓴다 | O |
| 자동완성 확정 | 덮어쓴다 | **X — draft만** |
| 화살표 버튼 | 덮어쓴다 | O |

**근거:** blur는 필드를 스쳐 지나가기만 해도 발생한다. 손으로 정한 물리명이 Tab 한 번에 날아가면
안 된다. 나머지 셋은 사용자가 명시적으로 한 동작이다.

### D7. 설정 UI는 **토글 하나**만 연다

프로젝트 설정에 「논리명을 밑줄로 구분」 체크박스. `case`·`separator`·`maxLengthBytes`는 지금처럼
화면 없이 둔다.

**근거:** 이번 사이클이 도입하는 규칙을 끄고 켜는 길은 있어야 한다(없으면 DB를 직접 고쳐야 한다).
나머지 셋은 각자 기존 모델에 미치는 영향을 따로 설계해야 하므로 함께 열지 않는다.

## 3. 구조

### 3.1 분해 — `decomposeByWords(logicalName, words, rules)`

인자에 `rules`가 붙는다(**시그니처 변경 — 모든 호출처가 따라간다**).

`logicalSeparator`가 `'_'`면 **split이 1차**다. 그런데 그것만으로는 안 된다.

⚠️ **급소: 구분자 없는 기존 논리명이 통째로 미등록 단어가 된다.** `회원주문번호`를 split하면 토큰이
하나이고 사전에 그런 단어는 없다 → 물리명 생성이 죽고 칩에 `회원주문번호`가 통으로 뜬다. **기존
프로젝트 전체가 그 꼴이 된다.**

**그래서 폴백을 둔다 — split한 토큰이 사전에 없으면 그 토큰을 기존 최장일치 그리디로 재분해한다.**

```
'회원_주문_번호'  → split → ['회원','주문','번호']  → 전부 사전에 있다
'회원주문번호'    → split → ['회원주문번호']        → 사전에 없다
                         → 그리디 재분해 → ['회원','주문','번호']  ✓
'회원_쿠폰'       → split → ['회원','쿠폰']         → '쿠폰'이 없다
                         → '쿠폰' 그리디 재분해 → 실패 → word:null 세그먼트
```

**바뀌는 것은 경고 한 줄뿐이다.** 물리명 생성·자동완성·칩은 기존과 같은 결과를 낸다. D3의 「강제」는
경고를 띄우라는 뜻이지 분해를 포기하라는 뜻이 아니다.

`logicalSeparator`가 `''`이면 지금과 완전히 같다(그리디만).

### 3.2 용어 정규화 — 비교와 삽입이 다르다

신설 순수 함수 2개(`naming.ts`):

```ts
/** 비교용 — 구분자를 벗긴다. 용어 매칭이 구분자 유무에 흔들리지 않게 한다. */
export function stripLogicalSeparator(name: string, rules: NamingRules): string

/** 삽입용 — 사전으로 분해해 세그먼트 사이에 구분자를 끼운다. */
export function withLogicalSeparator(name: string, words: Record<string, Word>, rules: NamingRules): string
```

`with`는 `decomposeByWords`의 **세그먼트 경계마다** 구분자를 넣는다. 미매칭 구간(`word: null`)도
세그먼트 하나로 취급해 그 앞뒤에 구분자가 붙는다 — `회원쿠폰`(쿠폰 미등록) → `회원_쿠폰`.
`logicalSeparator: ''`이면 원본을 그대로 돌려준다.

| 자리 | 어느 쪽 |
|---|---|
| `generatePhysicalName` 1단계(용어 완전일치) | `strip` 후 비교 |
| `restoreLogicalName` 1단계(용어 물리명 일치) | 용어 논리명을 `with`로 변환해 반환 |
| `suggestCompletions`의 용어 후보 `insert` | `with`로 변환한 값 |
| 경고의 `term-mismatch` 판정 | `strip` 후 비교 |

### 3.3 조립 — `restoreLogicalName`

약어를 논리명으로 되돌릴 때 `logicalSeparator`로 잇는다. `MBR_ORD_NO` → `회원_주문_번호`.
`logicalSeparator: ''`이면 지금처럼 붙여 쓴다.

### 3.4 자동완성 — `suggestCompletions`

**논리명 쿼리 산출이 물리명과 같은 방식이 된다** — `logicalSeparator`가 있으면 **마지막 구분자 뒤
토큰**. 지금의 "그리디 분해 후 마지막 `word: null` 세그먼트"보다 단순하고, 사전에 없는 단어가 껴도
경계가 흔들리지 않는다. `logicalSeparator: ''`이면 기존 방식으로 떨어진다.

용어 후보의 `insert`는 3.2대로 변환된 값이고 `start`는 0(입력 전체 치환)이다 — 직전 사이클 설계 §3.4
그대로다.

### 3.5 새 경고

`Warning['kind']`에 **`missing-logical-separator`** 를 더한다(기존 `duplicate-physical`·`unknown-word`
처럼 「무엇이 문제인가」를 앞에 두는 이름 관례를 따른다). HANDOFF 3.14의 등록처 4곳을 따른다.

**판정 조건 — 셋을 모두 만족할 때만 띄운다:**
1. `rules.logicalSeparator !== ''`
2. 논리명에 그 구분자가 없다
3. **분해 결과가 2개 이상**이다

⚠️ **3번이 없으면 `회원` 같은 단일 단어 논리명 전부에 경고가 붙어 신호가 죽는다.** 구분자는 단어가
둘 이상일 때만 의미가 있다.

게이트는 `rules` **안**이다(명명 규칙에 종속된 경고다 — `custom-required`·`required-empty`가 밖에
있는 것과 반대).

### 3.6 `NamingRules` 확장과 기본값 주입

```ts
NamingRules = { case, separator, logicalSeparator: '_' | '', maxLengthBytes }
```

**`NamingRulesSchema`(zod)를 core에 신설해 export한다.** `logicalSeparator`에 `.default('_')`를 건다.

⚠️ **급소는 서버가 지금 DB jsonb를 파싱하지 않는다는 것이다.** `project.ts:70`이
`access.project.namingRules ?? DEFAULT_NAMING_RULES`로 **전체가 null일 때만** 폴백하므로, 키 하나가
빠진 기존 행은 `logicalSeparator: undefined`인 채로 클라이언트에 나간다. **그 자리에 스키마 파싱을
태워야** 기본값이 주입된다. 이것이 D3를 성립시키는 유일한 지점이다.

부수로 **이월 항목 「core에 `NamingRulesSchema`(zod) export → server `project.ts`의 손-미러 제거」가
닫힌다**(`project.ts:11`).

**마이그레이션은 없다** — jsonb라 컬럼 변경이 필요 없고 읽기 시점 주입으로 충분하다.

### 3.7 UI — 화살표 2개

```
물리명 *
┌──────────────────────────┐
│ MBR_ORD_NO            ↓ │   ← 이 물리명으로 논리명을 채운다
└──────────────────────────┘
논리명 *
┌──────────────────────────┐
│ 회원_주문_번호          ↑ │   ← 이 논리명으로 물리명을 채운다
└──────────────────────────┘
```

`aria-label`은 「논리명 채우기」/「물리명 채우기」. 실패 토스트(「등록되지 않은 약어: …」)는 직전
사이클 그대로 유지한다.

`onMouseDown` `preventDefault`는 유지한다 — 직전 사이클이 계측으로 확정했듯 **효용은 포커스 유지**이고
(뮤테이션 수와 무관하다), 화살표에도 같은 값이 있다. 포커스 잠금 테스트도 화살표 기준으로 옮긴다.

**자동완성 확정이 상대 draft만 갱신하는 것이 D6의 핵심이다.** 확정은 커밋이 아니어야 하는데(이어서
칠 수 있어야 한다) 상대 적용은 모델 변경이라 커밋이 필요하다 — **두 draft를 컨테이너가 쥐고 있으므로
상대 `draft`만 바꾸면 된다.** 화면에는 즉시 보이고 커밋은 blur/Enter 때 두 필드가 함께 나간다
(Revision 1건).

### 3.8 설정 토글

프로젝트 설정에 체크박스 하나. `project.update`의 `namingRules`로 보낸다. 끄면(`''`) 경고가 사라지고
분해가 그리디로 돌아간다 — **저장된 논리명의 구분자는 그대로 남는다**(데이터를 건드리지 않는다).

## 4. 테스트

**core**
- 분해 폴백 — 구분자 없는 논리명이 그리디로 재분해되는지, split 토큰 중 **일부만** 사전에 없을 때
- 용어 정규화 **양방향** — `strip` 비교로 매칭되는지 / `with` 삽입이 구분자를 넣는지
- `restoreLogicalName`의 구분자 삽입, `logicalSeparator: ''`에서 기존 동작 유지
- `suggestCompletions` 쿼리 산출(구분자 있음/없음 두 경로)
- 새 경고 — **단일 단어 예외**(3.5의 3번 조건)를 반드시 잠근다
- `NamingRulesSchema` — 키가 없는 객체를 파싱하면 `'_'`가 주입되는지

**server**
- ⚠️ **`logicalSeparator` 키가 없는 기존 행을 읽으면 `'_'`가 나오는지.** 이번 파급의 급소다
  (`project.get`이 파싱을 안 태우면 `undefined`가 그대로 나간다)

**web**
- **덮어쓰기 4경로 전수** — blur / Enter / 자동완성 확정 / 화살표. 하나만 빠져도 정책이 조용히 갈린다
- 자동완성 확정이 상대 draft를 바꾸고 **커밋은 내지 않는다**
- 화살표 2개의 방향(누른 칸의 반대가 채워진다)
- 설정 토글이 `namingRules`를 보낸다

**cli**
- 옛 `erdd.config.yaml`(키 없음)이 그대로 로드되는지

**잠기지 않는 것 (명시)**
- 저장된 논리명의 구분자를 토글로 끈 뒤에도 그대로 남는다는 것(3.8)은 데이터 무변경이라 UI 테스트로는
  관측되지 않는다. core 수준에서 "규칙이 값을 바꾸지 않는다"로만 확인한다.
