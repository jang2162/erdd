# 물리명 우선 명명 + 필수값 표시 (트랙 A+B) — 설계

**작성일:** 2026-08-10 / **base:** `main` (`2b0bebc`) / **마이그레이션:** 없음 / **서버 변경:** 없음

> 이 사이클은 **트랙 C**(`2026-08-10-canvas-selection-clipboard-design.md`)와 **병렬**로 진행한다.
> 겹치는 파일은 `apps/web/src/editor/edit-panel.tsx` 하나다 — 이 트랙은 컬럼 행의 **입력 필드**를,
> 트랙 C는 컬럼 행의 **선택 상태·하이라이트**를 건드린다.

## 1. 목적과 범위

이 도구는 지금까지 **논리명에서 물리명이 나오는** 한 방향만 지원했다. 실제 설계에서는 반대 방향이
자주 필요하다 — 기존 DB의 물리명을 손에 쥔 채 논리명을 채워 넣거나, 물리명 규칙이 먼저 정해진
조직에서 물리명부터 입력한다. 이 사이클은 **양방향을 대칭으로** 만들고, 그 김에 폼이 어느 쪽을
먼저 요구하는지를 화면 순서로 드러낸다.

함께, 폼에서 **무엇이 필수이고 무엇이 선택인지 구분이 안 된다**는 문제를 푼다.

**범위 안**
- A-1 논리·물리가 함께 나오는 모든 폼의 순서를 물리 → 논리로
- A-2 물리명 → 논리명 역생성(자동 + 버튼), 기존 논리명 → 물리명과 완전 대칭
- A-3 `addTable`이 물리명을 비워 둔다 (이월 항목 해소)
- A-4 단어 사전의 역방향 등록 — 미등록 **약어**에 논리명을 붙여 등록
- B-1 폼 필수값 표시
- B-2 빈 필수값 경고 `required-empty`

**범위 밖**
- core `restoreLogicalName`의 알고리즘 변경 (이미 있고 DDL 역설계가 쓰고 있다)
- 사전 목록·Excel 시트·검사 화면의 **컬럼 순서** (폼만 바꾼다)
- 저장 차단 — 필수값이 비어도 저장은 된다 (D-B1)

## 2. 확정된 결정 (사용자 확정)

### D-A1. 역생성은 기존 정생성과 **완전 대칭**이다

기존 규칙(`edit-panel.tsx`): 논리명을 커밋할 때 **물리명이 비어 있으면** `generatePhysicalName`으로
채운다. 이미 값이 있으면 건드리지 않고, 「재생성」 버튼을 눌러야 덮어쓴다.

대칭 규칙: 물리명을 커밋할 때 **논리명이 비어 있으면** `restoreLogicalName`으로 채운다. 이미 값이
있으면 건드리지 않고, 「논리명 복원」 버튼을 눌러야 덮어쓴다.

**왜 이 대칭인가:** 둘 다 "빈 칸일 때만"이므로 두 자동 규칙이 서로를 덮어쓸 수 없다. 사용자가 손으로
다듬은 이름은 어느 방향으로도 사라지지 않는다. 항상 덮어쓰는 양방향 규칙은 검토했으나 배제했다 —
한쪽을 고칠 때마다 반대쪽의 수작업이 날아간다.

### D-A2. 물리가 위(왼쪽), 논리가 아래(오른쪽) — 논리·물리가 함께 나오는 **모든** 폼

컬럼 행은 좌우 2열 그리드를 유지하고 **순서만** 바꾼다(왼쪽=물리명). 세로 2행으로 바꾸면 컬럼이 많은
테이블에서 사이드바가 2배로 길어진다.

### D-A3. `addTable`은 물리명을 **빈 문자열**로 둔다. 논리명은 「테이블n」을 유지한다

이월 항목("새 테이블에 논리명을 입력해도 물리명이 자동 생성되지 않는다")의 두 선택지 중
**물리명을 비우는 쪽**이다. `TABLE_n` 패턴을 "임시값처럼 보이면 덮어쓴다"로 판정하는 쪽은 사용자가
진짜로 `TABLE_1`을 원한 경우와 구별되지 않아 배제했다.

논리명까지 비우지는 않는다 — 캔버스에 이름 없는 노드가 뜨는 것을 피한다.

### D-B1. 필수값은 **표시 + 경고**까지. 저장은 막지 않는다

설계 도구는 중간 상태 저장이 정상이다. 물리명을 아직 안 정한 테이블, 타입을 안 고른 컬럼이 모델에
남아 있는 것이 작업 흐름이다. 저장을 막으면 그 흐름이 끊긴다.

⚠️ **이 결정은 "새로 막지 않는다"는 뜻이다 — 이미 있는 차단은 그대로 둔다.** 단어·용어 다이얼로그는
이미 필수값이 비면 「저장」이 `disabled`다(`dict-panel.tsx:358`·`:488`의
`logicalNameInvalid || abbreviationInvalid`). 그 동작을 **제거하지 않는다.** 다이얼로그는 "닫는 순간
확정"이라 중간 상태가 성립하지 않고, 편집 패널은 "모델에 남는 미완성"이라 성립한다 — 둘의 성격이
달라 규칙도 다르다. 이 트랙이 다이얼로그에 더하는 것은 **별표 표시뿐**이다.

## 3. 의미 모델

### 3.1 "필수"의 정의는 **모델 zod 스키마**다

`packages/core/src/model.ts`에서 `.nullable()`이 붙지 않은 문자열 필드가 필수다. 이 기준을 쓰는
이유는 **손으로 관리하는 두 번째 목록을 만들지 않기 위해서**다 — 스키마가 이미 진실 원본이고,
필드를 추가·변경할 때 한 곳만 고치면 된다.

| 엔티티 | 필수 | 선택 |
|---|---|---|
| `table` | `logicalName`, `physicalName` | `comment`, `groupId` |
| `column` | `logicalName`, `physicalName`, `type` | `comment`, `defaultValue`, `domainId` |
| `word` | `logicalName`, `abbreviation` | `englishName`, `description` |
| `term` | `logicalName`, `physicalName` | `domainId`, `description` |
| `domain` | `name`, `logicalType` | `category`, `defaultValue`, `description`, 방언별 타입 |
| `index` | `name` | — |
| `customField` | `name` | (정의 자체의 `required` 플래그는 별개 축이다) |

⚠️ **주의: zod의 `z.string()`은 빈 문자열을 허용한다.** 그래서 "스키마가 강제하는 필수"가 아니라
**"비어 있으면 안 되는 필드"**라는 뜻으로 쓰는 것이다. 스키마는 목록의 출처일 뿐 검증자가 아니다.
검증은 `required-empty` 경고가 한다(3.4).

### 3.2 역생성의 실패는 **조용한 실패**다

`restoreLogicalName`은 모든 토큰이 사전에 있을 때만 `ok: true`를 낸다. 실패하면
`{ ok: false, unknownTokens }`다. 이때 **논리명을 채우지 않는다** — 부분 복원("MBR_XYZ" → "회원XYZ")은
사용자가 고치기보다 오해하기 쉬운 값을 남긴다.

실패는 이미 있는 경고 체계가 드러낸다: 물리명은 있는데 논리명이 비었으면 `required-empty`가
잡고(3.4), 그 물리명의 토큰이 사전에 없다는 사실은 사전 화면의 **미등록 약어** 섹션이 모아 보여준다
(3.3). 그래서 별도의 인라인 오류 표시를 넣지 않는다.

### 3.3 사전의 두 방향은 **같은 `createWord`로 끝난다**

기존 「미등록 단어」는 전 테이블·컬럼의 **논리명**을 `generatePhysicalName`으로 분해해 나온
`unknownWords`(사전에 없는 논리 단어)를 모아, 사용자가 **약어**를 입력하면 `createWord`로 등록한다.

역방향은 전 테이블·컬럼의 **물리명**을 `restoreLogicalName`으로 훑어 나온 `unknownTokens`(사전에 없는
약어)를 모아, 사용자가 **논리명**을 입력하면 **같은 `createWord`**로 등록한다.

`Word`는 `{ logicalName, abbreviation }` 쌍이므로 두 방향은 **같은 엔티티의 빈 칸이 어느 쪽이냐**만
다르다. 등록 경로를 하나로 두는 것이 이 대칭의 핵심이다 — 두 번째 생성 경로를 만들면 `origin`
처리·중복 검사가 갈린다.

**중복 판정:** 이미 같은 약어를 가진 단어가 있으면 그 약어는 애초에 `unknownTokens`에 나오지 않는다
(`abbreviationIndex`가 잡는다). 같은 논리명을 가진 단어가 이미 있는데 사용자가 그 논리명을 입력하는
경우는 막지 않는다 — 기존 정방향도 막지 않으며, 동명 단어는 `abbreviationIndex`가 id 순으로
결정론적으로 고른다.

### 3.4 `required-empty` 경고는 `custom-required`의 패턴을 그대로 쓴다

`computeWarnings`(`packages/core/src/warnings.ts`)에 이미 `custom-required`가 있다 — 커스텀 항목
정의가 `required`인데 값이 비면 경고를 낸다. 표준 필드에는 그런 경고가 **하나도 없다**(확인함).

`required-empty`를 같은 자리에 같은 모양으로 추가한다:
- `scope`: `'table' | 'column'` (기존 경고와 동일한 분배 경로)
- `message`: `필수 항목 "논리명"이(가) 비어 있습니다`

`buildNodes`가 scope별로 분배하고 `WarningBadge`가 띄우는 기존 배선을 그대로 타므로, 캔버스 배지와
편집 패널에는 추가 배선 없이 노출된다(HANDOFF 3.4의 "경고 표면은 이미 있다").

⚠️ **"추가 배선 없이"는 모델 검사 화면에는 해당하지 않는다** (구현 중 발견, 2026-08-10).
`apps/web/src/editor/naming-check.tsx`의 `KIND_LABEL`이 **`Record<Warning['kind'], string>`**이라
새 kind를 추가하면 **타입이 등록을 강제한다**(빠뜨리면 TS2741로 web typecheck가 깨진다). 즉
`KIND_LABEL`은 사실상 **새 경고 종류의 등록처**다 — `model-diff.ts`의 `KIND_ORDER`가 "7번째 엔티티
등록처"인 것과 같은 성격이고, 이쪽은 타입이 잡아 주므로 조용히 빠지지는 않는다.

라벨은 **「필수 값 누락」**이다. 바로 위의 `custom-required`가 이미 「필수 항목 미입력」이라
「필수 입력 누락」류로 지으면 사용자가 두 그룹을 구별하지 못한다 — 표준 필드와 커스텀 항목이
서로 다른 그룹으로 보여야 한다.

**범위:** 모델 검사 화면에 모이는 것은 `table`·`column`뿐이다. 사전·도메인 다이얼로그의 필수값은
경고 대상이 아니라 **표시(별표)만** 한다 — 그것들은 다이얼로그를 닫는 순간 확정되는 값이라
"모델에 남은 미완성 상태"가 아니다.

⚠️ **D-A3와의 상호작용: 새 테이블은 만들자마자 `required-empty`가 뜬다.** `addTable`이 물리명을
비우므로(D-A3) 물리명 필수 경고가 즉시 붙는다. **이것은 의도한 동작이다** — 물리명이 없는 테이블은
DDL에서 빠지므로(3.5) 사용자가 그 사실을 알아야 한다. 논리명을 입력하는 순간 물리명이 자동
생성되면서 경고가 사라지므로, 정상 흐름에서 경고가 보이는 시간은 짧다.

다만 **테스트가 이 상호작용을 잠가야 한다**(6.2) — 두 결정이 각각은 맞고 함께 놓았을 때 시끄러운
것이 이 사이클에서 가장 그럴듯한 실패 모드다.

### 3.5 빈 물리명과 DDL

`addTable`이 물리명을 비우면 물리명이 빈 테이블이 모델에 존재할 수 있다. DDL 생성기는
`quoteIdentifier(table.physicalName, dialect)`를 그대로 쓰므로(`ddl.ts:99`) `CREATE TABLE ""`가 나온다.

**정책: 물리명이 빈 테이블은 DDL에서 제외하고 경고한다.** 0컬럼 테이블에 이미 같은 정책이 있고
(HANDOFF 6절 "0컬럼 테이블은 DDL에서 제외 + 경고"), `ddlWarnings`가 그 자리다. 빈 물리명 컬럼도
같은 규칙으로 그 테이블을 제외한다 — 컬럼 하나가 빠진 DDL은 조용히 틀린 산출물이다.

## 4. core 변경

### 4.1 `warnings.ts` — `required-empty` 추가

- `Warning['kind']` union에 `'required-empty'` 추가
- `computeWarnings`에서 테이블(`logicalName`·`physicalName`)과 컬럼(`logicalName`·`physicalName`·`type`)의
  빈 값을 검사
- **`rules` 게이트 밖**에 둔다. 명명 규칙 설정과 무관한 완결성 경고다(HANDOFF 6절의
  `duplicate-physical-table` 이월 항목이 지적한 것과 같은 성격 — 새로 만드는 것은 처음부터 밖에 둔다)

### 4.2 `ddl.ts` / `ddlWarnings` — 빈 물리명 테이블 제외

- 테이블 물리명이 빈 문자열이거나, 그 테이블의 컬럼 중 물리명이 빈 것이 있으면 해당 테이블을
  `CREATE TABLE`·FK·인덱스·코멘트에서 전부 제외
- `ddlWarnings`가 그 사실을 경고로 낸다

**`restoreLogicalName`은 손대지 않는다.** 이미 `naming.ts:70`에 있고 DDL 역설계가 쓴다.

### 5.2 필수 표시의 형태

라벨 컴포넌트에 `required` prop을 받아 `*`를 붙이고 입력에 `aria-required="true"`를 준다. 개별 폼에서
문자열로 「(필수)」를 적지 않는다 — **한 곳에서 표시 방식을 바꿀 수 있어야** 다음에 형태를 조정할 때
폼 7개를 다시 훑지 않는다.

기존에 라벨 문자열로 박혀 있는 「도메인 (선택)」(`dict-panel.tsx`) 같은 표기는 제거한다. 필수에
별표가 붙으면 없는 쪽이 선택이라는 것이 규칙으로 읽히므로, 두 표기가 공존하면 규칙이 흐려진다.

### 5.3 `unregisteredAbbreviations(model, rules): string[]`

`unregisteredWords`(`dict-edits.ts:206`)의 대칭. 전 테이블·컬럼의 **물리명**을 `restoreLogicalName`으로
훑어 `ok: false`인 것의 `unknownTokens`를 dedupe해 모은다. 빈 물리명은 건너뛴다(정방향이 빈 논리명을
건너뛰는 것과 대칭).

### 5.4 매뉴얼 갱신

- `docs/manual/user-guide.md:156` — 「각 행에서 왼쪽이 논리명, 오른쪽이 물리명이다」 → 뒤집는다
- `:151` — 테이블 폼 서술의 입력 순서
- `:292` — 단어·용어 등록 다이얼로그의 필드 순서
- `:301` — 「물리명 자동 생성은 물리명이 비어 있을 때만」에 역방향 규칙을 대칭으로 추가
- 새 테이블의 초기 이름 서술(`:151` 「테이블1」/`TABLE_1`) — 물리명이 이제 빈다

### 6.3 구분력 (필수)

각 수정마다 프로덕션 변경을 되돌려 테스트가 **실제로 실패하는지** 확인하고 복구한다. 특히:

- **순서 테스트가 순서를 잡는지** — 두 입력의 순서를 되돌렸을 때 실패해야 한다. `getByLabelText`로
  값만 확인하는 단언은 순서를 전혀 잡지 못한다(둘 다 존재하기만 하면 통과한다). DOM 위치 비교로
  써야 한다
- **`required-empty`가 빈 값에만 반응하는지** — 경고 생성 조건을 `true`로 고정해도 통과하는 테스트가
  되기 쉽다. "값이 있으면 경고가 없다"를 반드시 함께 단언한다
- **역생성 자동 트리거가 "비어 있을 때만"인지** — 조건을 지워 항상 덮어쓰게 바꾸면 실패해야 한다

### 6.4 브라우저 스모크

1. 새 테이블 추가 → **물리명이 비어 있는지** 확인 → 논리명에 사전에 있는 단어를 입력 → 물리명 자동 생성
2. 컬럼에 물리명만 입력 → 논리명 자동 복원
3. 사전에 없는 약어로 물리명 입력 → 논리명이 비고 → 사전 화면 「미등록 약어」에 그 토큰이 뜨는지 →
   논리명을 붙여 등록 → 편집 패널에서 「논리명 복원」이 이제 성공하는지
4. 필수 필드를 비웠을 때 배지·모델 검사 화면에 경고가 뜨는지
5. **대조군**: 빈 물리명 테이블이 있는 상태로 DDL 내보내기 → 그 테이블이 빠지고 경고가 뜨는지

## 7. 알려진 한계 (이월 후보)

- **동명 약어가 여럿이면 역생성이 id 순으로 하나를 고른다**(`abbreviationIndex`의 기존 동작). 사용자가
  다른 쪽을 원해도 고를 수 없다
- **부분 복원을 제공하지 않는다**(3.2). 토큰 하나만 사전에 없어도 논리명이 통째로 비어 있다
- 사전 목록·Excel 시트·모델 검사 화면의 **컬럼 순서**는 그대로 논리명이 먼저다. 폼만 뒤집었으므로
  화면 간 순서가 갈린다 — 실사용에서 걸리면 다음 사이클에서 정리한다
- `required-empty`는 `table`·`column`만 본다. 도메인·단어·용어의 빈 필수값은 별표로만 알린다
