# 열려 있는 제품 결정 — 어느 주제에도 붙지 않는 것

`docs/guides/` 의 각 정본이 **자기 주제의 「알려진 한계」**를 갖는다.
여기 남는 것은 **범위 밖으로 미룬 제품 결정**과 **선행 결정이 있어야 착수되는 것**뿐이다.

**⚠️ 이 문서는 `ops/` 다 — 항목이 해소되면 지운다. 다 비면 파일째 지운다.**
착수한 항목의 「어기면 무엇이 깨지는가」가 생기면 `guides/` 의 해당 정본으로 올린다.

## 메일 발송 인프라

초대·비밀번호 재설정은 **링크로 해소됐고 발송 한 겹만 남았다.** 지금은 관리자가 화면의 링크를 복사해
직접 전달한다. 메일이 붙으면 셋이 함께 해소된다.

- **링크 자동 전달** — [../guides/auth-links.md](../guides/auth-links.md) 의 토큰·화면은 그대로 두고
  한 겹만 얹으면 된다. 설계가 그렇게 나뉘어 있다.
- **로그인 화면의 「비밀번호 찾기」** — 지금은 없다. 메일이 없는 상태에서 두면 계정 존재 여부를
  탐색당하는 미인증 공개 엔드포인트가 생길 뿐이고, 어차피 관리자가 링크를 전달해야 해서 뺐다.
- **승격 요청 큐의 알림** — 현재는 폴링 배지뿐이다
  ([../guides/shared-resources.md](../guides/shared-resources.md)).

**선행 결정:** 발송자 선택 · 도메인 인증 · 발송 실패 처리 · 개발 환경의 발송 차단.

> **사용자가 「지금 필요한 타이밍이 아니다」로 보류했다.** 서버를 세운 관리자가 링크를 직접 전달하는
> 것이 아직 감당된다. 항목 자체는 유효하니 지우지 않는다.

## MySQL 의 `TIMESTAMP` 함정 — 나머지 절반

nullable 쪽은 `NULL` 명시로 막았다(정본은 [export-format.md](../guides/export-format.md)
「MySQL 의 nullable `TIMESTAMP` 에는 `NULL` 을 명시한다」). **`TIMESTAMP NOT NULL` 은 그대로 남아
있다** — `explicit_defaults_for_timestamp = 0` 서버에서 실물로 확인했다.

- 테이블의 **첫** `TIMESTAMP NOT NULL` 컬럼은 `DEFAULT current_timestamp()` +
  `on update current_timestamp()` 를 받아 **다른 컬럼만 바꾸는 UPDATE 에도 값이 바뀐다.**
- **두 번째부터**는 `DEFAULT '0000-00-00 00:00:00'` 이 박혀 값을 안 넣으면 0 날짜가 조용히 들어간다.
- PK 인 `TIMESTAMP` 컬럼은 `NULL` 을 내도 MySQL 이 `NOT NULL` 로 바꾸므로 같은 자리에 남는다.

**막으려면 명시적 `DEFAULT` 를 내야 하는데 무엇을 줄지가 제품 결정이다** — `CURRENT_TIMESTAMP`
(자동 초기화는 남고 `ON UPDATE` 만 사라진다) / `'0000-00-00 00:00:00'`(엄격 모드에서 거부된다) /
사용자에게 강제 입력 중 어느 쪽도 기본값으로 삼기 어렵다. 착수하려면 그 결정이 먼저다.

## ⚠️ 배제한 것 — 다시 1순위로 올리지 마라

- **실제 DB 접속 스키마 스캔.** 「이 프로젝트 성격에 안 맞다」가 사용자 판단이다. 설계 도구가 운영
  DB 에 붙는 일이고, **DDL 텍스트 가져오기로 값의 대부분을 이미 얻는다.**

## 변경 기록 — 미룬 것

- **서버 모드의 변경 기록.** 문법·재생 엔진은 core 에 있어 재사용할 수 있다. 서버에는 기록을 둘
  테이블·프로시저·권한·실시간 전파가 새로 필요하다.
- **테이블 옵션 기록.** `tableOptions`(MySQL ENGINE 등)는 기록에 싣지 않는다.
  ([../guides/changeset-format.md](../guides/changeset-format.md) 「알려진 한계」)

## 기획에 있으나 구현되지 않은 것

매뉴얼을 쓰면서 전수 확인했고, **확인되지 않은 것은 매뉴얼에서 뺐다**(그래서 매뉴얼은 구현된 것만
설명한다). 값이 큰 것은 넷이다.

1. **프로젝트 명명 규칙·방언·이름 편집 화면** — 명명 규칙 일부만 열려 있다
   ([../guides/naming.md](../guides/naming.md) 「알려진 한계 · 설정 UI」).
2. **내보내기 범위의 「선택 테이블」** — **엔진은 되고 UI 만 없다**
   ([../guides/export-format.md](../guides/export-format.md)).
3. **DDL 가져오기의 파일 업로드** — 지금은 텍스트 영역뿐이다
   ([../guides/ddl-parser.md](../guides/ddl-parser.md)).
4. **다중 선택 후 그룹 일괄 배정** — `setTableGroup` 호출부가 둘 다 단일 대상이다.

나머지는 노드 접기 · 컬럼 순서 드래그 · 컬럼 단위 관계 드래그 · 인덱스 「탭」 · 도메인의 별도 일괄
반영 액션 · 테이블·컬럼 설명 입력 · 컬럼 기본값·자동증가 입력 · 스냅샷 설명 입력 · 자동 정렬의
「선택 테이블」 범위 · 인덱스 정렬 방향 역설계다(뒤 셋은 다른 문서의 「알려진 한계」와 겹친다).
