# ERDD 사용 매뉴얼

웹 UI 로 ERD 를 설계하는 사람(설계자·개발자·리뷰어)과 조직 관리자를 위한 기능별 레퍼런스입니다. 튜토리얼이 아니므로 필요한 기능의 절만 열면 됩니다. 각 절은 같은 순서를 따릅니다: 무엇(기능) · 어디서(위치) · 어떻게(조작) · 제약(권한·상한·주의). 화면에 보이는 문구는 보이는 그대로 굵게 적었습니다. 설치·운영·서버 구동은 [install.md](./install.md)에, 명령줄 도구는 [cli-guide.md](./cli-guide.md)에 있습니다. **서버 없이 `erdd serve` 로 연 로컬 모드**라면 [local-guide.md](./local-guide.md)도 함께 읽으세요. 에디터는 같지만 아래 20개 장 중 6개는 해당하지 않고 2개는 다르게 동작합니다.

## 1. 계정과 로그인

> [!NOTE]
> **로컬 모드에는 없습니다.** 계정도 로그인 화면도 없습니다. 에디터가 바로 열립니다(→ [로컬 모드 매뉴얼](./local-guide.md)).

**무엇** — ERDD 에는 스스로 가입하는 기능이 없습니다. **관리자가 발급한 일회용 초대 링크**를 열어 계정을 직접 만듭니다. 비밀번호를 잊었을 때도 같습니다. 관리자가 재설정 링크를 발급해 전달합니다.

**어디서** — `/login`(로그인), `/invite/:token`(초대 수락), `/reset/:token`(비밀번호 재설정). 세 화면 모두 **로그인 없이 열립니다.**

**어떻게 — 로그인** — `/login` 에서 **이메일**과 **비밀번호**를 입력하고 **로그인**을 누르세요. 처리하는 동안 버튼에 **확인 중…** 이 보입니다. 성공하면 홈 화면(`/`)으로 갑니다. 계정이 없는 사람을 위해 화면에 **계정이 없다면 관리자에게 요청하세요.** 가 적혀 있습니다.

**어떻게 — 초대 링크로 계정 만들기** — 관리자가 보낸 `/invite/:token` 링크를 여세요(제목 **초대 수락**). 상자에 초대받은 이메일이 보입니다. 조직 초대라면 들어갈 조직과 역할도 함께 보입니다. 예: **조직 〈이름〉에 관리자(으)로 참여합니다**. **이름**, **비밀번호**, **비밀번호 확인**을 입력하고 **계정 만들기**를 누르세요. 버튼에 **만드는 중…** 이 보입니다. ERDD 가 계정을 만들고 로그인 화면으로 보냅니다. **자동으로 로그인되지는 않습니다.**

**어떻게 — 비밀번호 재설정** — `/reset/:token`(제목 **비밀번호 재설정**)에서 **새 비밀번호**와 **새 비밀번호 확인**을 입력하고 **비밀번호 설정**을 누르세요. 성공하면 로그인 화면으로 갑니다.

**제약**

| 항목 | 값·동작 |
|---|---|
| 초대 링크 유효 기간 | 발급 후 7일 |
| 재설정 링크 유효 기간 | 발급 후 24시간 |
| 비밀번호 최소 길이 | 8자 |
| 재설정에 성공한 뒤 | **새 비밀번호를 정하면 다른 기기의 로그인이 모두 해제됩니다.** |
| 재설정 링크 발급만으로는 | 비밀번호가 바뀌지 않고 로그인 세션도 유지됩니다 |

두 비밀번호 입력이 다르면 **비밀번호가 서로 다릅니다** 가 나옵니다. 링크로 진행할 수 없으면 입력 양식이 사라지고 이유가 나옵니다. 다음 행동은 두 가지입니다.

- 새 링크를 받을 수 있는 경우(링크가 없거나, 만료됐거나, 회수됐을 때) 메시지는 **관리자에게 문의해 새 링크를 받으세요.** 입니다.
- 그 이메일의 계정이 이미 있는 경우 메시지는 **이 이메일에는 이미 계정이 있습니다 — 새 링크를 받을 수는 없으니 로그인하세요. 비밀번호를 모르면 관리자에게 재설정 링크를 요청하세요.** 입니다. 같은 이메일로 초대를 다시 만들 수 없다는 뜻입니다.

일시적인 실패(네트워크 끊김, 서버 오류)로는 링크가 죽지 않습니다. **지금은 처리하지 못했습니다. 잠시 후 다시 시도하세요.** 가 나오고 **입력한 값은 그대로 남으므로** 같은 버튼을 다시 누르면 됩니다. 초대 화면이 정보를 불러오지 못하면 **다시 시도** 버튼이 나옵니다.

## 2. 화면 지도

> [!NOTE]
> **로컬 모드에서는 다릅니다.** 화면은 에디터와 프로젝트 설정 둘뿐입니다(→ [로컬 모드 매뉴얼 4.1](./local-guide.md#41-화면은-둘뿐이다)).

**무엇** — 화면은 모두 9개입니다. 대부분 로그인이 필요합니다. 일회용 링크 화면과 로그인 화면 셋만 예외입니다.

**어디서** — 로그인하면 공통 상단 바가 보입니다. 왼쪽 로고는 홈으로 갑니다. 오른쪽에는 대기 중인 승격 요청 배지(→ [13절](#13-공용-리소스))와 사용자 메뉴가 있습니다. 에디터만은 자체 헤더가 있는 전용 전체 화면 레이아웃을 씁니다.

**지금 쓰고 있는 ERDD 의 버전**이 상단 바와 에디터 헤더 모두에서 로고 옆에 작은 글씨로 보입니다(`v0.5.0` 형태). CLI 의 `erdd --version` 과 같은 값입니다. 모델의 이력을 다루는 에디터의 **버전** 기능(→ [14절](#14-버전이력스냅샷비교))과는 다릅니다.

| 경로 | 화면 | 보호 | 내용 |
|---|---|---|---|
| `/login` | 로그인 | 공개 | 이메일·비밀번호 로그인 |
| `/invite/:token` | 초대 수락 | 공개 | 초대 링크로 계정 만들기 |
| `/reset/:token` | 비밀번호 재설정 | 공개 | 재설정 링크로 새 비밀번호 정하기 |
| `/` | 홈 | 로그인 | **〈이름〉님의 작업 공간**: 내 조직 카드와 **팀 조직 만들기** |
| `/org/:orgId` | 조직 상세 | 로그인 | 프로젝트 목록·생성, 멤버, 초대, 승격 요청, 조직 공용 리소스 |
| `/p/:projectId` | ERD 에디터 | 로그인 | 캔버스, 트리, 편집 패널, 에디터의 모든 기능 |
| `/p/:projectId/settings` | 프로젝트 설정 | 로그인 | 프로젝트 정보, 명명 규칙(논리명 구분자, 테이블 물리명 형식, 테이블 논리명 형식), 테이블 옵션, 프로젝트 멤버 관리 |
| `/settings` | 내 설정 | 로그인 | 비밀번호 변경, 액세스 토큰 |
| `/admin` | 계정 관리 | 로그인 + 서비스 역할 `admin` | 계정 초대·상태, 초대 목록, 전역 공용 리소스 |

없는 경로를 열면 **페이지를 찾을 수 없습니다** 와 **홈으로** 가 나옵니다. 사용자 메뉴(내 이름)에는 이메일과 함께 **설정**과 **로그아웃**이 있습니다. 서비스 역할이 `admin` 이면 **관리자**도 보입니다.

## 3. 조직·프로젝트와 권한

> [!NOTE]
> **로컬 모드에는 없습니다.** 조직도 멤버도 역할도 없고, 늘 관리 권한을 가집니다(→ [로컬 모드 매뉴얼 1절](./local-guide.md#1-이-문서를-읽는-사람)).

**무엇** — 조직은 멤버 관리의 단위이고, 프로젝트 하나는 DB 스키마 하나입니다. 권한은 겹쳐서 작동하는 **역할 축 셋**으로 정해집니다.

**어디서** — 홈 화면(`/`)에서 조직을 고르세요. 프로젝트 생성과 멤버 관리는 조직 상세 화면(`/org/:orgId`)에서 합니다. 프로젝트 멤버는 프로젝트 설정(`/p/:projectId/settings`)에서 관리합니다.

| 축 | 값 | 정하는 곳 | 성격 |
|---|---|---|---|
| 서비스 역할 | `admin` / `user`(**관리자** / **일반**) | 관리자가 계정을 초대할 때(`/admin`) | 서비스 전체의 관리자입니다. `/admin` 화면에 들어갈 수 있는 유일한 역할이고, 조직·프로젝트 권한과는 별개의 축입니다 |
| 조직 역할 | `owner` / `admin` / `member` | 조직 상세 화면의 **멤버** 표 | 아래 표 |
| 프로젝트 역할 | `admin` / `editor` / `viewer` | 프로젝트 설정의 **프로젝트 멤버** | 아래 표 |

| 조직 역할이 할 수 있는 것 | Owner | Admin | Member |
|---|:---:|:---:|:---:|
| 프로젝트 생성 | ○ | ○ | ✕ |
| 멤버 추가·제거, 역할 변경 | ○ | ○ | ✕ |
| Owner 지정·강등·제거 | ○ | ✕ | ✕ |
| 조직 초대 링크 발급·회수 | ○ | ○ | ✕ |
| 조직 라이브러리 관리, 승격 요청 승인 | ○ | ○ | ✕ |
| 프로젝트 접근 | 조직의 전부 | 조직의 전부 | 초대받은 것만 |

마지막 Owner 는 강등하거나 제거할 수 없습니다(**마지막 Owner는 강등할 수 없습니다**). 권한 없는 조작은 **조직 관리 권한이 없습니다** 로 거절됩니다.

프로젝트 쪽에서는 서버가 요구 접근 수준 셋을 검사합니다.

| 수준 | 통과하는 사람 | 허용하는 것 |
|---|---|---|
| 보기 | Org Owner/Admin, 또는 역할이 무엇이든 프로젝트 멤버 | 모델 보기, 내보내기, 실시간 세션 참여 |
| 편집 | Org Owner/Admin, Project Admin/Editor | 모든 모델 편집 |
| 관리 | Org Owner/Admin, Project Admin | 프로젝트 멤버 관리, 스냅샷 복원·삭제 |

Viewer 도 에디터에 들어갈 수 있지만, 하단 바의 편집 도구 자리에는 **읽기 전용** 배지만 보이고 노드 드래그·관계 연결·삭제가 잠깁니다. 편집을 시도하면 **이 프로젝트에 대한 편집 권한이 없습니다** 가 나옵니다.

**어떻게 — 조직·프로젝트 만들기** — 홈 화면에서 **팀 조직 만들기** → **조직 이름** → **만들기**를 누르세요. 만든 사람이 Owner 가 됩니다. 조직 상세 화면에서 **프로젝트 만들기** → **이름**, **설명 (선택)**, **대상 DB 방언** → **만들기**를 누르세요. 만든 사람이 Project Admin 이 됩니다. 방언은 **PostgreSQL**, **MySQL·MariaDB**, **Oracle**, **MSSQL** 넷이고 여럿을 켤 수 있습니다(기본값은 PostgreSQL). 하나도 고르지 않으면 **대상 DB를 하나 이상 선택하세요** 가 나옵니다.

**어떻게 — 멤버 추가** — 계정이 있는 사람은 조직 상세 화면 **멤버**의 **이메일로 추가**에 이메일을 입력하고 역할(Member/Admin)을 골라 **추가**를 누르세요. 계정이 없는 사람은 같은 화면의 **초대** 절에서 링크를 만드세요(→ [19절](#19-관리자-업무)). 화면에도 **아직 계정이 없는 사람을 부릅니다. 이미 가입한 사람은 위 멤버 추가를 쓰세요.** 라고 적혀 있습니다. 프로젝트에 사람을 더하려면 프로젝트 설정 → **프로젝트 멤버** → **조직 멤버 추가**에서 사람과 Admin/Editor/Viewer 를 골라 **추가**를 누르세요. 후보에는 **이미 조직 멤버인 사람만** 나옵니다.

**제약**

- 계정을 만들면 **〈이름〉의 공간** 이라는 **개인 조직**이 자동으로 만들어지고 본인이 Owner 가 됩니다. 홈 카드에 **개인 공간** 배지가 붙고 목록 맨 앞에 옵니다. 개인 조직에는 멤버를 더할 수 없고(**개인 조직에는 멤버를 추가할 수 없습니다**) 초대도 만들 수 없으므로 **멤버**와 **초대** 절이 보이지 않습니다.
- 프로젝트 설정에서 바꿀 수 있는 것은 프로젝트 멤버, 명명 규칙의 논리명 구분자 토글·테이블 물리명 형식·테이블 논리명 형식, 테이블 옵션의 방언 네 칸입니다. 이름, 설명, 대상 DB 방언은 읽기 전용으로 보입니다. 명명 규칙 절의 **논리명을 밑줄로 구분** 체크박스는 논리명을 「회원_주문_번호」 처럼 단어 사이에 밑줄을 넣어 쓸지를 정합니다. 기본값은 켜짐입니다. 꺼도 **이미 저장된 논리명의 밑줄은 지워지지 않습니다.** 같은 절의 **테이블 물리명 형식** 입력란은 테이블 물리명을 「접두 + 입력한 부분」으로 조합하는 템플릿입니다. 그 아래 **테이블 논리명 형식** 입력란은 같은 방식으로 산출물에서 테이블 논리명을 조합합니다(→ [10절](#10-명명-체계단어용어-사전)). 나머지 세 설정(대문자 스네이크, 물리명 구분자 `_`, 최대 30바이트)은 아직 화면이 없습니다. 그 아래 **테이블 옵션** 절에는 DDL 을 내보낼 때 `CREATE TABLE` 뒤에 붙는 방언별 문자열이 있습니다(→ [9.1절](#91-테이블-옵션enginecharset)). 두 절 모두 관리 권한이 있을 때만 보입니다. 방언은 만들 때 고른 그대로입니다.

## 4. 에디터 기본

**무엇** — 왼쪽 테이블 트리, 가운데 캔버스, 오른쪽 편집 패널의 세 칸을 위쪽 헤더와 아래쪽 하단 바가 감쌉니다. 헤더에는 열어서 작업하고 닫는 관리 도구가 있습니다. 하단 바에는 캔버스에 바로 작용하거나 캔버스가 어떻게 보일지 정하는 도구가 있습니다.

**어디서** — `/p/:projectId`. 헤더 왼쪽에는 로고와 ERDD 버전이 있습니다. 오른쪽에는 차례로 접속한 사용자의 아바타 → **버전** → **사전·리소스** → **모델 검사** → **파일** → **설정** → 사용자 메뉴가 있습니다. **사전·리소스**는 **도메인**, **단어·용어 사전**, **커스텀 항목**, **공용 리소스** 메뉴를 엽니다. **파일**은 **DDL·DBML 가져오기**와 **내보내기** 메뉴를 엽니다.

화면 맨 아래 **하단 바**에는 왼쪽부터 편집 도구(**테이블 추가**, **메모**, **자동 정렬**, **삭제**) → 실행 취소/다시 실행 → **뷰 전환** → 보기 모드(**논리명**, **물리명**, **혼합**) → 맨 오른쪽의 확대·축소(축소, 배율, 확대, **화면에 맞춤**)가 있습니다.

**어떻게 — 캔버스**

| 조작 | 결과 |
|---|---|
| 빈 곳 드래그 / 스크롤 휠 / 하단 바 오른쪽의 확대·축소 | 이동, 확대·축소, 화면에 맞춤 |
| 노드 클릭 / 관계선 클릭 | 그 테이블·메모·관계를 선택합니다 → 오른쪽 편집 패널이 바뀝니다 |
| 빈 곳 클릭 | 선택을 해제합니다 |
| 노드 드래그 | 위치를 바꿉니다(위치는 모델의 일부라 저장됩니다) |
| 테이블의 왼쪽·오른쪽 핸들을 다른 테이블로 드래그 | 관계를 만듭니다(→ [6절](#6-관계)) |

오른쪽 아래에 미니맵이 있고, 미니맵 자체도 드래그·확대할 수 있습니다.

**테이블을 지우는 방법은 하단 바의 삭제 버튼뿐입니다.** 캔버스에서 노드를 고르고 `Backspace` 를 누르면 화면에서 노드가 사라지지만 저장되지 않습니다. 화면을 다시 열거나 다른 편집이 들어오면 되살아납니다. 지울 때는 늘 하단 바의 **삭제**를 쓰세요.

**어떻게 — 하단 바의 편집 도구**(편집 권한이 있을 때만 보입니다)

| 버튼 | 동작 | 비활성 조건 |
|---|---|---|
| **테이블 추가** | 화면 가운데에 새 테이블을 만들고 선택합니다 | — |
| **메모** | 화면 가운데에 메모를 만듭니다 | 그룹 뷰 안에 있을 때 |
| **자동 정렬** | 보이는 테이블을 관계에 따라 계층으로 다시 배치합니다 | 보이는 테이블이 2개 미만일 때 |
| **삭제** | 선택한 테이블(여럿이면 전부)을 컬럼·인덱스·관계와 함께 삭제합니다 | 선택한 테이블이 없을 때 |
| **실행 취소** / **다시 실행** | 마지막 편집을 되돌리거나, 되돌린 편집을 다시 적용합니다 | 되돌리거나 다시 실행할 것이 없을 때 |

단축키는 `Cmd/Ctrl + Z`(실행 취소)와 `Cmd/Ctrl + Shift + Z`(다시 실행)입니다. 선택·복사·붙여넣기·삭제 단축키는 [20절](#20-선택과-복사)에 있습니다. **커서가 입력란이나 텍스트 영역에 있을 때, 또는 다이얼로그가 열려 있을 때는** 어느 단축키도 동작하지 않습니다. 그때는 브라우저 기본 동작에 양보합니다.

**어떻게 — 테이블 트리** — **테이블 검색**에 논리명이나 물리명의 일부를 입력하면 목록이 걸러집니다(대소문자 무시). 테이블은 그룹별로 묶이고, 어느 그룹에도 없는 테이블은 **미분류** 아래에 모입니다. 테이블을 클릭하면 캔버스가 그 테이블로 이동하고 선택됩니다. 검색란 오른쪽의 폴더 아이콘(**그룹 추가**)은 새 그룹을 만듭니다. 테이블이 없으면 **테이블을 추가해 설계를 시작하세요.** 가 나옵니다. 검색 결과가 없으면 **검색 결과가 없습니다.** 가 나옵니다.

**어떻게 — 트리에서 여러 개 선택** — `Cmd`/`Ctrl`+클릭은 테이블을 선택에 더하거나 뺍니다(토글). `Shift`+클릭은 화면에 보이는 순서대로 범위를 고릅니다. 검색에 걸러졌거나 그룹 뷰 밖이라 **지금 보이지 않는 테이블은 범위에 끌려 들어오지 않습니다.** 수정 키 없이 클릭하면 그 테이블 하나만 남습니다. 이 선택은 캔버스와 같은 선택이므로(→ [20절](#20-선택과-복사)) 트리에서 고른 것이 캔버스에서 강조되고, 캔버스에서 상자로 고른 것이 트리에 보입니다. 선택은 읽기 전용 권한에서도 됩니다.

**어떻게 — 드래그로 그룹 옮기기** — 트리 항목을 잡아 다른 그룹 블록(또는 **미분류**)에 놓으면 테이블의 그룹이 바뀝니다. **여러 개를 선택한 상태에서 그중 하나를 잡으면 선택한 항목이 모두 함께 옮겨집니다.** 선택 밖의 항목을 잡으면 그 항목만 옮겨집니다. 캔버스의 테이블 노드를 트리의 그룹 블록으로 드래그해도 똑같이 동작합니다. 드래그하는 동안 **N개 테이블** 태그가 커서를 따라오고 대상 그룹에 외곽선이 생깁니다. 찾은 테이블을 원하는 그룹에 놓을 수 있어야 하므로 검색이나 그룹 뷰로 숨겨진 그룹도 이때는 모두 나타납니다. 그룹 헤더, 그 아래 목록, 블록의 여백 어디에 놓아도 됩니다. 이미 그 그룹에 있는 테이블만 놓으면 아무 일도 일어나지 않습니다.

**어떻게 — 보기 모드** — 하단 바의 세 버튼 토글에서 **논리명**, **물리명**, **혼합** 중 하나를 고르세요. 혼합은 물리명과 논리명을 나란히 보여 줍니다. 기본값은 **물리명**입니다.

**제약** — 실행 취소 이력은 **최근 100단계**만, 그리고 이 브라우저 세션에서 내가 한 편집만 담습니다. 화면을 다시 열거나 다른 사람의 편집 때문에 모델을 다시 동기화하면 이력이 비워집니다. 실행 취소와 다시 실행도 서버로 가는 편집이라 이력에 **실행 취소**와 **다시 실행**으로 남습니다.

자동 정렬은 **보이는 범위만** 배치하므로, 그룹 뷰에서는 그 그룹의 배치만 바뀝니다. 서버가 편집을 거절하면 토스트로 이유를 알리고 화면을 서버 상태로 다시 맞춥니다.

## 5. 테이블과 컬럼

**무엇** — 테이블과 컬럼은 논리명(업무 용어)과 물리명(DB 식별자)을 따로 가집니다. 논리명을 입력하면 사전이 물리명을 자동으로 만듭니다. 테이블과 컬럼 모두 위가 물리명, 아래가 논리명으로 세로로 쌓입니다. 각 입력란 오른쪽 끝에는 화살표 버튼이 있습니다. 화살표는 누른 칸이 아니라 **반대쪽 칸**을 채웁니다.

**어디서** — 캔버스에서 테이블을 선택하면 오른쪽에 편집 패널이 열립니다. 아무것도 선택하지 않으면 **테이블을 선택하면 여기서 편집합니다.** 만 보입니다.

**어떻게 — 테이블** — **테이블 물리명**에 직접 입력하거나, 논리명 칸의 ↑(**물리명 채우기**)로 논리명에서 물리명을 만드세요. **논리명**에는 업무 이름을 입력하세요. 물리명이 비어 있었으면 그때 물리명이 만들어집니다. 반대로 물리명 칸의 ↓(**논리명 채우기**)는 물리명에서 논리명을 만듭니다. **화살표는 누른 칸의 반대쪽을 채웁니다**(물리명 칸의 화살표를 누르면 논리명이 바뀝니다). 지금 입력 중인 값으로 동작합니다. 입력을 마치고 다른 곳을 클릭할 필요가 없습니다. 입력하자마자 화살표를 누르면 친 값이 쓰입니다. **소속 그룹** 드롭다운으로 테이블을 그룹에 넣으세요(기본값은 **미분류**). 커스텀 항목이 정의돼 있으면 그 아래에 **커스텀 항목** 상자가 이어집니다(→ [11절](#11-커스텀-항목)). 새 테이블에는 「테이블1」 같은 자리표시 논리명만 붙고 물리명은 비어 있습니다. 논리명을 업무 이름으로 바꾸면 사전이 물리명을 만듭니다.

**어떻게 — 컬럼**

1. **컬럼** 옆의 **컬럼 추가**를 누르세요. 컬럼이 「컬럼1」/`COL_1`, 타입 `VARCHAR(255)`, NULL 허용으로 만들어집니다.
2. 각 행은 위가 물리명, 아래가 논리명이고 둘 다 「*」로 필수 표시가 붙습니다. 논리명을 입력하면 **물리명이 비어 있을 때만** 물리명이 만들어집니다. 그 이름이 사전의 용어와 맞으면 도메인도 함께 정해집니다(도메인이 비어 있을 때만). 물리명이 이미 채워져 있으면 둘 다 그대로입니다. 반대로 물리명을 입력하면 논리명이 비어 있을 때만 사전이 논리명을 복원합니다. 약어 하나라도 사전에 없으면 아무것도 채우지 않습니다.
3. 각 칸의 화살표는 내 값으로 반대쪽 칸을 채웁니다. 물리명 칸의 ↓ 는 **논리명 채우기**, 논리명 칸의 ↑ 는 **물리명 채우기**입니다. 이름을 만들 수 없으면 토스트로 이유를 알립니다(**등록되지 않은 약어: GRD, CD**). 이름 아래의 **용어 등록**은 지금의 논리명·물리명·도메인을 용어 사전에 등록합니다(→ [10절](#10-명명-체계단어용어-사전)). 같은 논리명의 용어가 이미 있거나 논리명·물리명 중 하나가 비어 있으면 잠깁니다. **화살표와 용어 등록 모두 지금 입력 중인 값을 봅니다.** 입력을 마치고 다른 곳을 클릭할 필요가 없고, 누른 뒤에도 커서가 입력란에 남습니다.
4. 이름을 입력하는 동안 입력란 아래에 자동완성 목록이 나옵니다. 논리명에서는 사전의 단어와 용어를 접두 일치로 제안합니다. 물리명에서는 약어와 용어 물리명을 제안합니다. ↓↑ 로 움직이고 Enter 로 확정하며 Esc 로 닫습니다. 확정은 **글자를 채울 뿐 저장하지 않으므로** 다음 단어를 이어서 칠 수 있습니다. 다만 반대쪽 칸은 그 자리에서 함께 바뀝니다(화면에서만이며 아직 저장되지 않습니다). 단어 제안은 사전에 아직 없는 꼬리 조각이 남아 있을 때만 나옵니다. 용어는 이름 전체를 보므로, 이름이 사전 단어로 깔끔하게 나뉘어도 계속 나옵니다. 예를 들어 「회원_주문」 까지 쳤으면 용어 「회원_주문_번호」 가 제안됩니다. 제안은 한 번에 최대 8개이고 그중 용어는 최대 3개입니다.
   - 논리명 구분자가 켜져 있으면 **꼬리 조각은 마지막 밑줄 뒤의 토막**입니다. 그래서 밑줄 없이 친 예전 이름(「회원주」)은 입력 전체가 한 조각으로 잡혀 단어 제안이 적게 나옵니다. 밑줄 하나(「회원_주」)를 치면 제안이 바로 돌아옵니다.
5. 이름 아래의 **미등록** 줄은 이름 중 사전에 없는 부분을 칩으로 보여 줍니다. 칩을 누르면 그 자리에 입력란이 열립니다. 논리명 쪽에서는 약어를, 물리명 쪽에서는 논리명을 입력하세요. 그다음 **단어 등록**을 누르면 바로 사전에 추가됩니다. 같은 이름이 사전에 이미 있으면 잠깁니다. 약어만 겹치면 경고만 나옵니다. 칩은 **저장된 값**을 따르므로 입력하는 동안 깜박이지 않습니다.
6. **도메인**에서 도메인을 고르거나 **없음**으로 비우세요.
7. **타입**에는 DB 타입을 직접 쓰세요. **도메인을 정하면 이 칸이 잠기고** **〈논리 타입〉 (도메인: 〈이름〉)** 이 읽기 전용으로 보입니다. 정수에는 접미로 `unsigned` 를 붙일 수 있습니다. `SMALLINT UNSIGNED`, `INT UNSIGNED`, `BIGINT UNSIGNED` 셋입니다(MySQL 에서 PK/FK 컬럼에 흔한 표기). MySQL DDL 로 내보내면 그대로 나갑니다. 나머지 세 방언에서는 부호 있는 타입 + `CHECK (column >= 0)` 으로 나갑니다.
8. **PK**·**NN** 체크박스로 기본 키와 NOT NULL 을 정하세요. 위아래 화살표로 순서를 바꾸고 휴지통으로 지웁니다.

**제약**

- 입력란은 **포커스를 잃을 때** 반영됩니다. 편집한 뒤 다른 칸을 누르거나 `Tab` 으로 옮겨야 저장됩니다. 로컬 모드에서는 `Cmd+S` 와 **저장**이 커서가 있는 칸을 먼저 반영하고 파일을 씁니다(→ [로컬 모드 매뉴얼](local-guide.md#44-편집은-드래프트에-저장이-파일에)).
- 컬럼을 지우면 그 컬럼을 쓰던 관계 매핑과 인덱스 컬럼도 정리됩니다. 매핑이 하나도 남지 않은 관계와 컬럼이 하나도 남지 않은 인덱스도 함께 사라집니다.
- 캔버스 노드에서는 열쇠 아이콘이 PK, `NN` 이 NOT NULL 을 뜻하고 타입은 오른쪽에 보입니다. 컬럼이 없는 테이블은 **컬럼 없음**을 보여 줍니다.
- **편집 패널에는 테이블·컬럼 설명(코멘트), 컬럼 기본값, 자동 증가 입력란이 없습니다.** 값은 모델에 있고 DDL 코멘트와 Excel 정의서에도 나오지만, 웹에서 채우는 방법은 DDL 가져오기(→ [16절](#16-가져오기))와 도메인 기본값(→ [9절](#9-도메인))뿐입니다.
- 한 테이블 안의 컬럼 물리명 중복과 테이블 물리명 중복은 경고가 아니라 **오류**로 판정합니다(→ [12절](#12-모델-검사)).
- 필수 항목(테이블 물리명·논리명, 컬럼 물리명·논리명·타입)의 라벨에는 별표가 붙고, 빈 값은 **필수 값 누락** 경고로 잡힙니다(→ [12절](#12-모델-검사)). **컬럼 행은 라벨을 그리지 않는 촘촘한 레이아웃이라 별표가 없습니다.** 그 행에서는 경고 배지로만 필수 여부를 알 수 있습니다.

## 6. 관계

**무엇** — 관계는 **자식 → 부모**의 외래 키입니다. 부모의 기본 키를 자식에 FK 컬럼으로 복사해 만듭니다.

**어디서** — 캔버스에서 관계선을 누르면 오른쪽에 **관계** 패널이 열립니다. 관계는 캔버스에서 만듭니다.

**어떻게 — 만들기** — 자식 테이블의 왼쪽이나 오른쪽 핸들을 잡아 부모 테이블에 놓으세요. 자식에 부모 기본 키 컬럼 수만큼 FK 컬럼이 생기고, 이름이 겹치면 `_2`, `_3` 이 붙습니다. 새 관계는 바로 선택됩니다. 부모에 기본 키가 없으면 **부모 테이블에 기본 키가 없습니다** 가 나오고 아무것도 만들어지지 않습니다.

**어떻게 — 편집** — 패널 위쪽에 **〈자식 물리명〉 → 〈부모 물리명〉** 이 보입니다.

| 항목 | 값 | 효과 |
|---|---|---|
| **카디널리티** | **1 : N** / **1 : 1** | 캔버스 표기가 바뀝니다. 1:1 이면 DDL 에 UNIQUE 제약도 나갑니다 |
| **식별 관계 (자식 기본 키 편입)** | 체크박스 | FK 컬럼이 자식 기본 키의 일부가 됩니다. 캔버스에서 실선입니다(비식별은 점선) |
| **관계명** | 자유 입력 | 비워 두면 이름을 저장하지 않습니다. DDL 의 FK 제약 이름으로 쓰입니다 |
| **컬럼 매핑** | 부모 PK 마다 자식 컬럼 | 왼쪽 드롭다운으로 자식 쪽 컬럼을 바꿉니다 |

캔버스에서 부모 끝은 늘 막대로, 자식 끝은 1:N 일 때 까마귀발로 그려집니다. 매핑을 다른 컬럼으로 바꾸면 새 컬럼의 PK 여부가 관계의 식별 여부에 맞춰지고, 이전 FK 컬럼은 그것을 쓰는 관계나 인덱스가 없을 때만 지워집니다. 오른쪽 위 휴지통(**관계 삭제**)으로 지우세요. **자식의 FK 컬럼은 일부러 남깁니다.** 필요 없으면 편집 패널에서 지우세요. 관계선을 선택하고 `Delete`/`Backspace` 를 눌러도 완전히 같은 일을 합니다(→ [20절](#20-선택과-복사)).

관계선은 테이블 가운데가 아니라 **실제로 연결되는 컬럼 행에** 붙습니다. 자식의 FK 컬럼 행이 부모의 참조 컬럼 행으로 바로 이어지므로, 어느 컬럼이 무엇을 참조하는지 그림에서 보입니다. 컬럼이 둘 이상인 복합 키 관계에서는 두 테이블 아래쪽에 `(column1, column2)` 행이 생기고 선 하나가 그 행끼리 잇습니다. 이 행은 표시 전용입니다. 누르거나 선택할 수 없고, 관계가 실제로 쓰는 컬럼 조합에만 나타납니다. 매핑이 아직 비어 있는 관계는 예전처럼 테이블 왼쪽이나 오른쪽 변의 가운데에 붙습니다.

### 교차 테이블로 풀기 (N:M)

**무엇** — 모델에는 N:M 관계 유형이 없습니다. 대신 1:N 관계 하나를 **교차 테이블 하나 + 식별 1:N 관계 둘**로 바꾸는 동작이 있습니다.

**어디서** — 관계 패널 아래쪽의 **교차 테이블로 풀기**(편집 권한이 있을 때만).

**어떻게** — 풀 1:N 관계를 선택하고 **교차 테이블로 풀기**를 누르세요. 원래 관계의 FK 컬럼이 자식에서 빠지고 원래 관계도 함께 사라집니다. 두 테이블 사이 가운데에 교차 테이블이 생깁니다. 논리명은 두 테이블의 논리명을 이은 것이고(예: 회원 + 상품 → 「회원상품」), 물리명은 사전으로 만듭니다. 부모 → 교차, 자식 → 교차의 **식별 1:N 관계 둘**이 생기고, 교차 테이블의 기본 키는 두 FK 의 복합 키가 됩니다. 이름을 바로 다듬을 수 있게 선택이 교차 테이블로 옮겨집니다.

**제약 — 풀기를 막는 조건 셋.** 하나라도 걸리면 버튼이 잠기고 이유가 함께 보입니다.

| 조건 | 화면 문구 |
|---|---|
| 식별 관계임 | **식별 관계는 풀 수 없습니다 — 위 "식별 관계" 체크를 먼저 해제하세요** |
| 부모에 기본 키가 없거나, **또는** 이 관계의 FK 컬럼을 빼고 나면 자식에 기본 키가 남지 않음 | **교차 테이블에 넘길 기본 키가 없습니다 — 부모에 기본 키가 있어야 하고, 자식에는 이 관계의 FK 를 뺀 기본 키가 남아야 합니다** |
| 지워질 FK 컬럼을 **다른 관계가** 부모 쪽에서 참조함 | **이 관계의 FK 컬럼을 다른 관계가 참조하고 있어 풀 수 없습니다 — 먼저 그 관계를 정리하세요** |

셋째 조건은 식별 관계 가드와 별개입니다. 식별 관계가 아니어도, FK 컬럼에 PK 체크만 켜져 있고 손자 테이블이 그 컬럼을 참조하는 3단 구조가 생길 수 있습니다. 그대로 풀면 손자 쪽에 아무것도 참조하지 않는 FK 컬럼이 남습니다. 그래서 따로 막습니다.

이 동작은 편집 하나이므로 **실행 취소 한 번이 전부를 되돌립니다.** 그룹 뷰에서 실행하면 교차 테이블이 그 그룹에 들어갑니다. 사전에 없는 단어 때문에 물리명을 만들 수 없으면 `TABLE_n` 형태의 자리표시 물리명이 쓰입니다.

## 7. 인덱스와 메모

### 인덱스

**무엇** — 테이블별 인덱스 정의입니다. 인덱스에는 정렬 방향이 붙은 순서 있는 컬럼 목록과 UNIQUE 표시가 있습니다.

**어디서** — 테이블을 선택했을 때 편집 패널 아래쪽의 **인덱스** 절.

**어떻게** — **인덱스 추가**를 누르면 `IX_1`, `IX_2` 처럼 쓰이지 않은 가장 작은 번호로 인덱스가 만들어집니다. **인덱스명**을 고치고(빈 이름은 무시됩니다) **UNIQUE** 로 고유 여부를 정한 뒤, 아래 **컬럼 추가…** 드롭다운에서 컬럼을 고르세요(이미 인덱스에 있는 컬럼은 선택지에서 빠집니다). 각 컬럼 행에서 **ASC**/**DESC** 는 방향을 뒤집고, 화살표는 순서를 바꾸고, 휴지통은 컬럼을 인덱스에서 뺍니다.

**제약** — 컬럼이 없는 인덱스는 **구성 컬럼 없음**으로 남습니다. 인덱스가 없으면 **인덱스가 없습니다.** 가 나옵니다. 읽기 전용 사용자에게도 방향 버튼은 보이지만 누를 수 없습니다(값을 보여 주는 역할도 하기 때문입니다).

### 메모

**무엇** — 캔버스 위의 자유 글 메모지입니다. 모델의 일부로 저장되고 모델과 함께 편집됩니다.

**어디서·어떻게** — 하단 바의 **메모**를 누르면 화면 가운데에 「메모」 라고 적힌 노란 메모가 생깁니다. 캔버스에서 누르면 오른쪽에 **메모** 패널이 열립니다. **내용**에 쓰고(줄바꿈이 유지됩니다) **색상**에서 배경색을 고르세요. 오른쪽 위 휴지통(**메모 삭제**)으로 지웁니다. 메모를 선택하고 `Delete`/`Backspace` 로 지우거나 `Cmd`/`Ctrl`+`C`, `X`, `V` 로 복사·잘라내기·붙여넣기를 할 수도 있습니다(→ [20절](#20-선택과-복사)).

**제약** — 메모는 **전체 뷰에서만 보입니다.** 그룹 뷰에서는 숨겨지고 하단 바의 **메모**도 잠깁니다. 메모는 그룹에 속하지 않습니다.

## 8. 그룹과 그룹 뷰

**무엇** — 그룹은 테이블을 업무 단위로 묶습니다. 두 가지로 쓰입니다. 전체 뷰에서 테이블 뒤에 그려지는 색상 영역과, 그 그룹만 보여 주는 그룹 뷰입니다.

**어디서** — 트리 위쪽의 폴더 아이콘(**그룹 추가**)으로 만드세요. 테이블을 여러 개 선택하면 오른쪽 패널에 **선택 테이블로 새 그룹** 버튼도 나옵니다. 캔버스에서 색상 영역의 라벨을 누르거나 트리에서 그룹 이름을 누르면 오른쪽에 **그룹** 패널이 열립니다. 뷰는 하단 바의 **뷰 전환** 드롭다운으로 바꿉니다.

**어떻게** — 트리의 **그룹 추가**를 누르면 「그룹1」 처럼 쓰이지 않은 번호와 자동으로 정해진 색으로 그룹이 만들어집니다. 그룹 패널에서 **이름**, **별칭**, **색상**, **설명**을 고치고 위쪽의 **소속 테이블 N개**를 확인하세요. 테이블을 그룹에 넣는 방법은 넷입니다. 그 테이블 편집 패널의 **소속 그룹**에서 고르기, 왼쪽 트리의 항목을 잡아 그룹 블록에 놓기, 캔버스의 테이블 노드를 트리의 그룹 블록으로 드래그하기, 테이블을 여러 개 선택하고 오른쪽 패널의 **선택 테이블의 그룹** 드롭다운으로 옮기기입니다. 여러 개를 선택했으면 한꺼번에 옮겨집니다(→ [4절](#4-에디터-기본)). 그룹이 바뀌면 테이블이 새 그룹 옆에 놓이도록 캔버스 좌표가 조정됩니다. 그룹 뷰에는 그룹 패널의 **이 그룹 뷰 열기**나 하단 바 **뷰 전환**의 **〈그룹명〉 뷰**로 들어가고, **전체 뷰**로 돌아옵니다. 그룹은 패널 오른쪽 위 휴지통(**그룹 삭제**)으로 지웁니다.

**어떻게 — 별칭** — 그룹 패널의 **별칭**은 물리명을 조합할 때 쓰는 짧은 식별자입니다. 그룹 이름은 `회원관리` 처럼 한글인 경우가 많아 물리명에 그대로 넣을 수 없으므로 별칭을 따로 둡니다. 영문 대문자, 숫자, 밑줄만 쓸 수 있습니다. 소문자는 대문자로 바뀌고, 한글과 다른 기호는 아예 입력되지 않습니다(입력하는 대로 걸러집니다). 입력란 오른쪽의 ↑(**이름으로 별칭 채우기**)는 그룹 이름을 사전에 돌려 약어 조합을 넣습니다. 사전에 없는 단어가 있으면 토스트가 그 단어를 알려 주고 값은 바뀌지 않습니다. 선택 항목이라 비워 둬도 됩니다. **별칭은 테이블 물리명·논리명 형식의 `{그룹별칭}` 변수를 통해 이름에 들어갑니다**(→ [10절](#10-명명-체계단어용어-사전)). 그 변수를 쓰는 형식이 없으면 별칭은 어떤 이름도 바꾸지 않습니다. 읽기 전용 권한에서는 잠기고 채우기 버튼이 보이지 않습니다.

**기존 그룹이 아니라 새 그룹으로 묶으려면** — 캔버스에서 `Shift`+드래그로 상자를 그리거나 트리에서 테이블을 여러 개 선택한 뒤, 오른쪽 패널의 **선택 테이블로 새 그룹**을 누르세요. 「그룹1」 같은 쓰이지 않은 번호와 색이 자동으로 정해지고, 선택한 테이블이 모두 그룹에 들어가며, 이름·색·설명을 그 자리에서 고칠 수 있게 오른쪽이 바로 **그룹** 패널로 바뀝니다(이때 테이블 선택은 해제됩니다). **테이블은 있던 자리에 그대로 있고 그 위에 색상 영역만 깔립니다.** 멀리 떨어진 테이블을 묶으면 영역이 그만큼 커져 사이에 있는 다른 테이블을 덮는 것처럼 보일 수 있습니다. 그때는 나중에 캔버스에서 드래그해 자리를 잡으세요. 편집 하나이므로 실행 취소 한 번이 전부를 되돌립니다.

| | 전체 뷰 | 그룹 뷰 |
|---|---|---|
| 보이는 테이블 | 전부 | 그 그룹의 테이블만 |
| 색상 영역 | 그룹 테이블을 감싸는 반투명 영역(선택하면 실선, 아니면 점선) | 숨김 |
| 메모 | 보임 | 숨김 |
| 테이블 위치 | 전체 뷰 좌표 | **그룹 뷰 전용 좌표**를 따로 저장 |
| 그룹 밖 테이블과의 관계 | 일반 연결선 | 상대 테이블이 **고스트 노드**로 보임 |

- **그룹 뷰의 배치는 독립적입니다.** 그룹 뷰에서 테이블을 옮겨도 전체 뷰 배치는 그대로입니다. 아직 그룹 뷰 좌표가 없는 테이블은 전체 뷰 좌표에서 시작합니다.
- 전체 뷰에서 **색상 영역을 드래그하면 그룹의 테이블이 함께 움직입니다.** 영역의 빈 부분을 누르면 선택이 해제되고, 라벨을 누르면 그룹이 선택됩니다.
- **고스트 노드**는 그룹 뷰에서 그룹 밖 테이블의 헤더만 반투명하게 보여 줍니다. **외부 참조 — 클릭해 이동** 이라는 힌트가 붙어 있고, 누르면 그 테이블이 속한 그룹 뷰(미분류면 전체 뷰)로 옮겨 갑니다. 드래그·선택·연결은 할 수 없습니다.
- 그룹 뷰를 보는 동안 누군가 그 그룹을 지우면 자동으로 전체 뷰로 떨어집니다. 그룹이 하나도 없으면 **뷰 전환** 드롭다운 자체가 보이지 않습니다.

## 9. 도메인

**무엇** — 도메인은 컬럼의 타입·기본값·허용값을 묶은 재사용 단위입니다. 「금액」 이나 「상태코드」 처럼 프로젝트 전체에서 같은 명세를 따라야 하는 컬럼에 적용하세요.

**어디서** — 에디터 헤더 **사전·리소스** → **도메인**. 다이얼로그 설명은 **공통 컬럼 타입·기본값·허용값을 재사용 단위로 관리합니다** 입니다.

**어떻게 — 정의** — **도메인 추가**를 누르고 **이름**과 **논리 타입**(예: `DECIMAL(15)`, `INT UNSIGNED`)을 입력하세요. 둘 다 필수이고, 하나라도 비어 있으면 **저장**이 잠깁니다. **분류**를 입력하면 목록이 그 분류로 묶입니다(비워 두면 **미분류**). **방언별 물리 타입 (선택)** 에는 **PostgreSQL**, **MySQL·MariaDB**, **Oracle**, **MSSQL** 네 칸이 있어 방언마다 타입을 정할 수 있습니다. 비워 두면 방언마다 논리 타입이 자동으로 변환됩니다. **기본값**, **허용값 (쉼표로 구분)**(예: `ACTIVE, INACTIVE`), **설명**을 채우고 **저장**을 누르세요.

**어떻게 — 컬럼에 적용** — 편집 패널의 컬럼 행에서 **도메인** 드롭다운으로 고르세요. 정하면 그 컬럼의 **타입** 칸이 잠기고 도메인의 논리 타입이 보입니다. 다시 직접 입력하려면 **없음**으로 돌리세요.

**어떻게 — 찾기** — 도메인이 하나라도 있으면 목록 위에 검색란(**이름 검색**)이 나와 이름으로 도메인을 찾습니다(대소문자 무시, 부분 일치). 맞는 것이 없으면 **검색 결과가 없습니다** 가 나옵니다. 목록은 50개씩 페이지로 나뉩니다. 두 페이지 이상이면 아래쪽에 **전체 N건**과 **이전 · 1 / 3 · 다음** 이 나옵니다. 분류 제목은 그 페이지에 있는 분류만 보여 줍니다.

**어떻게 — 고쳐서 일괄 반영** — 목록의 연필 아이콘으로 고치세요. **도메인은 값을 복사하지 않고 늘 살아 있는 참조이므로**, 저장하면 그 도메인을 쓰는 모든 컬럼에 바로 반영됩니다. 도메인을 쓰는 곳이 있으면 저장할 때 **N개 컬럼에 영향을 줍니다. 계속할까요?** 로 확인을 받습니다.

**제약**

- **삭제 가드**: 쓰이는 도메인은 지울 수 없습니다. 목록에 **사용처 N개** 가 보이고 그동안 휴지통이 잠깁니다. 먼저 컬럼에서 도메인을 비우세요.
- DDL 에 반영되는 것은 셋입니다. 타입(방언 물리 타입이 있으면 그것, 없으면 변환한 논리 타입). CHECK 제약(허용값이 있으면 `CHECK (column IN (…))`, 논리 타입이 부호 없음이고 방언이 MySQL 이 아니면 `CHECK (column >= 0)`. 둘 다 해당하면 둘 다 나갑니다). 기본값(컬럼 자체의 기본값이 있으면 그것이 이기고, 없으면 도메인 기본값). 부호 없음 `CHECK` 는 **방언별 물리 타입을 정했어도 나갑니다.** 덮어쓰기는 저장 형태에 관한 것이고 `CHECK` 는 값에 관한 것이라 서로를 배제하지 않습니다.
- 도메인은 Excel **도메인정의서** 시트로 내보내지고, 업로드로 등록할 수도 있습니다(→ [15절](#15-내보내기), [16절](#16-가져오기)).

### 9.1 테이블 옵션(`ENGINE`·`CHARSET`)

**무엇** — DDL 을 내보낼 때 `CREATE TABLE` 의 닫는 괄호 뒤에 그대로 붙는 문자열입니다.
MySQL 의 `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4` 처럼 **실무에서 대개 프로젝트 전체가 공유하는
물리 배포 설정**이라, 테이블마다가 아니라 프로젝트 설정에 둡니다. 모든 테이블이 같은 값을
받습니다.

**어디서** — 프로젝트 설정(`/p/:projectId/settings`) → **테이블 옵션**. **관리 권한**이 있을 때만
보입니다. 로컬 모드에서도 보입니다.

**어떻게** — **postgresql**, **mysql**, **oracle**, **mssql** 네 칸이 있고, 각 칸의 값은 **그 방언으로
내보낼 때만** 붙습니다. 값은 입력란이 포커스를 잃을 때(다른 곳을 누르거나 Tab) 저장됩니다. 방언마다
문법이 달라서 칸을 나눴습니다. 문자열 하나를 네 방언에 모두 붙이면 PostgreSQL DDL 뒤에 MySQL 의
`ENGINE=` 이 붙어 그 DDL 은 아예 실행되지 않습니다. 예: mysql
`ENGINE=InnoDB DEFAULT CHARSET=utf8mb4`, oracle `TABLESPACE users`, mssql `ON [PRIMARY]`.

**제약**

- **값을 검증하지 않습니다**(도메인의 방언별 물리 타입과 같은 정책). 잘못 쓰면 그 방언의 DDL 이
  실패하고, 실패가 바로 보입니다.
- ⚠️ **`COMMENT=` 를 쓰지 마세요.** 옵션은 테이블 코멘트 앞에 나가므로, 그 DDL 을 다시 가져오면
  여기 쓴 `COMMENT=` 가 테이블 코멘트로 읽힙니다.
- 칸을 비워 두면 아무것도 붙지 않습니다. 옵션을 쓰지 않는 프로젝트의 출력은 한 글자도 달라지지
  않습니다.
- 옵션은 DBML 에 나가지 않습니다(DBML 에는 테이블 옵션 문법이 없습니다).
- DDL 을 **가져올 때** 이 값을 채울 수도 있습니다(→ [16절](#16-가져오기)).

## 10. 명명 체계(단어·용어 사전)

**무엇** — 논리명에서 물리명을 자동으로 만들기 위한 사전입니다. 단어는 「고객」 → `CUST` 처럼 낱말 하나의 표준 약어입니다. 용어는 「고객주문번호」 → `CUST_ORD_NO` 처럼 **논리명 전체**에 대한 표준 물리명이고, 기본 도메인도 정할 수 있습니다.

**어디서** — 에디터 헤더 **사전·리소스** → **단어·용어 사전**. 제목은 **단어·용어 사전**이고 탭은 **단어**, **용어**, **미등록 항목**, **가져오기** 넷입니다.

**어떻게 — 물리명 생성 규칙**

1. **용어 완전일치가 먼저입니다.** 논리명 전체와 똑같은 용어가 있으면 그 물리명을 씁니다. 용어에 도메인이 있으면 컬럼의 도메인도 채웁니다.
2. 아니면 **단어 사전에 대한 최장 일치로 나눕니다.** 논리명을 앞에서부터 읽으며 가장 긴 단어를 먼저 맞추고, 단어들의 약어를 구분자 `_` 로 이어 대문자로 만듭니다.
3. 어느 단어와도 맞지 않는 부분은 결과에서 빠지고 **미등록 단어**로 보고됩니다.

같은 규칙이 편집 패널에서 논리명을 입력할 때, 논리명 칸의 ↑(**물리명 채우기**)를 누를 때, 입력하는 동안 자동완성 제안을 만들 때, 교차 테이블 이름을 만들 때, DDL 가져오기에서 물리명으로 논리명을 복원할 때 적용됩니다.

**어떻게 — 등록** — **단어** 탭 → **단어 추가** → **약어**와 **논리명**(필수), **영문명**과 **설명**(선택) → **저장**. **용어** 탭 → **용어 추가** → **물리명**과 **논리명**(필수), **도메인**과 **설명**(선택) → **저장**. 탭 설명은 **논리명 전체가 완전일치할 때 우선 적용되는 표준 물리명을 관리합니다** 입니다. 두 목록 모두 행마다 논리명과 물리명(단어는 약어)을 나란히 보여 줍니다. 쓰이는 항목에는 **사용처 N개** 가 보이고, 연필과 휴지통으로 고치고 지웁니다. 탭 제목에는 **단어 (3,280)**, **용어 (13,159)** 처럼 전체 수가 붙습니다. 목록 위 검색란은 단어 탭에서 **논리명·약어·영문명 검색**, 용어 탭에서 **논리명·물리명 검색**입니다(대소문자 무시, 부분 일치). 맞는 것이 없으면 **검색 결과가 없습니다** 가 나옵니다. 목록은 50개씩 페이지로 나뉩니다. 두 페이지 이상이면 아래쪽에 **전체 N건**과 **이전 · 1 / 264 · 다음** 이 나옵니다. 편집 패널의 컬럼 행에서 **용어 등록**을 눌러도 그 컬럼의 논리명·물리명·도메인이 용어로 등록됩니다.

**어떻게 — 용어를 고치고 쓰는 곳 갱신하기** — 이미 쓰이는 용어를 고치면 **"〈용어〉" 용어를 쓰는 N곳을 함께 갱신할까요?** 확인이 나옵니다. 무엇이 어디서 어떻게 바뀌는지 목록으로 보여 주고, **N곳에 반영**이나 **유지**를 고릅니다. **유지**는 용어만 바꾸고 쓰는 곳은 그대로 둡니다.

**어떻게 — 미등록 항목 모아서 등록하기** — **미등록 항목** 탭(수는 두 방향 후보의 합이고, 0 이면 괄호가 붙지 않습니다)에는 방향별 하위 탭 둘이 있습니다. 기본값은 **논리명 → 약어**이고, 각 하위 탭 이름에 그 방향의 수가 괄호로 붙습니다. **논리명 → 약어**는 테이블·컬럼 논리명을 나눌 때 사전에 없던 단어를 모읍니다. 후보마다 오른쪽의 **약어** 칸에 약어를 입력하고 **일괄 등록**을 누르면 **약어를 입력한 항목만** 편집 하나로 등록됩니다.

**물리명 → 논리명**은 반대입니다. 물리명을 나눌 때 사전에 없던 약어를 모읍니다. 후보마다 오른쪽의 **논리명** 칸에 논리명을 입력하고 같은 **일괄 등록**을 누르면 **논리명을 입력한 항목만** 등록됩니다. 이쪽은 이름을 직접 입력하므로, 사전에 이미 있거나 목록의 다른 항목과 겹치는 이름은 그 행에 **사전에 이미 있습니다** 나 **위 항목과 겹칩니다** 가 나오고 등록에서 빠집니다. 하위 탭을 바꾸면 입력하던 값이 비워집니다(후보 집합이 완전히 다르기 때문입니다). 어느 쪽이든 결과는 같은 단어 사전에 더해집니다.

> [!NOTE]
> 하나만 등록하려면 이 화면에 올 필요가 없습니다. 편집 패널의 이름 아래 **미등록** 칩에서 그 자리에 등록할 수 있습니다(→ [5절](#5-테이블과-컬럼)).

**제약**

- 사전은 **프로젝트마다** 있습니다. 조직·전역 수준의 표준 사전은 공용 리소스로 가져올 때만 들어옵니다(→ [13절](#13-공용-리소스)).
- 물리명 자동 생성은 포커스가 다른 곳으로 옮겨갈 때(blur) **물리명이 비어 있을 때만** 일어납니다. 이미 값이 있으면 논리명을 고쳐도 물리명은 그대로입니다. 덮어쓰려면 **Enter** 를 누르거나 논리명 칸의 ↑ 를 누르세요.
- 논리명 자동 복원도 대칭입니다. 이미 값이 있으면 물리명을 고쳐도 논리명은 그대로이고, **Enter** 나 물리명 칸의 ↓ 가 덮어씁니다. 물리명을 사전 약어로 끝까지 나눌 수 없으면(약어 하나라도 사전에 없으면) 아무것도 채우지 않고 화살표가 토스트로 이유를 알립니다.
- 자동완성은 **접두 일치**만 씁니다. 중간 일치와 초성 검색은 아직 없습니다.
- **컬럼의 도메인은 물리명이 비어 있었을 때만 자동으로 정해집니다.** 물리명이 이미 채워진 컬럼의 논리명을 용어 이름으로 바꾸면 도메인은 그대로입니다. **도메인** 드롭다운에서 직접 고르세요.
- 물리명 쪽 **미등록** 칩에서 등록하면 **약어는 그 칩으로 고정됩니다.** 다른 약어를 쓰려면 사전 화면에서 등록하세요.
- 용어와 실제 물리명이 어긋나면 모델 검사가 **용어 불일치**로 잡습니다(→ [12절](#12-모델-검사)).

**어떻게 — 테이블 물리명 형식**

**무엇** — 테이블의 최종 물리명을 「접두 + 입력한 부분」으로 조합합니다. `TB_{그룹별칭}_{물리명}` 이라고 쓰면, 그룹 별칭이 `MBR` 이고 물리명이 `ORD` 인 테이블이 DDL·DBML·Excel 에 `TB_MBR_ORD` 로 나갑니다. **비워 두면 입력한 물리명이 그대로 쓰입니다(기본값).**

**어디서** — 프로젝트 설정(`/p/:projectId/settings`) → **명명 규칙** → **테이블 물리명 형식**. **관리 권한**이 있을 때만 보입니다. 입력란 아래에 쓸 수 있는 변수 목록과 미리보기가 있습니다. 미리보기는 지금 프로젝트의 테이블 하나에 형식을 적용한 결과를 바로 보여 줍니다(테이블이 없으면 가상의 예를 보여 줍니다). 값은 입력란이 포커스를 잃을 때(다른 곳을 누르거나 Tab) 저장됩니다.

| 변수 | 값 |
|---|---|
| `{그룹별칭}` | 테이블이 속한 그룹의 별칭(그룹 패널에서 입력). 그룹이 없거나 별칭이 비어 있으면 빈 값 |
| `{그룹명}` | 테이블이 속한 그룹의 이름 |
| `{물리명}` | 편집 패널에서 입력한 테이블 물리명 |
| `{논리명}` | 테이블 논리명 |
| `{커스텀:항목이름}` | 그 이름의 **테이블** 커스텀 항목 값(없으면 정의의 기본값, 그것도 없으면 빈 값) |

- **빈 칸 주변의 밑줄은 접힙니다.** 그룹이 없는 테이블은 `TB__ORD` 가 아니라 `TB_ORD` 로 나옵니다.
- **⚠️ 접히는 것은 밑줄뿐이고, 칸 뒤의 리터럴은 남습니다.** `TB_{그룹별칭}_LOG` 같은 형식에서 별칭이 빈 테이블은 `TB_LOG` 로 나옵니다. 밑줄이 아닌 구분자는 남습니다(`TB_{그룹별칭}-LOG` 는 `TB_-LOG`).

  **예전 ERDD 버전으로 내보낸 DDL 은 지금 내보내는 DDL 과 테이블 이름이 다를 수 있습니다.** 그런 형식을 쓰고 내보낸 DDL 을 보관하고 있다면 한 번 비교해 보세요.
- **없는 변수는 그 칸을 비웁니다.** 오타(`{그룹별칙}`)가 있어도 화면이 깨지지 않고, 미리보기에서 그 칸이 비어 보이므로 바로 알아챌 수 있습니다.
- **편집 패널의 테이블 이름 입력란 아래에 조합 결과가 `물리 → TB_MBR_ORD` 로 보입니다.** 형식이 비어 있으면 보이지 않고, 컬럼에는 보이지 않습니다(컬럼에는 형식이 없습니다). 논리명 형식도 정했으면 그 아래 `논리 → …` 한 줄이 더 보입니다.

**적용되는 곳**

| 곳 | 값 |
|---|---|
| DDL(`CREATE TABLE`, 외래 키, 인덱스, 코멘트) · DBML · Excel 정의서의 물리명 열 | **조합된 이름** |
| 모델 검사: 물리명 중복(테이블), 길이 초과, 예약어 | **조합된 이름** |
| 모델 검사: 용어 불일치 | 입력한 물리명 |
| 편집 패널 입력란 · 사이드바 트리 · 복사 · CLI 파일 | 입력한 물리명 |

**제약**

- **저장되는 것은 입력한 부분뿐입니다.** 접두는 저장되지 않으므로, 형식을 바꾸거나 테이블을 다른 그룹으로 옮기면 최종 이름이 바로 따라 바뀝니다.
- 물리명이 비어 있어도 접두가 있으면 테이블이 DDL 에 나갑니다(`TB_MBR`). 채우라는 신호로 모델 검사의 **필수 값 누락**은 그대로 나옵니다.
- **왕복이 닫혀 있습니다.** 내보낸 DDL·DBML 의 첫 줄에는 주석 한 줄 `-- erdd:v2 {…}`(DBML 에서는 `// erdd:v2 …`) 이 붙어, 어느 최종 이름이 어느 부분에서 왔는지 기록합니다. 그 파일을 그대로 다시 가져오면 물리명 칸에 `ORD` 가 들어갑니다. 접두를 손으로 걷어낼 필요가 없습니다.
- **그 줄에는 그룹도 실립니다.** 각 테이블이 어느 그룹에 속했는지와 그 그룹의 별칭·색·코멘트를 기록합니다. 다시 읽으면 그룹이 다시 만들어지고 테이블이 그 안에 들어갑니다. 같은 이름의 그룹이 이미 있으면 그 그룹을 쓰고 기존 별칭·색·코멘트는 덮어쓰지 않습니다. 머릿말의 별칭이 기존과 다르면 ERDD 가 **머릿말의 별칭 … 과 기존 그룹의 별칭 … 가 달라 기존 값을 유지합니다** 로 알립니다. 그룹의 화면 좌표는 복원되지 않습니다(그룹 뷰를 처음 열 때 다시 배치됩니다).
- **⚠️ 그룹을 쓰면 형식이 없어도 DDL 첫 줄에 그 주석이 나옵니다.** 내보내는 테이블 중 하나라도 그룹에 속하면 그 줄이 나갑니다(프로젝트에 그룹이 있어도 범위를 좁혀 그룹 없는 테이블만 내보내면 그 줄은 나가지 않습니다. 머릿말은 내보내는 목록만 봅니다). 그룹도 형식도 쓰지 않는 프로젝트에서는 그 줄이 나가지 않습니다. 그래서 첫 테이블이 그룹에 들어가거나 마지막 테이블이 빠질 때 같은 프로젝트에서 내보낸 DDL 에 그 한 줄이 생기거나 사라집니다. 산출물을 버전 관리하며 그대로 비교한다면 차이로 보입니다(내용이 아니라 머릿말의 차이입니다).
- `erdd:v1` 머릿말도 **읽습니다.** 다만 v1 에는 그룹을 담을 자리가 없어 물리명·논리명만 복원되고 그룹은 복원되지 않습니다.
- **⚠️ 다만 두 경우에는 접두가 물리명에 박힙니다.**
  - 파일 첫 줄의 **`-- erdd:v2 …` 주석을 지운 뒤** 가져온 경우
  - 파일에서 **`CREATE TABLE` 문 하나만 잘라 붙여넣은** 경우. 머릿말이 따라오지 않아 이름 표가 없습니다

  이런 경우 `TB_MBR_ORD` 전체가 물리명이 되고, 다시 내보내면 `TB_MBR_TB_MBR_ORD` 가 됩니다. 가져온 뒤 접두를 손으로 걷어내세요. 남이 준 DDL(우리가 내보내지 않은 파일)도 마찬가지입니다. **그룹도 복원되지 않습니다.** 그룹 소속과 그 별칭·색·코멘트가 모두 사라집니다. 유일한 예외는 DBML 입니다. `TableGroup` 블록을 함께 붙여넣으면 그 블록이 기술하는 그룹 소속·색·코멘트가 복원되고 별칭만 사라집니다(DBML 의 `TableGroup` 블록에는 별칭을 쓸 자리가 없습니다).

**어떻게 — 테이블 논리명 형식**

**무엇** — 테이블의 최종 논리명을 조합합니다. `{그룹명}_{논리명}` 이라고 쓰면, 그룹 이름이 `회원관리` 이고 논리명이 `주문` 인 테이블이 DDL 코멘트·DBML note·Excel 논리명 열에 `회원관리_주문` 으로 나갑니다. **비워 두면 입력한 논리명이 그대로 쓰입니다(기본값).**

**어디서** — 프로젝트 설정(`/p/:projectId/settings`) → **명명 규칙** → **테이블 논리명 형식**. 물리명 형식 입력란 바로 아래에 있습니다. **관리 권한**이 있을 때만 보이고, 같은 종류의 미리보기가 있으며, 입력란이 포커스를 잃을 때 저장됩니다.

**쓸 수 있는 변수와 빈 칸 접기 규칙은 물리명 형식과 완전히 같습니다**(위 표).

**적용되는 곳**

| 곳 | 값 |
|---|---|
| DDL 코멘트(`COMMENT ON TABLE`, MySQL 인라인) · DBML note · Excel 정의서의 논리명 열 | **조합된 이름** |
| 용어 사전 조회 · **미등록 단어** 칩 · 논리명 구분자 경고 | 입력한 논리명 |
| 물리명 자동 생성 | 입력한 논리명 |
| 편집 패널 입력란 · 사이드바 트리 · 캔버스 · CLI 파일 | 입력한 논리명 |

**제약**

- **⚠️ 산출물 전용입니다.** 사전 조회, 단어 검사, 물리명 생성은 입력한 논리명을 그대로 봅니다. 그래야 사전에는 `주문` 만 등록하면 되고, 형식을 바꿔도 사전이 어긋나지 않습니다.
- 논리명 형식에 `{물리명}` 을 쓰면 **물리명 형식을 적용하기 전의 값**이 들어갑니다(두 형식은 서로를 먹이지 않습니다).
- 논리명과 물리명이 같을 때 코멘트를 생략하는 판정은 **양쪽 모두 조합된 이름**으로 합니다.
- **논리명도 왕복이 닫혀 있습니다.** 머릿말이 논리명 부분도 기록하므로, 다시 읽으면 `주문` 이 들어옵니다. 코멘트의 조합된 논리명(`회원관리_주문`)보다 머릿말이 우선합니다(설명은 코멘트에서 그대로 가져옵니다). 머릿말이 없으면 물리명과 마찬가지로 조합된 논리명 전체가 논리명 칸에 들어갑니다.
- 단어·용어 사전 시트의 **논리명** 열은 단어와 용어의 것이므로 조합하지 않습니다.
- 컬럼 논리명과 컬럼 물리명에는 형식이 없습니다.

## 11. 커스텀 항목

**무엇** — 테이블과 컬럼에 프로젝트 고유의 관리 항목을 더합니다. 「개인정보여부」 나 「암호화방식」 처럼 표준 모델에 없는 항목을 만듭니다.

**어디서** — 정의는 에디터 헤더 **사전·리소스** → **커스텀 항목**에서 합니다. 값은 편집 패널의 테이블 영역과 각 컬럼 행에 나오는 점선 **커스텀 항목** 상자에 입력합니다.

**어떻게 — 정의** — **커스텀 항목** → **항목 추가** → **이름**(필수) → **적용 대상**(테이블/컬럼)과 **타입**을 고르세요. **기본값**을 입력하면 값이 없는 대상에 그 값이 쓰입니다. **필수 (미입력 시 경고)** 를 켜면 값이 빈 대상에 경고가 붙습니다. **저장**으로 마칩니다. 항목이 하나라도 있으면 목록 위에 검색란(**이름 검색**)이 나오고, 목록은 50개씩 페이지로 나뉩니다. **검색하는 동안 순서(▲▼) 버튼이 잠깁니다.** 걸러진 목록에서 항목을 옮기면 보이지 않는 항목과 자리가 바뀌기 때문입니다.

| 타입 | 화면 표기 | 값 입력 |
|---|---|---|
| text | **텍스트** | 자유 입력 |
| boolean | **불리언** | 체크박스 |
| select | **선택형** | 드롭다운. **선택지 (쉼표로 구분)** 에 선택지가 하나 이상 있어야 합니다 |

**어떻게 — 값 입력** — 테이블이나 컬럼을 선택하면 **커스텀 항목** 상자가 보입니다. 필수 항목이 비어 있으면 상자 제목 옆에 **필수** 표시가, 항목 이름 뒤에 `*` 가 붙습니다. 선택형 값을 비우려면 **선택 안 함**을 고르세요.

**제약**

- **만든 뒤에는 타입과 적용 대상을 바꿀 수 없습니다**: **타입과 적용 대상은 변경할 수 없습니다. 바꾸려면 삭제 후 다시 만드세요.** 불리언은 늘 값이 있으므로 필수로 정할 수 없습니다(**불리언은 항상 값이 있으므로 필수로 지정할 수 없습니다.**).
- 선택형 기본값은 선택지 중 하나여야 하고, 불리언 기본값은 `true`/`false` 여야 합니다. 아니면 저장이 잠기고 이유가 빨갛게 보입니다.
- 어딘가에서 쓰이는 선택지를 지우면 ERDD 가 **삭제하는 선택지를 N곳에서 사용 중입니다. 값은 유지됩니다. 계속할까요?** 로 묻습니다. 값은 남고 드롭다운에 **〈값〉 (삭제된 선택지)** 로 비활성 표시됩니다. 항목 자체를 지우면 입력된 값도 함께 지워집니다: **"〈이름〉"을(를) 삭제하면 입력된 값 N건도 함께 삭제됩니다. 계속할까요?**
- 목록에서 위아래 화살표로 정한 순서가 편집 패널과 Excel 정의서의 열 순서가 됩니다.

## 12. 모델 검사

**무엇** — 모델 전체를 훑어 명명 규칙 위반, 구조 불일치, 필수 값 누락을 모읍니다.

**어디서** — 에디터 헤더의 **모델 검사**. 경고가 있으면 **모델 검사 (N)** 처럼 수가 붙습니다. 같은 경고가 캔버스 노드와 편집 패널에 삼각형 배지로 보이고, 마우스를 올리면 자세한 내용이 보입니다.

**어떻게** — **모델 검사**를 누르면 경고를 종류별로 묶어 보여 줍니다. 항목을 누르면 다이얼로그가 닫히고 그 테이블이나 관계가 선택됩니다(컬럼 경고는 그 컬럼이 속한 테이블로 이동합니다). 경고가 없으면 **경고가 없습니다. 명명이 규칙에 부합합니다.** 가 나옵니다.

**경고 종류 전체**

| 화면 표기 | 등급 | 뜻 | 해결 |
|---|---|---|---|
| **물리명 중복(컬럼)** | 오류 | 같은 테이블에 물리명이 같은 컬럼이 둘 이상 있음 | 물리명 하나를 바꿉니다 |
| **물리명 중복(테이블)** | 오류 | 물리명이 같은 테이블이 둘 이상 있음 | 테이블 물리명 하나를 바꿉니다 |
| **매핑 불완전** | 경고 | 부모 기본 키 컬럼 수와 관계의 컬럼 매핑 수가 다름 | 부모 PK 를 맞추거나 관계를 다시 만듭니다 |
| **타입 불일치** | 경고 | 매핑된 부모·자식 컬럼의 타입이 다름 | 한쪽 타입(또는 도메인)을 다른 쪽에 맞춥니다 |
| **미등록 단어** | 경고 | 논리명에 단어 사전에 없는 부분이 있음 | 편집 패널의 **미등록** 칩에서 바로 등록하거나, 사전 **미등록 항목** 탭의 **논리명 → 약어**에서 모아 등록합니다 |
| **용어 불일치** | 경고 | 용어가 논리명과 완전히 일치하는데 물리명이 그 표준과 다름 | 논리명 칸의 ↑ 로 다시 만들거나 용어를 고칩니다 |
| **논리명 구분자 없음** | 경고 | 논리명이 단어 둘 이상으로 나뉘는데 밑줄 구분자가 없음 | 메시지가 제안하는 꼴(「회원_주문」)로 바꾸거나, 프로젝트 설정에서 **논리명을 밑줄로 구분**을 끕니다 |
| **길이 초과** | 경고 | 물리명이 최대 길이(기본 30바이트)를 넘음 | 더 짧은 약어를 쓰거나 물리명을 줄입니다 |
| **예약어** | 경고 | 물리명이 프로젝트 대상 방언 중 하나의 예약어임 | 물리명을 바꿉니다 |
| **필수 항목 미입력** | 경고 | 필수로 정한 커스텀 항목이 비어 있음 | 값을 채우거나 필수 설정을 끕니다 |
| **필수 값 누락** | 경고 | 커스텀 항목이 아닌 **표준 항목**이 비어 있음: 테이블의 논리명·물리명, 컬럼의 논리명·물리명·타입 | 값을 채웁니다 |

- **오류**는 물리명 중복 두 종류뿐입니다(빨간 원 아이콘). 나머지는 경고입니다(노란 삼각형).
- 테이블 물리명 형식이 있는 프로젝트에서 **물리명 중복(테이블)**, **길이 초과**, **예약어**는 **조합된 최종 이름으로** 판정합니다. 그룹이 다른 같은 이름은 중복이 아니고, 접두를 붙이면 길이를 넘는 이름은 잡힙니다(→ [10절](#10-명명-체계단어용어-사전)).
- **길이 초과**는 바이트를 세므로, 한글 물리명은 글자 수가 보여 주는 것보다 훨씬 빨리 한도에 닿습니다.
- **예약어**는 프로젝트를 만들 때 고른 방언만 검사합니다. 그 목록에 없는 DB 의 예약어는 잡히지 않습니다.
- **매핑 불완전**과 **타입 불일치**는 관계마다 최대 한 번만 보고됩니다.
- 검사에 걸려도 저장이나 내보내기는 막히지 않습니다. 실제로 무언가를 막는 것은 모델 정합성 위반뿐입니다. 그때는 편집 자체가 거절되고 토스트로 이유를 알립니다.

## 13. 공용 리소스

> [!NOTE]
> **로컬 모드에는 없습니다.** 라이브러리, 승격, 승격 요청이 없습니다(→ [로컬 모드 매뉴얼 4.2](./local-guide.md#42-사용-매뉴얼의-어느-장이-해당하나)).

> [!NOTE]
> **파일로 주고받기** — 라이브러리를 파일로 내보내고 가져오는 것은 [19절의 라이브러리 관리](#라이브러리-관리)에서 다룹니다.

**무엇** — 표준 단어·용어·도메인·커스텀 항목을 프로젝트 밖에 두고 여러 프로젝트가 함께 쓰는 방법입니다. 라이브러리는 전역(서비스 전체)과 조직 두 층이 있고, 모델이 실제로 참조하는 것은 늘 **프로젝트에 만든 사본**입니다. 방향은 둘입니다: 가져오기(재동기화)(라이브러리 → 프로젝트)와 승격(프로젝트 → 라이브러리, 권한이 없으면 요청).

> [!NOTE]
> **CLI 로도 됩니다.** 파일로 편집하는 프로젝트는 `erdd dict pull`(가져오기·재동기화), `erdd dict push`(승격·승격 요청), `erdd dict requests`(내 요청과 처리 메모)로 같은 일을 합니다. 승인과 요청 취소는 이 화면에서 합니다(→ [CLI 매뉴얼 6.11](./cli-guide.md#611-erdd-dict--공용-사전)).

**어디서** — 프로젝트 쪽은 에디터 헤더 **사전·리소스** → **공용 리소스**이고, 탭은 **가져오기**와 **조직으로 승격** 둘입니다. 라이브러리를 만들고 항목을 더하는 화면은 조직 상세 화면의 **조직 공용 리소스**와 `/admin` 의 **전역 공용 리소스**입니다. 승격 요청은 조직 상세 화면의 **승격 요청** 절에서 승인합니다.

### 가져오기(재동기화)

1. **공용 리소스** → **가져오기** → 왼쪽에서 라이브러리를 고르세요(**전역**이나 **조직**과 항목 수가 보입니다).
2. 오른쪽 항목은 세 구역으로 나뉩니다.

| 구역 | 뜻 | 기본 선택 |
|---|---|---|
| **신규 추가** | 프로젝트에 아직 없는 항목 | 선택됨. 같은 이름이 이미 있으면 해제(**이름 중복** 배지) |
| **자동 갱신** | 가져온 뒤 프로젝트가 건드리지 않았는데 원본이 바뀐 항목 | 선택됨 |
| **충돌** | 프로젝트와 원본 양쪽에서 바뀐 항목 | **보류** |

구역마다 검색란(**논리명·물리명 검색**)과 페이지(50개씩)가 있고, 행마다 종류·논리명·물리명(단어는 약어)이 보입니다. 페이지를 바꾸거나 검색해도 체크는 유지됩니다.

3. 충돌 항목은 필드마다 **현재 〈값〉 → 원본 〈값〉** 을 보여 줍니다. 셋 중 하나를 고르세요. **원본 반영**은 원본 값으로 덮어씁니다. **프로젝트 유지**는 내용을 그대로 두고 **이 변경을 검토했다고 기록합니다**(다시 나타나지 않습니다). **보류**는 아무것도 기록하지 않으므로 다음에 다시 나타납니다.
4. 구역마다 **모두 선택** / **모두 해제**(충돌은 **모두 원본 반영** / **모두 프로젝트 유지**)로 한꺼번에 처리하세요. 이 버튼은 **보이는 페이지나 검색 결과가 아니라 구역 전체에** 적용됩니다. 검색 중이거나 페이지가 여럿이면 버튼 옆에 **구역 전체 N건에 적용** 이 보입니다.
5. 아래 **유지** 절에서 손대지 않고 남는 항목 수를 확인하세요: **최신 상태 N건 · 프로젝트 자체 항목 N건**. 원본에서 지워진 항목이 있으면 **원본에서 삭제된 항목 N건 — 프로젝트 사본은 그대로 둡니다.** 가 나옵니다.
6. **적용**을 누르세요. 오른쪽에 **처리 대상 N건** 이 보입니다.

**제약** — 첫 가져오기는 「모든 항목이 신규인 재동기화」와 같으므로 메뉴가 따로 없습니다. 5,000건이 넘는 적용은 여러 묶음으로 나눠 보냅니다. **적용** 버튼이 잠기고 **적용 중… 2 / 4** 처럼 진행을 보여 줍니다. 묶음이 몇 개든 적용은 편집 하나이므로 **실행 취소 한 번이 전부를 되돌립니다**(버전 이력에는 **… (1/4)** 처럼 묶음마다 따로 기록됩니다). 중간 묶음이 실패하면 거기서 멈추고 **4개 묶음 중 2개를 적용했고 나머지는 적용하지 못했습니다 — 〈오류〉** 를 보여 줍니다. 앞선 묶음은 이미 적용됐고 실행 취소 이력은 비워집니다. 되돌리려면 버전(이력) 화면에서 이전 스냅샷으로 돌아가세요. 원본에서 항목을 지워도 프로젝트 사본은 지워지지 않습니다.

### 승격 · 승격 요청

1. **공용 리소스** → **조직으로 승격** → 승격할 라이브러리를 고르세요.
2. 항목이 세 구역으로 보입니다.

| 구역 | 뜻 | 기본 선택 |
|---|---|---|
| **신규 추가** | 라이브러리에 없는 항목 | 선택됨 |
| **원본 갱신** | 이미 연결된 라이브러리 항목에 이 프로젝트의 값을 올림 | 선택됨. 가져온 뒤 원본이 바뀐 항목(배지)은 **해제** |
| **동명 발견** | 라이브러리에 이름이 같은 다른 항목이 있음 | 사람이 확인해야 하므로 **해제** |

구역마다 검색란과 페이지가 있고, **모두 선택** / **모두 해제**는 구역 전체에 적용됩니다(가져오기와 같고, 승인자의 검토 창과도 같습니다).

**동명 발견**에는 **대상 라이브러리에 같은 이름의 항목이 있습니다. 선택하면 그 항목을 이 프로젝트의 값으로 갱신하고 연결합니다.** 가 붙습니다. 도메인을 참조하는 용어를 그 도메인 없이 승격하면 **도메인 연결 비움** 배지가 붙습니다.

**가져온 뒤 원본이 바뀐 항목**(프로젝트가 마지막으로 가져온 뒤 다른 사람이 그 라이브러리 항목을 고친 경우)은 **원본 갱신** 구역에 **원본이 더 새롭습니다 — 먼저 가져오기(재동기화)로 받으세요** 배지와 함께 나오고 기본으로 해제됩니다. 이 프로젝트의 값은 그 사람의 새 값보다 오래됐으므로, 그대로 승격하면 고쳐진 원본이 옛 값으로 되돌아갑니다. **가져오기** 탭에서 먼저 재동기화하면 손대지 않은 항목은 원본 값에 맞춰지고, 프로젝트에서도 바뀐 항목은 충돌로 나옵니다. 거기서 **프로젝트 유지**를 고른 뒤 승격하면 배지 없이 올라갑니다. 체크해서 바로 승격할 수도 있지만, 그러면 원본의 새 값을 덮어씁니다.

3. **쓰기 권한이 있으면** 버튼은 **승격**입니다. 누르면 바로 승격되고 결과가 토스트로 나옵니다: **추가 N건 · 갱신 N건을 올렸습니다**. 5,000건이 넘으면 나눠서 승격하며 버튼에 **적용 중… 1 / 2** 처럼 진행이 보이고, 결과는 토스트 하나로 합쳐집니다. 도중에 실패하면 **N건 중 M건 승격했습니다 — 〈오류〉** 가 나오고 목록을 다시 불러옵니다(실패 전에 승격한 항목은 남습니다).
4. **권한이 없으면** 버튼은 **승격 요청**이고, 그 위에 **요청 메모 (선택)** 칸이 나옵니다. 요청은 라이브러리를 그대로 두고 요청 행만 더합니다. 요청 하나에는 최대 50,000건까지 담을 수 있습니다. 넘으면 **한 번에 요청할 수 있는 항목은 50,000건까지입니다. 나눠 선택해 주세요.** 가 나오고 아무것도 보내지 않습니다. 이미 적용됐거나 지워진 항목은 자동으로 빠지고 그 수를 알려 줍니다. 대기 중인 내 요청은 같은 탭 위쪽 **대기 중인 요청** 상자에 요청자·건수·메모와 함께 보이고, **요청 취소**로 닫을 수 있습니다.

**어떻게 — 승인(조직 관리자)**

1. 상단 바에 **승격 요청 N건** 배지가 나옵니다. **이 배지가 요청이 승인자에게 닿는 유일한 길입니다**(이메일 알림은 없습니다). 60초마다 새로 고칩니다. 조직이 하나면 그 조직으로, 여럿이면 홈 화면으로 갑니다. 홈 화면의 조직 카드에도 같은 배지가 붙습니다.
2. 조직 상세 화면의 **승격 요청** 절에서 상태 필터(**대기 중**, **승인됨**, **반려됨**, **취소됨**)로 목록을 보세요. 표에는 프로젝트, 라이브러리, 요청자, 항목, 메모가 있습니다.
3. 대기 중인 행의 **검토**를 누르면 **승격 요청 검토 — 〈프로젝트명〉** 다이얼로그가 열립니다. 서버가 그 순간의 계획을 계산합니다.
4. 승격할 항목을 고르고 **처리 메모 (선택)** 를 남기세요. 버튼은 고른 항목 수에 따라 바뀝니다. 하나 이상 고르면 **N건 승격**, 하나도 고르지 않으면 **반려**입니다. **반려하면 요청이 닫힙니다.**
   요청자가 마지막으로 받은 뒤(요청 전이든 후든) 라이브러리 항목이 바뀌었으면 **원본이 요청자가 받은 버전보다 새롭습니다 — 승인하면 최신 원본을 요청자의 값으로 되돌립니다** 배지가 나오고 그 항목은 기본으로 해제됩니다. 요청자가 본 값이 최신 원본보다 오래됐다는 뜻입니다. 체크해서 승인하면 최신 원본을 덮어쓰므로, 보통은 그 항목을 빼고 승인하거나 처리 메모로 요청자에게 재동기화한 뒤 다시 요청해 달라고 하세요.

**제약**

- 승격 요청의 대상은 **조직 라이브러리뿐**입니다. 전역 라이브러리는 쓰기 권한이 있는 사람(서비스 역할 `admin`)이 직접 승격합니다.
- 요청은 처리되면 닫힙니다. 처리된 행은 읽기 전용 이력이고 **검토** 버튼이 없습니다. 승인자의 처리 메모는 웹에서는 이 목록의 **처리 메모** 열에서만 볼 수 있습니다(요청자의 승격 탭에는 없고, CLI 의 `erdd dict requests` 가 보여 줍니다). 반려 사유도 같은 열에 들어갑니다.
- 라이브러리를 지우면 그 항목도 함께 지워집니다(**"〈이름〉"을(를) 삭제하면 항목 N개도 함께 삭제됩니다. 계속할까요?**). 항목 하나를 지울 때는 **"〈이름〉"을(를) 삭제할까요? 이미 가져간 프로젝트의 사본은 그대로 남습니다.** 로 묻습니다.
- 항목에는 버전 번호(`v1`, `v2`…)가 있고, 재동기화·승격 화면에서 **v2 → v3** 으로 보입니다.

## 14. 버전(이력·스냅샷·비교)

> [!NOTE]
> **로컬 모드에서는 다릅니다.** **이력** 탭이 없고(git 커밋이 그 자리를 대신합니다), 스냅샷은 `erdd/snapshots/` 에 저장되어 커밋됩니다. 미저장 편집이 있으면 스냅샷을 만들 수 없고, **복원**은 화면만 되돌리므로 파일에 쓰려면 **저장**해야 합니다(→ [로컬 모드 매뉴얼 6절](./local-guide.md#6-스냅샷)). 로컬 모드에는 **변경 기록** 탭도 있습니다(→ [로컬 모드 매뉴얼 5.6](./local-guide.md#56-변경-기록--마이그레이션을-쓰기-위한-수정-내역)).

**무엇** — 편집 이력(리비전), 이름 붙인 시점(스냅샷), 두 시점의 비교를 한 화면에서 다룹니다.

**어디서** — 에디터 헤더의 **버전**. 탭은 **스냅샷**, **이력**, **비교** 셋입니다.

**어떻게 — 이력** — **이력** 탭은 편집을 최신순으로 보여 줍니다. 줄마다 **#〈번호〉 〈요약〉** 과 작업자·시각이 있고, 오른쪽에 출처 배지가 있습니다: `web`(웹 UI), `cli`(CLI), `system`(복원 같은 시스템 작업). 더 있으면 **더 보기**가 불러옵니다.

**어떻게 — 스냅샷** — **스냅샷** 탭에서 **이름**(예: 「배포 전 백업」)을 입력하고 **스냅샷 만들기**를 누르세요. 목록의 항목을 누르면 요약(테이블 수와 처음 5개의 물리명)이 펼쳐집니다. **복원**은 **"〈이름〉" 스냅샷으로 복원할까요? 현재 편집 중인 내용이 대체됩니다.** 로 물은 뒤 그 시점으로 되돌립니다. 다이얼로그가 닫히고 화면이 다시 불러와집니다. **삭제**는 **"〈이름〉" 스냅샷을 삭제할까요?** 로 묻습니다.

**어떻게 — 비교**

1. **비교** 탭의 **기준**과 **비교** 드롭다운에서 각각 **현재**(편집 중인 모델)나 스냅샷을 고르세요. 기본값은 기준 = 최신 스냅샷, 비교 = **현재**입니다.
2. 아래에 **추가 N · 삭제 N · 변경 N** 과 변경 목록이 나옵니다. 줄마다 종류(테이블, 컬럼, 관계, 인덱스, 그룹, 도메인, 단어, 용어, 커스텀 항목, 메모), 대상 이름, 변경 유형(추가/삭제/변경)이 보이고, 바뀐 속성은 **이전값 → 이후값** 으로 펼쳐집니다. 대상 이름이 링크처럼 보이면 눌러서 그 엔티티로 이동할 수 있습니다.
3. **변경분 정의서**는 차이만 담은 `erdd_변경분정의서.xlsx` 를 내려받습니다. 시트 맨 위에 **기준: 〈…〉 · 비교: 〈…〉** 가 적혀 있습니다.

**제약**

- 스냅샷 복원과 삭제는 **프로젝트를 관리할 수 있는 사람만** 할 수 있습니다(Org Owner/Admin 또는 Project Admin). 다른 사람에게는 **복원**과 **삭제** 버튼이 보이지 않습니다.
- 복원은 `system` 출처로 이력에 기록되고, 복원 자체는 실행 취소할 수 없습니다. 실행 취소 이력은 비워집니다.
- 스냅샷을 만들 때는 이름만 입력할 수 있습니다. 목록의 설명 열은 값이 없어 **설명 없음**으로 보입니다.
- 비교에는 스냅샷이 하나 이상 필요합니다. 없으면 **비교하려면 스냅샷이 하나 이상 필요합니다. 아직 스냅샷이 없습니다** 가 나옵니다. 지금 모델에 없는 대상(지워진 테이블 등)은 눌러서 이동할 수 없습니다.
- 이력은 편집 요약만 담습니다. 무엇이 바뀌었는지 자세히 보여 주는 화면은 없습니다.

## 15. 내보내기

**무엇** — 설계를 실행할 수 있는 DDL, 문서 게시용 DBML, 공유용 이미지, 제출용 Excel 정의서로 내보냅니다. 모델을 바꾸지 않는 읽기 전용 기능입니다.

**어디서** — 에디터 헤더 **파일** → **내보내기**. 탭은 **DDL**, **DBML**, **이미지**, **Excel** 넷입니다.

### DDL

1. **방언**을 고르세요: **PostgreSQL**, **MySQL·MariaDB**, **Oracle**, **MSSQL**.
2. **범위**를 고르세요: **전체**, 또는 그룹 드롭다운에서 그룹 하나. 그룹 뷰를 보는 중에 다이얼로그를 열면 그 그룹이 기본으로 골라집니다.
3. 결과가 **DDL 미리보기**에 바로 나옵니다.
4. **복사**로 클립보드에 넣거나 **다운로드**로 `erdd_〈방언〉.sql` 을 받으세요.

| 부분 | 설명 |
|---|---|
| `CREATE TABLE` | 컬럼 타입, NOT NULL, 기본값, 자동 증가(방언 문법), 기본 키. **MySQL·MariaDB 에서는 NULL 허용 `TIMESTAMP` 컬럼에 `NULL` 을 명시합니다.** 서버 설정에 따라 컬럼이 저절로 `NOT NULL` 이 되거나 행을 고칠 때마다 현재 시각으로 바뀌는 것을 막기 위해서입니다 |
| CHECK 제약 | 도메인에 허용값이 있는 컬럼의 `column IN (…)` |
| 외래 키 | `ALTER TABLE … ADD CONSTRAINT … FOREIGN KEY`. 1:1 관계에는 UNIQUE 제약도 붙습니다 |
| 인덱스 | 컬럼마다 정렬 방향을 포함한 `CREATE [UNIQUE] INDEX` |
| 코멘트 | 테이블·컬럼 코멘트. PostgreSQL·Oracle 은 `COMMENT ON`, MSSQL 은 확장 속성, MySQL 은 `CREATE TABLE` 안의 인라인 |

**테이블 이름** — 프로젝트 설정의 **테이블 물리명 형식**이 비어 있지 않으면 `CREATE TABLE`, 외래 키, 인덱스, 코멘트가 **모두** 조합된 이름을 씁니다(→ [10절](#10-명명-체계단어용어-사전)).

**제약** — 컬럼이 없는 테이블은 빠지고, **DDL 경고** 아래에 **〈테이블〉: 컬럼이 없어 내보내기에서 제외됨** 이 나옵니다. 식별자를 만들 수 없으므로 **물리명이 빈 테이블, 또는 물리명이 빈 컬럼이 있는 테이블도 같은 식으로 빠지고** **〈테이블 또는 논리명〉: 물리명이 비어 있어 내보내기에서 제외됨** 이 나옵니다. 방언 변환이 불확실한 타입도 경고를 내고, 해석할 수 없는 타입은 입력한 그대로 나갑니다. 범위 밖 테이블과 이어지는 관계와 인덱스도 빠집니다.

### DBML

**DBML** 탭은 dbdocs 와 dbdiagram.io 가 읽는 DBML 을 만듭니다. 주된 쓰임은 **dbdocs 로 문서를 게시하는 것**입니다.

1. **방언**과 **범위**를 고르세요. **DDL 탭과 같은 선택을 공유합니다**(탭을 바꿔도 선택이 유지됩니다). 타입 해석도 DDL 과 같습니다(도메인의 방언별 매핑 포함).
2. 결과가 **DBML 미리보기**에 바로 나옵니다.
3. **복사**로 클립보드에 넣거나 **다운로드**로 `erdd_〈방언〉.dbml` 을 받으세요.

| 부분 | 설명 |
|---|---|
| `Project` | 프로젝트 이름과 `database_type`(고른 방언). 프로젝트 이름이 있을 때만 나갑니다 |
| `Table` | 그룹에 속하면 `headercolor`, `note` 에 「논리명 - 설명」 |
| 컬럼 설정 | `pk`(단일 기본 키) · `increment` · `not null` · `null` · `default` · `note`. `null` 은 **MySQL·MariaDB 방언의 NULL 허용 `TIMESTAMP` 컬럼에만** 붙고, 기본 키 컬럼에는 붙지 않습니다 |
| `indexes` 블록 | 인덱스(이름, `unique`)와 **복합 기본 키**(`[pk]`) |
| `TableGroup` | 그룹 이름, `color`, 소속 테이블 목록 |
| `Ref` | 관계. 1:N 은 `>`, 1:1 은 `-`. 복합 키는 괄호로 묶고, **이름을 붙인 관계만** 이름을 가집니다 |

**커스텀 항목 값**은 note 뒤에 JSON 으로 붙습니다. 예: `회원 - 회원 기본정보 {"보안등급":"2"}`. 키는 커스텀 항목 정의의 이름이고, 값이 빈 항목은 나가지 않습니다.

**제약** — 테이블 선택과 경고는 DDL 과 완전히 같습니다(컬럼이 0개이거나 물리명이 빈 테이블은 빠집니다). 도메인 허용값은 `enum` 으로 나가지 않습니다. 읽을 때 도메인으로 되돌릴 방법이 없어 「이름만 남은 타입」이 되기 때문입니다. 메모, 색상 영역, 좌표는 DBML 에 들어가지 않습니다.

### 이미지

**이미지** 탭에서 **PNG** 나 **SVG** 를 고르고 **다운로드**를 누르세요. **현재 화면(뷰·보기 모드)이 그대로 저장됩니다.** 전체 뷰·그룹 뷰와 논리명·물리명·혼합 설정이 반영됩니다. 다만 지금의 이동·배율과 무관하게 이미지에는 **모든 노드**가 들어갑니다. 노드가 없으면 **내보낼 노드가 없습니다** 로 실패합니다. 이미지 범위를 따로 고를 수는 없습니다. 좁히려면 그룹 뷰로 바꾼 뒤 내보내세요.

### Excel 정의서

**Excel** 탭에서 **범위**(**전체** 또는 그룹)를 고르고, **시트**에서 내보낼 시트를 켠 뒤(기본은 모두 켜짐) **다운로드**를 누르면 `erdd_정의서.xlsx`(그룹을 골랐으면 `erdd_정의서_〈그룹명〉.xlsx`)를 받습니다. 통합 문서의 순서는 다음과 같습니다.

| 시트 | 열 |
|---|---|
| **테이블 목록** | 그룹 · 논리명 · 물리명 · 설명(+ 테이블 커스텀 항목) |
| **테이블정의서** | 그룹 · 테이블 논리명 · 테이블 물리명 · 순번 · 논리명 · 물리명 · 도메인 · 타입 · PK · NOT NULL · 기본값 · 설명(+ 컬럼 커스텀 항목) |
| **단어사전** | 논리명 · 약어 · 영문명 · 설명 |
| **용어사전** | 용어 · 구성 단어 · 물리명 · 기본 도메인 · 설명 |
| **도메인정의서** | 이름 · 분류 · 논리 타입 · PostgreSQL · MySQL · Oracle · MSSQL · 기본값 · 허용값 · 설명 |

**변경분 정의서** 시트는 이 목록에 없습니다. 비교 화면에서만 만듭니다(→ [14절](#14-버전이력스냅샷비교)).

**제약** — **범위는 테이블 목록·테이블정의서에만 적용됩니다. 사전 3종은 항상 전체를 내보냅니다.** 사전은 그룹 개념이 없는 프로젝트 전체의 자산입니다. 시트를 하나도 켜지 않으면 **다운로드**가 잠깁니다. 모든 셀을 문자열로 쓰므로 `0001` 같은 물리명의 앞자리 0 이 유지되고, 표현이 업로드 파서와 대칭입니다. 도메인 허용값은 `, ` 로 이어 붙이므로, 쉼표가 든 허용값은 다시 업로드하면 정확히 복원되지 않습니다(알려진 한계).

## 16. 가져오기

**무엇** — 거꾸로 가는 길 둘입니다. 기존 DB 의 DDL(또는 DBML)을 붙여넣어 모델로 되돌리는 역설계와, 정해진 양식의 Excel 로 사전을 한꺼번에 등록하는 업로드입니다.

### DDL·DBML 가져오기

**어디서** — 에디터 헤더 **파일** → **DDL·DBML 가져오기**(다이얼로그 제목도 같습니다). 편집 권한이 없으면 이 항목이 메뉴에 없습니다.

1. 위쪽에서 형식을 고르세요: **DDL**(기본값) 또는 **DBML**. 형식을 바꾸면 손으로 고른 방언이 초기화됩니다(형식마다 자동 감지 결과가 다르기 때문입니다).
2. **방언**을 확인하세요. 붙여넣은 내용에서 자동으로 감지되고(DBML 은 `Project { database_type }` 에서), 해당 항목에 **(자동 감지)** 가 붙습니다. 드롭다운에서 언제든 바꿀 수 있습니다.
3. 텍스트 영역에 붙여넣으세요(**CREATE TABLE ... 형태의 DDL을 붙여넣으세요** / **Table "..." { ... } 형태의 DBML을 붙여넣으세요**).
4. 미리보기가 바로 나옵니다: **테이블 N개 · 컬럼 N개 · 관계 N개 · 인덱스 N개**, DBML 에 그룹이 있으면 **· 그룹 N개**, 건너뛴 테이블이 있으면 **건너뜀 N개 (이름이 겹침: …)**. 나열되는 것은 **원본 DDL 의 이름**이고, 아래 경고 목록이 테이블마다 무엇과 겹쳤는지 밝힙니다(머릿말이 이름을 복원했으면 둘이 다릅니다).
5. **가져오기 경고** 목록을 확인하세요.
6. 테이블 옵션이 감지됐고 프로젝트의 지금 값과 다르면 **프로젝트의 테이블 옵션도 갱신** 체크박스가 나옵니다(→ 아래 「테이블 옵션」). **관리 권한이 있을 때만 보입니다.**
7. **〈N〉개 테이블 만들기**를 누르세요. 테이블, 컬럼, 관계가 편집 하나로 적용되므로 실행 취소 한 번으로 되돌아갑니다.

**테이블 옵션**

DDL 의 `) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4` 같은 꼬리 절에서 `ENGINE`, `DEFAULT CHARSET`,
`COLLATE` 만 뽑아 한 줄로 정규화합니다. 테이블마다 다르면 **가장 많이 쓰인 값을 채택합니다**(같으면
DDL 에 먼저 나온 것). 채택한 값과 다른 테이블마다 경고가 하나씩 붙습니다. `AUTO_INCREMENT=` 시작값
같은 테이블별 값은 버립니다. 프로젝트 설정으로 올리면 모든 테이블의 시작값이 바뀌기 때문입니다.

체크박스는 **프로젝트의 그 방언 칸이 비어 있으면 켜진 채로**, 다른 값이 있으면 꺼진 채로 시작합니다.
정해 둔 값이 조용히 덮어써지지 않게 하기 위해서입니다. 언제든 뒤집을 수 있습니다.

> [!WARNING]
> **실행 취소가 갈립니다.** 테이블 생성은 실행 취소할 수 있지만 프로젝트 설정은 실행 취소할 수
> 없습니다. 설정은 편집 이력 밖에 있습니다. 다이얼로그의 문구도 그렇게 밝힙니다.

**부호 없음**

`int unsigned` 같은 표기는 논리 타입 `INT UNSIGNED` 로 들어옵니다. 정수 3종(`SMALLINT`, `INT`,
`BIGINT`)이 아닌 타입에 붙은 부호 없음(`decimal(10,2) unsigned` 등)은 **경고와 함께 버립니다.**
MySQL 5.7 이 쓰는 정수 표시폭(`int(11)`, `bigint(20)`)은 읽고 버립니다. 표시 전용 값이고 8.0.17 부터
deprecated 입니다.

**형식마다 다른 것은 파서뿐입니다.** 방언 선택, 미리보기, 경고, 적용은 모두 완전히 같은 경로를 탑니다.

**파서가 읽는 구문**

| 문 | 읽는 것 |
|---|---|
| `CREATE TABLE` | 컬럼 이름, 원본 타입 문자열(`UNSIGNED` 접미와 정수 표시폭 포함), `NOT NULL`, `DEFAULT`, 자동 증가, 인라인 `PRIMARY KEY`, MySQL 인라인 `COMMENT` |
| `CREATE TABLE` 의 꼬리 절 | `ENGINE`, `DEFAULT CHARSET`(`CHARACTER SET`), `COLLATE`(→ 위 「테이블 옵션」), MySQL 테이블 `COMMENT` |
| `CREATE TABLE` 안의 제약 | `PRIMARY KEY`, `UNIQUE`, `FOREIGN KEY … REFERENCES` |
| `ALTER TABLE … ADD` | `PRIMARY KEY`, `UNIQUE`, `FOREIGN KEY` |
| `CREATE [UNIQUE] INDEX` | 인덱스 이름, 대상 테이블, 컬럼 |
| `COMMENT ON` | 테이블·컬럼 코멘트 |

주석(`--`, `/* */`), 문자열 리터럴, 따옴표 식별자(`"…"`, `` `…` ``, `[…]`), 스키마 접두, Oracle 스크립트의 `/` 구분자를 처리합니다.

**파서가 하지 못하는 것** — 위 목록에 없는 문은 모두 건너뛰고 **〈행〉 〈키워드〉 구문을 건너뛰었습니다** 로 알립니다. 대표적으로 `CHECK` 제약(인라인이든 `ALTER TABLE … ADD CHECK` 든), `CREATE VIEW`/`SEQUENCE`/`TRIGGER`/`PROCEDURE`/`FUNCTION`, `GRANT`·`INSERT` 같은 DML·권한 문입니다. **인덱스 컬럼의 정렬 방향도 읽지 않습니다.** 가져온 인덱스는 모두 `ASC` 가 됩니다.

**그 밖의 제약**

- 같은 물리명의 테이블이 이미 있으면 건너뜁니다(**같은 이름의 테이블이 이미 있어 건너뜁니다**). DDL 안에 같은 이름이 두 번 나오면 뒤의 것을 건너뜁니다.
- **물리명에서 논리명을 복원하는 것은 사전에 달려 있습니다.** 모르는 약어가 있으면 **논리명을 복원하지 못했습니다 — 사전에 없는 단어: …** 가 나옵니다. 사전을 먼저 채우면 논리명도 복원됩니다.
- 모르는 타입은 쓴 그대로 둡니다(**…를 알지 못해 타입을 그대로 두었습니다**). 해석이 여럿 가능하면 하나를 고르고 다른 후보를 알려 줍니다.
- 참조하는 테이블이나 컬럼을 찾을 수 없는 FK, 테이블이나 컬럼을 찾을 수 없는 인덱스·UNIQUE 제약은 만들지 않고 각각 경고를 남깁니다.
- 5,000건이 넘는 가져오기는 여러 묶음으로 나눠 보냅니다. 버튼이 **적용 중… 1 / 2** 로 바뀌고 잠깁니다. 묶음이 몇 개든 실행 취소 한 번으로 되돌아가고, 중간 묶음이 실패했을 때의 동작은 [13절 가져오기](#가져오기재동기화)의 제약과 같습니다.

**DBML 파서가 읽는 것** — `Project`(`database_type`), `Table`(별칭 `as X` 는 무시, `headercolor`, `note`), 컬럼 줄(타입 + `pk`/`primary key`/`not null`/`null`/`unique`/`increment`/`default:`/`note:`/인라인 `ref:`), `indexes` 블록(단일·복합, `[pk]`, `unique`, `name:`), `Ref`(줄 형식과 블록 형식 모두, 이름 유무, `>` `<` `-`, 복합 키), `TableGroup`(`color`, `note`), 주석(`//`, `/* */`).

- **`TableGroup` 은 그룹이 됩니다.** 같은 이름의 그룹이 이미 있으면 그 그룹을 쓰고, 그 그룹의 색은 덮어쓰지 않습니다. 색은 `color` → 첫 소속 테이블의 `headercolor` → 팔레트 순서로 정합니다.

  ⚠️ **첫 줄 머릿말에 같은 이름의 그룹이 있으면 머릿말이 이깁니다.** 그 그룹의 소속·색·코멘트는 머릿말이 말하는 대로이고 블록의 내용은 쓰지 않습니다(우리가 내보낸 DBML 에서는 둘이 늘 일치합니다). 머릿말에 없는 그룹만 블록으로 만들어집니다.
- **note 뒤의 JSON 꼬리는 커스텀 항목 값으로 되읽습니다.** 정의가 없는 이름은 **커스텀 항목 정의가 없어 "〈이름〉" 값을 버렸습니다** 로 버립니다. 커스텀 항목을 먼저 정의하면 값도 들어옵니다.
- 방향은 자식 → 부모로 정규화합니다(`<` 는 뒤집습니다). `-` 는 1:1 관계가 되고 고유 인덱스를 만들지 않습니다. `Ref` 의 이름은 관계명으로 살아남습니다.
- `Enum` 정의, `sticky note`, `TablePartial`, `<>`(N:M) 관계, 그 밖의 모르는 블록은 경고와 함께 건너뜁니다. 인덱스의 백틱 식(`` (`id*2`) ``)도 컬럼으로 풀 수 없어 건너뜁니다.
- 도메인 연결과 인덱스 정렬 방향은 돌아오지 않습니다(DBML 에는 그것을 표현할 방법이 없습니다).

### Excel 사전 가져오기

**어디서** — 에디터 헤더 **사전·리소스** → **단어·용어 사전** → **가져오기** 탭.

1. **양식 다운로드**로 `erdd_사전양식.xlsx` 를 받으세요. 내보내기와 같은 헤더로 단어사전·용어사전·도메인정의서 세 시트의 헤더만 들어 있습니다.
2. **Excel 파일 선택**에서 `.xlsx` 파일을 고르세요. 읽자마자 미리보기가 나옵니다: **〈파일명〉 — 신규 N건 · 중복 N건 · 오류 N행**.
3. **중복 항목 처리**에서 **건너뛰기**나 **덮어쓰기**를 고르세요. 덮어쓰기를 고르면 **덮어쓰기는 파일에 있는 아래 컬럼만 갱신하고 나머지 값은 그대로 둡니다** 와 함께 시트별로 인식한 열이 나옵니다.
4. 오류와 경고는 시트와 행 번호와 함께 나옵니다(최대 20개, 나머지는 **외 N건**).
5. **적용 대상 N건** 을 확인하고 **가져오기 실행**을 누르세요.

**제약** — 사전 전체가 편집 하나로 나가므로 실행 취소 한 번으로 되돌아갑니다. 5,000건이 넘으면 여러 묶음으로 나눠 보내고 버튼에 **적용 중… 2 / 4** 처럼 진행이 보입니다(중간 묶음이 실패했을 때의 동작은 [13절 가져오기](#가져오기재동기화)의 제약과 같습니다). 파일 내용이 이미 사전과 같으면 **파일 내용이 현재 사전과 같아 바뀐 항목이 없습니다** 가 나옵니다. 적용 대상이 0건이면 버튼이 잠깁니다. 실행 중에는 버튼과 파일 선택이 모두 잠깁니다. 실패하면 미리보기가 남아 있으므로 그대로 다시 시도할 수 있습니다.

## 17. 실시간 동시편집

> [!NOTE]
> **로컬 모드에는 없습니다.** 참여자 표시도 커서도 없습니다. 로컬 모드는 한 사람이 작업한다고 가정합니다(→ [로컬 모드 매뉴얼 4.6](./local-guide.md#46-탭을-여러-개-열면)).

**무엇** — 여러 사람이 같은 프로젝트를 동시에 열고 편집할 수 있습니다. 다른 사람의 변경이 내 화면에 바로 나타나고, 누가 무엇을 보고 있는지 알 수 있습니다.

**어디서** — 따로 화면이 없습니다. 에디터에 들어가면 자동으로 연결됩니다. 접속한 사용자의 아바타는 헤더 오른쪽(**버전** 왼쪽)의 **함께 보는 사용자** 영역에 있습니다.

**어떻게 — 보이는 것**

- **접속한 사용자 아바타** — 같은 프로젝트를 보고 있는 다른 사람마다 이름 첫 글자가 사람마다 고정된 색의 둥근 배지로 보입니다. 최대 3명까지 보이고 나머지는 **+N** 으로 묶입니다. 마우스를 올리면 이름이 보입니다. 나 자신은 보이지 않고, 혼자면 영역이 비어 있습니다.
- **다른 사람의 선택 강조** — 다른 사람이 선택한 테이블·관계·메모에는 그 사람 색의 외곽선이, 테이블에는 이름표가 붙습니다. **여러 개를 선택했으면 모두 표시됩니다.** 일괄 삭제 전에 다른 사람이 지금 그 항목을 작업 중인지 보여야 하기 때문입니다(한 사람당 50개까지 보내므로 더 선택하면 처음 50개만 보입니다). 내 선택은 안쪽의 파란 테두리를 쓰므로 둘을 구별할 수 있습니다.
- **알림 토스트** — 보고 있는 항목이 다른 사람의 편집으로 바뀌면 **다른 사용자가 이 항목을 수정했습니다** 가 나옵니다. 지워지면 **다른 사용자가 이 항목을 삭제했습니다** 가 나옵니다. 여러 개를 선택한 상태에서 일부만 지워지면 **다른 사용자가 선택 항목 중 일부를 삭제했습니다** 가 나오고 나머지 선택은 유지됩니다. 지워진 항목만 선택에서 빠집니다. 보고 있는 테이블의 **컬럼이나 인덱스**가 바뀌어도 변경 알림이 나옵니다. 변경 묶음마다 최대 한 번입니다.

**제약**

- 두 사람이 같은 곳을 동시에 고치면 **나중에 도착한 편집이 이깁니다.** 글자나 필드 단위로 병합하지 않습니다.
- 내 편집이 서버로 가는 동안 다른 사람의 편집이 먼저 반영되면 화면 전체를 서버의 최신 상태로 다시 맞춥니다. 되돌릴 대상이 이미 사라졌을 수 있으므로 **이때 실행 취소 이력이 비워집니다.** 보고 있던 그룹 뷰는 유지되고, 선택은 대상이 아직 있을 때만 유지됩니다.
- 연결이 끊기면 1·2·4·8초 간격으로 자동으로 다시 연결합니다. 권한 문제로 끊겼으면 다시 시도하지 않습니다. 서버 상태를 불러올 수 없으면 **서버 상태를 불러오지 못했습니다. 새로고침해 주세요.** 가 나옵니다.
- Viewer 도 실시간 화면과 접속자 표시를 정상적으로 받습니다. 편집만 막힙니다.

## 18. 액세스 토큰

> [!NOTE]
> **로컬 모드에는 없습니다.** 부를 서버가 없습니다(→ [로컬 모드 매뉴얼](./local-guide.md)).

**무엇** — CLI 용 개인 액세스 토큰입니다. **CLI에서 쓰는 토큰입니다. 권한은 내 조직·프로젝트 역할을 그대로 따릅니다.**

**어디서** — `/settings`(사용자 메뉴 → **설정**)의 **액세스 토큰** 카드.

**어떻게** — **토큰 이름**에 알아볼 수 있는 이름(예: 「노트북」)을 입력하고 **발급**을 누르세요. 노란 상자에 토큰 값이 나오고, **복사**가 클립보드에 넣습니다. 폐기하려면 목록에서 **폐기**를 누른 뒤 빨간 **정말 폐기**를 한 번 더 누르세요.

**제약** — **이 값은 지금만 보입니다 — 창을 닫으면 다시 볼 수 없습니다.** 목록에는 이름과 마지막 사용일만 남으므로, 토큰을 잃으면 찾는 것이 아니라 다시 발급합니다. 토큰은 내 계정의 조직·프로젝트 역할과 같은 권한을 가지므로 토큰만으로 더 넓은 권한을 얻을 수는 없습니다. 반대로 **토큰은 발급한 사람이 웹에서 할 수 있는 모든 쓰기를 할 수 있습니다.** 조직 Owner/Admin 의 토큰은 CLI 로 프로젝트를 만들 수 있고(`erdd init --create`) 조직 공용 리소스에 승인 없이 바로 쓸 수 있으며(`erdd dict push`), 서비스 관리자의 토큰은 전역 공용 리소스에까지 씁니다. 그러니 에이전트와 CI 용 토큰은 editor 계정에서 발급하고(→ [CLI 매뉴얼 3.1](cli-guide.md#31-개인-액세스-토큰-발급)), 정말 필요한 곳에만 발급하며, 더 쓰지 않는 토큰은 바로 폐기하세요. 이름이 비어 있으면 **발급**이 잠깁니다. 발급한 토큰이 없으면 **발급한 토큰이 없습니다.** 가 나옵니다.

같은 화면 위쪽의 **비밀번호 변경** 카드에서 비밀번호를 바꿉니다. **현재 비밀번호**, **새 비밀번호**, **새 비밀번호 확인**을 입력하고 **변경 사항 저장**을 누르세요. **변경하면 다른 기기의 로그인이 해제됩니다.**

**CLI 자체의 사용법은 이 매뉴얼의 범위 밖입니다.** 토큰을 가진 뒤 할 일(명령, 파일 포맷, 동기화 방식)은 [CLI 매뉴얼](cli-guide.md)에 있습니다.

## 19. 관리자 업무

> [!NOTE]
> **로컬 모드에는 없습니다.** 계정, 초대, 전역 공용 리소스가 없습니다(→ [로컬 모드 매뉴얼](./local-guide.md)).

**무엇** — 서비스 역할이 `admin` 인 사람이 하는 일입니다: 계정 초대와 상태 관리, 비밀번호 재설정 링크 발급, 전역 공용 리소스 관리. 조직 수준의 일(조직 초대, 승격 요청 승인, 조직 라이브러리)은 Org Owner/Admin 이 조직 화면에서 합니다.

**어디서** — `/admin`(사용자 메뉴 → **관리자**, 제목 **계정 관리**). 조직 일은 `/org/:orgId` 에 있습니다.

### 계정 초대

**계정 초대**를 누르면 다이얼로그에 **계정을 만들지 않고 초대 링크만 만듭니다. 이름과 비밀번호는 본인이 정합니다.** 가 적혀 있습니다. **이메일**을 입력하고 **역할**에서 **일반**이나 **관리자**를 고른 뒤 **초대 링크 만들기**를 누르세요. 노란 상자에 링크가 **받는 사람**과 만료 시각과 함께 나옵니다. **복사**로 복사해 전달하고 **닫기**로 닫으세요.

**제약 — 이 화면에는 비밀번호 칸이 없습니다.** 관리자는 계정이 아니라 링크만 만듭니다. 화면에도 **초대 링크를 만들어 사람을 부르고, 만들어진 계정의 사용 상태를 관리합니다. 계정은 초대를 수락한 본인이 만들고 비밀번호도 본인만 정합니다.** 라고 적혀 있습니다. **이 링크는 지금만 볼 수 있습니다 — 창을 닫으면 다시 볼 수 없습니다. 잃으면 새로 발급하세요.** 평문 링크는 발급 응답에만 나오므로 목록에서 다시 찾을 수 없습니다. 이미 계정이 있는 이메일로는 초대를 만들 수 없습니다.

### 계정 상태와 재설정 링크

계정 표에는 이메일, 이름, 역할(**관리자** / **일반**), 상태(**활성** / **비활성**)가 있습니다.

- **비밀번호 재설정 링크** — 행의 **비밀번호 재설정 링크** → **링크 만들기**. **링크를 만들어 사용자에게 전달합니다. 발급만으로는 비밀번호가 바뀌지 않고 로그인 세션도 유지됩니다.** 발급한 뒤 화면이 다시 확인해 줍니다: **이 링크를 사용자에게 전달하세요. 사용자가 링크를 열어 새 비밀번호를 정해야 비밀번호가 바뀝니다.** 24시간 유효하고 목록 화면이 없으므로, 상자에 보이는 만료 시각이 확인할 수 있는 유일한 곳입니다.
- **활성/비활성** — 행의 **비활성화** / **활성화**로 계정을 쓸 수 있는지를 바꿉니다.

### 초대 목록과 회수

`/admin` 아래쪽의 **초대** 절은 **관리자가 만든 초대만** 보여 줍니다(조직 초대는 조직 화면에 따로 있습니다). 표에는 이메일, 역할, 상태, 만료, 동작이 있고, 상태는 **대기 중**, **사용됨**, **만료됨** 중 하나입니다. 회수는 **취소**입니다. 누르면 **초대를 취소했습니다** 가 나오고 링크가 바로 죽습니다. **만료됨**으로 보이는 행에도 취소 버튼이 있습니다. 만료는 내 브라우저 시계로 판정하므로, 시계가 빠르면 아직 살아 있는 초대가 만료된 것처럼 보일 수 있기 때문입니다. 이미 쓰인 초대에만 버튼이 없습니다. 보낸 초대가 없으면 **보낸 초대가 없습니다.** 가 나옵니다.

### 조직 초대(Org Owner/Admin)

조직 상세 화면의 **초대** 절에서 같은 방식으로 발급합니다. **초대할 이메일**과 역할(Member/Admin)을 고르고 **초대 링크 만들기**를 누르세요. 그 사람이 링크를 열어 계정을 만들면 동시에 그 역할로 이 조직에 들어옵니다. 목록·상태·취소는 관리자 화면과 같고, 취소하면 화면에 보이던 링크 상자도 사라집니다.

### 라이브러리 관리

전역 공용 리소스는 `/admin` 아래쪽에, 조직 공용 리소스는 조직 상세 화면 아래쪽에 있습니다(Org Owner/Admin 만 관리합니다). 둘은 완전히 같은 방식으로 동작합니다. **라이브러리 만들기** → **이름**, **설명 (선택)** → **만들기**로 만드세요. 목록의 행마다 설명(없으면 **설명 없음**)과 항목 수가 **〈설명〉 · 항목 16,565개** 처럼 보입니다. 행을 누르면 **라이브러리 조회 — 〈이름〉** 창이 열립니다. 탭에는 **단어 (3,280)**, **용어 (13,159)**, **도메인 (126)**, **커스텀 항목 (0)** 처럼 종류별 수가 붙고, 단어 탭이 먼저 열립니다. 탭마다 검색란(**논리명·물리명 검색**. 단어는 약어와 영문명으로도, 도메인과 커스텀 항목은 이름으로 찾을 수 있습니다)과 표가 있습니다. 두 페이지 이상이면 아래쪽에 50개씩 페이지가 나옵니다. 검색어를 바꾸면 1페이지로 가고, 탭마다 검색어와 페이지는 다른 탭에 갔다 와도 유지됩니다. 표에는 단어는 논리명·물리명·영문명, 용어는 논리명·물리명·도메인, 도메인은 이름·분류·논리 타입, 커스텀 항목은 이름·대상·타입이 있고, 그 뒤에 버전(`v1`…)이 붙습니다. 결과가 없으면 검색 중에는 **검색 결과가 없습니다** 가, 빈 탭에서는 **항목이 없습니다** 가 나옵니다. 관리 권한이 있으면 탭마다 **추가**가, 행마다 연필(수정)과 휴지통(삭제)이 있습니다. 삭제는 확인을 거칩니다. 라이브러리는 **"〈이름〉"을(를) 삭제하면 항목 N개도 함께 삭제됩니다. 계속할까요?**, 항목은 **"〈이름〉"을(를) 삭제할까요? 이미 가져간 프로젝트의 사본은 그대로 남습니다.** 입니다.

**내보내기** — 라이브러리 행의 다운로드 아이콘(읽을 수 있는 사람이면 관리 권한이 없어도 됩니다). 누르면
`〈이름〉.erdd-lib.yaml`(공용 라이브러리 파일)이 바로 내려받아집니다. 지워진 도메인을 가리키던 용어가 있었으면
**삭제된 도메인을 가리키던 용어 N건은 도메인 없이 내보냈습니다** 알림이 나옵니다.

**가져오기** — 라이브러리 행의 업로드 아이콘. 관리 권한이 있을 때만 보입니다.
**라이브러리 가져오기 — 〈이름〉** 다이얼로그를 엽니다.

**파일에서 만들기** — 목록 위쪽의 버튼(관리 권한만). **파일에서 만들기** 다이얼로그를 엽니다. 이
다이얼로그에는 파일을 고르기 전까지 채울 **이름**과 **설명 (선택)** 칸도 있습니다(파일을 고르면 파일의
라이브러리 이름과 설명으로 채워집니다. Excel 은 채우지 않습니다).

두 다이얼로그의 **파일 선택**은 공용 라이브러리 파일(`.yaml`/`.yml`)과 Excel 사전 양식(`.xlsx`. 헤더는
[16절 Excel 사전 가져오기](#excel-사전-가져오기)와 같습니다)을 받습니다. 파일을 고르면 형식 오류가 있을 때
줄마다 그대로 나열합니다(오류가 있으면 거기서 끝납니다). 없으면 미리보기를 자동으로 계산해 보여 줍니다.
구역은 **추가**, **갱신**, **그대로 N건**, **오래된 파일**, **파일에 없음** 이고, 남는 항목이 가리키는
도메인을 지우게 되면 같은 경고가 나옵니다. **오래된 파일** 항목은 파일의 항목을 이 라이브러리에서 가져간
뒤 서버가 앞서 나간 항목입니다(항목마다 **서버 v〈현재〉, 파일 v〈파일값〉** 이 붙습니다). 서버의 새 값을
파일의 옛 값으로 덮어쓰려면 체크박스 **오래된 파일 항목 N건 덮어쓰기**를 켜야 합니다. **파일에 없음**
항목은 체크박스 **파일에 없는 항목 N건 삭제**를 켤 때만 지워집니다(이미 가져간 프로젝트의 사본은 남는다는
알림도 함께 나옵니다). 파일 내용이 라이브러리와 완전히 같으면
**파일 내용이 라이브러리와 같아 바뀐 항목이 없습니다** 가 나오고 **가져오기 실행**이 비활성입니다.
미리보기를 받은 뒤 라이브러리가 바뀌었으면(예: 다른 사람이 먼저 가져오기를 적용했으면)
**미리보기 이후 라이브러리가 바뀌었습니다** 와 **다시 미리보기** 버튼이 나옵니다. 다시 미리보기 전까지
**가져오기 실행**은 막힙니다. **가져오기 실행**을 누르면 결과가 토스트로 나옵니다:
**추가 N · 갱신 N · 삭제 N**.

조직 상세 화면의 **승격 요청** 절에서 합니다. 절차와 제약은 [13절](#13-공용-리소스)에 있습니다. 요청이 승인자에게 닿는 유일한 길은 상단 바의 **승격 요청 N건** 배지입니다. 이메일이나 푸시 알림이 없으니 주기적으로 확인하세요.

## 20. 선택과 복사

**무엇** — 캔버스에서 테이블과 컬럼을 선택해 복사·잘라내기·붙여넣기·삭제합니다. 클립보드는 시스템 클립보드에 JSON 텍스트를 담으므로, 다른 탭과 다른 프로젝트에도 붙여넣을 수 있습니다.

**어디서** — 캔버스(테이블 노드)와 오른쪽 편집 패널. 단축키는 문서 어디서든(입력란 밖이면) 동작합니다. 정확한 조건은 아래 「단축키」를 보세요.

**어떻게 — 선택** — 테이블을 누르면 그 테이블 하나가 선택됩니다(→ [4절](#4-에디터-기본)). 테이블 안의 컬럼 행을 누르면 그 컬럼이 선택됩니다. 오른쪽 편집 패널이 바로 그 컬럼 행으로 스크롤하고 파란 테두리로 강조합니다(이미 보이면 패널은 움직이지 않습니다). `Cmd`/`Ctrl`+클릭은 컬럼을 선택에 더하거나 뺍니다(토글). `Shift`+클릭은 마지막으로 선택한 컬럼부터 누른 컬럼까지 순서대로 범위를 고릅니다. 컬럼 선택은 **한 테이블 안에서만** 됩니다. 컬럼을 누르면 그 컬럼이 속한 테이블만 선택되고(여러 테이블을 선택하고 있었어도 하나로 좁혀집니다), 컬럼 선택은 그 안에서 이어집니다.

**어떻게 — 테이블 여러 개 선택** — 방법은 둘입니다. 테이블을 `Cmd`/`Ctrl`+클릭하면 선택에 더하거나 뺍니다(토글). `Shift` 를 누른 채 캔버스 빈 곳에서 드래그하면 선택 상자가 그려지고, 상자에 걸린 테이블이 선택됩니다. 이때 선택은 더해지지 않고 상자에 걸린 것으로 **바뀝니다.** 색상 영역(그룹)과 메모는 상자에 걸려도 이 선택에 들어가지 않고, 그룹 뷰에서 관계 때문에 흐리게 보이는 바깥 테이블(고스트)도 들어가지 않습니다. 수정 키 없이 그냥 누르면 그 테이블 하나만 남고, 빈 곳을 누르면 선택이 해제됩니다.

테이블을 둘 이상 선택하면 컬럼 선택은 비워집니다. 컬럼 선택은 한 테이블 안에서만 되기 때문입니다. 이때 편집 패널은 입력 양식에서 **일괄 작업 패널**로 바뀝니다. **N개 테이블 선택됨** 아래에 선택한 테이블 목록, **선택 테이블의 그룹** 드롭다운, **선택 테이블 삭제** 버튼이 있습니다. 테이블 여러 개를 한 번에 붙여넣으면(아래) 붙여넣은 테이블이 모두 바로 이 상태로 선택됩니다.

**어떻게 — 일괄 작업 패널** — **선택 테이블의 그룹**에서 그룹을 고르면 선택한 테이블이 모두 그 그룹으로 옮겨집니다(드래그 앤 드롭과 같습니다 → [4절](#4-에디터-기본)). 드래그가 어려운 환경을 위한 대체 경로라 키보드로도 됩니다. **선택 테이블 삭제**는 **확인을 받습니다**: **선택한 테이블을 삭제할까요?** 와 **테이블 N개와 관계 M개가 삭제됩니다**, 그리고 함께 사라지는 컬럼·인덱스 수와 대상 목록입니다. 하단 바의 **삭제**와 `Delete`/`Backspace` 단축키도 둘 이상 선택했으면 같은 확인을 거칩니다(하나면 예전처럼 바로 지웁니다). 지울 항목이 5,000건을 넘으면 여러 묶음으로 나눠 지우고, 화면 위쪽 토스트에 **적용 중… 1 / 2** 처럼 진행이 보입니다(확인 창은 누르자마자 닫힙니다). 묶음이 몇 개든 실행 취소 한 번으로 되돌아갑니다.

**옮겨 가는 자리** — 그룹을 바꾸면 캔버스 좌표도 조정됩니다. 선택한 테이블은 서로의 상대 위치를 유지한 채 대상 그룹 영역의 오른쪽으로 옮겨지고, 그 자리에 이미 다른 테이블이 있으면 겹치지 않게 아래로 밀립니다. **대상 그룹이 비어 있거나 미분류로 옮길 때는 좌표를 건드리지 않습니다**(기준으로 삼을 영역이 없기 때문입니다). 그룹 이동과 좌표 조정은 편집 하나이므로 `Cmd`/`Ctrl`+`Z` 한 번으로 둘 다 되돌아갑니다.

**어떻게 — 복사와 붙여넣기**

- `Cmd`/`Ctrl`+`C` — 컬럼이 선택돼 있으면 그 컬럼만 클립보드에 넣습니다. 아니면 선택한 테이블을 모두 컬럼·인덱스와 함께 클립보드에 넣습니다.
- `Cmd`/`Ctrl`+`V` — 클립보드에 컬럼이 있으면 **테이블이 정확히 하나 선택돼 있을 때만** 그 테이블의 끝(순서상 마지막)에 붙습니다. 클립보드에 테이블이 있으면 캔버스에 붙습니다. 테이블마다 복사할 때의 원래 위치에서 오른쪽 아래로 조금 비켜 놓이고, 붙여넣은 테이블이 모두 바로 선택됩니다.
- 이 앱이 만들지 않은 클립보드 내용(다른 곳에서 복사한 일반 텍스트 등)을 붙여넣으면 조용히 무시합니다.

**어떻게 — 다른 프로젝트로** — 다른 탭과 다른 프로젝트에도 붙여넣을 수 있습니다. 컬럼의 도메인은 대상 프로젝트에 같은 이름의 도메인이 있으면 다시 연결되고, 없으면 **없음**이 됩니다. 그래도 타입 칸의 문자열 자체는 복사한 그대로입니다. 커스텀 항목 값도 마찬가지로 **같은 이름의 항목에만** 옮겨 가고, 같은 이름의 항목이 없으면 버려집니다.

**제약**

- **이름 충돌은 자동으로 풉니다.** 논리명이 겹치면 `_사본` 이 붙고, 그래도 겹치면 `_사본2`, `_사본3`… 순서입니다. 물리명은 `_COPY`, `_COPY2`… 순서입니다. 테이블 물리명, 컬럼 물리명, 인덱스 이름이 모두 같은 규칙을 따릅니다.
- **붙여넣기는 그룹 소속을 옮기지 않습니다.** 붙여넣은 테이블은 늘 미분류로 들어갑니다.
- **관계는 복사되지 않습니다.** 관계에는 상대 테이블이 필요하므로, FK 로 쓰이던 컬럼은 붙여넣으면 일반 컬럼이 됩니다. 필요하면 붙여넣은 뒤 캔버스의 핸들로 관계를 다시 그리세요(→ [6절](#6-관계)).
- **컬럼만 붙여넣으면 PK 가 옮겨 가지 않습니다.** 붙여넣기 한 번으로 대상 테이블의 기본 키가 조용히 바뀌지 않도록 `PK` 체크가 꺼진 채로 들어옵니다. 테이블 통째로 붙여넣으면 새 테이블이므로 PK 표시가 유지됩니다.

**단축키**

| 단축키 | 동작 |
|---|---|
| `Cmd`/`Ctrl` + `C` | 복사 |
| `Cmd`/`Ctrl` + `X` | 잘라내기(복사 + 삭제) |
| `Cmd`/`Ctrl` + `V` | 붙여넣기 |
| `Delete` / `Backspace` | 삭제 |

동작하지 않는 조건은 셋입니다.

- **커서가 입력란에 있으면**(`input`, `textarea`, `select`, 포커스된 편집 가능 영역) 모두 브라우저 기본 동작에 양보합니다.
- **다이얼로그가 하나라도 열려 있으면** 다이얼로그 뒤의 캔버스 선택을 실수로 지우지 않도록 모두 동작하지 않습니다.
- **읽기 전용 권한에서는** `Cmd`/`Ctrl`+`C` 만 동작하고 `X`, `V`, `Delete`/`Backspace` 는 무시됩니다.

**잘라내기와 삭제는 한꺼번에 많이 지워도 실행 취소 한 번입니다.** 선택한 테이블과 컬럼이 모두 편집 하나로 나가므로 `Cmd`/`Ctrl`+`Z` 한 번(→ [4절](#4-에디터-기본))이 지운 것을 모두 되살립니다. 하단 바의 **삭제** 버튼도 같습니다. 선택한 테이블이 모두 편집 하나로 지워집니다.

**메모와 관계선** — 같은 단축키가 메모(→ [7절](#7-인덱스와-메모))와 관계선(→ [6절](#6-관계))에도 동작합니다. **캔버스에서 메모나 관계선을 눌러 선택한 뒤** `C`, `X`, `Delete`/`Backspace` 를 누르세요.

| 선택한 항목 | `C` 복사 | `X` 잘라내기 | `Delete`/`Backspace` 삭제 |
|---|---|---|---|
| 메모 | O | O | O |
| 관계선 | — | — | O |

- **붙여넣기(`V`)는 무엇이 선택됐는지와 무관하므로** 위 표에 없습니다. 클립보드에 메모가 있으면 메모가, 테이블이 있으면 테이블이 붙습니다(무엇이 선택돼 있든). 컬럼만 예외로 「테이블이 정확히 하나 선택됨」이 필요합니다.
- **붙여넣은 메모**는 복사할 때의 원래 위치에서 오른쪽 아래로 조금 비켜 놓이고, 바로 선택됩니다(테이블과 같은 규칙). 다른 탭과 다른 프로젝트에도 붙여넣을 수 있습니다.
- **그룹 뷰에서는 메모를 붙여넣을 수 없습니다**(조용히 무시됩니다). 그룹 뷰에는 메모가 아예 보이지 않습니다. 그룹 뷰에서 하단 바의 **메모** 버튼이 잠기는 것과 같은 이유로, 붙여넣었는데 보이지 않는 상태를 피하기 위해서입니다. 전체 뷰로 돌아가 붙여넣으세요.
- **관계선은 복사되지 않습니다.** 관계는 부모·자식 테이블과 그 컬럼 쌍에 기대므로, 붙여넣을 때 어느 테이블에 붙일지 정할 방법이 없습니다. 지울 수만 있습니다.
- **관계선을 지워도 자식 테이블의 FK 컬럼은 남습니다.** 선만 사라지고 컬럼은 일반 컬럼으로 남습니다. 컬럼까지 없애려면 따로 지우세요. 오른쪽 패널의 **관계 삭제** 버튼과 완전히 같습니다.
- 메모와 관계선은 한 번에 하나만 선택할 수 있으므로 **삭제 확인 다이얼로그를 거치지 않습니다**(그 확인은 테이블을 둘 이상 선택했을 때만 나옵니다). 실수로 지웠으면 `Cmd`/`Ctrl`+`Z` 로 되돌리세요.
- 메모를 다른 앱(메모장, 이슈 트래커 등)에 붙여넣으면 사람이 읽을 글이 아니라 이 앱이 쓰는 JSON 문자열이 들어갑니다. 그 형식은 앱 안에서 메모를 복제하려고 있는 것이기 때문입니다.
