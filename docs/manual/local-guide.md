# ERDD 로컬 모드 매뉴얼

**서버도 계정도 데이터베이스도 없이**, 저장소 안의 YAML 파일만으로 ERD 를 그리는 방법을 처음부터
끝까지 담았다. `erdd serve` 한 줄이면 브라우저에 **서버 모드와 똑같은 웹 에디터**가 뜨고, 화면에서
바꾼 것이 그대로 `erdd/` 파일이 된다. 이력은 서버가 아니라 **git 커밋**이 남긴다.

**이 문서 하나로 끝난다.** 서버 설치·운영([install.md](install.md))은 읽을 필요가 없고, 화면 조작의
세부는 [사용 매뉴얼](user-guide.md), 명령 하나하나의 레퍼런스는 [CLI 매뉴얼](cli-guide.md)에서 필요할
때만 펼쳐 보면 된다.

**목차** — [1. 이 문서를 읽는 사람](#1-이-문서를-읽는-사람) · [2. 준비](#2-준비) · [3. 시작하기](#3-시작하기) · [4. 브라우저에서 되는 것과 없는 것](#4-브라우저에서-되는-것과-없는-것) · [5. 파일과 git](#5-파일과-git) · [6. 스냅샷](#6-스냅샷) · [7. 서버와 오가기](#7-서버와-오가기) · [8. 문제 해결](#8-문제-해결) · [부록: 검증 상태](#부록-검증-상태)

## 1. 이 문서를 읽는 사람

**로컬 모드가 맞는 경우** — 혼자 설계한다. 붙을 ERDD 서버가 없거나 세우고 싶지 않다. 스키마를 코드
저장소 안에 두고 git 으로 관리하고 싶다. 팀과의 공유는 PR 로 충분하다.

**서버 모드가 필요한 경우** — 여러 사람이 같은 프로젝트를 **동시에** 편집한다. 계정·권한·조직이
필요하다. 누가 언제 무엇을 바꿨는지 서버가 남겨야 한다. 조직 공용 리소스(표준 도메인·단어)를 여러
프로젝트가 나눠 쓴다. → [install.md](install.md)

| | **로컬 모드** | 서버 모드 |
|---|---|---|
| 진실 원천 | `erdd/` 파일 | 서버 DB |
| 여는 법 | `erdd serve` | 서버를 설치해 띄운다 |
| 필요한 것 | Node 22 + `@erdd/cli`(npm 에서 설치) | 그 위에 PostgreSQL·배포·계정 |
| 계정·로그인 | **없다** — 열면 바로 에디터다 | 있다 |
| 편집 이력 | **git 커밋** | 서버 Revision(+ git) |
| 파일에 반영 | **「저장」(`Cmd+S`)을 눌러야** 한다 | 즉시(서버 DB) |
| 동시 편집 | 없다 — 1인 전제다 | 실시간 |
| 배치 좌표·메모 | `erdd/layout.yaml`(커밋한다) | 서버 DB. 단, `erdd serve` 로 옮기면 그 좌표·메모는 `erdd/layout.yaml` 에 쌓인다(→ [7.1](#71-서버-프로젝트를-로컬-에디터로-열기)) |
| 스냅샷 | `erdd/snapshots/`(**커밋한다** — git 이력에 남는다) | 서버 DB |

**둘은 배타가 아니다.** 서버에 연결된 프로젝트를 `erdd serve` 로 열어 그림으로 다듬을 수 있고,
로컬로 시작한 프로젝트를 나중에 서버로 옮길 수도 있다 → [7절](#7-서버와-오가기).

## 2. 준비

### 2.1 필요한 것 — 준비 경로가 둘이다

**어느 쪽이든 결과는 같다.** `erdd serve` 로 여는 에디터도, 만들어지는 파일도 다르지 않다. 다른 것은
**무엇을 미리 갖춰야 하는가**뿐이다.

| | **[경로 A: npm 설치](#22-경로-a-npm-에서-설치한다-권장)** | [경로 B: 저장소 체크아웃](#23-경로-b-erdd-저장소-체크아웃--웹-번들을-한-번-빌드한다) |
|---|---|---|
| 언제 | **보통 이것이다** | npm 에 닿지 않거나(오프라인) ERDD 자체를 고칠 때 |
| Node.js | **22 이상**(패키지의 `engines` 가 강제한다) | **22 이상**(ERDD 저장소의 `.nvmrc` 도 `22`) |
| ERDD 저장소 체크아웃 | **필요 없다** | 필요하다 |
| `tsx` | 필요하다 (`pnpm add -D tsx`) — **`@erdd/cli` 가 대신 끌어오지 않는다** | 필요하다 |
| **웹 번들** | **필요 없다 — 패키지에 동봉돼 있다** | **직접 빌드한다** → [2.3](#23-경로-b-erdd-저장소-체크아웃--웹-번들을-한-번-빌드한다) |

DB 도, 도커도, 계정도 필요 없다. 둘 다 마찬가지다.

### 2.2 경로 A: npm 에서 설치한다 (권장)

스키마를 둘 **내 프로젝트** 안에서 한 줄이면 끝난다. 패키지는 **공개 npm** 에 있어 레지스트리 설정도
토큰도 필요 없다.

```bash
pnpm add -D @erdd/cli tsx
# npm 이면
npm install -D @erdd/cli tsx
```

- ⚠️ **`tsx` 는 빼면 안 된다.** 패키지에는 빌드 산출물이 아니라 원본 TypeScript 가 들어 있고,
  **`@erdd/cli` 가 `tsx` 를 대신 끌어오지 않는다** — 패키지 관리자가 무엇이든 내 프로젝트에 직접
  선언해야 한다. 빼도 `npx` 가 그때그때 받아 와 **도는 경우가 많지만** 그것은 네트워크·캐시에
  기대는 것이라 증상이 패키지 관리자마다 갈린다([8절](#8-문제-해결) 표) — 명시 선언이 유일하게
  보증된 경로다 (→ [CLI 매뉴얼 2.1](cli-guide.md#21-요구-사항)).
- **웹 번들 빌드가 필요 없다.** 에디터 화면이 패키지 안에 통째로 동봉돼 나오므로 [2.3](#23-경로-b-erdd-저장소-체크아웃--웹-번들을-한-번-빌드한다)
  은 이 경로에 해당하지 않는다. 설치본에는 저장소 배치가 존재할 수 없어 언제나 이 동봉본이 쓰인다.
- **이 매뉴얼도 설치본 안에 있다.** 패키지 루트의 `README.md` 와 함께 매뉴얼 네 편이
  `node_modules/@erdd/cli/docs/` 에 동봉된다 — 이 문서는 그중 `local-guide.md` 이고, 문서끼리의
  상대 링크도 그대로 살아 있다. ERDD 저장소를 클론하지 않아도 읽을 수 있다.

### 2.3 경로 B: ERDD 저장소 체크아웃 — 웹 번들을 한 번 빌드한다

⚠️ **이 절은 저장소 체크아웃으로 쓸 때만 해당한다.** npm 에서 설치했다면
([2.2](#22-경로-a-npm-에서-설치한다-권장)) 번들이 이미 패키지 안에 있으니 건너뛴다.

`erdd serve` 는 **미리 빌드된 웹 번들을 정적으로 내보낸다.** 갓 클론한 저장소에는 그 번들이 없으므로
한 번 만들어 둔다.

```bash
cd /path/to/ERDD
pnpm install
pnpm -C apps/web build      # → apps/web/dist 가 생긴다
```

⚠️ **빠뜨리면 「서버가 안 뜬다」가 아니라 「화면만 안 나온다」로 나타나 원인을 찾기 어렵다.**
`erdd serve` 는 평소와 똑같이 뜨고 터미널 출력도 같은데, 브라우저에는 에디터 대신 JSON 이 보인다.

```
{"message":"Route GET:/p/00000000-0000-7000-8000-000000000000 not found","error":"Not Found","statusCode":404}
```

ERDD 저장소를 `git pull` 로 갱신했다면 번들도 다시 빌드한다 — 옛 번들이 그대로 서빙된다.

**저장소에서는 방금 빌드한 `apps/web/dist` 가 언제나 이긴다.** 게시 준비로 `packages/cli/web` 에
복사본(`bundle:web`)을 만들어 둔 적이 있어도 `erdd serve` 는 계속 최신 빌드를 본다 — 화면이 안 바뀌면
그 복사본을 의심할 필요가 없다.

### 2.4 `erdd` 를 부를 수 있게 한다

**npm 에서 설치했다면**([2.2](#22-경로-a-npm-에서-설치한다-권장)) 이미 끝났다 —
`pnpm exec erdd …`(npm 이면 `npx erdd …`)로 부른다. 아래는 **저장소 체크아웃**([2.3](#23-경로-b-erdd-저장소-체크아웃--웹-번들을-한-번-빌드한다))
으로 쓸 때의 이야기다.

**가장 단순한 방법** — 셸 별칭을 하나 둔다.

```bash
# ~/.zshrc 등
alias erdd='npx tsx /path/to/ERDD/packages/cli/src/main.ts'
```

프로젝트에 체크아웃을 파일 의존성으로 링크하는 방법도 있다(`pnpm exec erdd …`). 그쪽의 주의
사항(`tsx` 를 함께 넣어야 하는 것, ERDD 체크아웃의 파일 권한이 바뀌는 것)은
[CLI 매뉴얼 2.4](cli-guide.md#24-방법-c-프로젝트에-의존성으로-링크) 에 있다.

⚠️ **명령은 언제나 「현재 디렉터리」를 프로젝트로 본다.** CLI 는 `erdd.config.yaml`·`erdd/`·`.erdd/`
를 전부 `process.cwd()` 에서 찾는다. ERDD 저장소 안에서 실행하면 엉뚱한 곳을 본다 — 스키마를 둘
**내 프로젝트 디렉터리**에서 실행한다.

**이 문서는 이후로 명령을 `erdd …` 로 적는다.** npm 에서 설치했다면 그 자리에 `pnpm exec erdd …`
(npm 이면 `npx erdd …`)를 넣어 읽으면 된다 — 옵션도 출력도 같다.

## 3. 시작하기

### 3.1 `erdd init --local` — 프로젝트를 만든다

```bash
$ cd /path/to/my-project
$ erdd init --local
로컬 전용 프로젝트를 만들었습니다. erdd serve로 여세요
```

**만들어지는 것은 딱 둘이다.**

| 파일 | 내용 |
|---|---|
| `erdd.config.yaml` | 방언·명명 규칙·테이블 옵션. `serverUrl`·`projectId` 는 `null` 이다 |
| `.gitignore` | `.erdd/` 한 줄이 추가된다(이미 있으면 건드리지 않는다) |

```yaml
serverUrl: null
projectId: null
dialects:
  - postgresql
namingRules:
  case: UPPER_SNAKE
  separator: _
  logicalSeparator: _
  maxLengthBytes: 30
  tablePhysicalTemplate: ""
  tableLogicalTemplate: ""
tableOptions:
  postgresql: ""
  mysql: ""
  oracle: ""
  mssql: ""
```

토큰도, 서버 왕복도, `erdd/` 디렉터리도 이 시점에는 없다(→ [3.3](#33-첫-저장이-erdd-를-만든다)).

**방언과 대소문자 규칙은 여기서 고른다.** 기본값이 위의 `postgresql` · `UPPER_SNAKE` 다.

| 옵션 | 기본값 | 값 |
|---|---|---|
| `--dialect` | `postgresql` | `postgresql` · `mysql` · `oracle` · `mssql` |
| `--case` | `UPPER_SNAKE` | `UPPER_SNAKE` · `lower_snake` |

```bash
$ erdd init --local --dialect mysql --case lower_snake
로컬 전용 프로젝트를 만들었습니다. erdd serve로 여세요

$ cat erdd.config.yaml
serverUrl: null
projectId: null
dialects:
  - mysql
namingRules:
  case: lower_snake
  separator: _
  logicalSeparator: _
  maxLengthBytes: 30
  tablePhysicalTemplate: ""
  tableLogicalTemplate: ""
```

**나머지 명명 규칙은 옵션이 없다** — `separator`·`logicalSeparator`·`maxLengthBytes`·이름 템플릿은
`erdd.config.yaml` 을 직접 고쳐 바꾼다(형식은 [CLI 매뉴얼 5.2](cli-guide.md#52-erddconfigyaml)).
잘못된 값을 주면 사용법 오류(`2`)로 멈춘다 —
`--case 값이 올바르지 않습니다: Camel — UPPER_SNAKE | lower_snake`.

⚠️ **이 둘은 `--local` 전용이다.** 서버에 연결하는 `erdd init` 에 함께 주면 사용법 오류(`2`)다 —
서버 프로젝트의 설정이 진실 원천이라 첫 `pull` 이 곧바로 덮어쓴다.

⚠️ **`--local` 은 `--yes` 로도 덮어쓰지 않는다.** `erdd.config.yaml` 이 이미 있으면
`erdd.config.yaml이 이미 있습니다. 지우고 다시 실행하세요` 로 멈춘다(종료 코드 `1`). 되물을 서버
프로젝트가 없어서, 덮어쓰면 공들여 맞춘 방언·명명 규칙을 조용히 잃기 때문이다.

### 3.2 `erdd serve` — 에디터를 연다

```bash
$ erdd serve
http://127.0.0.1:4300 에서 실행 중 (프로젝트: /path/to/my-project)
중지하려면 Ctrl+C
```

기본 브라우저가 자동으로 열린다(못 열면 `브라우저를 열지 못했습니다. 직접 … 을 여세요` 만 남기고
서버는 계속 돈다). 주소로 들어가면 곧바로 에디터다 — **로그인 화면은 없다.**

| 옵션 | |
|---|---|
| `--port <번호>` | 기본 `4300`. 이미 쓰이는 포트면 다음 포트를 자동으로 잡지 않고 **멈춘다**(종료 코드 `1`) |
| `--no-open` | 브라우저를 자동으로 열지 않는다 |

`serve` 는 `Ctrl+C` 까지 그 터미널을 붙잡는다. **여러 프로젝트를 동시에 열려면** 터미널을 따로
띄우고 포트를 달리 준다.

```bash
# 터미널 1
cd ~/work/shop  && erdd serve --port 4300
# 터미널 2
cd ~/work/admin && erdd serve --port 4301
```

**주소는 실행할 때마다 같다** — 로컬 전용 프로젝트의 id 는 고정값
(`00000000-0000-7000-8000-000000000000`)이라 북마크해도 된다. `/` 로 들어가면 그 프로젝트 화면으로
넘어간다(서버에 연결된 프로젝트를 열 때는 그쪽 id 가 쓰인다 → [7.1](#71-서버-프로젝트를-로컬-에디터로-열기)).

⚠️ **`127.0.0.1` 에만 바인딩되고 LAN 노출은 옵션으로도 열지 않는다.** 인증이 없는 서버이기 때문이다.
`Host` 헤더가 `127.0.0.1:<포트>`·`localhost:<포트>` 계열이 아니면 **403** 이다 — 사설 DNS 이름이나
리버스 프록시를 앞에 세워도 닿지 않는다. 바인딩만으로는 막지 못하는 **DNS 리바인딩**(악성 페이지가
당신의 브라우저를 통해 이 서버를 읽고 쓰는 것)을 함께 막는 장치다.

### 3.3 첫 **저장**이 `erdd/` 를 만든다

`init --local` 직후에는 `erdd/` 가 없다. 브라우저에서 테이블을 만들어도 아직 생기지 않는다 —
**「저장」(`Cmd+S`)을 눌러야** 그때 만들어진다(→ [4.4](#44-편집은-드래프트에-저장이-파일에)).
연 것만으로는 저장소에 아무 파일도 늘지 않는다.

```
erdd/
├─ tables/MBR.yaml        # 테이블 1개 = 파일 1개, 파일명 = 물리명
├─ groups.yaml
├─ words.yaml
├─ terms.yaml
├─ domains.yaml
├─ custom-fields.yaml
└─ layout.yaml            # 배치 좌표·메모
```

이미 `erdd/` 가 있는 저장소를 클론한 경우(팀원의 작업을 받은 경우)라면 `erdd serve` 가 그 파일을
그대로 읽어 연다. `init` 을 다시 돌릴 필요는 없다 — `erdd.config.yaml` 도 함께 커밋돼 있기 때문이다.

### 3.4 끝내기

**`Ctrl+C`** 로 끝낸다. 저장하지 않은 편집이 있으면 터미널에 이렇게 남는다.

```
미저장 편집이 있습니다 — 다음 erdd serve 에서 이어집니다
```

**잃지 않는다.** 미저장 편집은 `.erdd/draft.json` 에 있고 다음 `serve` 가 그대로 얹어 연다
(→ [4.4](#44-편집은-드래프트에-저장이-파일에)). 파일에 남기려면 끝내기 전에 저장한다.

## 4. 브라우저에서 되는 것과 없는 것

### 4.1 화면은 둘뿐이다

| 경로 | 화면 | |
|---|---|---|
| `/p/<id>` | ERD 에디터 | 캔버스·트리·편집 패널 — 서버 모드와 같다 |
| `/p/<id>/settings` | 프로젝트 설정 | 에디터 헤더의 「설정」 → [4.3](#43-프로젝트-설정) |

로그인·홈·조직·관리자 화면은 아예 없다. 헤더 왼쪽 로고를 눌러도 홈으로 가지 않고 **에디터로
되돌아온다** — 로컬 모드에는 갈 홈이 없기 때문이다.

### 4.2 사용 매뉴얼의 어느 장이 해당하나

다만 스무 개 장 중 여섯 개는 로컬 모드에 아예 해당하지 않고, 두 개는 내용이 다르다.

| 사용 매뉴얼 | 로컬 모드에서 |

하나가 리비전 하나고, `git log`·`git diff`·PR 리뷰가 이력 화면보다 낫다.

### 4.3 프로젝트 설정

에디터 헤더의 **「설정」** 을 누른다.

| 항목 | 로컬 모드에서 |
|---|---|
| 프로젝트 이름 | **「로컬 프로젝트」로 고정.** 바꿀 수 없다 — `erdd.config.yaml` 에 이름을 담을 자리가 없다 |
| 명명 규칙 | **여기서 고친다.** 저장하면 `erdd.config.yaml` 에 되쓰인다 |
| 테이블 옵션 | **여기서 고친다.** 방언 4칸이 그대로 보이고, 저장하면 `erdd.config.yaml` 의 `tableOptions` 에 되쓰인다. 서버 모드와 화면·동작이 같다 |
| 방언(`dialects`) | 화면에 편집 자리가 없다(서버 모드도 같다 — 프로젝트를 만들 때 정하는 값이다). `erdd.config.yaml` 의 `dialects` 를 직접 고치면 파일 감시가 반영한다 |
| 프로젝트 멤버 | 없다 |

### 4.4 편집은 드래프트에, 저장이 파일에

**화면 → 파일은 「저장」을 거친다.** 편집기와 같다 — 고치는 동안에는 파일이 그대로이고,
**`Cmd+S`**(또는 헤더의 「저장」)를 눌러야 `erdd/` 에 쓰인다.

| 헤더 | |
|---|---|
| **● 미저장** | 저장할 것이 남았다. 편집을 되돌려 원래대로 돌아오면 저절로 사라진다 |
| **저장** | 파일에 쓴다. 쓸 것이 없으면 비활성이다 |
| **⌄ → 변경 버리기** | 편집을 버리고 파일 내용으로 되돌린다(확인을 한 번 받는다) |

**미저장 편집은 잃지 않는다.** 저장하지 않은 것은 `.erdd/draft.json` 에 자동으로 기록되므로,
브라우저를 닫아도 `Ctrl+C` 로 끝내도 **다음 `erdd serve` 에서 그대로 이어진다.** 탭을 닫을 때
경고가 뜨지 않는 것은 그래서다 — 잃을 것이 없다.

**왜 이렇게 바뀌었나** — 버릴 시도와 중간 상태까지 전부 파일이 되면 `git diff` 가 지저분해진다.
드래프트는 `.erdd/`(gitignore) 안에 있으므로 **커밋 후보에 뜨지 않는다.**

**파일 → 화면** — 터미널·에디터·AI 에이전트·`git pull` 이 `erdd/` 나 `erdd.config.yaml` 을 고치면
**새로고침 없이** 화면이 따라온다. 브랜치를 갈아타도 마찬가지다.

```bash
# 다른 터미널에서
$EDITOR erdd/tables/MBR.yaml     # 저장하는 순간 브라우저가 바뀐다
git checkout feature/orders      # 브랜치의 스키마로 화면이 갈아탄다
```

⚠️ **미저장 편집이 있는데 파일이 밖에서 바뀌면** 화면을 자동으로 갈아치우지 않고 배너로 묻는다.

```
파일이 밖에서 바뀌었습니다. 내 편집을 유지하면 저장할 때 화면의 내용이 파일을 덮어씁니다.
                                            [내 편집 유지]  [파일 다시 읽기]
```

- **내 편집 유지** — 배너를 닫고 계속 편집한다. 이후 「저장」은 **화면 그대로** 파일을 만든다 —
  밖에서 새로 생긴 파일이 있으면 **지워진다.** 자동으로 합쳐 주지 않는다.
- **파일 다시 읽기** — 미저장 편집을 버리고 파일 내용으로 되돌린다(확인을 한 번 받는다).

⚠️ **저장은 못 본 변경을 덮지 않는다.** 배너가 아직 뜨지 않았더라도 「저장」은 누른 순간 파일을
다시 읽어 확인하고, 달라져 있으면 쓰지 않고 위 배너를 띄운다.

### 4.5 파일이 깨지면 편집이 잠긴다

`erdd/` 안의 YAML 이 파싱·스키마·무결성 검사에서 걸리면 마지막 정상 모델을 화면에 그대로 둔 채
편집만 잠긴다.

- 상단에 빨간 배너: `파일을 읽을 수 없어 편집이 잠겼습니다 — <경로>: <사유>`
- 하단 바가 「읽기 전용」으로 바뀌고 「파일」 메뉴에서 가져오기 항목이 사라진다
- **파일을 고치면 자동으로 풀린다.** 서버를 다시 띄울 필요가 없다

⚠️ **이 잠금은 데이터를 지키는 장치다.** 편집을 계속 받아 주면 성한 화면 상태가 깨진 파일을 통째로
덮어써, 손으로 고치던 내용이 사라진다. **`layout.yaml` 도 예외가 아니다** — 거기에는 좌표만이 아니라
**메모 본문**이 들어 있어서, 깨진 채로 편집을 허용하면 다음 저장이 `notes: []` 로 메모를 지운다. **파일이 깨진 동안에는 「저장」도 막힌다.**

명명 경고나 필수 커스텀 항목 누락은 오류가 아니다 — 잠기지 않고 「모델 검사」에 뜬다.

### 4.6 탭을 여러 개 열면

⚠️ **브라우저에서 한 편집은 그것을 낸 탭에만 보인다.** 파일이 **밖에서** 바뀌는 것은 모든 탭이 함께
받지만, 자기 편집을 되돌려 받으면 드래그하는 탭이 계속 튀기 때문에 걸러 낸다. 다른 탭은 다음 외부
변경 때 맞춰지고, 그 전에 맞추려면 새로고침한다. **로컬 모드는 한 사람이 한 화면에서 쓰는 것을
전제한다.**

다만 **「미저장」 표시는 모든 탭이 함께 받는다** — 드래프트는 서버가 하나로 들고 있어서, 어느 탭에서
저장하든 나머지 탭의 표시도 함께 내려간다.

## 5. 파일과 git

### 5.1 무엇이 어디에 있나

```
erdd.config.yaml            # 방언·명명 규칙·테이블 옵션 (serverUrl·projectId 는 null)  ← 커밋한다
erdd/                                                                        ← 커밋한다
├─ tables/*.yaml            # 테이블 1개 = 파일 1개, 파일명 = 물리명
├─ groups.yaml              # 테이블 그룹
├─ words.yaml               # 단어 사전
├─ terms.yaml               # 용어 사전
├─ domains.yaml             # 도메인(타입 표준)
├─ custom-fields.yaml       # 커스텀 항목 정의
├─ layout.yaml              # 배치 좌표·메모 → 5.3
├─ changes/               # 변경 기록 → 5.6
└─ snapshots/               # 스냅샷 → 6절
   ├─ index.yaml            #   목록(이름·설명·시각) — git diff 로 읽힌다
   └─ <id>.json.gz          #   스냅샷 1개 = 파일 1개(gzip)
.erdd/                                                                       ← 커밋하지 않는다
└─ draft.json               # 저장하지 않은 편집 → 4.4
```

파일 포맷의 상세(테이블 파일의 각 키, 사전 파일의 형태, `id` 를 다루는 법)는
[CLI 매뉴얼 5절](cli-guide.md#5-파일-구조와-포맷) 에 있다.

### 5.2 커밋

```bash
git add erdd erdd.config.yaml
git commit -m "스키마: 회원 등급 컬럼 추가"
```

- ⚠️ **커밋 전에 「저장」했는지 확인한다.** 미저장 편집은 `erdd/` 에 없으므로 커밋되지 않는다.
  터미널에서도 확인할 수 있다 — `erdd status` 가 「저장하지 않은 편집이 있습니다」를 알린다.
- **`erdd/snapshots/` 도 커밋 대상이다.** 스냅샷이 팀과 공유되고 이력에 남는다(→ [6절](#6-스냅샷)).
- **`.erdd/` 는 커밋하지 않는다.** `init --local` 이 `.gitignore` 에 한 줄을 넣어 둔다.
- **`erdd.config.yaml` 을 함께 커밋한다.** 팀원이 클론해 `erdd serve` 만 하면 같은 방언·명명 규칙·테이블 옵션으로
  같은 그림을 본다 — `init` 을 다시 돌릴 필요가 없다.
- 이 커밋이 로컬 모드의 **이력 전부**다. 되돌리기는 `git revert`, 비교는 `git diff` 다.

### 5.3 `erdd/layout.yaml` — 배치 좌표와 메모

```yaml
tables:
  - id: 01a01f7c-2227-70a0-ab77-d25ec5315f11
    name: MBR
    position:
      x: 431
      y: 362.5
    groupPosition: null
notes:
  - id: 01a01f80-f89f-7741-b076-c24985eeed41
    content: 메모
    position:
      x: 547
      y: 394
    color: "#FDF6E3"
```

- **테이블을 옮기면 이 파일만 바뀐다** — `erdd/tables/*.yaml` 은 한 글자도 안 바뀐다. 옮기기만 해도
  스키마 diff 가 뜨는 것을 막으려고 파일을 갈랐다.
- **커밋 대상이다.** 배치는 팀이 함께 보는 그림의 일부다.
- **식별은 `id` 다.** 물리명을 바꿔도 배치가 따라온다. 지운 테이블의 잔재는 조용히 버려진다.
- **없으면 물리명 오름차순 격자로 떨어진다.** 항목 하나가 망가진 것은 **그 항목만** 걸러지고 나머지는
  그대로 열린다(파일 전체가 깨진 것은 다르다 → [4.5](#45-파일이-깨지면-편집이-잠긴다)).

### 5.4 서버 없이 검사하기 — `erdd validate`

`erdd/` 파일만 보고 참조 무결성과 명명 규칙을 검사한다. 로컬 모드에서도 그대로 돈다.

```bash
erdd validate            # 정합성·명명 경고
erdd validate --strict   # 경고도 실패로 본다(종료 코드 1) — 커밋 훅·CI 용
```

`--json` 출력 규약과 CI 예시는 [CLI 매뉴얼 10절](cli-guide.md#10-자동화와-ci) 에 있다.

⚠️ **`pull`·`push`·`diff` 는 로컬 전용 프로젝트에서 멈춘다**(종료 코드 `1`). 서버가 없으니 당연하다.

```
오류: erdd.config.yaml에 연결 설정이 없습니다. erdd init으로 서버에 연결하거나 erdd serve로 로컬에서 여세요
```

### 5.5 DDL·DBML 로 주고받기 — `erdd export` · `erdd import`

둘 다 **서버를 부르지 않으므로 로컬 모드에서 그대로 돈다.**

```bash
erdd export > schema.sql             # 파이프에 안전하다 — 경고는 stderr 로 나간다
erdd export --format dbml -o s.dbml
erdd import legacy.sql --dry-run     # 먼저 계획만 본다
erdd import legacy.sql --yes         # 반영 — 머지다(있는 테이블은 건너뛴다)
```

기존 DB 덤프로 프로젝트를 시작할 때가 `import` 의 자리다. 반영 뒤에는 `erdd validate` 로 사전
(`words.yaml`·`terms.yaml`)을 정리하고 **git 커밋**한다 — 로컬 모드에서는 그것이 이력 전부다.

옵션·판별 순서·`--json` 모양은 [CLI 매뉴얼 6.9·6.10](cli-guide.md#69-erdd-export) 에 있다.

### 5.6 변경 기록 — 마이그레이션을 쓰기 위한 수정 내역

**무엇** — 테이블·컬럼·관계·인덱스를 고친 내역을 DB·도구에 묶이지 않는 텍스트로 `erdd/changes/` 에
남긴다. **ERDD 는 SQL 을 만들지 않는다.** 각 프로젝트가 이 기록을 보고 자기 도구(Flyway·Liquibase·
ORM 마이그레이션 등)와 자기 DB 문법으로 마이그레이션을 쓴다. 기록 하나가 마이그레이션 하나다.

**어디서** — 에디터 헤더의 **「버전」 → 「변경 기록」** 탭, 또는 터미널의 `erdd changes`.

**어떻게**

1. 편집하고 **「저장」** 한다(미저장 편집이 있으면 기록을 만들 수 없다).
2. 「변경 기록」 탭 위쪽의 **「미기록 변경」** 에 만들어질 기록이 미리 보인다.
3. 「이름」(예: 「회원 등급 추가」)을 넣고 **「변경 기록 만들기」**. `erdd/changes/<시각>_<이름>.erddc`
   가 생긴다.
4. 기록 파일을 커밋하고, 그 파일을 보고 마이그레이션을 쓴다. 마이그레이션 파일 이름이나 주석에 기록
   파일명을 적어 두면 어디까지 옮겼는지 알기 쉽다.

터미널에서는:

```bash
erdd changes                       # 미기록 변경 미리보기
erdd changes new "회원 등급 추가"   # 기록 만들기
erdd changes --check               # 미기록 변경이 있으면 종료 코드 1 (CI)
```

기록은 이렇게 생겼다 — 위에서 아래로 옮기면 SQL 의존성이 맞는 순서다. 줄 끝 `@…` 는 ERDD 가 대상을
찾는 꼬리표라 옮기지 않는다.

```
alter table MBR {                                               @01a0…
  rename column TEL_NO -> MBL_TEL_NO                            @01a0…
  add column GRD_CD VARCHAR(10) [null, after: MBR_NM]           @01a0…
  modify column MBR_NM {                                        @01a0…
    type: VARCHAR(50) -> VARCHAR(100)
    nullable: yes -> no
  }
}
```

문법 전체와 규칙은 [변경 기록 문법](../guides/changeset-format.md) 에 있다.

**이미 운영 중인 DB 에 도입할 때** — 첫 기록은 스키마 전체의 `create` 가 된다. 터미널에서
`erdd changes new "운영 DB" --baseline` 으로 만들면 「이미 DB 에 있다, 마이그레이션 불필요」 표시
(`baseline: true`)가 붙는다.

**브랜치** — 두 브랜치가 각자 기록을 만들어도 파일명이 달라 git 충돌 없이 합쳐진다. 합친 뒤
`erdd changes` 가 「미기록 변경 없음」이면 정상이다. 두 기록이 같은 컬럼의 같은 속성을 다르게 바꿨으면
「⚠️ 기록 간 경합」 경고가 뜬다 — 각 브랜치의 마이그레이션이 다른 전제로 쓰였다는 뜻이니 확인하고,
남은 차이는 새 기록으로 만든다. 두 브랜치가 같은 것을 지웠거나, 한쪽이 바꾼 이름을 다른 쪽이 참조해도
같은 ⚠️ 경고가 뜨고 기록은 멈추지 않는다 — 남은 차이는 역시 새 기록으로 정리한다.

⚠️ **기록 파일은 고치지 않는다.** 잘못 만들었고 아직 공유하지 않았다면 파일을 지우고 다시 만든다 — 이유는
[변경 기록 문법](../guides/changeset-format.md) 「기록 파일은 고치지 않는다」.

**기록을 만들 수 없는 경우** — 미저장 편집이 있을 때, 기록할 변경이 없을 때가 가장 흔하다. 전체 목록은
[변경 기록 문법](../guides/changeset-format.md) 「기록을 만들 수 없는 경우」.

## 6. 스냅샷

**무엇** — 지금 모델 전체에 이름을 붙여 통째로 담아 두고, 나중에 그 시점으로 되돌리거나 지금과
비교한다.

**어디서** — 에디터 헤더의 **「버전」** → 「스냅샷」·「비교」 탭. (서버 모드에 있는 「이력」 탭은
로컬 모드에 없다.)

**어떻게** — 「이름」을 넣고 「스냅샷 만들기」. 목록 항목을 누르면 테이블 개수와 앞 5개 물리명이
펼쳐진다. 「복원」은 확인 후 그 시점으로 되돌리고, 「삭제」도 확인을 한 번 받는다. 「비교」 탭에서
「기준」·「비교」로 스냅샷과 「현재」를 골라 차이를 보고 「변경분 정의서」 엑셀로 내려받을 수 있다.
화면 조작의 세부는 [사용 매뉴얼 14절](user-guide.md#14-버전이력스냅샷비교) 과 같다.

⚠️ **미저장 편집이 있으면 스냅샷을 만들 수 없다** — 「저장하지 않은 편집이 있습니다. 먼저 저장한 뒤
스냅샷을 만드세요」로 거절된다. 스냅샷은 **저장된 상태**에 이름을 붙이는 것이라, 파일 어디에도 없는
상태를 가리키는 버전이 생기면 안 된다.

⚠️ **「복원」은 곧바로 파일을 바꾸지 않는다.** 복원하면 화면이 그 시점으로 돌아가고 「미저장」이
되며, **「저장」을 눌러야** `erdd/` 가 그 내용으로 다시 쓰인다(→ [4.4](#44-편집은-드래프트에-저장이-파일에)).

**어디에 담기나** — `erdd/snapshots/` 안에 **스냅샷 하나당 파일 하나**(gzip)로 담긴다.
목록에 보이는 이름·설명·시각은 같은 디렉터리의 평문 `index.yaml` 에 있다.

```
erdd/snapshots/
├─ index.yaml                              # 이름·설명·시각·리비전
├─ 018f6b0e-1111-7000-8000-….json.gz       # 모델 전체 사본(압축)
└─ 018f6b12-2222-7000-8000-….json.gz
```

✅ **스냅샷은 git 에 담긴다.** `erdd/` 아래라 커밋 대상이고, 팀원에게도 다른 컴퓨터에도 함께 간다.
파일 하나당 스냅샷 하나라 새로 만들어도 **그 파일 하나만 커밋에 추가된다.** 무엇이 늘었는지는
`index.yaml` 의 diff 로 읽힌다.

```bash
git add erdd/snapshots
git commit -m "스냅샷: 회원 도메인 정리 전"
```

- **파일명은 id 뿐이다.** 스냅샷 이름을 파일명에 넣지 않는다 — 한글 이름은 macOS 와 git 이 서로
  다르게 정규화해 플랫폼마다 다른 파일로 보인다. id 는 시간순으로 정렬되므로 `ls` 가 곧 시간순이다.
- **복원은 실행 취소로 되돌릴 수 없다** — 복원 직후 실행 취소 이력이 비워진다. 되돌리려면 다른
  스냅샷으로 복원하거나(저장하지 않았다면 「변경 버리기」로 충분하다) git 에서 `erdd/` 를 되살린다.
- `erdd/snapshots/` 를 손으로 고치지 않는다. 내용이 깨지면 그 스냅샷은 「스냅샷이 손상됐습니다」로
  거절된다(없다고 하지 않고 깨졌다고 알리는 것이 의도다).
- **`index.yaml` 이 깨져도 목록·복원은 그대로 된다** — 이름만 임시로 `(이름 없음) …` 으로 보인다.
  그 상태에서 스냅샷을 새로 만들거나 지우면 깨진 파일을 **덮어쓰지 않고**
  `index.corrupt-<시각>.yaml` 로 옮겨 둔다. 거기에 옛 이름이 그대로 있으니 손으로 되살릴 수 있다.
  (머지 충돌 마커가 남은 `index.yaml` 이 이 상태의 가장 흔한 원인이다.)

**옛 스냅샷은 자동으로 옮겨진다.** 전에 쓰던 `.erdd/snapshots.json` 이 있으면 `erdd serve` 가 처음
뜰 때 한 번 새 위치로 옮기고 이렇게 알린다.

```
스냅샷 3개를 erdd/snapshots/ 로 옮겼습니다 — 이제 커밋 대상입니다. git add erdd/snapshots
```

옛 파일은 지우지 않고 `.erdd/snapshots.json.migrated` 로 이름만 바뀐다. 내용이 깨진 항목은 **옮기지
않고** 그 이름을 함께 알린다 — 손상을 커밋 대상으로 승격시키지 않기 위해서다.

## 7. 서버와 오가기

로컬 모드와 서버 연결은 **배타가 아니다.** `erdd.config.yaml` 에 `serverUrl`·`projectId` 가 있으면
연결형, 없으면 로컬 전용일 뿐, `erdd serve` 는 **어느 쪽에서도 뜨고 언제나 파일만 본다.**

### 7.1 서버 프로젝트를 로컬 에디터로 열기

받아 온 스키마를 **그림으로** 확인하고 다듬은 뒤 되미는 흐름이다. 서버에 닿지 않는 곳(비행기·서버가 있는 네트워크 밖)
에서도 편집할 수 있다.

```bash
erdd pull                      # 서버 스키마를 파일로 받는다
erdd serve                     # 브라우저에서 그림으로 보고 고친다 (Ctrl+C 로 종료)
erdd validate                  # 서버 없이 검사
erdd diff                      # 올릴 변경·내려올 변경·충돌 미리보기
erdd push -m "회원 등급 컬럼 추가"
```

- 열리는 프로젝트는 config 의 `projectId` 다 — 주소가 `/p/<서버의 프로젝트 id>` 가 된다.
- **`serve` 를 띄워 둔 채 다른 터미널에서 `erdd pull` 을 돌려도 된다.** 파일 감시가 잡아 화면이
  따라온다.
- ⚠️ **`pull` 은 로컬 변경을 덮어쓴다.** 손댄 파일이 있으면 목록을 보여주고 `계속할까요?` 로 한 번
  묻는다 — 브라우저에서 편집하던 중이라면 여기서 멈추고 먼저 `push` 한다.
- ⚠️ **좌표와 메모는 서버로 올라가지 않는다.** `erdd/layout.yaml` 은 `push` 가 보내지도, `pull` 이
  덮어쓰지도 않는다. 서버 모드의 좌표·메모는 서버 DB 에 따로 있고 둘은 서로 모른다.

### 7.2 로컬로 시작한 프로젝트를 서버로 옮기기

⚠️ **전용 명령이 없고, `erdd.config.yaml` 에 연결 설정을 적는 것만으로는 되지 않는다.** `push` 는
「마지막 pull 시점」(`.erdd/base.json`)을 기준선으로 요구하는데 로컬 전용 프로젝트에는 그것이 없어
`기준 시점이 없습니다. 먼저 erdd pull을 실행하세요`(종료 코드 `1`)로 멈춘다.

**순서.** 되살리기 위해 **먼저 커밋해 두는 것이 핵심이다.**

```bash
git add erdd erdd.config.yaml && git commit -m "스키마: 서버 이관 전 상태"

erdd init --server https://erdd.example.com --token "$ERDD_TOKEN" --project <새-프로젝트-id> --yes
erdd pull                        # ⚠️ 비어 있는 서버 상태가 erdd/ 를 덮는다
git checkout HEAD -- erdd        # 방금 커밋해 둔 내 스키마를 되얹는다
erdd diff                        # 전부 「추가」로 보이는 것이 정상이다
erdd push -m "로컬에서 설계한 스키마 이관"
```

- 서버에 **빈 프로젝트를 먼저 만들어** 그 id 를 `--project` 로 준다(웹에서 만든다).
- `--yes` 는 「`erdd.config.yaml` 이 이미 있습니다. 덮어쓸까요?」를 건너뛴다. 로컬 전용 config 를
  서버 연결 config 로 바꾸는 것이 여기서는 의도한 동작이다(`--local` 과 달리 이쪽은 덮어써진다).
- `init` 이 `erdd.config.yaml` 을 서버 값(방언·명명 규칙)으로 덮어쓴다. 로컬에서 맞춰 둔 규칙과
  다르면 웹의 프로젝트 설정에서 맞춘다.
- `layout.yaml` 은 올라가지 않는다. 파일은 그대로 두면 되고, 이후로도 `erdd serve` 로 열 때만 쓰인다.
- 서버 쪽 배치는 웹 에디터에서 「자동 정렬」로 새로 잡는다.

## 8. 문제 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| `erdd serve` 는 떴는데 브라우저에 `{"message":"Route GET:/p/… not found"…}` 만 나온다 | 웹 번들(`apps/web/dist`)이 없다. **저장소 체크아웃에서 쓸 때만 나는 증상이다** — 레지스트리 설치본에는 번들이 동봉돼 있다 | ERDD 체크아웃에서 `pnpm -C apps/web build` (→ [2.3](#23-경로-b-erdd-저장소-체크아웃--웹-번들을-한-번-빌드한다)) |
| `sh: tsx: command not found` (종료 코드 127) | 프로젝트에 `tsx` 가 없다. **빠뜨렸을 때의 증상이 패키지 관리자마다 다르다** — pnpm 은 `npx` 가 그때그때 받아 와 **대개는 돌지만** 네트워크가 없으면 죽고, npm 평면 배치는 캐시가 없으면 `ENOTCACHED` 로 죽는다 | `pnpm add -D tsx` (→ [2.1](#21-필요한-것--준비-경로가-둘이다)) |
| `pnpm exec erdd …` 가 `ERR_PNPM_IGNORED_BUILDS`(`esbuild`)로 죽는다 | **pnpm 11 의 동작이다.** `pnpm exec` 이 먼저 의존성 상태를 확인하며 `pnpm install` 을 돌리는데, 빌드 스크립트가 승인되지 않은 패키지(`tsx` 가 끌어오는 `esbuild`)가 있으면 그 install 이 실패한다. `@erdd/cli` 와 무관하고 pnpm 10 에서는 나지 않는다 | pnpm 이 안내하는 `pnpm approve-builds` 로 `esbuild` 를 승인한다. 그 전에도 **`./node_modules/.bin/erdd` 를 직접 부르면 그대로 동작한다**(실측) |
| `erdd.config.yaml이 없습니다. erdd init을 먼저 실행하세요` | 프로젝트 루트가 아닌 곳에서 실행했다 | 프로젝트 루트로 이동하거나 `erdd init --local` |
| `erdd.config.yaml이 이미 있습니다. 지우고 다시 실행하세요` | `init --local` 인데 config 가 이미 있다 | 기존 파일을 지우고 다시 실행한다. `--yes` 로도 덮이지 않는다 |
| `포트 4300이 이미 사용 중입니다 …` | 다른 `erdd serve` 나 다른 프로그램이 그 포트를 물고 있다 | `--port` 로 다른 포트를 준다. 자동으로 옆 포트를 잡지 않는 것은 의도다 |
| `--port abc` 가 사용법 오류(`2`)로 죽는다 | 정수가 아니다 | 포트 번호를 준다 |
| 브라우저에 「파일을 읽을 수 없어 편집이 잠겼습니다」 배너가 뜨고 편집이 안 된다 | `erdd/` 안의 YAML 이 깨졌다 | 배너가 가리키는 파일을 고친다. 고치면 자동으로 풀린다 (→ [4.5](#45-파일이-깨지면-편집이-잠긴다)) |
| 테이블이 격자로 나란히 놓여 있다 | `erdd/layout.yaml` 이 없거나 그 테이블 항목이 없다 | 정상이다. 옮기거나 「자동 정렬」을 하면 좌표가 저장된다 |
| 다른 탭이 방금 한 편집을 따라오지 않는다 | 자기 편집은 그것을 낸 탭에만 보인다 | 새로고침한다 (→ [4.6](#46-탭을-여러-개-열면)) |
| 화면에서 고쳤는데 `git status` 에 아무것도 안 뜬다 | **저장하지 않았다.** 편집은 `.erdd/draft.json`(gitignore) 에만 있다 | 헤더의 「저장」 또는 `Cmd+S`. 터미널에서는 `erdd status` 가 알려 준다 (→ [4.4](#44-편집은-드래프트에-저장이-파일에)) |
| 「파일이 밖에서 바뀌었습니다」 배너가 뜬다 | 미저장 편집이 있는데 `git pull`·에이전트 등이 `erdd/` 를 고쳤다 | 「내 편집 유지」(저장하면 화면이 파일을 덮는다) 또는 「파일 다시 읽기」(내 편집을 버린다) (→ [4.4](#44-편집은-드래프트에-저장이-파일에)) |
| 「저장하지 않은 편집이 있습니다. 먼저 저장한 뒤 스냅샷을 만드세요」 | 스냅샷은 저장된 상태만 담는다 | 먼저 저장한다 (→ [6절](#6-스냅샷)) |
| `erdd serve` 를 껐다 켰더니 편집이 그대로 남아 있다 | 정상이다 — 미저장 편집은 드래프트에 남는다 | 그대로 이어서 작업하거나 「변경 버리기」로 버린다 (→ [4.4](#44-편집은-드래프트에-저장이-파일에)) |
| 터미널에서 파일을 고쳤는데 화면이 안 바뀐다 | 파일 감시 등록이 실패했다(플랫폼·권한·`EMFILE`) | 새로고침한다. `serve` 를 띄운 터미널에 `[watchProject] …` 경고가 남는다 |
| `erdd.config.yaml에 연결 설정이 없습니다 …` | 로컬 전용 프로젝트에서 `pull`·`push`·`diff` 를 돌렸다 | 로컬로 쓰려면 `erdd serve`, 서버에 붙이려면 `erdd init` (→ [7.2](#72-로컬로-시작한-프로젝트를-서버로-옮기기)) |
| `erdd.config.yaml에 serverUrl과 projectId는 함께 있어야 합니다 …` | 둘 중 하나만 적혀 있다 | 둘을 함께 적거나 둘 다 지운다(둘 다 없으면 로컬 전용이다) |
| `기준 시점이 없습니다. 먼저 erdd pull을 실행하세요` | 연결 설정만 적고 `push` 했다 | [7.2](#72-로컬로-시작한-프로젝트를-서버로-옮기기) 의 순서를 따른다 |
| 사설 도메인이나 리버스 프록시로 붙으면 **403** 이다 | `Host` 검사 | 루프백 주소로 연다. LAN·프록시 노출은 의도적으로 막혀 있다 (→ [3.2](#32-erdd-serve--에디터를-연다)) |
| 「공용 리소스」·「이력」·사용자 메뉴가 안 보인다 | 로컬 모드에 없는 기능이다 | 정상이다 (→ [4.2](#42-사용-매뉴얼의-어느-장이-해당하나)) |
| `변경 기록은 로컬 모드 전용입니다 …` | 서버에 연결된 프로젝트에서 `erdd changes` 를 돌렸다 | 서버 모드에는 변경 기록이 없다 |

CLI 전반의 문제 해결(서버 연결·토큰·충돌)은 [CLI 매뉴얼 11절](cli-guide.md#11-문제-해결) 에 있다.

## 부록: 검증 상태

**로컬 모드 동작은 2026-08-20 에 실제로 돌려 확인했다** — 명령 출력·종료 코드와 브라우저 스모크
11항목의 목록은 [CLI 매뉴얼 부록](cli-guide.md#로컬-모드-2026-08-20) 에 있다.

**이 문서를 쓰며 추가로 확인한 것(2026-08-21).**

- **웹 번들이 없을 때의 증상** — `apps/web/dist` 를 치우고 `erdd serve` 를 돌렸다. 터미널 출력은
  평소와 같고 `/` 는 `/p/<id>` 로 302 하는데, 그 주소가 본문 [2.3](#23-경로-b-erdd-저장소-체크아웃--웹-번들을-한-번-빌드한다)
  에 인용한 JSON 404 를 낸다.
- 로컬 전용 프로젝트에서 `init --local` 이 만드는 것이 `erdd.config.yaml`·`.gitignore`(`.erdd/` 한 줄)
  뿐인 것, `status` 의 사람용·`--json` 출력, `validate` 가 그대로 도는 것.

**패키지로 설치한 배치에서 확인한 것(2026-08-29).**

- **레지스트리 설치본에서 `erdd serve` 가 그대로 뜬다** — `pnpm pack` 으로 만든 tarball 을 별도의
  소비처 프로젝트에 설치해(웹을 **한 번도 빌드하지 않은** 프로젝트다) `erdd serve --no-open` 을
  돌렸고, `/p/<id>` 가 **200 + HTML**, `/assets/index-*.js` 가 200 + 1,162,100 바이트,
  `/trpc/model.get` 이 200 이었다. 설치본의 `node_modules/@erdd/cli/web` 파일 수는 101,
  `engines` 는 `{"node":">=22"}` 다. 그 프로젝트에서 `erdd --help`·`init --local`·`validate` 도
  종료 코드 `0` 이었다.
- **저장소 배치에서는 방금 빌드한 `apps/web/dist` 가 이긴다** — 두 후보(`apps/web/dist` 와
  `packages/cli/web`)에 서로 다른 표식 파일을 두고 어느 쪽이 서빙되는지 갈랐다. 저장소 배치의
  `/p/<id>` 도 200 이다. **게시 준비로 만든 복사본이 최신 빌드를 가리지 않는다.**
- **`tsx` 는 소비처가 직접 선언해야 한다** — [2.2](#22-경로-a-npm-에서-설치한다-권장) 의
  `pnpm add -D @erdd/cli tsx` 경로는 깨끗한 캐시 + 오프라인에서도 종료 코드 `0` 이다. `tsx` 를
  `@erdd/cli` 의 `dependencies` 에 넣어 대신 해결하려던 시도는 **pnpm 소비처를 오히려 회귀시켜**
  (되던 것이 `127` 로) 되돌렸다.

**공개 npm 에서 설치해 확인하지는 않았다.** 위 항목은 `pnpm pack` 한 tarball 을 설치한 것이다.
npm 에 게시된 판을 빈 프로젝트에 [2.2](#22-경로-a-npm-에서-설치한다-권장) 그대로 깔아 `erdd --help`·
`init --local`·`validate` 의 종료 코드와 `erdd serve` 의 `/p/<id>` 응답을 확인하는 것이 남아 있다.

**서버를 붙여 확인하지 않은 것** — [7절](#7-서버와-오가기)의 `pull`·`push` 왕복과 [7.2](#72-로컬로-시작한-프로젝트를-서버로-옮기기)
의 이관 순서는 소스와 단위 테스트를 읽고 옮긴 것이다. 인용한 문구는 구현과 테스트의 기대값에서
그대로 가져왔다.

**기준** — `packages/cli/src/{commands/{init,serve}.ts,local/*,config.ts}`,
`packages/core/src/{layout,local}.ts`, `apps/web/src` 의 로컬 모드 분기.
기능이 바뀌면 이 문서도 함께 고쳐야 한다.
