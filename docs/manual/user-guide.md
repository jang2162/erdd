# ERDD 사용 매뉴얼

웹 UI로 ERD를 설계하는 사람(설계자·개발자·리뷰어)과 조직 관리자를 위한 **기능별 레퍼런스**다. 튜토리얼이 아니므로 찾는 기능의 절만 열면 된다. 각 절은 **무엇**(기능) · **어디서**(위치) · **어떻게**(조작) · **제약**(권한·상한·주의) 순서다. 화면에 실제로 보이는 문구는 「」로 감쌌다. 설치·운영·서버 구동은 [install.md](./install.md), 명령줄 도구는 [cli-guide.md](./cli-guide.md)에 있다. **서버 없이 `erdd serve`로 연 로컬 모드**라면 [local-guide.md](./local-guide.md)를 함께 본다 — 에디터 화면은 같지만 아래 20개 장 중 6개는 해당하지 않고 2개는 다르다.

## 1. 계정과 로그인

> **로컬 모드에는 없다** — 계정도 로그인 화면도 없이 열면 바로 에디터다(→ [로컬 모드 매뉴얼](./local-guide.md)).

**무엇** — ERDD에는 셀프 가입이 없다. 계정은 **관리자가 발급한 일회용 초대 링크**를 본인이 열어 직접 만든다. 비밀번호를 잊었을 때도 같다 — 관리자가 재설정 링크를 발급해 전달한다.

**어디서** — `/login`(로그인), `/invite/:token`(초대 수락), `/reset/:token`(비밀번호 재설정). 세 화면 모두 **로그인 없이 열린다**.

**어떻게 — 로그인** — `/login`에서 「이메일」·「비밀번호」를 넣고 「로그인」을 누른다(처리 중에는 「확인 중…」). 성공하면 홈(`/`)으로 간다. 계정이 없으면 화면이 「계정이 없다면 관리자에게 요청하세요.」라고 안내한다.

**어떻게 — 초대 링크로 계정 만들기** — 관리자가 전달한 `/invite/:token`을 연다(제목 「초대 수락」). 상자에 초대받은 이메일이 보이고, 조직 초대라면 「조직 〈이름〉에 관리자(으)로 참여합니다」처럼 합류할 조직과 역할이 함께 표시된다. 「이름」·「비밀번호」·「비밀번호 확인」을 넣고 「계정 만들기」를 누르면(「만드는 중…」) 계정이 만들어지고, **자동 로그인되지 않고** 로그인 화면으로 이동한다.

**어떻게 — 비밀번호 재설정** — `/reset/:token`(제목 「비밀번호 재설정」)에서 「새 비밀번호」·「새 비밀번호 확인」을 넣고 「비밀번호 설정」을 누른다. 성공하면 로그인 화면으로 간다.

**제약**

| 항목 | 값·동작 |
|---|---|
| 초대 링크 유효기간 | 발급 후 7일 |
| 재설정 링크 유효기간 | 발급 후 24시간 |
| 비밀번호 최소 길이 | 8자 |
| 재설정 성공 시 | 「새 비밀번호를 정하면 다른 기기의 로그인이 모두 해제됩니다.」 |
| 재설정 링크 발급만으로는 | 비밀번호가 바뀌지 않고 로그인 세션도 유지된다 |

두 비밀번호 입력이 다르면 「비밀번호가 서로 다릅니다」가 뜬다. 링크가 더 진행할 수 없으면 폼이 사라지고 사유가 뜨는데 다음 행동이 두 갈래다. **다시 받을 수 있는 경우**(없는 링크·기한 지남·취소됨)는 「관리자에게 문의해 새 링크를 받으세요.」이고, **그 이메일에 이미 계정이 있는 경우**는 「이 이메일에는 이미 계정이 있습니다 — 새 링크를 받을 수는 없으니 로그인하세요. 비밀번호를 모르면 관리자에게 재설정 링크를 요청하세요.」다. 뒤쪽은 같은 이메일로 초대를 다시 만들 수 없다는 뜻이다.

일시적 실패(네트워크 단절·서버 오류)에는 링크가 죽지 않는다. 「지금은 처리하지 못했습니다. 잠시 후 다시 시도하세요.」가 뜨고 **입력한 내용은 남으므로** 같은 버튼으로 다시 누르면 된다. 초대 화면이 정보를 못 불러왔을 때는 「다시 시도」 버튼이 나온다.

## 2. 화면 지도

> **로컬 모드에서는 다르다** — 화면이 에디터와 프로젝트 설정 둘뿐이다(→ [로컬 모드 매뉴얼 4.1](./local-guide.md#41-화면은-둘뿐이다)).

**무엇** — 전체 화면은 9개다. 대부분 로그인이 필요하고 일회용 링크와 로그인 화면 3개만 예외다.

**어디서** — 로그인 후에는 공통 상단바가 있다. 왼쪽 로고는 홈으로, 오른쪽에는 승격 요청 대기 배지(→ [13절](#13-공용-리소스))와 사용자 메뉴가 있다. 에디터만 전체화면 전용 레이아웃이라 자체 헤더를 쓴다.

| 경로 | 화면 | 보호 | 내용 |
|---|---|---|---|
| `/login` | 로그인 | 비보호 | 이메일·비밀번호 로그인 |
| `/invite/:token` | 초대 수락 | 비보호 | 초대 링크로 계정 생성 |
| `/reset/:token` | 비밀번호 재설정 | 비보호 | 재설정 링크로 새 비밀번호 설정 |
| `/` | 홈 | 로그인 | 「〈이름〉님의 작업 공간」 — 내 조직 카드, 「팀 조직 만들기」 |
| `/org/:orgId` | 조직 상세 | 로그인 | 프로젝트 목록·생성, 멤버, 초대, 승격 요청, 조직 공용 리소스 |
| `/p/:projectId` | ERD 에디터 | 로그인 | 캔버스·트리·편집 패널과 모든 에디터 기능 |
| `/p/:projectId/settings` | 프로젝트 설정 | 로그인 | 프로젝트 정보 확인, 명명 규칙(논리명 구분자·테이블 물리명 형식·테이블 논리명 형식), 테이블 옵션, 프로젝트 멤버 관리 |
| `/settings` | 내 설정 | 로그인 | 비밀번호 변경, 액세스 토큰 |
| `/admin` | 계정 관리 | 로그인 + 서비스 역할 `admin` | 계정 초대·상태, 초대 목록, 전역 공용 리소스 |

없는 경로로 가면 「페이지를 찾을 수 없습니다」와 「홈으로」가 나온다. 사용자 메뉴(내 이름)에는 이메일과 함께 「설정」·「로그아웃」이 있고, 서비스 역할이 `admin`이면 「관리자」가 추가로 보인다.

## 3. 조직·프로젝트와 권한

> **로컬 모드에는 없다** — 조직도 멤버도 역할도 없고 언제나 관리 권한이다(→ [로컬 모드 매뉴얼 1절](./local-guide.md#1-이-문서를-읽는-사람)).

**무엇** — 조직이 멤버 관리 단위이고, 프로젝트 하나가 DB 스키마 하나다. 권한은 **역할 축 세 개**가 겹쳐 결정된다.

**어디서** — 홈(`/`)에서 조직을 고르고, 조직 상세(`/org/:orgId`)에서 프로젝트를 만들고 멤버를 관리한다. 프로젝트 멤버는 프로젝트 설정(`/p/:projectId/settings`)에서 관리한다.

| 축 | 값 | 어디서 정하는가 | 성질 |
|---|---|---|---|
| 서비스 역할 | `admin` / `user` (「관리자」/「일반」) | 관리자가 계정을 초대할 때(`/admin`) | 서비스 전체 관리자. `/admin` 화면에 들어갈 수 있는 유일한 역할이고 조직·프로젝트 권한과 별개 축이다 |
| 조직 역할 | `owner` / `admin` / `member` | 조직 상세의 「멤버」 표 | 아래 표 |
| 프로젝트 역할 | `admin` / `editor` / `viewer` | 프로젝트 설정의 「프로젝트 멤버」 | 아래 표 |

| 조직 역할이 할 수 있는 일 | Owner | Admin | Member |
|---|:---:|:---:|:---:|
| 프로젝트 만들기 | ○ | ○ | ✕ |
| 멤버 추가·제거·역할 변경 | ○ | ○ | ✕ |
| Owner를 만들거나 강등·제거 | ○ | ✕ | ✕ |
| 조직 초대 링크 발급·취소 | ○ | ○ | ✕ |
| 조직 라이브러리 관리, 승격 요청 승인 | ○ | ○ | ✕ |
| 프로젝트 접근 | 조직의 전부 | 조직의 전부 | 초대된 것만 |

마지막 Owner는 강등·제거되지 않는다(「마지막 Owner는 강등할 수 없습니다」). 권한 없는 조작은 「조직 관리 권한이 없습니다」로 거절된다.

프로젝트 쪽은 서버가 요구 수준을 세 단계로 판정한다.

| 수준 | 통과하는 사람 | 되는 일 |
|---|---|---|
| 조회 | Org Owner/Admin, 또는 프로젝트 멤버 아무 역할 | 모델 조회, 내보내기, 실시간 참여 |
| 편집 | Org Owner/Admin, Project Admin/Editor | 모델 편집 전부 |
| 관리 | Org Owner/Admin, Project Admin | 프로젝트 멤버 관리, 스냅샷 복원·삭제 |

Viewer는 에디터에 들어갈 수 있지만 하단 바의 편집 도구 자리에 「읽기 전용」 배지만 보이고 노드 드래그·관계 연결·삭제가 잠긴다. 편집을 시도하면 「이 프로젝트에 대한 편집 권한이 없습니다」가 뜬다.

**어떻게 — 조직·프로젝트 만들기** — 홈에서 「팀 조직 만들기」 → 「조직 이름」 → 「만들기」(만든 사람이 Owner). 조직 상세에서 「프로젝트 만들기」 → 「이름」, 「설명 (선택)」, 「대상 DB 방언」 → 「만들기」(만든 사람이 Project Admin). 방언은 「PostgreSQL」·「MySQL·MariaDB」·「Oracle」·「MSSQL」 네 가지이고 여럿을 켤 수 있다(기본값은 PostgreSQL). 하나도 고르지 않으면 「대상 DB를 하나 이상 선택하세요」가 뜬다.

**어떻게 — 멤버 넣기** — 계정이 **있는** 사람은 조직 상세 「멤버」의 「이메일로 추가」에 이메일을 넣고 역할(Member/Admin)을 골라 「추가」한다. 계정이 **없는** 사람은 같은 화면의 「초대」 절에서 링크를 만든다(→ [19절](#19-관리자-업무)) — 화면도 「아직 계정이 없는 사람을 부릅니다. 이미 가입한 사람은 위 멤버 추가를 쓰세요.」라고 안내한다. 프로젝트에 넣을 때는 프로젝트 설정 → 「프로젝트 멤버」 → 「조직 멤버 추가」에서 사람과 Admin/Editor/Viewer를 골라 「추가」한다. **이미 조직 멤버인 사람만** 후보로 나온다.

**제약**

- 계정을 만들면 「〈이름〉의 공간」이라는 **개인 조직**이 자동으로 생기고 본인이 Owner가 된다. 홈 카드에 「개인 공간」 배지가 붙고 목록 맨 앞에 온다. 개인 조직에는 멤버를 추가할 수 없고(「개인 조직에는 멤버를 추가할 수 없습니다」) 초대도 만들 수 없어, 「멤버」·「초대」 절이 보이지 않는다.
- **프로젝트 설정에서 바꿀 수 있는 것은 프로젝트 멤버, 「명명 규칙」의 논리명 구분자 토글·테이블 물리명 형식·테이블 논리명 형식, 그리고 「테이블 옵션」의 방언 4칸이다.** 이름·설명·대상 DB 방언은 읽기 전용으로만 표시된다. 「명명 규칙」 절의 **「논리명을 밑줄로 구분」** 체크박스는 논리명을 「회원_주문_번호」처럼 단어마다 밑줄로 나눠 적을지를 정한다(기본 켜짐) — 끄더라도 **이미 저장된 논리명의 밑줄은 그대로 남는다.** 같은 절의 **「테이블 물리명 형식」** 입력란은 테이블 물리명을 「접두 + 입력한 부분」으로 조합하는 틀이고, 그 아래 **「테이블 논리명 형식」** 입력란은 같은 방식으로 **산출물의** 테이블 논리명을 조합하는 틀이다(→ [10절](#10-명명-체계단어용어-사전)). 나머지 셋(대문자 스네이크, 물리명 구분자 `_`, 최대 30바이트)은 아직 화면이 없다. 그 아래 **「테이블 옵션」** 절은 DDL 로 내보낼 때 `CREATE TABLE` 뒤에 붙일 방언별 문자열이다(→ [9.1절](#91-테이블-옵션enginecharset)). 두 절 다 **관리 권한**이 있어야 보인다. 방언은 만들 때 고른 값이 그대로 유지된다.

## 4. 에디터 기본

**무엇** — 왼쪽 **테이블 트리**, 가운데 **캔버스**, 오른쪽 **편집 패널** 세 칸을 위쪽 **헤더**와 아래쪽 **하단 바**가 감싼다. 헤더에는 열어서 작업하고 닫는 관리 도구가, 하단 바에는 캔버스를 직접 조작하거나 어떻게 볼지 정하는 도구가 모여 있다.

**어디서** — `/p/:projectId`. 헤더 왼쪽에 로고가, 오른쪽에 접속자 아바타 → 「버전」 → 「사전·리소스」 → 「모델 검사」 → 「파일」 → 「설정」 → 사용자 메뉴가 순서대로 놓인다. 「사전·리소스」를 누르면 「도메인」·「단어·용어 사전」·「커스텀 항목」·「공용 리소스」가, 「파일」을 누르면 「DDL·DBML 가져오기」·「내보내기」가 메뉴로 열린다.

화면 맨 아래 **하단 바**에는 왼쪽부터 편집 도구(「테이블 추가」·「메모」·「자동 정렬」·「삭제」) → 실행 취소/다시 실행 → 「뷰 전환」 → 보기 모드(「논리명」·「물리명」·「혼합」) → 오른쪽 끝에 줌(축소·배율·확대·「화면에 맞춤」)이 놓인다.

**어떻게 — 캔버스**

| 조작 | 결과 |
|---|---|
| 빈 공간 드래그 / 휠 / 하단 바 오른쪽 줌 | 화면 이동, 확대·축소, 화면 맞춤 |
| 노드 클릭 / 관계선 클릭 | 그 테이블·메모·관계를 선택 → 오른쪽 편집 패널이 바뀐다 |
| 빈 공간 클릭 | 선택 해제 |
| 노드 드래그 | 위치 변경(위치도 모델이라 저장된다) |
| 테이블 좌·우 손잡이를 다른 테이블로 드래그 | 관계 생성(→ [6절](#6-관계)) |

우하단에 미니맵이 있고 미니맵 자체를 드래그·확대할 수 있다.

**테이블을 지우는 방법은 하단 바 「삭제」뿐이다.** 캔버스에서 노드를 고른 뒤 `Backspace` 를 누르면 그
노드가 화면에서 사라지는데, **저장되지 않는다** — 화면을 새로 열거나 다른 편집이 들어오면 그대로
되살아난다. 지울 때는 반드시 하단 바 「삭제」를 쓴다.

**어떻게 — 하단 바의 편집 도구**(편집 권한이 있을 때만 보인다)

| 버튼 | 동작 | 비활성 조건 |
|---|---|---|
| 「테이블 추가」 | 화면 중앙에 새 테이블을 만들고 선택한다 | — |
| 「메모」 | 화면 중앙에 메모를 만든다 | 그룹 뷰에 들어가 있으면 |
| 「자동 정렬」 | 보이는 테이블을 관계 기준 계층으로 재배치한다 | 보이는 테이블이 2개 미만 |
| 「삭제」 | 선택한 테이블(여러 개면 전부)과 그 컬럼·인덱스·관계를 함께 지운다 | 선택한 테이블이 없으면 |
| 「실행 취소」 / 「다시 실행」 | 직전 편집을 되돌리거나 되돌린 편집을 다시 적용한다 | 대상이 없으면 |

**단축키**는 `Cmd/Ctrl + Z`(실행 취소)와 `Cmd/Ctrl + Shift + Z`(다시 실행)다. 선택·복사·붙여넣기·삭제
단축키는 [20절](#20-선택과-복사)에 있다. 어느 것이든 **입력란·텍스트 영역에 커서가 있거나 다이얼로그가
열려 있으면** 동작하지 않고 브라우저 기본 동작에 양보한다.

**어떻게 — 테이블 트리** — 「테이블 검색」에 논리명·물리명의 일부를 넣으면 목록이 걸러진다(대소문자 무시). 그룹별로 묶여 나오고 그룹에 넣지 않은 테이블은 「미분류」 아래에 모인다. 테이블을 클릭하면 캔버스가 그 테이블로 이동하고 선택된다. 검색창 오른쪽 폴더 아이콘(「그룹 추가」)으로 새 그룹을 만든다. 테이블이 없으면 「테이블을 추가해 설계를 시작하세요.」, 검색 결과가 없으면 「검색 결과가 없습니다.」가 뜬다.

**어떻게 — 트리에서 여러 개 고르기** — `Cmd`/`Ctrl`+클릭이면 그 테이블을 선택에 더하거나 뺀다(토글). `Shift`+클릭이면 **화면에 보이는 순서 그대로** 범위를 잡는다 — 검색으로 걸러졌거나 그룹 뷰 밖이라 **지금 안 보이는 테이블은 범위에 끌려 들어오지 않는다**. 수식 키 없이 클릭하면 다시 하나만 남는다. 이 선택은 캔버스와 **같은 선택**이라(→ [20절](#20-선택과-복사)) 트리에서 고른 것이 캔버스에서도 하이라이트되고, 캔버스에서 상자로 고른 것이 트리에도 나타난다. 선택은 읽기 전용 권한으로도 된다.

**어떻게 — 끌어서 그룹 옮기기** — 트리 항목을 잡아 다른 그룹 블록(또는 「미분류」)에 놓으면 그 테이블의 소속이 바뀐다. **여러 개를 골라 둔 상태에서 그중 하나를 잡으면 고른 것 전부가 함께 간다**(선택 밖의 항목을 잡으면 그것 하나만 간다). **캔버스의 테이블 노드를 끌어와 트리의 그룹 블록에 놓아도** 같다. 끄는 동안 커서를 따라 「N개 테이블」 딱지가 붙고 놓을 그룹이 테두리로 표시되며, **검색이나 그룹 뷰 때문에 가려져 있던 그룹도 이때는 전부 보인다**(안 그러면 찾은 테이블을 원하는 그룹에 놓을 수 없다). 그룹 헤더뿐 아니라 그 아래 목록과 블록 여백 어디에 놓아도 걸린다. 이미 그 그룹에 있는 테이블만 놓으면 아무 일도 일어나지 않는다.

**어떻게 — 보기 모드** — 하단 바의 3버튼 토글에서 「논리명」·「물리명」·「혼합」을 고른다. 혼합은 물리명과 논리명을 나란히 보여준다. 기본값은 「물리명」이다.

**제약** — 실행 취소 이력은 **최근 100단계**까지, 그리고 **이 브라우저 세션에서 내가 한 편집만** 쌓인다. 화면을 새로 열거나 남의 편집으로 모델을 다시 맞추면 이력이 비워진다. 실행 취소·다시 실행도 서버에 반영되는 편집이므로 이력에 「실행 취소」·「다시 실행」으로 남는다. 자동 정렬은 **보이는 범위 만** 정렬하므로 그룹 뷰에서는 그 그룹의 배치만 바뀐다. 편집이 서버에 거절되면 사유를 토스트로 알리고 화면을 서버 상태로 되맞춘다.

## 5. 테이블과 컬럼

**무엇** — 테이블·컬럼은 **논리명**(업무 용어)과 **물리명**(DB 식별자)을 따로 갖는다. 논리명을 넣으면 사전으로 물리명이 자동 생성된다. 테이블도 컬럼도 **물리명이 위, 논리명이 아래**로 세로로 놓이고, 각 입력란 안 오른쪽 끝에 **화살표 버튼**이 하나씩 붙는다 — 누른 칸이 아니라 **반대편 칸**을 채운다.

**어디서** — 캔버스에서 테이블을 선택하면 오른쪽 편집 패널이 열린다. 선택이 없으면 「테이블을 선택하면 여기서 편집합니다.」만 보인다.

**어떻게 — 테이블** — 「테이블 물리명」에 직접 입력하거나, **논리명 칸**의 ↑(「물리명 채우기」)로 논리명 기준으로 물리명을 만든다. 「논리명」에는 업무 이름을 넣는다(물리명이 비어 있었다면 이때 자동 생성된다) — 반대로 **물리명 칸**의 ↓(「논리명 채우기」)는 물리명 기준으로 논리명을 만든다. **화살표는 누른 칸의 반대편을 채운다**(물리명 칸의 화살표를 누르면 논리명이 바뀐다). **지금 치고 있는 값을 기준으로 돈다** — 입력을 마치고 다른 곳을 클릭할 필요 없이 바로 눌러도 방금 친 값이 반영된다. 「소속 그룹」 드롭다운으로 그룹에 넣는다(기본은 「미분류」). 커스텀 항목이 정의돼 있으면 「커스텀 항목」 상자가 이어서 나온다(→ [11절](#11-커스텀-항목)). 논리명만 「테이블1」 같은 임시값이 붙고 물리명은 비어 있다 — 논리명을 업무 이름으로 고치면 사전으로 물리명이 생성된다.

**어떻게 — 컬럼**

1. 「컬럼」 옆 「컬럼 추가」. 「컬럼1」/`COL_1`, 타입 `VARCHAR(255)`, NULL 허용으로 만들어진다.
2. 각 행은 위가 물리명, 아래가 논리명이고 둘 다 「*」로 필수 표시가 붙는다. 논리명을 넣으면 **물리명이 비어 있을 때** 자동 생성되고, 그때 사전 용어에 일치하면 **도메인까지 함께 지정**된다(도메인이 비어 있을 때만). 물리명이 이미 차 있으면 둘 다 그대로 둔다. 반대로 물리명을 넣으면 **논리명이 비어 있을 때만** 사전으로 논리명이 자동 복원되고, 사전에 없는 약어가 하나라도 있으면 채우지 않는다.
3. 각 입력란 안의 화살표는 **반대편 칸**을 내 값 기준으로 채운다 — 물리명 칸의 ↓는 「논리명 채우기」, 논리명 칸의 ↑는 「물리명 채우기」다. 만들 수 없으면 사유가 토스트로 뜬다(「등록되지 않은 약어: GRD, CD」). 이름 아래 「용어 등록」은 지금의 논리명·물리명·도메인을 용어 사전에 등록한다(→ [10절](#10-명명-체계단어용어-사전)) — 같은 논리명의 용어가 이미 있거나 논리명·물리명 중 하나라도 비어 있으면 잠긴다. **화살표도 「용어 등록」도 지금 치고 있는 값을 본다** — 입력을 마치고 다른 곳을 클릭할 필요가 없고, 누른 뒤에도 커서가 입력란에 남는다.
4. **이름을 치는 동안 자동완성 목록**이 입력란 아래에 뜬다. 논리명에서는 사전 단어와 용어를, 물리명에서는 약어와 용어 물리명을 접두일치로 제안한다(↓↑로 옮기고 Enter로 확정, Esc로 닫는다). 확정은 **저장이 아니라 글자 채우기**라 이어서 다음 단어를 칠 수 있다 — 다만 **반대편 칸은 그 자리에서 함께 바뀐다**(화면만 바뀌고 저장은 아직이다). 단어 후보는 아직 사전에 없는 **꼬리 조각**이 남아 있을 때만 뜨지만, **용어는 이름 전체를 보므로 사전 단어로 딱 떨어져도 계속 뜬다** — 「회원_주문」까지 쳤을 때 용어 「회원_주문_번호」가 제안되는 것이 그 경우다. 한 번에 8개까지, 그중 용어는 3개까지 보인다.
   - 논리명 구분자가 켜져 있으면 **꼬리 조각은 마지막 밑줄 뒤 토큰**이다. 그래서 밑줄 없이 이어 친
     옛 이름(「회원주」)에서는 입력 전체가 한 토막으로 잡혀 단어 후보가 줄어든다 — 밑줄을 한 번
     찍어 주면(「회원_주」) 곧바로 후보가 돌아온다.
5. 이름 아래 「미등록」 줄에는 그 이름에서 사전에 없는 구간이 칩으로 뜬다. 칩을 누르면 그 자리에 입력칸이 펼쳐진다 — 논리명 쪽은 약어를, 물리명 쪽은 논리명을 넣고 「단어 등록」을 누르면 사전에 바로 들어간다. 사전에 같은 이름이 이미 있으면 잠기고, 약어만 겹치는 것은 경고만 뜬다. 칩은 **저장된 값** 기준이라 치는 동안 깜박이지 않는다.
6. 「도메인」에서 도메인을 고르거나 「없음」으로 해제한다.
7. 「타입」에 DB 타입을 직접 쓴다. **도메인을 지정하면 이 칸이 잠기고** 「〈논리 타입〉 (도메인: 〈이름〉)」이 읽기 전용으로 표시된다. 정수에는 **부호 없음**을 접미로 붙일 수 있다 — `SMALLINT UNSIGNED`·`INT UNSIGNED`·`BIGINT UNSIGNED` 셋이다(MySQL 에서 PK/FK 에 흔히 쓰는 표기다). MySQL DDL 로 내보내면 그대로 나가고, 나머지 세 방언에서는 부호 있는 타입 + `CHECK (컬럼 >= 0)` 로 나간다.
8. 「PK」·「NN」 체크박스로 기본 키·NOT NULL을 정한다. 위·아래 화살표로 순서를 바꾸고 휴지통으로 지운다.

**제약**

- 입력란은 **포커스를 잃을 때** 반영된다. 고친 뒤 다른 칸을 클릭하거나 `Tab`으로 이동해야 저장된다.
- 컬럼을 지우면 그 컬럼을 쓰던 관계 매핑·인덱스 구성 컬럼도 함께 정리된다. 매핑이 하나도 남지 않는 관계, 구성 컬럼이 없어진 인덱스는 함께 사라진다.
- 캔버스 노드에는 PK에 열쇠 아이콘, NOT NULL에 `NN` 표시가 붙고 오른쪽에 타입이 보인다. 컬럼이 없으면 「컬럼 없음」이다.
- **테이블·컬럼의 설명(코멘트), 컬럼 기본값, 자동증가는 편집 패널에 입력란이 없다.** 값 자체는 모델에 있어 DDL 코멘트·Excel 정의서에 실리지만, 웹에서 채우는 경로는 DDL 가져오기(→ [16절](#16-가져오기))와 도메인 기본값(→ [9절](#9-도메인))뿐이다.
- 같은 테이블 안 컬럼 물리명이나 테이블 물리명이 겹치면 경고가 아니라 **오류** 등급이다(→ [12절](#12-모델-검사)).
- 필수 항목(테이블 물리명·논리명, 컬럼 물리명·논리명·타입)의 라벨에는 별표가 붙고, 비어 있으면 「필수 값 누락」 경고로 잡힌다(→ [12절](#12-모델-검사)). **컬럼 행은 라벨을 화면에 그리지 않는 압축 레이아웃이라 별표가 붙지 않는다** — 그 행에서 필수 여부는 경고 배지로만 알 수 있다.

## 6. 관계

**무엇** — 관계는 **자식 → 부모** 방향의 외래 키다. 부모의 기본 키를 자식에 FK 컬럼으로 복사해 만든다.

**어디서** — 캔버스에서 관계선을 클릭하면 오른쪽에 「관계」 패널이 열린다. 만들기는 캔버스에서 한다.

**어떻게 — 만들기** — **자식** 테이블의 좌·우 손잡이를 잡아 **부모** 테이블 위로 끌어다 놓는다. 부모의 기본 키 개수만큼 FK 컬럼이 자식에 생기고 이름이 겹치면 `_2`, `_3`이 붙는다. 만들어진 관계가 곧바로 선택된다. 부모에 기본 키가 없으면 「부모 테이블에 기본 키가 없습니다」가 뜨고 만들어지지 않는다.

**어떻게 — 편집** — 패널 위에 「〈자식 물리명〉 → 〈부모 물리명〉」이 표시된다.

| 항목 | 값 | 효과 |
|---|---|---|
| 「카디널리티」 | 「1 : N」 / 「1 : 1」 | 캔버스 표기가 바뀌고, 1:1은 DDL에 UNIQUE 제약이 함께 나간다 |
| 「식별 관계 (자식 기본 키 편입)」 | 체크박스 | FK 컬럼이 자식의 기본 키에 들어간다. 캔버스에서 실선(비식별은 점선) |
| 「관계명」 | 자유 입력 | 비우면 없음으로 저장된다. DDL의 FK 제약 이름에 쓰인다 |
| 「컬럼 매핑」 | 부모 PK별 자식 컬럼 선택 | 왼쪽 드롭다운으로 자식 쪽 컬럼을 바꾼다 |

캔버스에서 부모 끝은 항상 막대, 자식 끝은 1:N일 때 까마귀발로 그려진다. 매핑을 다른 컬럼으로 바꾸면 새 컬럼의 PK 여부가 관계의 식별 상태에 맞춰지고, 이전 FK 컬럼은 아무 관계·인덱스도 쓰지 않을 때만 삭제된다. 오른쪽 위 휴지통(「관계 삭제」)으로 지우는데 **자식의 FK 컬럼은 일부러 남는다** — 필요 없으면 편집 패널에서 직접 지운다. 관계선을 고른 채 `Delete`/`Backspace`를 눌러도 **완전히 같은 동작**이다(→ [20절](#20-선택과-복사)).

관계선은 테이블 가운데가 아니라 **실제로 이어지는 컬럼 행**에 붙는다. 자식의 FK 컬럼 행과 부모의
참조 컬럼 행이 직접 이어지므로 어느 컬럼이 무엇을 참조하는지 그림만 보고 알 수 있다. 컬럼이
둘 이상인 **복합 키 관계**는 두 테이블 맨 아래에 `(컬럼1, 컬럼2)` 행이 생기고 그 행끼리 선
하나로 이어진다. 이 행은 **보기 전용**이라 클릭하거나 선택할 수 없고, 관계가 실제로 쓰는 컬럼
조합에만 생긴다. 매핑이 아직 비어 있는 관계는 예전처럼 테이블 좌·우 가운데에 붙는다.

### 교차 테이블로 풀기 (N:M)

**무엇** — 모델에는 N:M 관계 타입이 없다. 대신 1:N 관계 하나를 **교차 테이블 1개 + 식별 1:N 관계 2개**로 바꿔 주는 동작이 있다.

**어디서** — 관계 패널 맨 아래 「교차 테이블로 풀기」(편집 권한이 있을 때만).

**어떻게** — 풀 1:N 관계를 선택하고 「교차 테이블로 풀기」를 누른다. 원본 관계의 FK 컬럼이 자식에서 제거되고 그와 함께 원본 관계도 사라진다. 두 테이블 사이 중간 지점에 교차 테이블이 생기는데, 논리명은 **두 테이블의 논리명을 붙인 것**(예: 회원 + 상품 → "회원상품")이고 물리명은 사전으로 생성된다. 부모 → 교차, 자식 → 교차로 **식별 1:N 관계 2개**가 만들어지고 교차 테이블의 기본 키는 양쪽 FK를 합친 복합 키가 된다. 선택이 교차 테이블로 옮겨져 바로 이름을 다듬을 수 있다.

**제약 — 풀 수 없는 세 조건.** 해당하면 버튼이 잠기고 이유가 함께 표시된다.

| 조건 | 화면 문구 |
|---|---|
| 식별 관계다 | 「식별 관계는 풀 수 없습니다 — 위 "식별 관계" 체크를 먼저 해제하세요」 |
| 부모에 기본 키가 없다 **또는** 자식에서 이 관계의 FK 컬럼을 뺀 뒤 남는 기본 키가 없다 | 「교차 테이블에 넘길 기본 키가 없습니다 — 부모에 기본 키가 있어야 하고, 자식에는 이 관계의 FK 를 뺀 기본 키가 남아야 합니다」 |
| 지울 FK 컬럼을 **다른 관계가 부모 쪽으로 참조**한다 | 「이 관계의 FK 컬럼을 다른 관계가 참조하고 있어 풀 수 없습니다 — 먼저 그 관계를 정리하세요」 |

세 번째는 식별 관계 가드와 별개다. 식별 관계가 아니어도 FK 컬럼에 PK 체크만 켜져 있고 그 컬럼을 손자 테이블이 참조하는 3단 구조가 만들어질 수 있는데, 그대로 풀면 손자 쪽에 아무도 참조하지 않는 FK 컬럼이 남는다. 그래서 따로 막는다.

이 동작은 편집 1건이므로 **실행 취소 한 번으로 통째로 되돌아간다**. 그룹 뷰에서 실행하면 교차 테이블이 그 그룹에 배정된다. 사전에 없는 단어로 물리명을 만들 수 없으면 `TABLE_n` 형태의 임시 물리명이 붙는다.

## 7. 인덱스와 메모

### 인덱스

**무엇** — 테이블별 인덱스 정의. 구성 컬럼의 순서·정렬 방향과 UNIQUE 여부를 갖는다.

**어디서** — 테이블을 선택한 편집 패널 맨 아래 「인덱스」 절.

**어떻게** — 「인덱스 추가」를 누르면 `IX_1`, `IX_2`처럼 쓰이지 않은 가장 작은 번호로 만들어진다. 「인덱스명」을 고치고(빈 이름은 무시된다), 「UNIQUE」로 유니크 여부를 정하고, 아래 「컬럼 추가…」 드롭다운에서 구성 컬럼을 고른다(이미 들어간 컬럼은 후보에서 빠진다). 각 컬럼 행의 「ASC」/「DESC」로 방향을 뒤집고, 화살표로 순서를 바꾸고, 휴지통으로 구성에서 뺀다.

**제약** — 구성 컬럼이 없으면 「구성 컬럼 없음」으로 남는다. 인덱스가 없으면 「인덱스가 없습니다.」가 보인다. 읽기 전용 사용자에게도 방향 버튼은 보이지만 눌리지 않는다(값 표시를 겸한다).

### 메모

**무엇** — 캔버스에 붙이는 자유 텍스트 쪽지. 모델의 일부로 저장되고 함께 편집된다.

**어디서·어떻게** — 하단 바 「메모」를 누르면 화면 중앙에 「메모」라는 내용의 노란 쪽지가 생긴다. 캔버스에서 클릭하면 오른쪽에 「메모」 패널이 열린다. 「내용」에 쓰고(줄바꿈이 그대로 유지된다) 「색상」에서 배경색을 고른다. 오른쪽 위 휴지통(「메모 삭제」)으로 지운다. 메모를 고른 채 `Delete`/`Backspace`로 지우고 `Cmd`/`Ctrl`+`C`·`X`·`V`로 복사·잘라내기·붙여넣기 할 수도 있다(→ [20절](#20-선택과-복사)).

**제약** — 메모는 **전체 뷰에서만 보인다.** 그룹 뷰에서는 숨겨지고 하단 바의 「메모」도 잠긴다. 메모는 그룹에 소속되지 않는다.

## 8. 그룹과 그룹 뷰

**무엇** — 그룹은 테이블을 업무 단위로 묶는 장치다. 전체 뷰에서 테이블 뒤에 깔리는 **색상 영역**, 그리고 그 그룹만 따로 보는 **그룹 뷰** 두 가지로 쓰인다.

**어디서** — 트리 상단 폴더 아이콘(「그룹 추가」)으로 만들고, 테이블을 여러 개 골라 두면 오른쪽 패널에도 「선택 테이블로 새 그룹」 버튼이 뜬다. 캔버스의 색상 영역 라벨이나 트리의 그룹 이름을 클릭하면 오른쪽에 「그룹」 패널이 열린다. 하단 바의 「뷰 전환」 드롭다운으로 뷰를 옮긴다.

**어떻게** — 트리에서 「그룹 추가」를 누르면 「그룹1」처럼 쓰이지 않은 번호로 만들어지고 색이 자동 배정된다. 그룹 패널에서 「이름」·「별칭」·「색상」·「설명」을 고치고, 위쪽에서 「소속 테이블 N개」를 확인한다. 테이블을 넣는 길은 넷이다 — 그 테이블의 편집 패널에서 「소속 그룹」을 고르거나, **왼쪽 트리에서 항목을 잡아 그룹 블록에 끌어다 놓거나**, **캔버스의 테이블 노드를 트리의 그룹 블록으로 끌어다 놓거나**, 여러 개를 골라 둔 채 오른쪽 패널의 「선택 테이블의 그룹」 드롭다운으로 옮긴다. 여러 개를 골라 두면 한 번에 옮겨진다(→ [4절](#4-에디터-기본)). 그룹이 바뀌면 캔버스 좌표도 새 그룹 옆으로 함께 조정된다. 그룹 패널의 「이 그룹 뷰 열기」 또는 하단 바 「뷰 전환」의 「〈그룹명〉 뷰」로 그룹 뷰에 들어가고 「전체 뷰」로 돌아온다. 패널 오른쪽 위 휴지통(「그룹 삭제」)으로 그룹을 지운다.

**어떻게 — 별칭** — 그룹 패널의 「별칭」은 물리명 조합에 쓸 짧은 식별자다. 그룹 이름은 `회원관리`처럼 한글이라 물리명에 그대로 넣을 수 없어서 따로 둔다. **영문 대문자·숫자·밑줄만 들어간다** — 소문자를 치면 대문자로 바뀌고 한글·특수문자는 **아예 입력되지 않는다**(치는 동안 걸러진다). 칸 안 오른쪽의 ↑(「이름으로 별칭 채우기」)를 누르면 그룹 이름을 사전으로 돌려 약어 조합을 넣는다 — 사전에 없는 단어가 있으면 그 단어를 토스트로 알리고 값을 바꾸지 않는다. 선택 입력이라 비워 둬도 된다. **지금은 어디에도 쓰이지 않는다** — 테이블명 형식 템플릿이 붙는 다음 단계에서 소비된다. 읽기 전용 권한이면 잠기고 채우기 버튼도 뜨지 않는다.

**이미 있는 그룹이 아니라 새 그룹으로 묶으려면** — 캔버스에서 `Shift`+드래그로 상자를 그리거나 트리에서 여러 개를 골라 둔 다음, 오른쪽 패널의 「선택 테이블로 새 그룹」을 누른다. 「그룹1」처럼 쓰이지 않은 번호와 색이 자동으로 붙고 고른 테이블 전부가 그 그룹에 들어가며, 오른쪽이 곧바로 「그룹」 패널로 바뀌어 이름·색상·설명을 그 자리에서 고칠 수 있다(이때 테이블 선택은 풀린다). **테이블은 있던 자리에 그대로 있고 색상 영역만 씌워진다** — 멀리 떨어진 테이블끼리 묶으면 영역이 그만큼 커져 사이의 다른 테이블까지 덮어 보일 수 있으니, 그럴 때는 만든 뒤 캔버스에서 끌어 정리한다. 편집 1건이므로 **실행 취소 한 번으로 통째로 되돌아간다**.

| | 전체 뷰 | 그룹 뷰 |
|---|---|---|
| 보이는 테이블 | 전부 | 그 그룹 소속만 |
| 색상 영역 | 소속 테이블을 감싸는 반투명 영역(선택 시 실선, 아니면 점선) | 안 보임 |
| 메모 | 보임 | 안 보임 |
| 테이블 위치 | 전체 좌표 | **그룹 뷰 전용 좌표** — 따로 저장된다 |
| 그룹 밖 테이블과의 관계 | 그대로 연결선 | 상대를 **고스트 노드**로 표시 |

- **그룹 뷰의 배치는 독립이다.** 그룹 뷰에서 옮겨도 전체 뷰 배치는 그대로다. 그룹 뷰 좌표가 아직 없는 테이블은 전체 좌표를 시작점으로 쓴다.
- 전체 뷰에서 **색상 영역을 드래그하면 소속 테이블이 함께 이동**한다. 영역의 빈 곳을 클릭하면 선택이 해제되고, 라벨을 클릭하면 그룹이 선택된다.
- **고스트 노드**는 그룹 뷰에서 그룹 밖 테이블을 헤더만 반투명하게 보여주는 노드다. 「외부 참조 — 클릭해 이동」 안내가 붙고, 클릭하면 그 테이블이 속한 그룹 뷰(미분류면 전체 뷰)로 이동한다. 드래그·선택·연결은 되지 않는다.
- 그룹 뷰를 보는 중에 다른 사람이 그 그룹을 지우면 자동으로 전체 뷰로 떨어진다. 그룹이 하나도 없으면 「뷰 전환」 드롭다운 자체가 나타나지 않는다.

## 9. 도메인

**무엇** — 도메인은 컬럼의 타입·기본값·허용값을 묶은 재사용 단위다. 「금액」이나 「상태코드」처럼 프로젝트 전체에서 같은 규격을 써야 하는 컬럼에 붙인다.

**어디서** — 에디터 헤더 「사전·리소스」 → 「도메인」. 다이얼로그 설명은 「공통 컬럼 타입·기본값·허용값을 재사용 단위로 관리합니다」다.

**어떻게 — 정의** — 「도메인 추가」 → 「이름」과 「논리 타입」(예: `DECIMAL(15)`, `INT UNSIGNED`)을 넣는다(둘은 필수이고 하나라도 비면 「저장」이 잠긴다). 「분류」를 넣으면 목록이 그 분류로 묶인다(비우면 「미분류」). 「방언별 물리 타입 (선택)」에는 「PostgreSQL」·「MySQL·MariaDB」·「Oracle」·「MSSQL」 네 칸이 있어 방언별 타입을 따로 지정할 수 있고, 비우면 논리 타입을 방언별로 자동 변환한다. 「기본값」, 「허용값 (쉼표로 구분)」(예: `ACTIVE, INACTIVE`), 「설명」을 채우고 「저장」한다.

**어떻게 — 컬럼에 지정** — 편집 패널의 컬럼 행에서 「도메인」 드롭다운으로 고른다. 지정하면 그 컬럼의 「타입」 칸이 잠기고 도메인의 논리 타입이 표시된다. 「없음」으로 되돌리면 다시 직접 입력할 수 있다.

**어떻게 — 수정과 일괄 반영** — 목록에서 연필 아이콘으로 편집한다. **도메인은 값을 복사하지 않고 항상 살아 있는 참조**라서, 저장하면 그 도메인을 쓰는 모든 컬럼에 즉시 반영된다. 사용 중이면 저장할 때 「N개 컬럼에 영향을 줍니다. 계속할까요?」로 확인한다.

**제약**

- **삭제 가드**: 사용 중인 도메인은 지울 수 없다. 목록에 「사용처 N개」가 표시되고 그 동안 휴지통이 잠긴다. 먼저 컬럼에서 도메인을 해제해야 한다.
- DDL에 반영되는 것은 셋이다. **타입**(그 방언의 물리 타입이 있으면 그것, 없으면 논리 타입을 변환한 값), **CHECK 제약**(허용값이 있으면 `CHECK (컬럼 IN (…))`, 논리 타입이 부호 없음이고 MySQL 이 아니면 `CHECK (컬럼 >= 0)` — 둘 다 있으면 둘 다 나간다), **기본값**(컬럼에 자체 기본값이 있으면 그것이 이기고 없으면 도메인 기본값). 부호 없음의 `CHECK` 는 **방언별 물리 타입을 지정해도 나간다** — 오버라이드는 저장 형태에 대한 것이고 `CHECK` 는 값에 대한 것이라 서로 배타적이지 않다.
- 도메인은 Excel 「도메인정의서」 시트로 내보내고 업로드로도 등록할 수 있다(→ [15절](#15-내보내기), [16절](#16-가져오기)).

### 9.1 테이블 옵션(`ENGINE`·`CHARSET`)

**무엇** — DDL 로 내보낼 때 `CREATE TABLE` 의 닫는 괄호 뒤에 그대로 붙는 문자열이다.
MySQL 의 `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4` 처럼 **실무에서 프로젝트 전체가 같은 값을 쓰는
물리 배포 설정**이라 테이블별이 아니라 프로젝트 설정에 둔다. 모든 테이블에 같은 값이 붙는다.

**어디서** — 프로젝트 설정(`/p/:projectId/settings`) → 「테이블 옵션」. **관리 권한**이 있어야
보인다. 로컬 모드에서도 보인다.

**어떻게** — 「PostgreSQL」·「MySQL」·「Oracle」·「MSSQL」 네 칸이 있고 **해당 방언으로 내보낼 때만**
그 칸의 값이 붙는다. 입력란에서 포커스를 빼면(다른 곳을 클릭하거나 Tab) 저장된다. 방언마다 문법이
달라 칸을 나눈 것이다 — 한 문자열을 네 방언에 다 붙이면 MySQL 의 `ENGINE=` 이 PostgreSQL DDL 뒤에
나가 아예 실행되지 않는다. 예: mysql `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4`,
oracle `TABLESPACE users`, mssql `ON [PRIMARY]`.

**제약**

- **값을 검증하지 않는다**(도메인의 「방언별 물리 타입」과 같은 방침). 잘못 적으면 그 방언의 DDL 이
  실패하고, 그것은 즉시 보이는 실패다.
- ⚠️ **`COMMENT=` 를 적지 마라.** 옵션은 테이블 코멘트보다 **앞**에 나가므로, 그 DDL 을 다시
  가져오면 여기 적은 `COMMENT=` 가 테이블 코멘트로 읽힌다.
- 비워 두면 아무것도 붙지 않는다 — 옵션을 쓰지 않는 프로젝트의 산출물은 한 글자도 달라지지 않는다.
- DBML 에는 나가지 않는다(DBML 에 테이블 옵션 문법이 없다).
- DDL 을 **가져올 때**도 이 값을 채울 수 있다(→ [16절](#16-가져오기)).

## 10. 명명 체계(단어·용어 사전)

**무엇** — 논리명에서 물리명을 자동으로 만들기 위한 사전이다. **단어**는 "고객"→`CUST` 처럼 낱말 하나의 표준 약어이고, **용어**는 "고객주문번호"→`CUST_ORD_NO` 처럼 **논리명 전체**에 대한 표준 물리명이다(기본 도메인도 함께 지정할 수 있다).

**어디서** — 에디터 헤더 「사전·리소스」 → 「단어·용어 사전」. 제목은 「단어·용어 사전」이고 「단어」·「용어」·「미등록 항목」·「가져오기」 네 탭이 있다.

**어떻게 — 물리명 생성 규칙**

1. **용어 완전일치가 먼저다.** 논리명 전체와 정확히 같은 용어가 있으면 그 용어의 물리명을 쓰고, 용어에 도메인이 지정돼 있으면 컬럼 도메인까지 함께 채운다.
2. 없으면 **단어 사전으로 최장 일치 분해**한다. 논리명을 앞에서부터 읽으며 가장 긴 단어를 먼저 맞추고, 각 단어의 약어를 구분자 `_`로 이어 붙여 대문자로 만든다.
3. 어느 단어에도 안 맞는 구간은 결과에서 빠지고 **미등록 단어**로 보고된다.

이 규칙은 편집 패널에서 논리명을 넣을 때, 논리명 칸의 ↑(「물리명 채우기」)를 누를 때, 이름을 치는 동안 자동완성 후보를 낼 때, 교차 테이블 이름을 만들 때, DDL을 가져와 물리명에서 논리명을 되돌릴 때 모두 같이 쓰인다.

**어떻게 — 등록** — 「단어」 탭 → 「단어 추가」 → 「약어」·「논리명」(필수), 「영문명」·「설명」(선택) → 「저장」. 「용어」 탭 → 「용어 추가」 → 「물리명」·「논리명」(필수), 「도메인」·「설명」(선택) → 「저장」(탭 설명은 「논리명 전체가 완전일치할 때 우선 적용되는 표준 물리명을 관리합니다」다). 두 목록 모두 「사용처 N개」가 표시되고 연필·휴지통으로 수정·삭제한다. 편집 패널의 컬럼 행에서 「용어 등록」을 눌러도 그 컬럼의 논리명·물리명·도메인이 그대로 용어로 등록된다.

**어떻게 — 용어 수정과 사용처 반영** — 이미 쓰이는 용어를 고치면 「"〈용어〉" 용어를 쓰는 N곳을 함께 갱신할까요?」 확인 창이 뜬다. 어디의 무엇이 어떻게 바뀌는지 목록이 보이고 「N곳에 반영」과 「유지」 중에 고른다. 「유지」는 용어만 바꾸고 사용처는 그대로 둔다.

**어떻게 — 미등록 항목 모아 등록** — 「미등록 항목」 탭(건수는 두 방향 후보 수의 합이고, 0이면 괄호가 붙지 않는다) 안에 **방향별 하위 탭 2개**가 있다. 기본은 「논리명 → 약어」이고, 각 하위 탭 이름 뒤 괄호에 그 방향의 건수가 붙는다. 「논리명 → 약어」는 테이블·컬럼 논리명을 분해하다 사전에 없던 단어의 목록이다 — 각 후보 오른쪽 「약어」 칸에 약어를 넣고 「일괄 등록」을 누르면 **약어를 입력한 항목만** 한 번의 편집으로 등록된다. 「물리명 → 논리명」은 그 반대다 — 물리명을 분해하다 사전에 없던 약어의 목록이고, 각 후보 오른쪽 「논리명」 칸에 논리명을 넣고 같은 「일괄 등록」을 누르면 **논리명을 입력한 항목만** 등록된다. 이쪽은 이름을 직접 치므로 **사전에 이미 있는 이름이거나 목록 안에서 서로 겹치면** 그 행에 「사전에 이미 있습니다」·「위 항목과 겹칩니다」가 뜨고 그 항목은 등록에서 빠진다. 하위 탭을 옮기면 입력하던 값은 비워진다(후보 집합이 통째로 다르다). 둘 다 결과는 같은 단어 사전에 추가되는 것이다.

> 낱개로 하나만 등록할 거라면 이 화면까지 오지 않아도 된다 — 편집 패널의 이름 아래 「미등록」 칩에서 그 자리에 등록할 수 있다(→ [5절](#5-테이블과-컬럼)).

**제약**

- 사전은 **프로젝트별**이다. 조직·전역의 표준 사전은 공용 리소스로 가져와야 들어온다(→ [13절](#13-공용-리소스)).
- 물리명 자동 생성은 다른 곳으로 포커스가 옮겨갈 때(blur) **물리명이 비어 있을 때만** 일어난다. 이미 값이 있으면 논리명을 고쳐도 물리명은 그대로다 — **Enter**를 치거나 **논리명 칸의 ↑**를 눌러야 덮어쓴다.
- 논리명 자동 복원도 대칭이다. 이미 값이 있으면 물리명을 고쳐도 논리명은 그대로고, **Enter**나 **물리명 칸의 ↓**가 덮어쓴다. 물리명을 사전 약어로 전부 분해할 수 없으면(사전에 없는 약어가 하나라도 있으면) 아무것도 채우지 않고, 화살표는 사유를 토스트로 알린다.
- 자동완성은 **접두일치**만 본다. 중간 일치·초성 검색은 아직 없다.
- 컬럼의 **도메인 자동 지정은 물리명이 비어 있던 경우에만** 일어난다. 물리명을 이미 채워 둔 컬럼의 논리명을 용어 이름으로 고쳐도 도메인은 그대로다 — 「도메인」 드롭다운에서 직접 고른다.
- 물리명 쪽 「미등록」 칩으로 등록할 때는 **약어가 그 칩으로 고정**된다 — 약어 자체를 다르게 쓰려면 사전 화면에서 등록한다.
- 용어와 실제 물리명이 어긋나면 모델 검사가 「용어 불일치」로 잡는다(→ [12절](#12-모델-검사)).

**어떻게 — 테이블 물리명 형식**

**무엇** — 테이블의 최종 물리명을 「접두 + 입력한 부분」으로 조합한다. `TB_{그룹별칭}_{물리명}` 이라고 적어 두면 그룹 별칭이 `MBR` 이고 물리명이 `ORD` 인 테이블은 DDL·DBML·Excel 에 `TB_MBR_ORD` 로 나간다. **비워 두면 입력한 물리명을 그대로 쓴다(기본값).**

**어디서** — 프로젝트 설정(`/p/:projectId/settings`) → 「명명 규칙」 → 「테이블 물리명 형식」. **관리 권한**이 있어야 보인다. 입력란 아래에 쓸 수 있는 변수 목록과 **미리보기**가 있다 — 현재 프로젝트의 테이블 하나에 형식을 적용한 결과가 즉시 뜬다(테이블이 하나도 없으면 가상 예시로 보여 준다). 입력란에서 포커스를 빼면(다른 곳을 클릭하거나 Tab) 저장된다.

| 변수 | 값 |
|---|---|
| `{그룹별칭}` | 소속 그룹의 별칭(그룹 패널에서 입력). 그룹이 없거나 별칭이 비면 빈 값 |
| `{그룹명}` | 소속 그룹 이름 |
| `{물리명}` | 편집 패널에 입력한 테이블 물리명 |
| `{논리명}` | 테이블 논리명 |
| `{커스텀:항목이름}` | 그 이름의 **테이블용** 커스텀 항목 값(없으면 정의 기본값, 그것도 없으면 빈 값) |

- **빈 자리의 밑줄이 접힌다.** 그룹이 없는 테이블은 `TB__ORD` 가 아니라 `TB_ORD` 로 나온다.
- **⚠️ 접기 규칙이 바뀌었습니다.** `TB_{그룹별칭}_LOG` 처럼 변수 뒤에 낱말이 붙은 형식을 쓰고 있었다면, 별칭이 빈 테이블의 결과가 `TB_` 에서 **`TB_LOG`** 로 달라집니다(지우는 단위가 「뒤 리터럴 통째」에서 「밑줄만」으로 좁아졌습니다). **이미 내보낸 DDL 과 새로 내보낸 DDL 의 테이블 이름이 갈립니다** — 그 형식을 쓰고 있었다면 한 번 확인하세요. 밑줄이 아닌 구분자(`TB_{그룹별칭}-LOG`)는 남습니다(`TB_-LOG`).
- **없는 변수를 적으면 그 자리가 빈다.** 오타(`{그룹별칙}`)를 내도 화면이 죽지 않고, 미리보기가 그 자리를 비워 보여 주므로 즉시 알아챈다.
- **편집 패널의 테이블 이름 칸 아래에 `물리 → TB_MBR_ORD` 로 조합 결과가 뜬다.** 형식이 비어 있으면 뜨지 않고, **컬럼에는 뜨지 않는다**(컬럼에는 형식이 없다). 논리명 형식도 걸려 있으면 그 아래에 `논리 → …` 줄이 하나 더 붙는다.

**어디에 적용되는가**

| 자리 | 값 |
|---|---|
| DDL(`CREATE TABLE`·외래 키·인덱스·코멘트) · DBML · Excel 정의서의 물리명 열 | **조합된 이름** |
| 모델 검사 — 물리명 중복(테이블)·길이 초과·예약어 | **조합된 이름** |
| 모델 검사 — 용어 불일치 | 입력한 물리명 |
| 편집 패널 입력란 · 사이드바 트리 · 복사 · CLI 파일 | 입력한 물리명 |

**제약**

- **저장되는 것은 입력한 부분뿐이다.** 접두는 저장하지 않으므로, 형식을 바꾸거나 그룹을 옮기면 최종 이름이 즉시 따라간다.
- 물리명이 비어도 접두가 있으면 DDL 에 나간다(`TB_MBR`). 다만 모델 검사의 「필수 값 누락」은 그대로 뜬다 — 채우라는 안내다.
- **왕복은 닫혀 있습니다.** 내보낸 DDL·DBML 의 **첫 줄에 `-- erdd:v2 {…}`(DBML 은 `// erdd:v2 …`) 주석 한 줄**이 실려, 어떤 최종 이름이 어떤 부분에서 나왔는지 적어 둡니다. 그 파일을 그대로 다시 가져오면 물리명 칸에 `ORD` 가 들어옵니다 — 접두를 손으로 지울 필요가 없습니다.
- **그 줄은 그룹도 함께 나릅니다.** 각 테이블이 **어느 그룹에 속했는지**와 그 그룹의 **별칭·색·코멘트**가 같이 실립니다. 되읽으면 그룹이 다시 만들어지고 테이블이 그 안에 들어갑니다. 같은 이름의 그룹이 이미 있으면 **그 그룹을 쓰고 기존 별칭·색·코멘트를 덮어쓰지 않습니다** — 머릿말의 별칭이 기존 것과 다르면 「머릿말의 별칭 … 과 기존 그룹의 별칭 … 가 달라 기존 값을 유지합니다」로 알립니다. **그룹의 화면 좌표는 복원되지 않습니다**(그룹 뷰를 처음 열 때 다시 배치됩니다).
- **⚠️ 그룹을 쓰면 형식이 없어도 DDL 첫 줄에 주석이 생깁니다.** 예전에는 형식을 안 쓰는 프로젝트의 산출물이 한 글자도 바뀌지 않았는데, 이제는 **내보내는 테이블 중 그룹에 속한 것이 하나라도 있으면** 그 줄이 나갑니다(프로젝트에 그룹이 있어도 **범위를 좁혀 그룹 없는 테이블만 내보내면** 그 줄은 안 나갑니다 — 머릿말은 내보내는 목록만 봅니다). 그래서 **이미 내보낸 DDL 과 새로 내보낸 DDL 이 그 한 줄만큼 갈립니다** — 산출물을 형상 관리에 넣고 그대로 비교하는 절차가 있다면 한 번은 걸립니다(내용 차이가 아니라 머릿말이 는 것입니다). **그룹도 형식도 안 쓰는 프로젝트**에서는 여전히 그 줄이 나가지 않습니다.
- 예전에 내보낸 `erdd:v1` 머릿말도 **그대로 읽습니다.** 다만 v1 에는 그룹 자리가 없어 물리명·논리명만 복원되고 그룹은 복원되지 않습니다.
- **⚠️ 다만 두 경우에는 옛 동작(접두가 물리명에 박힘)이 됩니다.**
  - 파일 **첫 줄의 `-- erdd:v2 …` 주석을 지우고** 가져온 경우
  - **`CREATE TABLE` 한 문장만 잘라 붙인** 경우 — 머릿말이 함께 오지 않아 표가 없습니다

  이때는 `TB_MBR_ORD` 가 통째로 물리명이 되고, 다시 내보내면 `TB_MBR_TB_MBR_ORD` 가 됩니다 — 가져온 뒤 접두를 손으로 지우세요. 남이 준 DDL(우리가 내보낸 것이 아닌 파일)도 같습니다. **그룹도 같이 못 살립니다** — 그룹 배정과 별칭·색·코멘트가 함께 사라집니다. DBML 만 예외로, `TableGroup` 블록을 같이 붙여넣으면 **그 블록이 말하는 그룹 배정·색·코멘트는 살아나고 별칭만 사라집니다**(DBML 의 `TableGroup` 블록에는 별칭을 적을 자리가 없습니다).

**어떻게 — 테이블 논리명 형식**

**무엇** — 테이블의 최종 논리명을 조합한다. `{그룹명}_{논리명}` 이라고 적어 두면 그룹 이름이 `회원관리` 이고 논리명이 `주문` 인 테이블은 DDL 코멘트·DBML note·Excel 논리명 열에 `회원관리_주문` 으로 나간다. **비워 두면 입력한 논리명을 그대로 쓴다(기본값).**

**어디서** — 프로젝트 설정(`/p/:projectId/settings`) → 「명명 규칙」 → 「테이블 논리명 형식」. 물리명 형식 입력란 바로 아래에 있다. **관리 권한**이 있어야 보이고, 같은 방식으로 미리보기가 붙고 포커스를 빼면 저장된다.

**쓸 수 있는 변수와 빈 자리 접기 규칙은 물리명 형식과 완전히 같다**(위 표).

**어디에 적용되는가**

| 자리 | 값 |
|---|---|
| DDL 코멘트(`COMMENT ON TABLE`·MySQL 인라인) · DBML note · Excel 정의서의 논리명 열 | **조합된 이름** |
| 용어 사전 조회 · 「미등록 단어」 칩 · 논리명 구분자 경고 | 입력한 논리명 |
| 물리명 자동 생성 | 입력한 논리명 |
| 편집 패널 입력란 · 사이드바 트리 · 캔버스 · CLI 파일 | 입력한 논리명 |

**제약**

- **⚠️ 산출물 전용입니다.** 사전 조회·단어 검사·물리명 생성은 **입력한 논리명**을 그대로 봅니다 — 그래야 사전에 `주문` 만 등록해 두면 되고, 형식을 바꿔도 사전이 어긋나지 않습니다.
- `{물리명}` 을 논리명 형식에 써도 **물리명 형식이 적용되기 전의 값**이 들어갑니다(두 형식이 서로를 되먹지 않습니다).
- 논리명과 물리명이 같아서 코멘트를 생략하는 판정은 **양쪽 다 조합된 이름**으로 합니다.
- **왕복은 논리명도 함께 닫힙니다.** 머릿말에 논리명 부분도 적히므로 되읽으면 `주문` 이 들어옵니다 — 코멘트의 조합 논리명(`회원관리_주문`)보다 **머릿말이 우선**입니다(설명은 코멘트에서 그대로 가져옵니다). 머릿말이 없으면 조합 논리명이 통째로 논리명 칸에 들어갑니다 — 물리명과 같은 성질입니다.
- 단어사전·용어사전 시트의 「논리명」 열은 단어·용어의 것이라 조합되지 않습니다.
- 논리명과 컬럼 물리명에는 형식이 없다.

## 11. 커스텀 항목

**무엇** — 테이블·컬럼에 프로젝트 고유의 관리 항목을 덧붙인다. "개인정보여부"나 "암호화방식"처럼 표준 모델에 없는 칸을 만든다.

**어디서** — 정의는 에디터 헤더 「사전·리소스」 → 「커스텀 항목」. 값 입력은 편집 패널의 테이블 영역과 각 컬럼 행에 나타나는 점선 상자 「커스텀 항목」이다.

**어떻게 — 정의** — 「커스텀 항목」 → 「항목 추가」 → 「이름」(필수) → 「적용 대상」(테이블/컬럼)과 「타입」을 고른다. 「기본값」을 넣으면 값을 입력하지 않은 대상에 그 값이 쓰이고, 「필수 (미입력 시 경고)」를 켜면 값이 빈 대상에 경고가 붙는다. 「저장」으로 마친다.

| 타입 | 화면 표기 | 값 입력 방식 |
|---|---|---|
| text | 「텍스트」 | 자유 입력 |
| boolean | 「불리언」 | 체크박스 |
| select | 「선택형」 | 드롭다운. 「선택지 (쉼표로 구분)」이 최소 1개 필요 |

**어떻게 — 값 입력** — 테이블·컬럼을 선택하면 「커스텀 항목」 상자가 나온다. 필수 항목이 비어 있으면 상자 제목 옆에 「필수」 표시가, 항목 이름 뒤에 `*`가 붙는다. 선택형에서 값을 비우려면 「선택 안 함」을 고른다.

**제약**

- **타입과 적용 대상은 만든 뒤 바꿀 수 없다** — 「타입과 적용 대상은 변경할 수 없습니다. 바꾸려면 삭제 후 다시 만드세요.」 불리언은 항상 값이 있어 필수로 지정할 수 없다(「불리언은 항상 값이 있으므로 필수로 지정할 수 없습니다.」).
- 선택형 기본값은 선택지 중 하나여야 하고 불리언 기본값은 `true`/`false`여야 한다. 어기면 저장이 잠기고 사유가 붉게 표시된다.
- 선택지를 지울 때 그 값을 쓰는 곳이 있으면 「삭제하는 선택지를 N곳에서 사용 중입니다. 값은 유지됩니다. 계속할까요?」로 확인한다. 값은 남고 드롭다운에 「〈값〉 (삭제된 선택지)」로 비활성 표시된다. 항목 자체를 지우면 입력된 값도 사라진다 — 「"〈이름〉"을(를) 삭제하면 입력된 값 N건도 함께 삭제됩니다. 계속할까요?」
- 목록의 위·아래 화살표로 정한 순서가 편집 패널과 Excel 정의서의 열 순서가 된다.

## 12. 모델 검사

**무엇** — 모델 전체를 훑어 명명 규칙 위반·구조 불일치·필수 항목 미입력을 모아 보여준다.

**어디서** — 에디터 헤더의 「모델 검사」. 경고가 있으면 「모델 검사 (N)」처럼 건수가 붙는다. 같은 경고는 캔버스 노드와 편집 패널에도 삼각형 배지로 표시되고 마우스를 올리면 내용이 보인다.

**어떻게** — 「모델 검사」를 누르면 경고가 종류별로 묶여 나온다. 항목을 클릭하면 다이얼로그가 닫히고 해당 테이블·관계가 선택된다(컬럼 경고는 그 컬럼이 속한 테이블로 이동한다). 경고가 없으면 「경고가 없습니다. 명명이 규칙에 부합합니다.」가 뜬다.

**경고 종류 전수**

| 화면 표기 | 등급 | 무슨 뜻인가 | 어떻게 해소하는가 |
|---|---|---|---|
| 「물리명 중복(컬럼)」 | 오류 | 같은 테이블 안에 물리명이 같은 컬럼이 둘 이상 | 한쪽 물리명을 바꾼다 |
| 「물리명 중복(테이블)」 | 오류 | 물리명이 같은 테이블이 둘 이상 | 한쪽 테이블 물리명을 바꾼다 |
| 「매핑 불완전」 | 경고 | 부모 기본 키 개수와 관계의 컬럼 매핑 수가 다르다 | 부모 PK 구성을 맞추거나 관계를 다시 만든다 |
| 「타입 불일치」 | 경고 | 매핑된 부모·자식 컬럼의 타입이 다르다 | 한쪽 타입(또는 도메인)을 상대에 맞춘다 |
| 「미등록 단어」 | 경고 | 논리명 안에 단어 사전에 없는 구간이 있다 | 편집 패널의 「미등록」 칩에서 바로 등록하거나, 사전 「미등록 항목」 탭의 「논리명 → 약어」에서 모아 등록한다 |
| 「용어 불일치」 | 경고 | 논리명과 완전일치하는 용어가 있는데 물리명이 그 표준과 다르다 | 논리명 칸의 ↑로 다시 만들거나 용어를 고친다 |
| 「논리명 구분자 없음」 | 경고 | 논리명이 두 단어 이상으로 갈리는데 밑줄 구분자가 없다 | 메시지가 알려 주는 형태(「회원_주문」)로 고치거나, 프로젝트 설정에서 「논리명을 밑줄로 구분」을 끈다 |
| 「길이 초과」 | 경고 | 물리명이 최대 길이(기본 30바이트)를 넘는다 | 더 짧은 약어를 쓰거나 물리명을 줄인다 |
| 「예약어」 | 경고 | 물리명이 프로젝트 대상 방언 중 하나의 예약어다 | 물리명을 바꾼다 |
| 「필수 항목 미입력」 | 경고 | 필수로 지정한 커스텀 항목이 비어 있다 | 값을 채우거나 필수 지정을 해제한다 |
| 「필수 값 누락」 | 경고 | 커스텀 항목이 아니라 **표준 필드**(테이블의 논리명·물리명, 컬럼의 논리명·물리명·타입)가 비어 있다 | 값을 채운다 |

- 물리명 중복 둘만 **오류**(빨간 원형 아이콘)이고 나머지는 경고(노란 삼각형)다.
- 「물리명 중복(테이블)」·「길이 초과」·「예약어」는 **테이블 물리명 형식이 걸린 프로젝트에서 조합된 최종 이름**으로 판정한다 — 다른 그룹의 같은 이름은 중복이 아니고, 접두를 더해 길이를 넘기면 잡힌다(→ [10절](#10-명명-체계단어용어-사전)).
- 「길이 초과」는 바이트 기준이라 한글 물리명은 글자 수보다 훨씬 빨리 상한에 닿는다.
- 「예약어」는 프로젝트를 만들 때 고른 방언만 검사한다. 그 목록에 없는 DB의 예약어는 잡히지 않는다.
- 「매핑 불완전」·「타입 불일치」는 관계당 최대 1건씩 보고된다.
- 검사에 걸려도 저장·내보내기가 막히지 않는다. 실제로 막히는 것은 모델 무결성 위반뿐이고, 그때는 편집 자체가 거절되며 사유가 토스트로 뜬다.

## 13. 공용 리소스

> **로컬 모드에는 없다** — 라이브러리·승격·승격 요청이 모두 없다(→ [로컬 모드 매뉴얼 4.2](./local-guide.md#42-사용-매뉴얼의-어느-장이-해당하나)).

**무엇** — 표준 **단어·용어·도메인·커스텀 항목**을 프로젝트 밖에 모아 두고 여러 프로젝트가 나눠 쓰는 장치다. 라이브러리는 **전역**(서비스 전체)과 **조직** 2계층이고, 실제 모델이 참조하는 것은 언제나 프로젝트로 **복사된 사본**이다. 방향이 둘 있다 — **가져오기(재동기화)**(라이브러리 → 프로젝트)와 **승격**(프로젝트 → 라이브러리, 권한이 없으면 **요청**).

**어디서** — 프로젝트 쪽은 에디터 헤더 「사전·리소스」 → 「공용 리소스」이고 탭이 「가져오기」·「조직으로 승격」 둘이다. 라이브러리 자체를 만들고 항목을 넣는 화면은 조직 상세의 「조직 공용 리소스」와 `/admin`의 「전역 공용 리소스」다. 승격 요청 승인은 조직 상세의 「승격 요청」 절이다.

### 가져오기(재동기화)

1. 「공용 리소스」 → 「가져오기」 → 왼쪽에서 라이브러리를 고른다(「전역」/「조직」과 항목 수가 함께 표시된다).
2. 오른쪽에 항목이 세 구역으로 나뉘어 나온다.

| 구역 | 뜻 | 기본 선택 |
|---|---|---|
| 「신규 추가」 | 프로젝트에 아직 없는 항목 | 선택됨. 단 같은 이름이 이미 있으면(「이름 중복」 배지) 해제 |
| 「자동 갱신」 | 가져온 뒤 프로젝트에서 손대지 않았는데 원본이 바뀐 항목 | 선택됨 |
| 「충돌」 | 프로젝트에서도 고쳤고 원본도 바뀐 항목 | 「보류」 |

3. 충돌 항목은 필드별로 「현재 〈값〉 → 원본 〈값〉」이 보인다. 셋 중 하나를 고른다. 「원본 반영」은 원본 값으로 덮고, 「프로젝트 유지」는 내용을 그대로 두고 **이 변경을 검토했다고 기록하며**(다음에 다시 뜨지 않는다), 「보류」는 아무것도 기록하지 않아 다음에 다시 뜬다.
4. 구역별 「모두 선택」/「모두 해제」(충돌은 「모두 원본 반영」/「모두 프로젝트 유지」)로 일괄 처리한다.
5. 아래 「유지」 절에서 손대지 않는 항목 수를 확인한다 — 「최신 상태 N건 · 프로젝트 자체 항목 N건」, 원본에서 삭제된 항목이 있으면 「원본에서 삭제된 항목 N건 — 프로젝트 사본은 그대로 둡니다.」
6. 「적용」을 누른다. 오른쪽에 「처리 대상 N건」이 표시된다.

**제약** — 최초 가져오기는 「전 항목이 신규인 재동기화」와 같아 별도 메뉴가 없다. 한 번에 적용할 수 있는 항목은 5,000건이고 넘으면 「한 번에 5000건까지 적용할 수 있습니다. 나눠 선택해 주세요.」가 뜬다. 적용은 편집 1건이라 **실행 취소 한 번으로 되돌아간다**. 원본에서 항목이 삭제돼도 프로젝트 사본은 지워지지 않는다.

### 승격 · 승격 요청

1. 「공용 리소스」 → 「조직으로 승격」 → 올릴 라이브러리를 고른다.
2. 항목이 세 구역으로 나온다.

| 구역 | 뜻 | 기본 선택 |
|---|---|---|
| 「신규 추가」 | 라이브러리에 없는 항목 | 선택됨 |
| 「원본 갱신」 | 이미 연결된 라이브러리 항목을 이 프로젝트 값으로 올린다 | 선택됨 |
| 「동명 발견」 | 같은 이름의 다른 항목이 라이브러리에 있다 | **해제** — 사람이 확인해야 한다 |

「동명 발견」에는 「대상 라이브러리에 같은 이름의 항목이 있습니다. 선택하면 그 항목을 이 프로젝트의 값으로 갱신하고 연결합니다.」가 함께 표시된다. 도메인을 참조하는 용어를 올리는데 그 도메인을 함께 고르지 않았으면 「도메인 연결 비움」 배지가 붙는다.

3. **쓰기 권한이 있으면** 버튼이 「승격」이다. 누르면 바로 올라가고 결과가 토스트로 나온다.
4. **권한이 없으면** 버튼이 「승격 요청」이고 위에 「요청 메모 (선택)」 칸이 생긴다. 요청하면 라이브러리는 그대로이고 요청 행만 남는다. 이미 반영됐거나 삭제된 항목은 자동으로 빠지며 그 수가 함께 안내된다. 대기 중인 내 요청은 같은 탭 위쪽 「대기 중인 요청」 상자에 요청자·건수·메모로 보이고 「요청 취소」로 닫을 수 있다.

**어떻게 — 승인(조직 관리자)**

1. 상단바에 「승격 요청 N건」 배지가 뜬다. **이 배지가 요청이 승인자에게 닿는 유일한 경로다**(메일 알림은 없다). 60초마다 갱신되고 조직이 하나면 그 조직으로, 여럿이면 홈으로 이동한다. 홈의 조직 카드에도 같은 배지가 붙는다.
2. 조직 상세의 「승격 요청」 절에서 상태 필터(「대기 중」·「승인됨」·「반려됨」·「취소됨」)로 목록을 본다. 표는 프로젝트·라이브러리·요청자·항목·메모다.
3. 대기 중 행의 「검토」로 「승격 요청 검토 — 〈프로젝트명〉」 다이얼로그를 연다. 계획은 그 시점에 서버가 계산해 내려준다.
4. 올릴 항목을 고르고 「처리 메모 (선택)」를 남긴다. 버튼은 고른 항목 수에 따라 바뀐다 — 하나라도 고르면 「N건 승격」, 아무것도 고르지 않으면 「반려」다. **반려는 요청을 닫는다.**

**제약**

- 승격 요청 대상은 **조직 라이브러리뿐**이다. 전역 라이브러리는 쓰기 권한이 있는 사람(서비스 역할 `admin`)이 직접 승격한다.
- 요청은 한 번 처리하면 닫힌다. 처리된 행은 읽기 전용 이력이고 「검토」 버튼이 없다. 승인자가 남긴 처리 메모는 이 목록의 「처리 메모」 칸에서만 볼 수 있고 반려 사유도 같은 칸이다.
- 라이브러리를 지우면 항목도 함께 지워진다(「"〈이름〉"을(를) 삭제하면 항목 N개도 함께 삭제됩니다. 계속할까요?」). 항목 하나를 지울 때는 「"〈이름〉"을(를) 삭제할까요? 이미 가져간 프로젝트의 사본은 그대로 남습니다.」로 확인한다.
- 항목에는 버전 번호(`v1`, `v2`…)가 붙고 재동기화·승격 화면이 「v2 → v3」처럼 표시한다.

## 14. 버전(이력·스냅샷·비교)

> **로컬 모드에서는 다르다** — 「이력」 탭이 없고(그 자리를 git 커밋이 맡는다), 스냅샷은 `erdd/snapshots/`에 담겨 **커밋된다**. 미저장 편집이 있으면 스냅샷을 만들 수 없고, 「복원」은 화면만 되돌리므로 「저장」해야 파일에 반영된다(→ [로컬 모드 매뉴얼 6절](./local-guide.md#6-스냅샷)).

**무엇** — 편집 이력(리비전), 이름 붙인 시점 저장(스냅샷), 두 시점의 차이 비교를 한 화면에서 다룬다.

**어디서** — 에디터 헤더의 「버전」. 안에 「스냅샷」·「이력」·「비교」 세 탭이 있다.

**어떻게 — 이력** — 「이력」 탭에 편집이 최신부터 나열된다. 각 줄은 「#〈번호〉 〈요약〉」과 함께 실행자·시각을 보여주고, 오른쪽에 출처 배지가 붙는다 — `web`(웹 UI), `cli`(CLI), `system`(복원 등 시스템 작업). 더 있으면 「더 보기」로 이어 붙인다.

**어떻게 — 스냅샷** — 「스냅샷」 탭에서 「이름」(예: 「배포 전 백업」)을 넣고 「스냅샷 만들기」를 누른다. 목록 항목을 클릭하면 요약이 펼쳐진다(테이블 개수와 앞 5개 물리명). 「복원」은 「"〈이름〉" 스냅샷으로 복원할까요? 현재 편집 중인 내용이 대체됩니다.」로 확인한 뒤 그 시점으로 되돌리고, 다이얼로그가 닫히며 화면이 다시 로드된다. 「삭제」는 「"〈이름〉" 스냅샷을 삭제할까요?」로 확인한다.

**어떻게 — 비교**

1. 「비교」 탭의 「기준」·「비교」 드롭다운에서 각각 「현재」(편집 중인 모델)나 스냅샷을 고른다. 기본값은 기준=가장 최근 스냅샷, 비교=「현재」다.
2. 아래에 「추가 N · 삭제 N · 변경 N」과 변경 목록이 나온다. 각 줄은 종류(테이블·컬럼·관계·인덱스·그룹·도메인·단어·용어·커스텀 항목·메모), 대상 이름, 변경 유형(추가/삭제/변경)이고 변경된 속성은 「이전값 → 이후값」으로 펼쳐진다. 대상 이름이 링크처럼 보이면 클릭해 그 엔티티로 이동한다.
3. 「변경분 정의서」로 차이만 담은 `erdd_변경분정의서.xlsx`를 내려받는다. 시트 맨 위에 「기준: 〈…〉 · 비교: 〈…〉」이 적힌다.

**제약**

- **스냅샷 복원·삭제는 프로젝트를 관리할 수 있는 사람만** 할 수 있다(Org Owner/Admin 또는 Project Admin). 그 외에는 「복원」·「삭제」 버튼이 보이지 않는다.
- 복원은 이력에 `system` 출처로 남고, 복원 자체를 실행 취소로 되돌릴 수는 없다 — 실행 취소 이력이 비워진다.
- 스냅샷을 만들 때 넣을 수 있는 것은 이름뿐이다. 목록의 설명 칸은 값이 없어 「설명 없음」으로 표시된다.
- 비교하려면 스냅샷이 최소 하나 필요하다. 없으면 「비교하려면 스냅샷이 하나 이상 필요합니다. 아직 스냅샷이 없습니다」가 뜬다. 현재 모델에 없는 대상(삭제된 테이블 등)은 클릭해 이동할 수 없다.
- 이력에는 편집 요약만 남는다. 어떤 변경이 나갔는지 상세를 보는 화면은 없다.

## 15. 내보내기

**무엇** — 설계 결과를 실행 가능한 DDL, 문서 발행용 DBML, 공유용 이미지, 제출용 Excel 정의서로 내보낸다. 모델을 바꾸지 않는 읽기 전용 기능이다.

**어디서** — 에디터 헤더 「파일」 → 「내보내기」. 안에 「DDL」·「DBML」·「이미지」·「Excel」 네 탭이 있다.

### DDL

1. 「방언」을 고른다 — 「PostgreSQL」·「MySQL·MariaDB」·「Oracle」·「MSSQL」.
2. 「범위」를 고른다 — 「전체」 또는 그룹 드롭다운에서 그룹 하나. 그룹 뷰를 보던 중에 다이얼로그를 열면 그 그룹이 기본 선택된다.
3. 「DDL 미리보기」에 결과가 즉시 나온다.
4. 「복사」로 클립보드에 담거나 「다운로드」로 `erdd_〈방언〉.sql`을 받는다.

| 구성 | 설명 |
|---|---|
| `CREATE TABLE` | 컬럼 타입·NOT NULL·기본값·자동증가(방언별 문법), 기본 키. **MySQL·MariaDB 는 NULL 을 허용하는 `TIMESTAMP` 컬럼에 `NULL` 을 함께 적는다** — 서버 설정에 따라 그 컬럼이 제멋대로 `NOT NULL` 이 되고 값이 수정될 때마다 현재 시각으로 바뀌는 것을 막는다 |
| CHECK 제약 | 도메인 허용값이 있는 컬럼에 `컬럼 IN (…)` |
| 외래 키 | `ALTER TABLE … ADD CONSTRAINT … FOREIGN KEY`. 1:1 관계는 UNIQUE 제약이 함께 나간다 |
| 인덱스 | `CREATE [UNIQUE] INDEX`, 구성 컬럼의 정렬 방향 포함 |
| 코멘트 | 테이블·컬럼 코멘트. PostgreSQL·Oracle은 `COMMENT ON`, MSSQL은 확장 속성, MySQL은 `CREATE TABLE` 안에 인라인 |

**테이블 이름** — 프로젝트 설정의 「테이블 물리명 형식」이 비어 있지 않으면 `CREATE TABLE`·외래 키·인덱스·코멘트가 **모두** 조합된 이름을 쓴다(→ [10절](#10-명명-체계단어용어-사전)).

**제약** — 컬럼이 하나도 없는 테이블은 빠지고 「〈테이블〉: 컬럼이 없어 내보내기에서 제외됨」이 「DDL 경고」 에 뜬다. **물리명이 빈 테이블, 또는 물리명이 빈 컬럼을 가진 테이블도 같은 방식으로 빠지고** 「〈테이블 또는 논리명〉: 물리명이 비어 있어 내보내기에서 제외됨」이 뜬다 — 식별자를 만들 수 없기 때문이다. 방언 변환이 확실하지 않은 타입도 경고로 나오고, 해석하지 못한 타입은 입력 원문을 그대로 출력한다. 범위 밖 테이블과 이어진 관계·인덱스는 함께 빠진다.

### DBML

「DBML」 탭은 dbdocs·dbdiagram.io 가 읽는 DBML 을 낸다. 주 용도는 **dbdocs 문서 발행**이다.

1. 「방언」과 「범위」를 고른다 — **DDL 탭과 같은 선택을 공유한다**(탭을 오가도 유지된다). 타입 해석도 DDL 과 같다(도메인의 방언별 매핑 포함).
2. 「DBML 미리보기」에 결과가 즉시 나온다.
3. 「복사」로 클립보드에 담거나 「다운로드」로 `erdd_〈방언〉.dbml` 을 받는다.

| 구성 | 설명 |
|---|---|
| `Project` | 프로젝트명과 `database_type`(고른 방언). 프로젝트명이 있을 때만 나간다 |
| `Table` | 그룹에 속하면 `headercolor`, `note` 에 「논리명 - 설명」 |
| 컬럼 설정 | `pk`(단일 기본 키) · `increment` · `not null` · `null` · `default` · `note`. `null` 은 **MySQL·MariaDB 방언에서 NULL 을 허용하는 `TIMESTAMP` 컬럼에만** 붙고, 기본 키 컬럼에는 붙지 않는다 |
| `indexes` 블록 | 인덱스(이름·`unique`)와 **복합 기본 키**(`[pk]`) |
| `TableGroup` | 그룹 이름과 `color`, 소속 테이블 목록 |
| `Ref` | 관계. 1:N 은 `>`, 1:1 은 `-`. 합성키는 괄호로 묶고, **이름을 지어 둔 관계만** 이름이 붙는다 |

**커스텀 항목 값**은 note 끝에 JSON 으로 붙는다 — 예: `회원 - 회원 기본정보 {"보안등급":"2"}`. 키는 커스텀 항목 **정의의 이름**이고, 값이 빈 항목은 나가지 않는다.

**제약** — 테이블 선정과 경고는 DDL 과 완전히 같다(0컬럼·빈 물리명 테이블 제외). 도메인 허용값을 `enum` 으로 내지는 않는다 — 되읽을 때 도메인으로 되돌릴 방법이 없어 「이름만 남은 타입」이 되기 때문이다. 메모·색상 영역·좌표는 DBML 에 담기지 않는다.

### 이미지

「이미지」 탭에서 「PNG」/「SVG」를 고르고 「다운로드」를 누른다. 「현재 화면(뷰·보기 모드)이 그대로 저장됩니다」 — 전체 뷰/그룹 뷰와 논리명·물리명·혼합 설정이 반영된다. 다만 현재 팬·줌과 무관하게 **모든 노드가 다 들어가도록** 전체를 담는다. 노드가 없으면 「내보낼 노드가 없습니다」로 실패한다. 이미지 범위는 따로 고를 수 없다 — 좁히려면 그룹 뷰로 전환한 뒤 내보낸다.

### Excel 정의서

「Excel」 탭에서 「범위」(「전체」 또는 그룹)를 고르고, 「시트」에서 내보낼 시트를 켠 뒤(기본은 전부 켜짐) 「다운로드」로 `erdd_정의서.xlsx`(그룹을 골랐으면 `erdd_정의서_〈그룹명〉.xlsx`)를 받는다. 워크북 순서는 아래와 같다.

| 시트 | 열 |
|---|---|
| 「테이블 목록」 | 그룹 · 논리명 · 물리명 · 설명 (+ 테이블 커스텀 항목) |
| 「테이블정의서」 | 그룹 · 테이블 논리명 · 테이블 물리명 · 순번 · 논리명 · 물리명 · 도메인 · 타입 · PK · NOT NULL · 기본값 · 설명 (+ 컬럼 커스텀 항목) |
| 「단어사전」 | 논리명 · 약어 · 영문명 · 설명 |
| 「용어사전」 | 용어 · 구성 단어 · 물리명 · 기본 도메인 · 설명 |
| 「도메인정의서」 | 이름 · 분류 · 논리 타입 · PostgreSQL · MySQL · Oracle · MSSQL · 기본값 · 허용값 · 설명 |

「변경분 정의서」 시트는 이 목록에 없다 — 비교 화면에서만 만든다(→ [14절](#14-버전이력스냅샷비교)).

**제약** — 「범위는 테이블 목록·테이블정의서에만 적용됩니다. 사전 3종은 항상 전체를 내보냅니다」 — 사전은 그룹 개념이 없는 프로젝트 전역 자산이다. 시트를 하나도 켜지 않으면 「다운로드」가 잠긴다. 모든 셀은 문자열로 쓴다 — 물리명 `0001`의 앞 0이 사라지지 않고 업로드 파서와 표현이 대칭이 된다. 도메인 허용값은 `, `로 이어 붙이므로 값 자체에 쉼표가 든 허용값은 업로드로 되돌릴 때 정확히 복원되지 않는다 (알려진 한계).

## 16. 가져오기

**무엇** — 두 가지 역방향 경로다. 기존 DB의 **DDL(또는 DBML)을 붙여넣어 모델로 되돌리는 역설계**, 그리고 정해진 양식의 **Excel로 사전을 한 번에 등록하는 업로드**.

### DDL·DBML 가져오기

**어디서** — 에디터 헤더 「파일」 → 「DDL·DBML 가져오기」(다이얼로그 제목도 같다). 편집 권한이 없으면 메뉴에 이 항목이 없다.

1. 맨 위에서 형식을 고른다 — 「DDL」(기본) 또는 「DBML」. 형식을 바꾸면 수동으로 고른 방언이 초기화된다(형식마다 자동 감지 결과가 다르다).
2. 「방언」을 확인한다. 붙여넣은 내용으로 자동 감지되며(DBML 은 `Project { database_type }` 으로) 해당 항목에 「(자동 감지)」가 붙는다. 드롭다운에서 언제든 바꿀 수 있다.
3. 텍스트 영역에 붙여넣는다(「CREATE TABLE ... 형태의 DDL을 붙여넣으세요」 / 「Table "..." { ... } 형태의 DBML을 붙여넣으세요」).
4. 미리보기가 즉시 나온다 — 「테이블 N개 · 컬럼 N개 · 관계 N개 · 인덱스 N개」, DBML 에 그룹이 있으면 「· 그룹 N개」, 건너뛴 테이블이 있으면 「건너뜀 N개 (이름이 겹침: …)」 — 나열되는 것은 **DDL 원문 이름**이고, 무엇과 겹쳤는지는 그 아래 경고 목록이 테이블마다 적는다(머릿말이 이름을 되돌린 경우 둘이 다르다).
5. 「가져오기 경고」 목록을 확인한다.
6. 테이블 옵션이 잡혔고 프로젝트의 현재 값과 다르면 **「프로젝트의 테이블 옵션도 갱신」 체크박스**가 뜬다(→ 아래 「테이블 옵션」). **관리 권한이 있어야 보인다.**
7. 「〈N〉개 테이블 만들기」를 누른다. 테이블·컬럼·관계는 한 번의 편집으로 반영되므로 실행 취소 한 번으로 되돌아간다.

**테이블 옵션**

DDL 의 `) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4` 같은 꼬리 절에서 `ENGINE`·`DEFAULT CHARSET`·
`COLLATE` 만 뽑아 한 줄로 정규화하고, 테이블마다 다르면 **가장 많이 쓰인 것을 채택**한다(동수면
DDL 에 먼저 나온 것). 채택값과 다른 테이블마다 경고 1건이 뜬다. `AUTO_INCREMENT=` 시작값처럼
테이블별 값은 버린다 — 프로젝트 설정으로 올리면 모든 테이블의 시작값을 바꾸게 된다.

체크박스의 초기 상태는 프로젝트의 그 방언 칸이 **비어 있으면 켬**, **값이 있고 다르면 끔**이다.
설정해 둔 값을 조용히 덮어쓰지 않기 위해서다. 언제든 뒤집을 수 있다.

⚠️ **되돌리기가 갈린다.** 테이블 생성은 실행 취소로 되돌아가지만 **프로젝트 설정은 되돌아가지
않는다** — 설정은 편집 이력 밖이다. 다이얼로그도 그 사실을 문구로 알린다.

**부호 없음**

`int unsigned` 같은 표기는 논리 타입 `INT UNSIGNED` 로 들어온다. 정수 3종
(`SMALLINT`·`INT`·`BIGINT`) 밖에 붙은 부호 없음(`decimal(10,2) unsigned` 등)은 **떨어뜨리고 경고**
한다. MySQL 5.7 이 내는 정수 표시폭(`int(11)`·`bigint(20)`)은 읽어서 버린다 — 8.0.17 부터
deprecated 인 표시 전용 값이다.

**형식에 따라 갈리는 것은 파서뿐이다** — 방언 선택·미리보기·경고·op 상한·적용은 완전히 같은 경로를 탄다.

**파서가 읽는 구문**

| 문장 | 읽어 들이는 것 |
|---|---|
| `CREATE TABLE` | 컬럼 이름·타입 원문(`UNSIGNED` 접미와 정수 표시폭 포함)·`NOT NULL`·`DEFAULT`·자동증가·인라인 `PRIMARY KEY`, MySQL 인라인 `COMMENT` |
| `CREATE TABLE` 의 꼬리 절 | `ENGINE`·`DEFAULT CHARSET`(`CHARACTER SET`)·`COLLATE`(→ 아래 「테이블 옵션」), MySQL 테이블 `COMMENT` |
| `CREATE TABLE` 안의 제약 | `PRIMARY KEY`, `UNIQUE`, `FOREIGN KEY … REFERENCES` |
| `ALTER TABLE … ADD` | `PRIMARY KEY`, `UNIQUE`, `FOREIGN KEY` |
| `CREATE [UNIQUE] INDEX` | 인덱스 이름·대상 테이블·구성 컬럼 |
| `COMMENT ON` | 테이블·컬럼 코멘트 |

주석(`--`, `/* */`), 문자열 리터럴, 따옴표 식별자(`"…"`, `` `…` ``, `[…]`), 스키마 접두사, Oracle 스크립트의 `/` 구분자를 모두 처리한다.

**파서가 못 하는 것** — 위 목록에 없는 문장은 전부 건너뛰고 「〈행〉 〈키워드〉 구문을 건너뛰었습니다」 로 보고한다. 대표적으로 `CHECK` 제약(인라인이든 `ALTER TABLE … ADD CHECK`든), `CREATE VIEW`/`SEQUENCE`/`TRIGGER`/`PROCEDURE`/`FUNCTION`, `GRANT`·`INSERT` 등 DML·권한 문장이 그렇다. 인덱스 구성 컬럼의 **정렬 방향도 읽지 않는다** — 가져온 인덱스는 모두 `ASC`가 된다.

**그 밖의 제약**

- 이미 같은 물리명의 테이블이 있으면 건너뛴다(「같은 이름의 테이블이 이미 있어 건너뜁니다」). DDL 안에 같은 이름이 두 번 있으면 뒤엣것을 건너뛴다.
- 물리명에서 **논리명을 되돌리는 것은 사전에 달려 있다.** 약어를 모르면 「논리명을 복원하지 못했습니다 — 사전에 없는 단어: …」가 뜬다. 사전을 먼저 채워 두면 논리명까지 복원된다.
- 타입을 모르면 원문을 그대로 두고(「…를 알지 못해 타입을 그대로 두었습니다」), 여러 해석이 가능하면 하나를 고른 뒤 대안을 알려 준다.
- 참조 대상 테이블·컬럼을 찾지 못한 FK, 소속 테이블·컬럼을 찾지 못한 인덱스와 UNIQUE 제약은 만들지 않고 각각 경고로 남는다.
- 한 번에 보낼 수 있는 양(5,000건)을 넘으면 「한 번에 가져올 수 있는 양을 넘었습니다. 입력을 나눠 올려주세요.」가 뜨고 버튼이 잠긴다.

**DBML 파서가 읽는 것** — `Project`(`database_type`), `Table`(별칭 `as X` 는 무시, `headercolor`·`note`), 컬럼 줄(타입 + `pk`/`primary key`/`not null`/`null`/`unique`/`increment`/`default:`/`note:`/인라인 `ref:`), `indexes` 블록(단일·합성, `[pk]`·`unique`·`name:`), `Ref`(줄·블록 두 형태, 이름 유무, `>` `<` `-`, 합성키), `TableGroup`(`color`·`note`), 주석(`//`, `/* */`).

- **`TableGroup` 은 그룹으로 만든다.** 같은 이름의 그룹이 이미 있으면 그것을 쓰고 **그 그룹의 색을 덮어쓰지 않는다.** 색은 `color` → 첫 소속 테이블의 `headercolor` → 팔레트 순으로 정해진다. ⚠️ **첫 줄 머릿말에 같은 이름의 그룹이 있으면 머릿말이 이긴다** — 그 그룹의 멤버·색·코멘트는 머릿말이 말하는 것으로 정해지고 블록 쪽 내용은 쓰이지 않는다(우리가 내보낸 DBML 은 둘이 늘 일치한다). 머릿말에 없는 그룹만 블록으로 만든다.
- **note 의 JSON 꼬리는 커스텀 항목 값으로 되읽는다.** 정의가 없는 이름은 버리고 「커스텀 항목 정의가 없어 "〈이름〉" 값을 버렸습니다」로 알린다 — 먼저 커스텀 항목을 정의해 두면 값까지 들어온다.
- 방향은 자식→부모로 정규화한다(`<` 는 뒤집는다). `-` 는 1:1 관계가 되고 유니크 인덱스를 만들지 않는다. `Ref` 에 붙은 이름은 관계 이름으로 살아남는다.
- `Enum` 정의, `sticky note`, `TablePartial`, `<>`(N:M) 관계, 그 밖에 모르는 블록은 건너뛰고 경고한다. 인덱스의 백틱 표현식(`` (`id*2`) ``)도 컬럼으로 해소되지 않아 건너뛴다.
- 도메인 연결과 인덱스 정렬 방향은 되돌아오지 않는다(DBML 에 표현이 없다).

### Excel 사전 가져오기

**어디서** — 에디터 헤더 「사전·리소스」 → 「단어·용어 사전」 → 「가져오기」 탭.

1. 「양식 다운로드」로 `erdd_사전양식.xlsx`을 받는다. 단어사전·용어사전·도메인정의서 3시트에 헤더만 들어 있고 내보내기와 같은 헤더를 쓴다.
2. 「Excel 파일 선택」에서 `.xlsx`를 고른다. 읽는 즉시 미리보기가 나온다 — 「〈파일명〉 — 신규 N건 · 중복 N건 · 오류 N행」.
3. 「중복 항목 처리」에서 「건너뛰기」 또는 「덮어쓰기」를 고른다. 덮어쓰기를 고르면 「덮어쓰기는 파일에 있는 아래 컬럼만 갱신하고 나머지 값은 그대로 둡니다」와 함께 시트별 인식 컬럼이 표시된다.
4. 오류·경고가 있으면 시트·행 번호와 함께 나온다(최대 20건, 나머지는 「외 N건」).
5. 「적용 대상 N건」을 확인하고 「가져오기 실행」을 누른다.

**제약** — 사전 전체가 편집 1건으로 나가므로 실행 취소 한 번으로 되돌아간다. 파일 내용이 이미 사전과 같으면 「파일 내용이 현재 사전과 같아 바뀐 항목이 없습니다」가 뜬다. 적용 대상이 0건이거나 상한 (5,000건)을 넘으면 버튼이 잠기고, 넘을 때는 「한 번에 보낼 수 있는 최대 5000건을 넘습니다. 파일을 나눠서 올려 주세요」가 뜬다. 처리 중에는 버튼과 파일 선택이 함께 잠기고, 실패하면 미리보기가 남아 그대로 다시 시도할 수 있다.

## 17. 실시간 동시편집

> **로컬 모드에는 없다** — 참여자 표시도 커서도 없다. 한 사람이 쓰는 것을 전제한다(→ [로컬 모드 매뉴얼 4.6](./local-guide.md#46-탭을-여러-개-열면)).

**무엇** — 같은 프로젝트를 여러 사람이 동시에 열어 편집할 수 있다. 남의 변경이 즉시 내 화면에 반영되고 누가 무엇을 보고 있는지도 보인다.

**어디서** — 별도 화면이 없다. 에디터에 들어가면 자동으로 연결된다. 접속자 아바타는 헤더 오른쪽(「버전」 왼쪽)의 「함께 보는 사용자」 영역이다.

**어떻게 — 보이는 것**

- **접속자 아바타** — 같은 프로젝트를 보고 있는 다른 사람의 이름 첫 글자가 사람별 고정 색의 동그란 배지로 뜬다. 최대 3명까지 보이고 나머지는 「+N」으로 묶인다. 마우스를 올리면 이름이 나온다. 나 자신은 표시되지 않고 혼자면 영역이 비어 있다.
- **남의 선택 하이라이트** — 다른 사람이 선택한 테이블·관계·메모에 그 사람의 색으로 외곽선이 붙고 테이블에는 이름표가 뜬다. **여러 개를 고르고 있으면 고른 것 전부에 표시된다** — 일괄 삭제 전에 「지금 남이 그걸 만지고 있다」가 보여야 하기 때문이다(한 사람당 최대 50개까지 전달되고 그보다 많이 고르면 앞의 50개만 보인다). 내 선택은 안쪽 파란 테두리라 서로 구분된다.
- **알림 토스트** — 내가 보고 있는 대상이 남의 편집으로 바뀌면 「다른 사용자가 이 항목을 수정했습니다」, 지워지면 「다른 사용자가 이 항목을 삭제했습니다」가 뜬다. **여러 개를 고른 상태에서 그중 일부만 지워지면 「다른 사용자가 선택 항목 중 일부를 삭제했습니다」가 뜨고 남은 선택은 유지된다** — 지워진 것만 선택에서 빠진다. 내가 보고 있는 테이블의 **컬럼·인덱스**가 바뀐 경우에도 수정 알림이 뜬다. 한 번의 변경 묶음에 최대 1건이다.

**제약**

- 같은 곳을 동시에 고치면 **나중에 도착한 편집이 이긴다.** 문자·필드 단위로 합쳐 주지 않는다.
- 내 편집이 서버에 들어가는 동안 남의 편집이 먼저 들어가면 화면을 서버 최신 상태로 통째로 다시 맞춘다. 이때 **실행 취소 이력이 비워진다** — 되돌리려는 대상이 이미 사라졌을 수 있기 때문이다. 보고 있던 그룹 뷰는 유지되고 선택은 대상이 아직 있을 때만 남는다.
- 연결이 끊기면 1·2·4·8초 간격으로 자동 재접속한다. 권한 문제로 끊긴 경우에는 재시도하지 않는다. 서버 상태를 못 불러오면 「서버 상태를 불러오지 못했습니다. 새로고침해 주세요.」가 뜬다.
- Viewer도 실시간 화면과 접속자 표시를 정상적으로 받는다 — 편집만 막힌다.

## 18. 액세스 토큰

> **로컬 모드에는 없다** — 부를 서버가 없다(→ [로컬 모드 매뉴얼](./local-guide.md)).

**무엇** — CLI에서 쓰는 개인 액세스 토큰이다. 「CLI에서 쓰는 토큰입니다. 권한은 내 조직·프로젝트 역할을 그대로 따릅니다.」

**어디서** — `/settings`(사용자 메뉴 → 「설정」)의 「액세스 토큰」 카드.

**어떻게** — 「토큰 이름」에 알아볼 이름(예: 「노트북」)을 넣고 「발급」을 누른다. 토큰 값이 노란 상자에 나오고 「복사」로 클립보드에 담는다. 폐기하려면 목록에서 「폐기」를 누르고 빨갛게 바뀐 「정말 폐기」를 한 번 더 누른다.

**제약** — **「이 값은 지금만 보입니다 — 창을 닫으면 다시 볼 수 없습니다.」** 목록에는 이름과 마지막 사용 날짜만 남으므로, 잃으면 조회가 아니라 재발급이다. 토큰의 권한은 내 계정의 조직·프로젝트 역할과 같아 토큰만으로 더 넓은 권한을 얻을 수 없다. 이름이 비면 「발급」이 잠기고, 발급한 토큰이 없으면 「발급한 토큰이 없습니다.」가 보인다.

같은 화면 위쪽 「비밀번호 변경」 카드에서 비밀번호도 바꾼다 — 「현재 비밀번호」·「새 비밀번호」·「새 비밀번호 확인」을 넣고 「변경 사항 저장」. 「변경하면 다른 기기의 로그인이 해제됩니다.」

**CLI 사용법 자체는 이 매뉴얼의 범위가 아니다.** 토큰을 쥐고 나서 하는 일 — 명령·파일 포맷·동기화 방식은 [CLI 매뉴얼](cli-guide.md)에 있다.

## 19. 관리자 업무

> **로컬 모드에는 없다** — 계정·초대·전역 공용 리소스가 모두 없다(→ [로컬 모드 매뉴얼](./local-guide.md)).

**무엇** — 서비스 역할 `admin`인 사람이 하는 일이다 — 계정 초대·상태 관리, 비밀번호 재설정 링크 발급, 전역 공용 리소스 관리. 조직 단위 업무(조직 초대, 승격 요청 승인, 조직 라이브러리)는 Org Owner/Admin이 조직 화면에서 한다.

**어디서** — `/admin`(사용자 메뉴 → 「관리자」, 제목 「계정 관리」). 조직 업무는 `/org/:orgId`.

### 계정 초대

「계정 초대」를 누르면 다이얼로그가 「계정을 만들지 않고 초대 링크만 만듭니다. 이름과 비밀번호는 본인이 정합니다.」라고 알린다. 「이메일」을 넣고 「역할」에서 「일반」/「관리자」를 고른 뒤 「초대 링크 만들기」를 누르면 링크가 노란 상자에 나오고 「받는 사람」과 유효 기한이 함께 표시된다. 「복사」로 담아 전달하고 「닫기」로 닫는다.

**제약 — 이 화면에는 비밀번호 입력란이 없다.** 관리자는 계정을 만들지 않고 링크만 만든다. 화면도 「초대 링크를 만들어 사람을 부르고, 만들어진 계정의 사용 상태를 관리합니다. 계정은 초대를 수락한 본인이 만들고 비밀번호도 본인만 정합니다.」라고 명시한다. 「이 링크는 지금만 볼 수 있습니다 — 창을 닫으면 다시 볼 수 없습니다. 잃으면 새로 발급하세요.」 — 발급 응답에서만 평문 링크가 나오므로 목록에서 다시 찾을 수 없다. 이미 계정이 있는 이메일로는 초대를 만들 수 없다.

### 계정 상태와 재설정 링크

계정 표에는 이메일·이름·역할(「관리자」/「일반」)·상태(「활성」/「비활성」)가 나온다.

- **비밀번호 재설정 링크** — 행의 「비밀번호 재설정 링크」 → 「링크 만들기」. 「링크를 만들어 사용자에게 전달합니다. 발급만으로는 비밀번호가 바뀌지 않고 로그인 세션도 유지됩니다.」 발급 뒤에도 「이 링크를 사용자에게 전달하세요. 사용자가 링크를 열어 새 비밀번호를 정해야 비밀번호가 바뀝니다.」라고 다시 확인해 준다. 유효기간은 24시간이고 목록 화면이 없으므로 상자에 뜬 기한이 확인할 수 있는 유일한 자리다.
- **활성/비활성** — 행의 「비활성화」/「활성화」로 계정 사용 상태를 바꾼다.

### 초대 목록과 회수

`/admin` 아래쪽 「초대」 절에 **관리자가 만든 초대만** 나온다(조직 초대는 조직 화면에 따로 있다). 표는 이메일·역할·상태·만료·동작이고 상태는 「대기 중」·「사용됨」·「만료됨」이다. **회수**는 「취소」이고, 누르면 「초대를 취소했습니다」가 뜨며 그 링크는 즉시 죽는다. 「만료됨」으로 보이는 행에도 취소 버튼이 남는다 — 만료 판정은 내 브라우저 시계 기준이라 시계가 앞서 있으면 아직 살아 있는 초대가 만료로 보일 수 있다. 이미 사용된 초대에만 버튼이 없다. 보낸 초대가 없으면 「보낸 초대가 없습니다.」가 보인다.

### 조직 초대(Org Owner/Admin)

조직 상세의 「초대」 절에서 같은 방식으로 발급한다. 「초대할 이메일」과 역할(Member/Admin)을 골라 「초대 링크 만들기」를 누르면, 그 사람이 링크를 열어 계정을 만드는 동시에 이 조직에 그 역할로 합류한다. 목록·상태·취소는 관리자 화면과 같고, 취소하면 화면에 떠 있던 링크 상자도 함께 사라진다.

### 라이브러리 관리

**전역 공용 리소스**는 `/admin` 맨 아래, **조직 공용 리소스**는 조직 상세 맨 아래(Org Owner/Admin만 관리)에 있고 조작은 완전히 같다. 「라이브러리 만들기」 → 「이름」·「설명 (선택)」 → 「만들기」로 만들고, 라이브러리를 클릭해 펼치면 「도메인」·「단어」·「용어」·「커스텀 항목」 네 구역이 나온다. 구역별 「추가」로 항목을 만들고 연필로 고치고 휴지통으로 지운다(항목에는 버전 `v1`…이 표시된다). 삭제는 확인 창을 거친다 — 라이브러리는 「"〈이름〉"을(를) 삭제하면 항목 N개도 함께 삭제됩니다. 계속할까요?」, 항목은 「"〈이름〉"을(를) 삭제할까요? 이미 가져간 프로젝트의 사본은 그대로 남습니다.」

### 승격 요청 승인

조직 상세의 「승격 요청」 절에서 한다. 조작 순서와 제약은 [13절](#13-공용-리소스)에 있다. 승인자에게 요청이 닿는 경로는 상단바의 「승격 요청 N건」 배지뿐이다 — 메일·푸시 알림이 없으므로 주기적으로 확인해야 한다.

## 20. 선택과 복사

**무엇** — 캔버스에서 테이블·컬럼을 선택해 복사·잘라내기·붙여넣기·삭제한다. 클립보드는 시스템 클립보드에 담는 JSON 텍스트라 다른 탭·다른 프로젝트에도 붙여넣을 수 있다.

**어디서** — 캔버스(테이블 노드)와 오른쪽 편집 패널. 단축키는 문서 어디서나(입력란 밖이면) 먹는다 — 자세한 조건은 아래 「단축키」를 보라.

**어떻게 — 선택** — 테이블을 클릭하면 그 테이블 하나가 선택된다(→ [4절](#4-에디터-기본)). 테이블 안의 컬럼 행을 클릭하면 그 컬럼이 선택되고, 오른쪽 편집 패널이 즉시 그 컬럼 행으로 스크롤해 파란 테두리로 강조한다(이미 보이는 위치면 패널이 움직이지 않는다). `Cmd`/`Ctrl`+클릭이면 그 컬럼을 선택에 더하거나 뺀다(토글), `Shift`+클릭이면 마지막으로 선택한 컬럼부터 클릭한 컬럼까지 순서대로 범위 선택한다. 컬럼 선택은 **한 테이블 안에서만** 성립한다 — 컬럼을 클릭하면 그 컬럼이 속한 테이블 하나만 선택되고(이전에 여러 테이블을 선택해 뒀어도 하나로 줄어든다) 그 안에서 컬럼 선택이 이어진다.

**어떻게 — 테이블 여러 개 선택** — 방법이 둘이다. 테이블을 `Cmd`/`Ctrl`+클릭하면 그 테이블을 선택에 더하거나 뺀다(토글). 캔버스의 빈 곳에서 `Shift`를 누른 채 드래그하면 선택 상자가 그려지고, 상자에 걸린 **테이블들**이 선택된다 — 이때 선택은 더해지는 것이 아니라 상자에 걸린 것으로 **교체**된다. 색상 영역(그룹)·메모는 상자에 걸려도 이 선택에 들어가지 않고, 그룹 뷰에서 관계로 이어져 흐리게 보이는 바깥 테이블(고스트)도 마찬가지다. 수식 키 없이 그냥 클릭하면 다시 그 테이블 하나만 남고, 빈 곳을 클릭하면 선택이 풀린다.

테이블이 2개 이상 선택되면 컬럼 선택은 비워진다 — 컬럼 선택은 한 테이블 안에서만 성립하기 때문이다. 그리고 편집 패널이 폼 대신 **일괄 작업 패널**로 바뀐다 — 「N개 테이블 선택됨」 아래에 고른 테이블 목록, 「선택 테이블의 그룹」 드롭다운, 「선택 테이블 삭제」 버튼이 있다. 여러 테이블을 한 번에 붙여넣으면(아래) 붙여넣은 테이블 전체가 곧바로 이 상태로 선택된다.

**어떻게 — 일괄 작업 패널** — 「선택 테이블의 그룹」에서 그룹을 고르면 선택한 테이블 전부가 그 그룹으로 옮겨진다(끌어 놓는 것과 같은 동작이다 → [4절](#4-에디터-기본)). **드래그가 어려운 환경을 위한 대체 경로**이므로 키보드로도 된다. 「선택 테이블 삭제」는 **확인을 거친다** — 「선택한 테이블을 삭제할까요?」와 함께 「테이블 N개와 관계 M개가 삭제됩니다」, 그리고 함께 사라지는 컬럼·인덱스 수와 대상 목록이 표시된다. 하단 바의 「삭제」와 `Delete`/`Backspace` 단축키도 **2개 이상이면 같은 확인을 거친다**(1개면 기존대로 바로 지운다). 한 번에 지울 것이 너무 많으면(상한 5000개 항목) 「한 번에 지우기에 너무 많습니다」가 뜨고 삭제가 잠긴다 — 나눠서 지우면 된다.

**어디로 옮겨지는가** — 그룹을 바꾸면 캔버스 좌표도 함께 조정된다. 고른 테이블들의 **서로 간 배치를 유지한 채** 대상 그룹 영역 오른쪽으로 옮겨지고, 그 자리에 다른 테이블이 있으면 겹치지 않게 아래로 밀린다. **대상 그룹이 비어 있거나 「미분류」로 옮길 때는 좌표를 건드리지 않는다**(기준으로 삼을 영역이 없기 때문이다). 그룹 이동과 좌표 조정은 **한 번의 편집**이라 `Cmd`/`Ctrl`+`Z` 한 번으로 둘 다 되돌아간다.

**어떻게 — 복사·붙여넣기**

- `Cmd`/`Ctrl`+`C` — 컬럼이 선택돼 있으면 그 컬럼들만, 아니면 선택된 테이블 전체를 컬럼·인덱스까지 함께 클립보드에 담는다.
- `Cmd`/`Ctrl`+`V` — 클립보드가 컬럼이면 **테이블을 정확히 하나 선택한 상태에서만** 그 테이블의 맨 끝(순서 마지막)에 붙는다. 클립보드가 테이블이면 캔버스에 붙는다 — 각 테이블은 복사할 때의 원래 위치에서 오른쪽 아래로 약간 밀려 놓이고, 붙여넣은 테이블 전체가 곧바로 선택된다.
- 이 앱이 만든 것이 아닌 클립보드 내용(다른 곳에서 복사한 일반 텍스트 등)을 붙여넣으면 조용히 무시된다.

**어떻게 — 다른 프로젝트로** — 다른 탭·다른 프로젝트에 붙여넣어도 된다. 컬럼의 도메인은 **이름이 같은 도메인이 대상 프로젝트에 있으면 다시 연결**되고, 없으면 「없음」이 된다 — 이때도 타입 칸의 문자열 자체는 복사한 값 그대로 유지된다. 커스텀 항목도 같은 방식으로 **이름이 같은 항목에만** 값이 실리고, 이름이 같은 항목이 없으면 그 값은 버려진다.

**제약**

- **이름 충돌은 자동으로 풀린다.** 논리명이 겹치면 `_사본`을 붙이고, 그래도 겹치면 `_사본2`, `_사본3`… 순으로 붙는다. 물리명은 `_COPY`, `_COPY2`… 순이다. 테이블 물리명·컬럼 물리명·인덱스 이름 모두 같은 규칙을 따른다.
- **그룹 소속은 붙여넣기에 실리지 않는다.** 붙여넣은 테이블은 항상 미분류로 들어간다.
- **관계는 복사되지 않는다.** 관계는 상대 테이블이 있어야 성립하므로, FK로 쓰이던 컬럼도 붙여넣으면 그냥 평범한 컬럼이 된다. 필요하면 붙여넣은 뒤 캔버스에서 손잡이로 관계를 다시 긋는다(→ [6절](#6-관계)).
- **컬럼만 붙여넣을 때는 PK를 이어받지 않는다.** `PK` 체크가 꺼진 채로 들어온다 — 대상 테이블의 기본 키 구성이 붙여넣기 한 번으로 조용히 바뀌지 않게 하기 위해서다. 테이블째 붙여넣을 때는 새 테이블이라 PK 표시가 그대로 유지된다.

**단축키**

| 단축키 | 동작 |
|---|---|
| `Cmd`/`Ctrl` + `C` | 복사 |
| `Cmd`/`Ctrl` + `X` | 잘라내기(복사 + 삭제) |
| `Cmd`/`Ctrl` + `V` | 붙여넣기 |
| `Delete` / `Backspace` | 삭제 |

동작하지 않는 조건이 셋 있다. **입력란**(`input`·`textarea`·`select`·포커스 편집 가능 영역)에 커서가 있을 때는 전부 브라우저 기본 동작에 양보한다. **다이얼로그가 하나라도 열려 있을 때**도 전부 먹지 않는다 — 다이얼로그 뒤에 깔린 캔버스 선택을 실수로 지우는 사고를 막기 위해서다. **읽기 전용 권한**이면 `Cmd`/`Ctrl`+`C`만 되고 `X`·`V`·`Delete`/`Backspace`는 무시된다.

**잘라내기·삭제는 여러 개를 한 번에 지워도 실행 취소가 한 번이다.** 선택된 테이블·컬럼 전체가 한 번의 편집으로 나가므로, `Cmd`/`Ctrl`+`Z`(→ [4절](#4-에디터-기본)) 한 번으로 지운 것 전부가 되돌아온다. 하단 바의 「삭제」 버튼도 같다 — 선택한 테이블 전부가 한 번의 편집으로 지워진다.

**메모와 관계선** — 같은 단축키가 메모(→ [7절](#7-인덱스와-메모))와 관계선(→ [6절](#6-관계))에도 먹는다. `C`·`X`·`Delete`/`Backspace`는 **캔버스에서 메모나 관계선을 클릭해 고른 뒤** 누른다.

| 고른 것 | `C` 복사 | `X` 잘라내기 | `Delete`/`Backspace` 삭제 |
|---|---|---|---|
| 메모 | O | O | O |
| 관계선 | — | — | O |

- **붙여넣기(`V`)는 무엇을 골랐는지와 무관하다** — 위 표에 없는 것은 그 때문이다. 클립보드에 메모가 들어 있으면 메모가 붙고, 테이블이 들어 있으면 테이블이 붙는다(무엇을 고른 상태든 상관없다). 컬럼만 예외로 「테이블을 정확히 하나 고른 상태」를 요구한다.
- **메모 붙여넣기**는 복사할 때의 원래 위치에서 오른쪽 아래로 약간 밀려 놓이고, 붙여넣은 메모가 곧바로 선택된다(테이블과 같은 규칙이다). 다른 탭·다른 프로젝트에 붙여넣어도 된다.
- **그룹 뷰에서는 메모를 붙여넣을 수 없다**(조용히 무시된다). 그룹 뷰가 메모를 아예 보여주지 않기 때문이고, 하단 바의 「메모」 버튼이 그룹 뷰에서 잠기는 것과 같은 이유다 — 붙었는데 보이지 않는 상태를 만들지 않는다. 전체 뷰로 나와서 붙여넣는다.
- **관계선은 복사되지 않는다** — 관계는 부모·자식 두 테이블과 컬럼 짝에 기대어 성립하므로, 붙여넣을 때 어느 테이블에 이어 붙일지가 정해지지 않기 때문이다. 삭제만 된다.
- **관계선을 지워도 자식 테이블의 FK 컬럼은 남는다.** 선만 사라지고 컬럼은 평범한 컬럼으로 남으므로, 컬럼까지 없애려면 그 컬럼을 따로 지운다. 우측 패널의 「관계 삭제」 버튼과 완전히 같은 동작이다.
- 메모·관계선은 하나씩만 고를 수 있어 **삭제 확인 다이얼로그를 거치지 않는다**(그 확인은 테이블을 2개 이상 골랐을 때만 뜬다). 실수로 지웠으면 `Cmd`/`Ctrl`+`Z`로 되돌린다.
- 메모를 다른 앱(메모장·이슈 트래커 등)에 붙여넣으면 사람이 읽는 글이 아니라 이 앱이 쓰는 JSON 문자열이 나온다 — 앱 안에서 메모를 복제하기 위한 형식이기 때문이다.
