# 계정·조직·온보딩

## 목적

가입부터 첫 프로젝트 생성까지의 계정 체계와 조직 관리를 정의한다. 개인 사용자와 팀을 하나의 조직 모델로 수용해 데이터 모델을 균일하게 유지한다.

## 사용자 시나리오

- 개인 개발자가 이메일로 가입하고, 자동 생성된 개인 공간에서 바로 첫 프로젝트를 만든다.
- DA가 팀 조직을 만들어 설계자들을 이메일로 초대하고 역할을 지정한다.
- 미가입 상태로 초대받은 개발자가 초대 링크에서 가입을 마치자 조직에 자동 합류된다.

## 기능 상세

### 가입과 인증

- 이메일+비밀번호 가입 → 인증 메일 발송 → 링크 확인 후 계정 활성화.
- 비밀번호 재설정: 이메일 링크.
- 세션: httpOnly 쿠키 기반 서버 세션.
- 메일 발송은 어댑터로 추상화한다(개발 환경은 콘솔 출력, 운영은 SMTP/SES 등 배포 시 선택).
- 소셜 로그인(Google 등)은 현재 비범위([90-roadmap](90-roadmap.md) "추후 검토").

### 조직: 개인과 팀

Organization은 `종류(개인/팀)`를 가진다(→ [01-concepts](01-concepts.md)).

- **개인 조직**: 가입 완료 시 자동 생성. UI에서 "개인 공간"으로 표시. 삭제·멤버 초대·소유권 이전 불가. 무료 티어 = 개인 조직의 플랜(제한 집행은 Phase 4 과금 설계에서).
- **팀 조직**: 사용자가 직접 생성(생성자가 Owner). Phase 1에서는 플랜 제한 없이 동작한다.

### 조직 초대

- Org Owner/Admin이 이메일로 초대하며 역할(Admin/Member)을 지정한다.
- 기존 회원은 초대 링크 수락으로 즉시 합류, 미가입자는 가입 완료 시 자동 합류.
- 초대는 7일 만료. pending 목록에서 재발송/취소 가능.
- 프로젝트 참여는 조직 멤버 중에서 ProjectMember(Admin/Editor/Viewer)로 추가한다([01-concepts](01-concepts.md)의 권한 모델).

### 온보딩

- 가입 → 개인 조직 자동 생성 → 첫 프로젝트 생성 유도(이름 + 대상 DB 방언 선택).
- ApiToken 발급 UI는 CLI와 함께 Phase 4(→ [16-cli](16-cli.md)).

## 다른 영역과의 연계

- 조직·멤버·권한 엔티티 정의(→ [01-concepts](01-concepts.md)).
- API 토큰 인증(→ [16-cli](16-cli.md)).
- 무료 티어 제한과 과금(→ [00-vision](00-vision.md), Phase 4).

## 단계별 범위

- **Phase 1**: 위 기능 전체 — 가입/인증/비밀번호 재설정, 개인·팀 조직, 초대, 온보딩. 플랜 제한 없음.
- **Phase 4**: 무료 티어 제한 집행(과금 설계와 함께).
