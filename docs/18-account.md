# 계정·조직·온보딩

## 목적

계정 체계와 조직 관리를 정의한다. 초기 운영은 셀프 가입 대신 **서비스 관리자가 계정을 생성해 전달하는 폐쇄형 모델**로 시작한다 — 메일 발송 인프라 없이 동작한다. 개인 사용자와 팀을 하나의 조직 모델로 수용해 데이터 모델을 균일하게 유지한다.

## 사용자 시나리오

- 서비스 관리자가 관리자 페이지에서 설계자 계정(이메일·이름·초기 비밀번호)을 만들어 전달한다.
- 설계자가 이메일+비밀번호로 로그인해, 자동 생성된 개인 공간에서 첫 프로젝트를 만들고 비밀번호를 변경한다.
- DA가 팀 조직을 만들고, 등록된 사용자를 이메일로 찾아 멤버로 추가한다.

## 기능 상세

### 인증과 계정

- 로그인: 이메일+비밀번호. 세션은 httpOnly 쿠키 기반 서버 세션.
- 사용자는 로그인 후 자신의 비밀번호를 변경할 수 있다(설정 화면). 비밀번호 분실은 관리자 재설정으로 대응한다.
- 셀프 가입, 이메일 인증, 비밀번호 재설정 메일, 소셜 로그인은 현재 비범위([90-roadmap](90-roadmap.md) "추후 검토").

### 서비스 관리자와 관리자 페이지

User는 서비스 역할(admin/user)과 활성 여부를 가진다(→ [01-concepts](01-concepts.md)). 최초 admin 계정은 서버 부트스트랩(환경 변수 기반 시드)으로 생성한다.

관리자 페이지(admin 전용):

- 계정 목록·검색
- 계정 생성: 이메일, 이름, 초기 비밀번호 지정. **생성 시 개인 조직이 자동 생성된다.**
- 비밀번호 재설정: 새 초기 비밀번호 지정(기존 세션 무효화)
- 계정 비활성화/활성화: 비활성 계정은 로그인 불가

### 조직: 개인과 팀

Organization은 `종류(개인/팀)`를 가진다.

- **개인 조직**: 계정 생성 시 자동 생성. UI에서 "개인 공간"으로 표시. 삭제·멤버 추가·소유권 이전 불가. 무료 티어 = 개인 조직의 플랜(제한 집행은 Phase 4 과금 설계에서).
- **팀 조직**: 사용자가 직접 생성(생성자가 Owner). Phase 1에서는 플랜 제한 없이 동작한다.

### 조직 멤버 관리

- Org Owner/Admin이 **등록된 사용자를 이메일로 찾아 멤버로 직접 추가**하고 역할(Admin/Member)을 지정한다. 이메일 초대 링크(미가입자 초대 포함)는 메일 인프라와 함께 추후 검토.
- 마지막 Owner는 제거·강등할 수 없다. Owner 역할 부여/회수는 Owner만 가능하다.
- 프로젝트 참여는 조직 멤버 중에서 ProjectMember(Admin/Editor/Viewer)로 추가한다([01-concepts](01-concepts.md)의 권한 모델).

### 온보딩

- 로그인 → 개인 공간 → 첫 프로젝트 생성 유도(이름 + 대상 DB 방언 선택).
- ApiToken 발급 UI는 CLI와 함께 Phase 4(→ [16-cli](16-cli.md)).

## 다른 영역과의 연계

- 조직·멤버·권한 엔티티 정의(→ [01-concepts](01-concepts.md)).
- API 토큰 인증(→ [16-cli](16-cli.md)).
- 무료 티어 제한과 과금(→ [00-vision](00-vision.md), Phase 4).

## 단계별 범위

- **Phase 1**: 위 기능 전체 — 로그인/비밀번호 변경, 관리자 페이지(계정 생성·재설정·비활성화), 개인·팀 조직, 멤버 직접 추가, 온보딩.
- **Phase 4**: 무료 티어 제한 집행(과금 설계와 함께).
- **추후 검토**: 셀프 가입(이메일 인증), 초대·비밀번호 재설정 메일, 소셜 로그인.
