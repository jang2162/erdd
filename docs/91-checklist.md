# 구현 전 구체화 체크리스트

구현 착수 전에 결정·문서화가 필요한 항목을 추적한다. 위에서 아래 순서로 진행하고, 완료 시 체크하고 결과가 반영된 문서를 링크한다.

## Phase 1 착수 전 (필수)

- [x] **아키텍처** — 기술 스택, 데이터 계층(상태 + op 로그), identity 모델(UUIDv7), 스냅샷·diff 전략 → [02-architecture](02-architecture.md)
- [x] **논리 타입 체계** — 논리 타입 17종과 문법, 4방언 기본 변환 표, 자동증가, 관대한 파싱 정책 → [14-domain](14-domain.md)
- [ ] **관계(FK) 편집 시맨틱** — 관계 생성 시 FK 컬럼 자동 생성 여부, 식별 관계의 자식 PK 전파, 부모 PK 변경 시 FK 동기화, 자기참조·동일 테이블 쌍 다중 관계 → [10-editor](10-editor.md)에 반영 예정
- [ ] **계정·온보딩** — 인증 방식, 조직 생성·초대 플로우, 개인(무조직) 사용자 모델(무료 티어와 개념 모델의 정합) → [01-concepts](01-concepts.md) 보강 또는 신규 문서
- [ ] **CLI 파일 포맷 내부 명세** — `id` 필드 포함 YAML 구조, JSON Schema. 공개는 Phase 4이나 내부 정의는 Phase 1 병행([90-roadmap](90-roadmap.md) 전제) — 구현과 병행 확정 가능

## Phase 2 착수 전

- [ ] **단어 분해 알고리즘** — 최장 일치 모호성 처리 규칙, 동의어의 매칭 역할, 영문·한영 혼합 논리명 처리
- [ ] **Term 물리명 관리** — 저장값 vs 파생값, 명명 규칙(케이스/구분자) 변경 시 기존 물리명 처리, 용어 수정 일괄 반영의 Revision 기록 방식
- [ ] **표준 사전 데이터 소싱** — 행안부 표준 사전의 출처·라이선스·갱신 주기 확인, 서비스 전역 리소스의 버전 관리 방식
- [ ] **Excel 산출물 상세 양식** — 시트별 헤더·컬럼 구성 확정 (구현과 병행 가능)

## Phase 3 착수 전

- [ ] **실시간 프로토콜 상세** — 채널 인증, 재수화 한계 기준(간극이 크면 전체 리로드), presence 메시지 설계 (기반은 [02-architecture](02-architecture.md)에 정의됨)
- [ ] **diff 화면과 변경분 정의서** — diff 결과 표시 상세, 변경분 정의서 양식

## Phase 4 착수 전

- [ ] **CLI 상세** — base 사본 저장 방식, push 충돌 출력 형식, `--json` 출력 스키마, 패키지명 확정(현 `schemantic` 가칭 → ERDD 네이밍 정리)
- [ ] **에이전트 스킬 문서** — 동봉할 SKILL.md 내용 설계
- [ ] **DDL 역설계 범위** — 지원 방언별 파싱 범위와 한계, 파서 라이브러리 선택
- [ ] **과금 플랜** — 티어 구성, 제한 항목, 결제 연동
