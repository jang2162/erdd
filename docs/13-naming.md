# 명명 체계 — 단어/용어 사전과 물리명 자동생성

## 목적

행안부 표준 체계와 호환되는 **단어–용어–도메인 3단 명명 체계**로 논리명/물리명을 일관되게 관리한다. 검증은 경고 수준으로 하여 작업 흐름을 막지 않는다.

## 사용자 시나리오

- 프로젝트 시작 시 서비스가 제공하는 행안부 표준 단어사전을 프로젝트로 가져온다.
- 컬럼 논리명에 "회원번호"를 입력하면 물리명 `MBR_NO`와 도메인 "번호"가 자동 제안된다.
- 사전에 없는 단어 "쿠폰"을 쓰면 경고 배지가 뜨고, 그 자리에서 약어 `CPN`으로 단어를 등록한다.
- 산출물 제출 전, 미등록 단어 목록 화면에서 남은 경고를 일괄 정리한다.

## 기능 상세

### 3단 체계

| 단계 | 예 | 역할 |
|---|---|---|
| Word(단어) | 회원 = `MBR`, 번호 = `NO` | 명명의 최소 단위. 물리 약어의 원천 |
| Term(용어) | 회원번호 = [회원]+[번호] → `MBR_NO`, 기본 도메인 "번호" | 컬럼 논리명과 1:1로 대응하는 표준 명칭 |
| Domain(도메인) | 번호 → 방언별 물리 타입 | 타입의 표준 정의(→ [14-domain](14-domain.md)) |

### 프로젝트 명명 규칙 설정

- 물리명 케이스: `UPPER_SNAKE`(기본) / `lower_snake`.
- **물리명** 단어 구분자: `_`(기본) / 없음. 약어를 잇는다.
- **논리명** 단어 구분자: `_`(기본) / 없음. 물리명과 **별도 축**이다 — 한글 논리명과 영문 약어는
  구분자 정책이 다를 이유가 충분하고, 공유하면 물리명 규칙을 바꾸는 순간 저장된 논리명 전체가
  규칙 위반이 된다. 프로젝트 설정의 「논리명을 밑줄로 구분」 체크박스가 이것 하나만 연다.
- 물리명 최대 길이 경고 기준(기본 30바이트 — Oracle 구버전 호환).
- 대상 DB 방언의 예약어 충돌 경고.
- **테이블 물리명 형식**(템플릿). 비우면 입력한 물리명을 그대로 쓴다(기본). → 아래 절.
- **테이블 논리명 형식**(템플릿). 비우면 입력한 논리명을 그대로 쓴다(기본). **산출물 전용이다.** → 아래 절.

#### 논리명 구분자

논리명 **저장값 자체**에 구분자가 들어간다 — 모델에 `회원_주문_번호`가 그대로 저장되고 DDL 코멘트·
Excel 정의서·DBML·CLI 파일에 나가는 값도 그것이다.

- **분해는 구분자 split 이 1차이고, 사전에 없는 토큰만 최장일치 그리디로 재분해한다(폴백).**
  이 폴백이 급소다 — 구분자가 없는 기존 논리명(`회원주문번호`)은 split 하면 토큰이 하나이고 사전에
  그런 단어는 없어서, 폴백이 없으면 **통째로 미등록 단어**가 되어 물리명 생성이 죽는다. 기존
  프로젝트가 전부 그 꼴이 된다. 폴백 덕에 바뀌는 것은 경고 한 줄뿐이다.
- **용어는 저장값을 바꾸지 않는다.** 비교할 때 양쪽에서 구분자를 벗겨 맞추고, 논리명에 넣을 때만
  구분자 형식으로 변환한다. 용어는 전역·조직 라이브러리에서 내려오므로 남의 데이터에 이 프로젝트의
  구분자 정책을 강요할 수 없다.
- **끄면 저장된 밑줄은 그대로 남는다.** 규칙은 값을 바꾸지 않는다(일괄 변환 도구는 없다).
- 기존 프로젝트의 명명 규칙에는 이 키가 없다. **읽는 시점에 기본값 `_` 를 주입**하므로 기존
  프로젝트를 열면 구분자 없는 논리명이 전부 경고로 뜬다 — 사용자가 보고 고친다.

### 그룹 별칭

그룹에는 **물리 식별자 별칭**(`alias`)이 있다. 그룹 이름은 `회원관리`처럼 한글이라 물리명 조합에 쓸 수
없어서 따로 두는 값이고, 규칙은 물리명과 같다 — **영문 대문자·숫자·밑줄**. 그룹 패널에서 직접 치거나
「이름으로 별칭 채우기」로 그룹 이름을 사전에 태워 만든다. 선택 입력이라 없으면 빈 문자열이다
(`null` 이 아니다 — 비어 있을 수 있는 식별자라 `physicalName` 쪽 성격이다).

- **규칙은 타이핑 중에 강제한다** — 커밋 후 거절해 토스트를 내는 쪽보다 예측 가능하고, 한글을 치면
  아무것도 안 들어가서 규칙을 즉시 알 수 있다. 나중에 규칙을 세우면 이미 입력된 값이 전부 위반이
  된다(논리명 구분자에서 겪은 형태).
- **소비처는 테이블 물리명 형식이다**(아래 절). `{그룹별칭}` 변수로 조합에 들어간다.
  **내보내기 머릿말도 별칭을 함께 싣는다** — 되읽을 때 그룹까지 복원하기 위해서다(아래 「왕복」 절).
- **중복 별칭 자체는 여전히 막지 않는다.** 두 그룹이 같은 별칭이면 조합 결과가 같아질 수 있는데,
  그때는 **테이블 물리명 중복 경고**가 최종 이름 기준으로 뜬다 — 별칭이 아니라 결과를 본다.

### 테이블 물리명 형식(템플릿)

테이블의 **최종 물리명**을 「접두 + 입력한 부분」으로 조합한다. 프로젝트 설정의 「테이블 물리명 형식」에
틀을 적으면 DDL·DBML·Excel·검사가 조합된 이름을 쓴다. **비우면 조합하지 않고 입력한 물리명을 그대로
쓴다**(기존 동작 그대로가 기본값이다).

예: 형식이 `TB_{그룹별칭}_{물리명}` 이고 그룹 별칭이 `MBR`, 입력한 물리명이 `ORD` 면 → `TB_MBR_ORD`.

#### 저장은 부분, 산출은 조합

**모델에 저장되는 `physicalName` 은 사용자가 입력한 부분뿐이다.** 접두는 저장하지 않는다 — 형식을
바꾸면 모든 테이블의 저장값을 일괄 변환해야 하고, 그룹을 옮기면 이름이 낡는다.

| 자리 | 쓰는 값 |
|---|---|
| DDL(CREATE TABLE·FK·인덱스·코멘트·정렬) | **조합** |
| DBML(Table·Ref·TableGroup 멤버·note 판정) | **조합** |
| Excel 정의서(테이블 목록·테이블 정의서의 물리명 열) | **조합** |
| 검사 — 물리명 중복·최대 길이·예약어 | **조합** |
| 검사 — 용어 불일치 | **부분** |
| 편집 패널 입력란·사이드바 트리·클립보드 복사·CLI 파일·역설계 | **부분** |

용어 검사만 부분 기준인 이유: 용어 사전에 등록하는 표준 물리명은 사용자가 입력하는 값이라 접두가 없다.
조합 이름과 비교하면 접두 때문에 **항상** 불일치가 뜬다.

#### 쓸 수 있는 변수

| 변수 | 값 |
|---|---|
| `{그룹별칭}` | 소속 그룹의 물리 식별자 별칭. 그룹이 없거나 별칭이 비면 빈 값 |
| `{그룹명}` | 소속 그룹 이름(한글) |
| `{물리명}` | 입력한 물리명(부분) |
| `{논리명}` | 논리명 |
| `{커스텀:항목이름}` | 테이블용 커스텀 항목 값. 「값 > 정의 기본값 > 빈 값」 |

- **알 수 없는 변수는 빈 값이다.** 설정 화면의 오타(`{그룹별칙}`)로 모델 전체가 죽으면 안 된다 —
  설정 화면의 미리보기가 그 자리를 비워 보여 주므로 즉시 알 수 있다.
- 짝이 맞지 않는 중괄호(`TB_{물리명`)는 오류를 던지지 않고 리터럴로 남는다.
- 커스텀 항목은 **정의 이름**으로 지목한다(값 맵의 키는 UUID 라 사람이 쓸 수 없다). **테이블용**
  항목만 잡힌다 — 같은 이름의 컬럼용 항목은 무시된다.

#### 빈 구간 접기

**빈 변수는 자기 자신과 바로 뒤 리터럴 선두의 밑줄들을 지운다. 뒤에 리터럴이 없으면 바로 앞
리터럴 말미의 밑줄들을 지운다. 변수 값은 절대 건드리지 않는다.** 그룹이 없는 테이블이 `TB__ORD`
로 나가면 안 된다.

| 형식 | 상황 | 결과 |
|---|---|---|
| `TB_{그룹별칭}_{물리명}` | 그룹 없음 | `TB_ORD` |
| `{그룹별칭}_{물리명}` | 그룹 없음 | `ORD` |
| `{그룹별칭}_{물리명}` | 물리명 비었음 | `MBR` |
| `TB_{그룹별칭}_{그룹명}_{물리명}` | 그룹 없음(연속으로 빔) | `TB_ORD` |
| `{그룹별칭}_{물리명}` | 둘 다 비었음 | `` (빈 문자열) |
| `TB_{물리명}` | 물리명이 `A__B` | `TB_A__B` |
| `TB_{그룹별칭}_LOG` | 그룹 없음 | `TB_LOG` |
| `{그룹별칭}_LOG_{물리명}` | 그룹 없음 | `LOG_ORD` |
| `TB_{그룹별칭}__LOG` | 그룹 없음 | `TB_LOG` |
| `TB_{그룹별칭}_{그룹명}` | 그룹 없음(뒤에 리터럴 없음) | `TB` |
| `{물리명}{그룹별칭}` | 물리명이 `ORD_`, 그룹 없음 | `ORD_` |

⚠️ 「부분 이름 안의 연속 밑줄」 줄이 **정규식 후처리(`_{2,}` → `_`)로 흉내내지 않는** 이유다 —
구분자가 `_` 가 아닐 수 있고, 부분 이름 안에 사용자가 일부러 넣은 연속 밑줄까지 접힌다.

⚠️ **지우는 단위는 「밑줄」이지 「리터럴 토큰 하나」가 아니다.** 변수 뒤 리터럴이 `_` 하나가 아니라
`_LOG` 여도 낱말은 남는다 — `TB_{그룹별칭}_LOG` 는 별칭이 있으면 `TB_MBR_LOG`, 비면 `TB_LOG` 다.
표 마지막 세 줄이 그 경계를 함께 적은 것이다: 밑줄이 여럿이면 **전부** 지우고, 뒤에 리터럴이 없으면
앞 리터럴 말미의 밑줄을 지우되 **연속으로 빈 자리는 건너뛰며 계속 훑는다**(`TB_{A}_{B}` 가 둘 다
비면 `TB_` 가 아니라 `TB`). 그리고 **변수 값은 손대지 않는다** — 사용자가 물리명을 `ORD_` 로 넣었으면
말미 밑줄이 살아남는다.

⚠️ **밑줄이 아닌 구분자는 남는다.** `TB_{그룹별칭}-LOG` 에서 별칭이 비면 `TB_-LOG` 가 된다.
「글자·숫자가 아닌 문자」로 넓히지 않는 이유는 **논리명 템플릿의 리터럴이 한글이기 때문이다**
(`{그룹명} 소속 {논리명}`). 넓히면 한글 리터럴을 먹는다. 밑줄이 아닌 구분자를 쓰려면 그 자리를
비우지 않도록 형식을 짜라.

#### 경계

- **부분이 비어도 접두가 있으면 유효한 이름이다.** `TB_{그룹별칭}_{물리명}` 에서 물리명이 비어도
  `TB_MBR` 이 나가므로 DDL 에서 제외하지 않는다. 다만 「필수 항목이 비었다」 경고는 그대로 뜬다 —
  내보내기를 막지는 않되 채우라고 알린다. 조합 결과까지 비면 그때는 제외하고 경고한다.
- **중복은 최종 이름 기준이다.** 다른 그룹의 같은 부분 이름(`ORD`)은 최종 이름이 갈리므로 중복이
  아니다. 반대로 부분이 달라도 조합 결과가 같으면 중복이다 — 실제 DB 에서 충돌하는 것은 최종 이름이다.
- **왕복은 머릿말이 있을 때만 닫힌다.** 우리가 내보낸 파일에는 부분을 적은 주석 한 줄이 머리에
  실려 있어 되읽으면 `ORD` 로 돌아온다. 그 줄이 없으면(남의 DDL·머릿말을 지운 파일) `TB_MBR_ORD`
  가 통째로 물리명(부분)이 된다 — **역분해는 여전히 하지 않는다**. 아래 「왕복」 절을 보라.
- **컬럼에는 템플릿을 의도적으로 두지 않는다.** 「아직 안 만들었다」가 아니다. 근거 셋 —
  ① 이 체계에서 **컬럼 물리명은 표준용어의 물리명 그 자체**인데(위 3단 체계 표), 접두가 붙으면
  최종 이름이 표준용어와 **정의상 항상** 어긋나고 용어 불일치 검사는 부분 기준이라 **경고조차 뜨지
  않는다** — 표준을 벗어난 이름이 조용히 산출물로 나간다. ② 테이블 템플릿을 정당화한 「중복은 최종
  기준」의 대응물이 없다 — 컬럼 물리명 중복은 같은 테이블 안에서만 보는데 접두는 그 안에서 상수라
  판정이 한 건도 안 바뀐다. ③ 왕복을 닫는 비용이 남는 값(길이·예약어 검사)보다 크다.
  **뒤집을 조건과, 뒤집을 때 쓸 설계**는
  [결정 문서](superpowers/specs/2026-08-20-column-name-template-decision.md)에 있다.
  테이블 논리명에는 템플릿이 있다 — 아래 절.

### 테이블 논리명 형식(템플릿)

테이블의 **최종 논리명**을 조합한다. 프로젝트 설정의 「테이블 논리명 형식」에 틀을 적으면 DDL 코멘트·
DBML note·Excel 논리명 열이 조합된 이름을 쓴다. **비우면 조합하지 않고 입력한 논리명을 그대로 쓴다**
(기존 동작 그대로가 기본값이다).

예: 형식이 `{그룹명}_{논리명}` 이고 그룹 이름이 `회원관리`, 입력한 논리명이 `주문` 이면 → `회원관리_주문`.

**변수 다섯과 빈 구간 접기 규칙은 물리명 형식과 완전히 같다**(위 두 절). 조합 몸통이 하나다.

#### ⚠️ 산출물 전용이다

| 자리 | 쓰는 값 |
|---|---|
| DDL 코멘트(`COMMENT ON TABLE`·mysql 인라인)·경고 라벨 폴백 | **조합** |
| DBML note | **조합** |
| Excel 정의서(테이블 목록의 논리명 열·테이블 정의서의 「테이블 논리명」 열) | **조합** |
| 용어 사전 조회·미등록 단어 검사·논리 구분자 경고 | **부분** |
| 물리명 재생성(`generatePhysicalName`) | **부분** |
| 편집 패널 입력란·사이드바 트리·캔버스·CLI 파일 | **부분** |

사전·검사·재생성이 부분 기준인 이유:

- **사전**: 조합 이름으로 사전을 찾으면 사용자가 **조합된 이름**(`회원관리_주문`)을 등록해야 한다.
  형식을 바꾸는 순간 사전 전체가 어긋난다.
- **재생성**: 조합 논리명으로 물리명을 만들면 그룹 약어가 물리명 부분에 들어가고, 거기에 물리명
  템플릿의 접두가 다시 붙어 **이중 적용**된다.

⚠️ `warnings.ts` 나 `generatePhysicalName` 경로에서 `composeTableLogicalName` 을 부르면 설계 D1 위반이다.

#### 경계

- **`{물리명}` 은 조합 물리명이 아니라 부분이다.** 논리 형식에 `{물리명}` 을 써도 물리명 템플릿이
  적용되기 전의 저장값이 들어간다. 변수는 언제나 **저장된 부분**을 돌려주므로 두 템플릿이 서로를
  참조해도 재귀가 원리적으로 성립하지 않는다.
- **「논리명 == 물리명이면 코멘트 생략」 판정은 양쪽 다 최종 이름으로 한다.** 한쪽만 조합하면 최종
  산출물에서 같은 이름인데도 코멘트가 한 번 더 나간다.
- **왕복은 머릿말이 있을 때만 닫힌다.** 머릿말은 논리명 부분도 함께 싣는다 — 되읽을 때 **머릿말이
  코멘트를 이긴다**. 코멘트에는 조합된 논리명이 들어 있기 때문이다(설명은 코멘트에서 그대로 가져온다).
  머릿말이 없으면 조합 논리명이 통째로 논리명(부분)에 박힌다 — 물리명과 같은 성질이다.
- **단어사전·용어사전 시트의 논리명은 조합되지 않는다.** 그 열은 `Word`·`Term` 의 것이지 테이블의
  것이 아니다.

### 왕복 — 내보낸 파일을 되읽으면 부분이 돌아온다

내보낸 DDL·DBML 의 **머리에 주석 한 줄**이 실린다. 조합된 최종 이름에서 사용자가 입력한 **부분**으로
되돌리는 표이고, **그룹 배정과 그룹 속성**도 함께 나른다.

```
-- erdd:v2 {"t":{"TB_MBR_ORD":{"p":"ORD","l":"주문","g":"회원"}},"g":{"회원":{"a":"MBR","c":"#4A90D9","n":"회원 도메인"}}}
CREATE TABLE TB_MBR_ORD (…);
```

`t` 는 「조합된 최종 물리명 → 물리 부분(`p`)·논리 부분(`l`)·속한 그룹 이름(`g`)」이고, `g` 는
「그룹 이름 → 별칭(`a`)·색(`c`)·코멘트(`n`)」다. **빈 값은 키를 생략한다**(머릿말을 짧게 유지한다).

DBML 은 접두만 갈린다(`// erdd:v2 …`). 그 줄은 `Project` 블록보다 **앞**에 온다 — 파서가 첫 비주석
줄에서 멈추므로 뒤에 있으면 안 읽힌다.

가져오기는 이 표를 보고 물리명·논리명을 부분으로 되돌린다. **역분해가 아니다** — 접두를 잘라내려고
이름을 뜯어보지 않고, 내보낼 때 적어 둔 값을 그대로 읽는다. 그래서 접두에 밑줄이 섞이든 그룹 별칭이
물리명과 겹치든 상관없이 정확하다.

**옛 `erdd:v1` 머릿말도 계속 읽는다** — 이미 내보낸 덤프가 그대로 살아야 한다. v1 은 최상위가 곧
테이블 표였고 **그룹 자리가 없다**(`-- erdd:v1 {"TB_MBR_ORD":{"p":"ORD","l":"주문"}}`). 그래서 v1
덤프에서는 이름만 돌아오고 그룹은 복원되지 않는다 — 원문에 안 적혀 있으므로 그것이 맞는 동작이다.

#### 조건과 예외

- **그룹도 템플릿도 안 쓰면 머릿말이 아예 안 나간다.** 실을 것이 없으면 줄 자체를 내지 않으므로
  그런 프로젝트의 산출물은 **한 글자도 바뀌지 않는다.** ⚠️ **「템플릿만 안 쓰면」이 아니다** —
  머릿말이 그룹 배정도 나르므로 **템플릿이 없어도 그룹에 속한 테이블이 하나라도 있으면 나간다.**
  조합해도 결과가 부분과 같고 그룹에도 안 속한 테이블은 표에서 빠진다.
- **머릿말을 지우면 옛 동작이다.** 그 줄을 지우거나 `CREATE TABLE` 한 문장만 잘라 붙이면 표가 없어
  조합된 이름이 통째로 부분이 된다.
- **이름을 손으로 고치면 그 테이블만 옛 동작이다.** 표의 키(조합된 이름)와 실제 `CREATE TABLE` 의
  이름이 안 맞으면 그 항목은 무시된다.
- **깨진 머릿말은 통째로 무시한다.** JSON 이 깨졌거나 모르는 버전(`erdd:v3`)이면 표가 없는 것으로
  보고 넘어간다 — 가져오기가 실패하지는 않는다. 마커 뒤에 공백이 없는 줄(`-- erdd:v2{…}`)도
  머릿말로 보지 않는다.
- **복원되는 것은 테이블의 물리명·논리명 + 그룹 배정 + 그룹의 별칭·색·코멘트다.**
  **복원하지 않는 것은 명명 규칙(템플릿) 자체 · 그룹 좌표 · 컬럼**이다. 규칙을 안 실으므로 가져오는
  쪽 프로젝트의 규칙이 그대로 적용된다 — 템플릿이 없으면 부분 이름 그대로 보이고, 걸면 그때
  조합된다. 컬럼에는 템플릿이 없으므로(위 「경계」) 해당 사항이 없다.
- **같은 이름의 그룹이 이미 있으면 그 그룹에 넣고 속성을 덮어쓰지 않는다.** 머릿말은 「그 그룹에
  넣어라」까지만 말한다. 다만 **별칭이 다르면 경고한다** — 별칭은 `{그룹별칭}` 으로 물리명 조합에
  들어가 **최종 이름을 바꾸므로**, 조용히 갈리면 사용자가 보는 이름이 원본과 달라지는데 이유를 알
  길이 없다. 색·코멘트는 표시용이라 갈려도 경고하지 않는다(전부 경고하면 진짜 신호가 묻힌다).
- **DBML 의 `TableGroup` 블록과 겹치면 머릿말이 이긴다.** 별칭은 머릿말에만 있고, 머릿말은 우리가
  쓴 것이 확실한 반면 블록은 사람이 손댔을 수 있다. 블록에만 있는 그룹은 그대로 살린다 — 남이 준
  DBML 은 머릿말이 없어 지금까지의 동작 그대로다.
- **복원된 이름이 기존 테이블과 부딪히면 건너뛴다.** 충돌은 DDL 원문 이름이 아니라 **실제로
  만들어질 이름**으로 보고, 키는 **(그룹, 부분 이름) 쌍**이다 — 그룹이 갈라 주면 원본에서 정상
  공존하던 두 테이블(`TB_MBR_ORD`·`TB_PRD_ORD`, 부분은 둘 다 `ORD`)이 서로를 밀어내지 않는다.
  ⚠️ **그룹 자리가 없는 v1 머릿말에서는 그 둘이 여전히 부딪힌다**(원문에 그룹이 없어 키의 그룹이
  빈 문자열이 된다).

### 물리명 자동생성 플로우

컬럼(또는 테이블) 논리명 입력 시:

1. **용어 완전 일치** — 용어사전에 논리명이 있으면 그 물리명과 기본 도메인을 제안.
2. **단어 분해 조합** — 없으면 논리명을 단어사전 기준 최장 일치 우선으로 분해(예: "회원상태코드" → 회원+상태+코드)하고, 각 단어의 약어를 구분자로 조합해 물리명 생성. 이때 "용어로 등록" 버튼으로 결과를 용어사전에 축적할 수 있다.
3. **분해 실패** — 사전에 없는 단어가 포함되면 해당 부분을 경고 배지로 표시. 물리명은 사용자가 직접 입력하고, 인라인으로 단어 등록을 유도한다.
4. 자동 제안 후에도 물리명은 항상 수동 수정 가능. 사전과 불일치하면 경고 배지만 표시한다(저장 허용).

역방향(물리명 → 논리명)도 같은 사전으로 대칭이다. 조립할 때는 논리명 구분자로 잇는다
(`MBR_ORD_NO` → `회원_주문_번호`).

**상대 필드를 채우는 경로는 넷이고, 덮어쓰기는 blur 만 제외한다.**

| 경로 | 상대 필드 | 커밋 |
|---|---|---|
| 다른 곳으로 포커스가 옮겨갈 때(blur) | **비어 있을 때만** | O |
| Enter | 덮어쓴다 | O |
| 자동완성 확정 | 덮어쓴다 | **X — 화면만** |
| 화살표 버튼 | 덮어쓴다 | O |

blur 는 필드를 스쳐 지나가기만 해도 발생한다 — 손으로 정한 물리명이 Tab 한 번에 날아가면 안 된다.
나머지 셋은 사용자가 명시적으로 한 동작이다.

**단, 넷 모두 「편집이 없으면 아무 일도 하지 않는다」가 앞선다.** 값을 고치지 않은 채 Enter 만 치거나
포커스를 스쳐 지나가면 커밋도 없고 상대 필드도 그대로다 — Revision 이 남지 않는다. 「Enter 는 덮는다」는
**고친 값을 확정할 때**의 규칙이지, 아무것도 안 고친 Enter 까지 덮으라는 뜻이 아니다(그것은 blur 를
덮어쓰기에서 뺀 근거와 같은 성격의 사고다).

⚠️ 판정은 **내 필드의 값만** 보지 않는다. 자동완성 확정이 상대 필드를 바꿔 둔 뒤 내 값을 원래대로
되돌린 경우, 내 기준으로는 「안 고쳤다」지만 화면에 보이는 상대 값은 아직 저장되지 않았다 — 그때는
커밋한다.

### 이름을 치는 자리에서 사전을 완성한다

명명은 사전을 먼저 채우고 이름을 짓는 순서가 아니다 — 이름을 치다 사전에 없는 단어를 만나는 것이
정상 동선이고, 그 자리에서 사전이 자란다. 편집 패널의 테이블·컬럼 이름 입력이 이 흐름을 담는다.

- **자동완성** — 논리명에서는 단어 논리명과 용어를, 물리명에서는 약어와 용어 물리명을 접두일치로
  제안한다. 확정은 저장이 아니라 그 구간의 치환이라 이어서 다음 단어를 칠 수 있다.
  - **단어**는 입력 중인 이름에서 **아직 사전에 매칭되지 않은 꼬리 한 조각**을 쿼리로 삼는다.
    꼬리가 없으면(= 사전 단어로 딱 떨어지면) 단어 후보를 내지 않는다 — 그러지 않으면 한 글자마다
    사전 전체가 뜬다.
  - **용어는 입력 전체**로 찾는다. 용어의 적용 규칙이 논리명 전체 완전일치이므로 꼬리 조각으로
    찾으면 의미가 달라진다. **그래서 꼬리가 없어도 용어 후보는 나온다** — 「회원주문」까지 쳤을 때
    용어 「회원주문번호」가 가장 값진 후보인데, 하필 그때가 사전 단어로 딱 떨어지는 순간이다.
  - 한 번에 8개까지 보이고 그중 용어는 최대 3개다 — 용어가 많은 프로젝트에서 단어 후보가 밀려나지
    않게 칸을 나눠 둔다.
- **미등록 칩과 인라인 등록** — 저장된 이름에서 사전에 없는 구간을 칩으로 상시 보여 주고, 칩을 누르면
  그 자리에서 등록한다(논리명 쪽은 약어를, 물리명 쪽은 논리명을 받는다). 사전 화면의 일괄 등록과
  **같은 단어 등록 경로**이고, 등록과 함께 반대편 이름이 비어 있으면 같은 편집 한 건으로 채운다.
- 칩은 **저장된 값** 기준, 자동완성은 **입력 중인 값** 기준이다 — 역할을 갈라 두지 않으면 타이핑 중
  마지막 구간이 늘 미등록이라 칩이 깜박인다.

### 경고 체계

- 경고 종류: 미등록 단어 포함, 용어-물리명 불일치, 최대 길이 초과, 예약어 사용, 물리명 중복(이건 오류 수준으로 강조하되 저장은 허용), **논리명 구분자 없음**.
- 「논리명 구분자 없음」은 **단어가 둘 이상으로 분해될 때만** 띄운다 — 단일 단어 논리명에까지 붙이면
  경고가 노이즈가 되어 신호가 죽는다.
- **테이블 물리명 형식이 걸린 프로젝트에서는 중복·최대 길이·예약어를 「조합된 최종 이름」으로 판정한다.**
  용어-물리명 불일치만 입력한 부분으로 판정한다(위 「테이블 물리명 형식」 절).
- 노출 위치: 캔버스 노드 배지, 편집 패널, 프로젝트 전체 "명명 검사" 화면(경고 모아보기, 항목별 바로가기).

### 사전 관리 화면

- 단어/용어/도메인 탭별 목록: 검색, 추가/수정/삭제, Excel 일괄 업로드(→ [17-import-export](17-import-export.md)).
- **사용처 조회**: 단어·용어가 어떤 테이블/컬럼에서 쓰이는지 역참조 목록.
- 용어 수정 시 사용 중인 컬럼에 변경 반영 여부를 선택(일괄 반영 / 유지).
- **미등록 항목 모아보기**: 경고 상태인 후보를 모아 일괄 등록. **방향별 하위 탭 2개**(「논리명 → 약어」·
  「물리명 → 논리명」)로 가르고, 두 방향은 방향 값만 다른 한 컴포넌트가 그린다 — 등록 규칙이 갈릴
  자리를 만들지 않는다. 낱개 등록은 편집 패널의 미등록 칩이 맡는다(이 화면은 모아 처리 전용이다).
  ⚠️ **역방향은 사용자가 논리명을 직접 치므로 중복이 생길 수 있다** — 사전에 이미 있는 이름이나 배치
  안에서 서로 겹치는 이름은 그 행에 사유를 표시하고 등록에서 뺀다. 정방향은 후보가 미등록 목록에서
  오므로 정의상 중복이 아니다.

### 공용 사전 가져오기와 재동기화

[01-concepts](01-concepts.md#공용-리소스-패턴-복사fork--재동기화)의 공통 패턴을 따른다.

- 서비스 전역 리소스: 행안부 표준 단어사전 등 공공 표준을 ERDD이 큐레이션해 제공.
- 조직 리소스: 조직 표준 사전을 만들어 여러 프로젝트에서 재사용.
- 프로젝트에서 가져온 뒤 자유 수정, 원본 갱신 시 수동 재동기화(충돌 항목별 선택).
