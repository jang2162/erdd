# 도메인

## 목적

컬럼 타입을 도메인(타입의 표준 정의)으로 관리해, DB 방언별 타입 매핑과 타입 일관성을 한곳에서 통제한다.

## 사용자 시나리오

- 설계자가 도메인 "금액"을 만들고 방언별 타입(PostgreSQL `numeric(15)`, Oracle `NUMBER(15)` 등)을 정의한다.
- 컬럼에 도메인 "금액"을 지정하면 타입이 자동 결정되고, DDL 내보내기 시 대상 방언에 맞는 타입이 출력된다.
- 금액 정밀도 정책이 바뀌어 도메인을 `numeric(18,2)`로 수정하자, 사용 중인 47개 컬럼에 일괄 반영된다.

## 기능 상세

### 도메인 정의

| 속성 | 설명 |
|---|---|
| 이름 | 예: 금액, 일자, 여부, 명, 번호 |
| 분류 | 도메인 그룹(예: 숫자/문자/일시/코드) — 목록 정리용 |
| 논리 데이터 타입 | 방언 중립 표기(예: `DECIMAL(15)`, `VARCHAR(100)`, `CHAR(1)`) |
| 방언별 물리 타입 | PostgreSQL / MySQL·MariaDB / Oracle / MSSQL 각각의 타입. 미지정 방언은 논리 타입에서 기본 변환 |
| 기본값 | 선택 |
| 허용값 | 선택. 예: 여부 도메인 `Y/N` — DDL의 CHECK 제약으로 출력 |
| 설명 | 선택 |

### 컬럼과의 관계

- 컬럼은 도메인을 참조하거나, 도메인 없이 직접 타입을 입력한다. **도메인은 권장 사항**이며 미지정에 경고를 주지 않는다.
- 도메인 지정 시 타입 입력란은 도메인 값으로 잠기고, 해제하면 직접 입력으로 전환.
- 용어(Term)에 기본 도메인이 연결되어 있으면 논리명 입력 시 함께 자동 제안된다(→ [13-naming](13-naming.md)).

### 일괄 반영

- 도메인 수정 시 사용 중인 컬럼 수와 목록을 보여주고 확인 후 일괄 반영. 반영은 Revision 1건으로 기록된다.
- 도메인 삭제는 사용 중인 컬럼이 없을 때만 허용(사용처 목록 안내).

### 공용 도메인

[01-concepts](01-concepts.md#공용-리소스-패턴-복사fork--재동기화)의 공통 패턴을 따른다. 서비스 전역의 표준 도메인 세트(공공 표준 기반)와 조직 도메인 세트를 프로젝트로 가져와 사용한다.
