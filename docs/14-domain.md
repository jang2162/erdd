# 도메인과 타입 체계

## 목적

컬럼 타입의 기반이 되는 **논리 타입 체계**(방언 중립 타입과 4방언 변환)를 정의하고, 그 위에 도메인(타입의 표준 정의)으로 타입 일관성을 한곳에서 통제한다.

## 사용자 시나리오

- 설계자가 도메인 "금액"을 만들고 방언별 타입(PostgreSQL `numeric(15)`, Oracle `NUMBER(15)` 등)을 정의한다.
- 컬럼에 도메인 "금액"을 지정하면 타입이 자동 결정되고, DDL 내보내기 시 대상 방언에 맞는 타입이 출력된다.
- 금액 정밀도 정책이 바뀌어 도메인을 `numeric(18,2)`로 수정하자, 사용 중인 47개 컬럼에 일괄 반영된다.

## 기능 상세

### 논리 타입 체계 (Phase 1)

방언 중립의 논리 타입 17종. 직접 입력 컬럼의 타입 표기이자, 도메인의 "논리 데이터 타입" 표기이며, DDL 내보내기의 변환 원천이다. 파서·변환기는 `packages/core`에 위치한다(→ [02-architecture](02-architecture.md)).

**입력 정책 — 관대한 파싱.** 타입 입력란은 텍스트 + 자동완성이다.

- 파서는 대소문자를 무시하고 흔한 별칭을 수용한다(`INTEGER`→`INT`, `NUMERIC`/`NUMBER(p,s)`→`DECIMAL`, `VARCHAR2`→`VARCHAR`, `TIMESTAMP`→`DATETIME`, `BOOL`→`BOOLEAN` 등).
- 해석 성공 시 **정규형으로 정규화해 저장**한다(예: `varchar2(100)` → `VARCHAR(100)`). diff·산출물 표기가 일관돼진다.
- 해석 실패 시 **입력 원문 그대로 저장하고 "방언 변환 불가" 경고 배지**를 표시한다(저장 허용). DDL에는 모든 방언에 원문을 그대로 출력한다 — PostGIS `geometry` 같은 벤더 타입을 수용하는 통로.
- `CHAR(n)`·`VARCHAR(n)`은 길이 필수, `DECIMAL(p[,s])`은 s 생략 시 0. 문법에 맞지 않으면 해석 실패로 취급한다.

**기본 변환 표.** 직접 입력 컬럼의 방언 변환이자, 도메인에서 방언별 타입을 지정하지 않았을 때의 기본 변환.

| 논리 타입 | PostgreSQL | MySQL/MariaDB | Oracle | MSSQL |
|---|---|---|---|---|
| `CHAR(n)` | char(n) | CHAR(n) | CHAR(n) | NCHAR(n) |
| `VARCHAR(n)` | varchar(n) | VARCHAR(n) | VARCHAR2(n) | NVARCHAR(n) |
| `TEXT` | text | LONGTEXT | CLOB | NVARCHAR(MAX) |
| `SMALLINT` | smallint | SMALLINT | NUMBER(5) | SMALLINT |
| `INT` | integer | INT | NUMBER(10) | INT |
| `BIGINT` | bigint | BIGINT | NUMBER(19) | BIGINT |
| `DECIMAL(p,s)` | numeric(p,s) | DECIMAL(p,s) | NUMBER(p,s) | DECIMAL(p,s) |
| `FLOAT` | real | FLOAT | BINARY_FLOAT | REAL |
| `DOUBLE` | double precision | DOUBLE | BINARY_DOUBLE | FLOAT |
| `BOOLEAN` | boolean | TINYINT(1) | NUMBER(1) | BIT |
| `DATE` | date | DATE | DATE | DATE |
| `TIME` | time | TIME | TIMESTAMP ¹ | TIME |
| `DATETIME` | timestamp | DATETIME | DATE ² | DATETIME2 |
| `TIMESTAMPTZ` | timestamptz | TIMESTAMP | TIMESTAMP WITH TIME ZONE | DATETIMEOFFSET |
| `BLOB` | bytea | LONGBLOB | BLOB | VARBINARY(MAX) |
| `JSON` | jsonb | JSON | CLOB ³ | NVARCHAR(MAX) |
| `UUID` | uuid | CHAR(36) | RAW(16) | UNIQUEIDENTIFIER |

¹ Oracle에는 TIME이 없어 TIMESTAMP로 매핑하고 경고를 표시한다. ² Oracle DATE는 초 단위까지 포함하는 한국 실무 관례를 따른다. 밀리초가 필요하면 도메인에서 TIMESTAMP로 오버라이드. ³ 구버전 호환 우선(21c+의 JSON 타입은 도메인 오버라이드로 사용). MSSQL 문자열은 한글 안전성을 위해 N계열(NCHAR/NVARCHAR)을 기본으로 한다.

**자동증가(auto-increment).** 컬럼 속성으로 지정한다. 정수형(`SMALLINT`/`INT`/`BIGINT`) PK에서만 유효하고 그 외에는 경고. DDL 출력: PostgreSQL·Oracle `GENERATED BY DEFAULT AS IDENTITY`, MySQL `AUTO_INCREMENT`, MSSQL `IDENTITY(1,1)`.

### 도메인 정의

| 속성 | 설명 |
|---|---|
| 이름 | 예: 금액, 일자, 여부, 명, 번호 |
| 분류 | 도메인 그룹(예: 숫자/문자/일시/코드) — 목록 정리용 |
| 논리 데이터 타입 | 위 논리 타입 체계의 문법을 따름(예: `DECIMAL(15)`, `VARCHAR(100)`, `CHAR(1)`) |
| 방언별 물리 타입 | PostgreSQL / MySQL·MariaDB / Oracle / MSSQL 각각의 타입. 미지정 방언은 기본 변환 표를 적용 |
| 기본값 | 선택 |
| 허용값 | 선택. 예: 여부 도메인 `Y/N` — DDL의 CHECK 제약으로 출력 |
| 설명 | 선택 |

### 컬럼과의 관계

- 컬럼은 도메인을 참조하거나, 도메인 없이 직접 타입을 입력한다. **도메인은 권장 사항**이며 미지정에 경고를 주지 않는다.
- 도메인 지정 시 타입 입력란은 도메인 값으로 잠기고, 해제하면 직접 입력으로 전환.
- 용어(Term)에 기본 도메인이 연결되어 있으면 논리명 입력 시 함께 자동 제안된다(→ [13-naming](13-naming.md)).

### 일괄 반영

- 도메인 수정 시 사용 중인 컬럼 수와 목록을 보여주고 확인 후 일괄 반영. 반영은 Revision 1건으로 기록된다.
- 도메인 삭제는 사용 중인 컬럼이 없을 때만 허용(사용처 목록 안내).

### 공용 도메인

[01-concepts](01-concepts.md#공용-리소스-패턴-복사fork--재동기화)의 공통 패턴을 따른다. 서비스 전역의 표준 도메인 세트(공공 표준 기반)와 조직 도메인 세트를 프로젝트로 가져와 사용한다.

## 단계별 범위

- **Phase 1**: 논리 타입 체계 전체(파서, 정규화, 기본 변환 표, 자동증가), 컬럼 직접 타입 입력. 도메인 없이도 에디터·DDL 내보내기가 동작해야 한다.
- **Phase 2**: 도메인 정의·지정·일괄 반영, 공용 도메인 세트.
